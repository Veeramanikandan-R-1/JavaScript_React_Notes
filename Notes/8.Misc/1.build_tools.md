# Build Tools — React Interview Notes

For a **5-year React developer**, focus less on memorizing commands and more on understanding **why each tool exists, how they work together, and what happens during development/build/production**.

---

## 1. npm

**npm (Node Package Manager)** is the default package manager that comes with Node.js.

### Responsibilities

* Install/manage dependencies
* Version management
* Run project scripts
* Resolve dependency tree
* Publish packages to npm registry

### `package.json`

Defines project metadata, dependencies and scripts.

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "test": "vitest"
  },
  "dependencies": {
    "react": "^19.0.0"
  },
  "devDependencies": {
    "vite": "^7.0.0"
  }
}
```

### Install

```bash
npm install react
npm install -D eslint
```

* `dependencies` → required by application
* `devDependencies` → required during development/build/testing

### `package-lock.json`

Locks the **exact dependency tree** so different environments install consistent versions.

```bash
npm install
npm ci
```

**Interview point:**

* `npm install` → resolves/updates dependencies and may modify lockfile.
* `npm ci` → clean, reproducible install based strictly on lockfile; commonly used in CI/CD.

### Scripts

```bash
npm run dev
npm run build
npm run lint
```

Some commands have shortcuts:

```bash
npm test
npm start
```

# 2. Yarn

**Yarn** is another JavaScript package manager, alternative to npm.

```bash
yarn add react
yarn add -D eslint
yarn install
```

Uses:

```text
yarn.lock
```

instead of `package-lock.json`.

### npm vs Yarn

| npm                 | Yarn                                             |
| ------------------- | ------------------------------------------------ |
| Comes with Node.js  | Installed separately/corepack depending on setup |
| `package-lock.json` | `yarn.lock`                                      |
| `npm install`       | `yarn install`                                   |
| `npm run dev`       | `yarn dev`                                       |
| `npm install pkg`   | `yarn add pkg`                                   |

### Important

Modern Yarn has different modes/versions, notably **Yarn Berry (v2+)**, with features such as Plug'n'Play (PnP).

**Interview:** Don't say Yarn is simply "faster than npm" as a universal fact. Modern npm and Yarn have both evolved significantly.

---

# 3. pnpm

**pnpm** is a package manager focused heavily on **efficient disk usage and fast installs**.

```bash
pnpm install
pnpm add react
pnpm add -D eslint
```

Uses:

```text
pnpm-lock.yaml
```

### Key concept — Content-addressable store

Instead of every project keeping separate copies of the same package:

```text
Project A ──┐
Project B ──┼──> pnpm store
Project C ──┘
```

Packages are stored centrally and linked into projects.

### Advantages

* Less disk usage
* Faster installation in many scenarios
* Strict dependency behavior
* Excellent monorepo/workspace support

### pnpm workspace

```yaml
# pnpm-workspace.yaml
packages:
  - "apps/*"
  - "packages/*"
```

Useful for monorepos.

### npm vs Yarn vs pnpm

|                      | npm                 | Yarn                  | pnpm                   |
| -------------------- | ------------------- | --------------------- | ---------------------- |
| Lock file            | `package-lock.json` | `yarn.lock`           | `pnpm-lock.yaml`       |
| Main strength        | Standard/default    | Alternative ecosystem | Efficiency + monorepos |
| Workspaces           | ✅                   | ✅                     | ✅                      |
| Shared package store | ❌                   | Depends on setup      | ✅                      |

# 4. Vite

**Vite is a modern frontend build tool and development server.**

Commonly used with:

```bash
npm create vite@latest
```

### Why Vite?

Traditional bundlers often bundle a lot of the application before serving it during development.

Vite uses the browser's **native ES modules (ESM)** during development and transforms modules on demand.

```text
Browser
   ↓
Vite Dev Server
   ↓
Request specific module
   ↓
Transform only what's needed
```

This gives very fast startup and HMR.

### Production

Vite uses **Rollup-based production builds** (with modern Vite versions also incorporating other tooling internally for some tasks).

```bash
npm run build
```

Typical output:

```text
dist/
 ├── index.html
 ├── assets/
 │    ├── index-xxx.js
 │    └── index-xxx.css
```

### HMR

**HMR = Hot Module Replacement**

When you modify a component:

```jsx
function App() {
  return <h1>Hello</h1>;
}
```

Vite updates the affected module without requiring a complete page reload in many cases.

### Vite config

```js
// vite.config.js
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()],
  server: {
    port: 3000
  }
});
```

### Environment variables

```env
VITE_API_URL=https://api.example.com
```

```js
const url = import.meta.env.VITE_API_URL;
```

**Important:** Variables exposed to client-side code are **not secrets**.

### Interview points

Know:

* Dev server
* Native ESM
* HMR
* Plugins
* Environment variables
* Production build
* Code splitting
* Asset handling
* Vite vs Webpack

# 5. Webpack — High Level

**Webpack is a module bundler.**

It takes application modules and builds optimized bundles.

```text
src/
 ├── index.jsx
 ├── App.jsx
 ├── Button.jsx
 └── styles.css
        ↓
     Webpack
        ↓
dist/
 ├── main.js
 └── styles.css
```

### Core concepts

#### 1. Entry

Starting point of dependency graph.

```js
module.exports = {
  entry: "./src/index.jsx"
};
```

#### 2. Output

Where bundles are generated.

```js
output: {
  filename: "bundle.js"
}
```

#### 3. Loaders

Webpack itself doesn't understand every file type.

Loaders transform files.

```js
module: {
  rules: [
    {
      test: /\.css$/,
      use: ["style-loader", "css-loader"]
    }
  ]
}
```

Examples:

```text
JS/JSX → Babel
CSS → css-loader
Images → asset modules
```

#### 4. Plugins

Plugins perform broader build-level tasks.

```js
plugins: [
  new HtmlWebpackPlugin()
]
```

Examples:

* `HtmlWebpackPlugin`
* `DefinePlugin`
* `MiniCssExtractPlugin`

#### 5. Code Splitting

```js
import("./AdminPage");
```

Webpack can generate a separate chunk.

```text
main.js
admin-page.chunk.js
```

Loaded only when required.

#### 6. Tree Shaking

Removes unused exports from the production bundle when the module system/build configuration allows it.

```js
// utils.js
export const add = () => {};
export const subtract = () => {};
```

```js
import { add } from "./utils";
```

Unused code can potentially be removed from the production bundle.

### Webpack vs Vite

| Webpack                                 | Vite                                          |
| --------------------------------------- | --------------------------------------------- |
| Mature module bundler                   | Modern build tool/dev server                  |
| Bundles during traditional dev workflow | Uses native ESM during dev                    |
| Highly configurable                     | Generally simpler configuration               |
| Large ecosystem                         | Modern plugin ecosystem                       |
| Can be complex                          | Faster/simple dev experience in many projects |

**Interview one-liner:**

> Webpack is primarily a highly configurable module bundler, while Vite focuses on a fast native-ESM development experience and optimized production builds.

# 6. Babel

**Babel is a JavaScript compiler/transpiler.**

It converts modern JavaScript/JSX into code compatible with the desired target environments.

### Example

Input:

```jsx
const App = () => <h1>Hello</h1>;
```

Babel can transform JSX into JavaScript representation that the runtime can execute.

Modern Babel may produce output conceptually similar to:

```js
const App = () => React.createElement("h1", null, "Hello");
```

> Exact React JSX output depends on the configured JSX transform.

### Presets

A preset is a collection of Babel plugins/configuration.

Common:

```text
@babel/preset-env
@babel/preset-react
```

Example:

```js
module.exports = {
  presets: [
    "@babel/preset-env",
    "@babel/preset-react"
  ]
};
```

### Important distinction

**Babel ≠ bundler**

```text
Babel
  ↓
Transforms source code

Webpack/Vite
  ↓
Builds/bundles/transforms assets
```

Modern Vite React setups may use **esbuild or SWC** for some transformations depending on configuration/plugins, so don't assume every Vite project uses Babel.

### Babel vs TypeScript

TypeScript compiler can perform type checking and transpilation, but:

```text
TypeScript → type checking
Babel → transformation
```

Babel generally **does not type-check TypeScript**.

# 7. ESLint

**ESLint is a static code analysis/linting tool.**

It identifies:

* Bugs
* Bad patterns
* Code-quality issues
* Style problems
* React-specific issues

Example:

```js
const user = "John";

console.log(username);
```

ESLint can detect:

```text
'username' is not defined
```

### Configuration

Modern ESLint commonly uses:

```text
eslint.config.js
```

Example:

```js
export default [
  {
    rules: {
      "no-unused-vars": "error",
      "no-console": "warn"
    }
  }
];
```

### Levels

```text
"off"
"warn"
"error"
```

### React

ESLint can be extended with React-specific plugins/configurations.

Examples of rules:

```text
react/jsx-key
react-hooks/rules-of-hooks
react-hooks/exhaustive-deps
```

### Run

```bash
npm run lint
```

### ESLint vs TypeScript

```text
TypeScript
   ↓
Type correctness

ESLint
   ↓
Code quality / patterns / potential bugs
```

They complement each other.

# 8. Prettier

**Prettier is an opinionated code formatter.**

It handles formatting such as:

* Indentation
* Quotes
* Semicolons
* Line wrapping
* Trailing commas
* Consistent formatting

Before:

```js
const user={name:"John",age:25}
```

After Prettier:

```js
const user = {
  name: "John",
  age: 25,
};
```

### Configuration

```json
{
  "semi": true,
  "singleQuote": true,
  "tabWidth": 2,
  "printWidth": 100
}
```

### Run

```bash
npx prettier . --write
```

### ESLint vs Prettier

This is a very common interview question.

| ESLint                      | Prettier                    |
| --------------------------- | --------------------------- |
| Linting                     | Formatting                  |
| Finds code-quality problems | Makes formatting consistent |
| Can enforce coding rules    | Opinionated formatting      |
| Can detect potential bugs   | Doesn't aim to detect bugs  |

Typical setup:

```text
Developer writes code
       ↓
Prettier → formatting
       ↓
ESLint → quality/lint rules
       ↓
Build/Test
       ↓
Deploy
```

Modern ESLint/Prettier integrations should avoid overlapping formatting rules.

# How Everything Fits Together

A typical React project:

```text
              package.json
                    │
       ┌────────────┼────────────┐
       ↓            ↓            ↓
      npm          ESLint      Prettier
       │
       ↓
   Dependencies
       │
       ↓
      Vite
       │
       ├──────────→ Dev Server + HMR
       │
       ↓
   Build Process
       │
       ├── Transform JS/JSX
       ├── Process CSS/assets
       ├── Tree Shaking
       ├── Code Splitting
       └── Minification
       │
       ↓
     dist/
       │
       ↓
   Production
```

# ⭐ Important Interview Questions

### 1. npm vs npx?

```bash
npm install package
```

Installs a package.

```bash
npx create-vite
```

Runs a package executable, typically without requiring a global installation.

---

### 2. npm vs pnpm?

**npm** is the standard Node package manager.

**pnpm** uses a shared content-addressable store and linking strategy to reduce disk usage and improve dependency installation efficiency.

---

### 3. Vite vs Webpack?

> Vite provides a fast development server using native ESM and performs an optimized production build; Webpack is a highly configurable module bundler that builds a dependency graph and bundles modules.

---

### 4. What does Babel do?

> Babel transforms modern JavaScript/JSX syntax into JavaScript suitable for configured target environments. It is a compiler/transformation tool, not primarily a bundler or type checker.

---

### 5. ESLint vs Prettier?

> ESLint checks code quality and coding rules; Prettier formats code consistently.

---

### 6. What is HMR?

> Hot Module Replacement updates changed modules during development without requiring a full page reload in many cases.

---

### 7. What is tree shaking?

> Tree shaking removes unused code from the production dependency graph/bundle when static analysis and module semantics allow it.

```js
import { add } from "./math";
```

If `subtract` isn't used, the build may remove it.

---

### 8. What is code splitting?

Breaking a large JavaScript bundle into smaller chunks that can be loaded when needed.

```js
const Admin = lazy(() => import("./Admin"));
```

Conceptually:

```text
Initial Load
   ↓
main.js

User opens Admin
   ↓
admin.chunk.js
```

## 🔥 30-Second Mental Model

Remember this:

```text
npm / Yarn / pnpm
        ↓
Package management
        ↓
Vite / Webpack
        ↓
Development + Build
        ↓
Babel / SWC / esbuild
        ↓
Code transformation
        ↓
ESLint
        ↓
Code quality
        ↓
Prettier
        ↓
Code formatting
        ↓
Production bundle
```

**Most important distinction:**

> **Package manager → npm/Yarn/pnpm**
> **Build tool/bundler → Vite/Webpack**
> **Compiler/transpiler → Babel**
> **Linter → ESLint**
> **Formatter → Prettier**
