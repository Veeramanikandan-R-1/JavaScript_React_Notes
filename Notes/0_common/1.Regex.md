# 1. What is Regex?

**Regex (Regular Expression)** is a pattern used to **search, match, validate, extract, or replace text**.

Think of it as a **rule** that describes what text should look like.

Example:

```
Pattern: Only digits

12345   ✅
987654  ✅
abc123  ❌
```

---

## Why do React Developers Use Regex?

Common use cases:

* Form validation
* Password validation
* Email validation
* Phone number validation
* Search filtering
* String replacement
* Parsing URLs
* Input sanitization

Example:

```javascript
const regex = /^[0-9]+$/;

regex.test("12345"); // true
regex.test("abc");   // false
```

# 4. Common Regex Methods

Returns `true` or `false`.


Returns matched text.

```javascript

```


---

```javascript
"abc123".replace(/[0-9]/g, "");
```

Output

```
abc
```

---

## search()

Returns index of first match.


Output

```

```

---

## split()

```javascript
"a,b;c".split(/[,;]/);
```

Output

```
["a","b","c"]
```

## Strong Password

```javascript
/^(?=.*[A-Z])(?=.*[a-z])(?=.*\d).{8,}$/
```

Requires

* uppercase
* lowercase
* number
* minimum 8 characters

This regex:

```javascript
/^(?=.*[A-Z])(?=.*[a-z])(?=.*\d).{8,}$/
```

is commonly used for **password validation**.

### Break it down

| Part          | Meaning                                        |
| ------------- | ---------------------------------------------- |
| `^`           | Start of string                                |
| `(?=.*[A-Z])` | Must contain **at least one uppercase letter** |
| `(?=.*[a-z])` | Must contain **at least one lowercase letter** |
| `(?=.*\d)`    | Must contain **at least one digit**            |
| `.{8,}`       | Must contain **at least 8 characters**         |
| `$`           | End of string                                  |

### The important part: `(?=...)`

`(?=...)` is called a **positive lookahead**.

It checks whether something exists **without consuming characters**.

For example:

```regex
(?=.*[A-Z])
```

means:

> Starting from here, look ahead and make sure there is at least one uppercase letter somewhere in the string.

---

### Example

```javascript
const regex = /^(?=.*[A-Z])(?=.*[a-z])(?=.*\d).{8,}$/;

regex.test("Hello123"); // true
regex.test("hello123"); // false → no uppercase
regex.test("HELLO123"); // false → no lowercase
regex.test("HelloWorld"); // false → no digit
regex.test("He1abc");    // false → less than 8 characters
```

### Easy way to remember

Think of it as:

```text
^
 ↓
Must have uppercase  → (?=.*[A-Z])
Must have lowercase  → (?=.*[a-z])
Must have number     → (?=.*\d)
Must have 8+ chars   → .{8,}
 ↓
$
```

So the regex means:

> **"From beginning to end, the string must be at least 8 characters long and contain at least one uppercase letter, one lowercase letter, and one number."**

### Interview tip ⭐

The three `(?=...)` parts are **lookaheads**. They allow us to apply multiple independent conditions to the same string without consuming characters.

# Performance Considerations

* Compile and reuse regex patterns instead of creating them repeatedly in loops.
* Keep patterns as simple as possible.
* Avoid overly complex nested patterns, as they can become hard to read and may hurt performance.
* For very complex parsing tasks (HTML, JSON, XML), prefer dedicated parsers over regex.

---

# Common Mistakes

❌ Forgetting `^` and `$` when validating the whole string.

Example:

```javascript
/\d+/
```

Matches

```
abc123xyz
```

Not suitable for full validation.

Use

```javascript
/^\d+$/
```

---

❌ Forgetting the `g` flag when replacing all matches.

```javascript
text.replace(/\d/, "");
```

Removes only the first digit.

---

❌ Using regex for HTML parsing.

Use an HTML parser instead.

---

❌ Writing unreadable, extremely long regex patterns.

Keep patterns maintainable and document them if needed.

---

# Best Practices

* Use regex only where it simplifies the problem.
* Validate on both client and server.
* Reuse regex constants.
* Use descriptive variable names.

```javascript
const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
```

* Prefer browser validation (`type="email"`, `required`) for basic checks and React/business validation for application-specific rules.

# Frequently Asked Interview Questions

### 1. What is Regex?

A pattern-matching language used to search, validate, extract, and replace text.

---

### 2. What is the difference between `test()` and `match()`?

* `test()` returns `true` or `false`.
* `match()` returns the matched value(s) or `null`.

---

### 3. What do `^` and `$` mean in Regex?

* `^` matches the beginning of the string.
* `$` matches the end of the string.
* Together (`^...$`) ensure the **entire string** matches the pattern.

---

### 4. What is the difference between `*` and `+`?

* `*` = zero or more occurrences.
* `+` = one or more occurrences.

---

### 5. What is the difference between `\d` and `[0-9]`?

They are functionally equivalent; `\d` is simply a shorthand for `[0-9]`.

---

### 6. What is the purpose of the `g` flag?

It finds **all** matches instead of stopping after the first one.

---

### 7. What is the purpose of the `i` flag?

It makes matching case-insensitive.

---

### 8. How do you validate a phone number in React using Regex?

```javascript
const phoneRegex = /^\d{10}$/;

phoneRegex.test(phone);
```

---

### 9. Why shouldn't Regex alone be used for validation?

Client-side regex improves UX but can be bypassed. Important validation must also be performed on the server.

---

### 10. When should you avoid using Regex?

Avoid using regex for parsing structured formats like HTML, XML, or JSON. Use dedicated parsers instead.

### ipv4 regex

# A Correct IPv4 Regex

A commonly used regex is:

```javascript
const regex =
/^(25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)(\.(25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)){3}$/;
```

---

## How it works

Each octet is

```regex
25[0-5]
```

Matches

```text
250-255
```

---

```regex
2[0-4]\d
```

Matches

```text
200-249
```

---

```regex
1\d\d
```

Matches

```text
100-199
```

---

```regex
[1-9]?\d
```

Matches

```text
0-99
```

Examples

```text
0
5
10
25
99
```

---

Then

```regex
(\.octet){3}
```

means

```text
.first.second.third.fourth
```

---

# Testing

```javascript
const regex =
/^(25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)(\.(25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)){3}$/;

console.log(regex.test("255.255.255.255")); // true
console.log(regex.test("192.168.1.1"));     // true
console.log(regex.test("10.0.0.1"));        // true
console.log(regex.test("0.0.0.0"));         // true
console.log(regex.test("256.0.0.1"));       // false
console.log(regex.test("300.1.1.1"));       // false
console.log(regex.test("192.168.1"));       // false
console.log(regex.test("192.168.1.1.1"));   // false
```

---

## Interview Tip

You are **not expected to memorize** an IPv4 regex in a React interview. What interviewers care about is whether you can explain the logic:

* Split the IP into **4 octets**.
* Each octet must be **0–255**.
* Octets are separated by **literal dots (`\.`)**.
* Use alternation (`|`) to represent the valid numeric ranges:

  * `250–255` → `25[0-5]`
  * `200–249` → `2[0-4]\d`
  * `100–199` → `1\d\d`
  * `0–99` → `[1-9]?\d`

Being able to explain the ranges is usually more valuable than recalling the exact regex from memory.
