# Git — Interview Notes

**Git** is a **distributed version control system (VCS)** used to track code changes, collaborate with developers, and manage different versions of a project.

For a **5-year React developer**, focus on the workflow, branching, merge/rebase, conflict handling, and recovery commands.

---

## 1. Basic Git Workflow

```text
Working Directory
      ↓ git add
Staging Area
      ↓ git commit
Local Repository
      ↓ git push
Remote Repository
```

Typical workflow:

```bash
git status
git add .
git commit -m "Add login validation"
git push origin feature/login
```

### Important commands

```bash
git clone <url>       # Clone repository
git status            # Check changes
git add file.js       # Stage specific file
git add .             # Stage all changes
git commit -m "msg"   # Create commit
git push              # Push commits
git pull              # Fetch + merge
git fetch             # Download remote changes only
```

---

## 2. `git fetch` vs `git pull`

### `git fetch`

Downloads remote changes but **doesn't modify your current branch**.

```bash
git fetch origin
```

### `git pull`

Essentially:

```text
git fetch + git merge
```

```bash
git pull origin main
```

**Interview:** Prefer `fetch` when you want to inspect remote changes before integrating them.

---

## 3. Branching

Branches allow developers to work independently.

```bash
git branch
git branch feature/login
git switch feature/login
```

Modern shortcut:

```bash
git switch -c feature/login
```

Typical workflow:

```bash
git switch main
git pull

git switch -c feature/login

# Make changes

git add .
git commit -m "Implement login"

git push -u origin feature/login
```

---

## 4. Merge

Combines one branch into another.

```bash
git switch main
git merge feature/login
```

Example:

```text
main:    A---B---C
              \
feature:       D---E

After merge:

main:    A---B---C-------M
              \         /
feature:       D---E-----
```

### Merge advantages

* Preserves branch history
* Safe for shared branches
* May create a **merge commit**

---

## 5. Rebase ⭐

Moves/replays your commits on top of another branch.

```bash
git switch feature/login
git rebase main
```

Before:

```text
main:    A---B---C
              \
feature:       D---E
```

After:

```text
main:    A---B---C
                  \
feature:           D'---E'
```

### Merge vs Rebase

| Merge                            | Rebase                            |
| -------------------------------- | --------------------------------- |
| Preserves history                | Rewrites commit history           |
| Can create merge commit          | Creates linear history            |
| Safer for shared branches        | Better for local feature branches |
| Doesn't rewrite existing commits | Changes commit hashes             |

**Important:** Avoid rebasing commits that have already been shared/pushed and are being used by others, unless your team explicitly follows that workflow.

---

## 6. Merge Conflict ⭐

Occurs when Git cannot automatically determine which changes to keep.

Example:

```text
<<<<<<< HEAD
const name = "John";
=======
const name = "David";
>>>>>>> feature/login
```

Resolve manually:

```js
const name = "David";
```

Then:

```bash
git add .
git commit
```

For rebase:

```bash
git add .
git rebase --continue
```

Abort if necessary:

```bash
git merge --abort
```

or:

```bash
git rebase --abort
```

---

## 7. `git stash`

Temporarily saves uncommitted changes.

Useful when you need to switch branches without committing incomplete work.

```bash
git stash
git switch main

# Later
git switch feature/login
git stash pop
```

Useful commands:

```bash
git stash list
git stash pop
git stash apply
git stash drop
```

### `pop` vs `apply`

* `apply` → applies stash but keeps it
* `pop` → applies stash and removes it if successful

---

## 8. `git cherry-pick` ⭐

Applies a **specific commit** from another branch.

```bash
git cherry-pick abc123
```

Example:

```text
feature-A: A---B---C
                  ↑
               bug fix

feature-B: A---D
```

Cherry-pick `C`:

```text
feature-B: A---D---C'
```

Useful when you need **one particular fix** without merging the entire branch.

---

## 9. `git reset` ⭐

Moves `HEAD` to another commit.

### Soft

```bash
git reset --soft HEAD~1
```

Removes commit but **keeps changes staged**.

### Mixed — default

```bash
git reset HEAD~1
```

Removes commit and **keeps changes unstaged**.

### Hard ⚠️

```bash
git reset --hard HEAD~1
```

Removes commit **and changes** from working tree.

```text
--soft → commit removed → changes staged
--mixed → commit removed → changes unstaged
--hard → commit + changes removed
```

**Be very careful with `--hard`.**

---

## 10. `git revert` ⭐

Creates a **new commit that reverses an existing commit**.

```bash
git revert abc123
```

Example:

```text
A---B---C
        ↓ revert C

A---B---C---C'
```

### Reset vs Revert

| Reset                  | Revert                   |
| ---------------------- | ------------------------ |
| Moves HEAD             | Creates new commit       |
| Rewrites history       | Preserves history        |
| Good for local commits | Good for shared branches |
| Can remove commits     | Safely undoes changes    |

**Interview:** For a commit already pushed to a shared branch, prefer `revert` rather than `reset`.

---

## 11. Amend Commit

Modify the latest commit.

```bash
git add .
git commit --amend
```

Change commit message:

```bash
git commit --amend -m "Fix login validation"
```

Useful when you forgot to include a file or made a small mistake in the latest commit.

---

## 12. Squash Commits

Combine multiple commits into one.

```bash
git rebase -i HEAD~3
```

Example:

```text
commit 1
commit 2
commit 3
```

Squash:

```text
single clean commit
```

Commonly done before merging a feature branch to keep history clean.

---

## 13. `git log`

View commit history:

```bash
git log
```

Useful:

```bash
git log --oneline
git log --oneline --graph --all
```

Example:

```text
a12bc34 Fix login
b34cd56 Add validation
c45de67 Initial commit
```

---

## 14. `git diff`

See changes.

```bash
git diff              # Unstaged changes
git diff --staged     # Staged changes
git diff main         # Compare with main
```

---

## 15. `.gitignore`

Specifies files Git should not track.

React example:

```gitignore
node_modules/
.env
dist/
build/
coverage/
```

**Never commit secrets** such as API keys, passwords, or private credentials.

## 17. Useful Recovery Commands

### See previous commits

```bash
git reflog
```

`reflog` is extremely useful for recovering commits after operations like reset/rebase.

### Restore modified file

```bash
git restore file.js
```

### Unstage file

```bash
git restore --staged file.js
```

---

# ⭐ Most Important Interview Differences

### Merge vs Rebase

> **Merge preserves history; rebase creates a linear history by replaying commits.**

### Reset vs Revert

> **Reset rewrites/moves history; revert creates a new commit that undoes changes.**

### Fetch vs Pull

> **Fetch downloads changes; pull downloads and integrates them.**

### Stash vs Commit

> **Stash temporarily stores unfinished changes; commit permanently records changes in Git history.**

### Cherry-pick vs Merge

> **Cherry-pick takes specific commits; merge integrates the branch's history.**

# 🔥 Typical Real-World Workflow

As a React developer, you might typically do:

```bash
git switch main
git pull origin main

git switch -c feature/user-profile

# Develop React feature

git status
git add .
git commit -m "Add user profile"

git fetch origin
git rebase origin/main

# Resolve conflicts if any

git push -u origin feature/user-profile
```

Then create a **PR → Code Review → CI/CD → Merge**.

### 5-Year Interview Must Know

Focus especially on:

**Branching → Merge → Rebase → Conflicts → Stash → Cherry-pick → Reset → Revert → Squash → Fetch/Pull → Git workflow → Reflog**.
