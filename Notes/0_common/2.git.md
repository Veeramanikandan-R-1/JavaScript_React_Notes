## 1. Branching

A **branch** is an independent line of development.

Example:

```text
main
  |
  A---B---C
       \
        D---E   feature/login
```

You can work on a feature without directly changing `main`.

```bash
git switch -c feature/login
```

Typical workflow:

```text
main
 ↓
create feature branch
 ↓
develop
 ↓
commit
 ↓
PR
 ↓
merge into main
```

**Remember:**

> Branch = separate line of development.

---

# 2. Merge

**Merge combines changes from one branch into another.**

Example:

```text
main:     A---B---C
               \
feature:        D---E

             ↓ merge

main:     A---B---C-------M
               \         /
feature:        D---E----
```

Command:

```bash
git switch main
git merge feature/login
```

Git may create a **merge commit**.

### Simple definition

> Merge combines branch histories while preserving the existing history.

---

# 3. Rebase

**Rebase moves/replays your commits on top of another branch.**

Before:

```text
main:     A---B---C
               \
feature:        D---E
```

After:

```text
main:     A---B---C
                   \
feature:            D'---E'
```

Commands:

```bash
git switch feature
git rebase main
```

### Merge vs Rebase

**Merge:**

```text
A---B---C------M
     \        /
      D---E--
```

**Rebase:**

```text
A---B---C---D'---E'
```

Rebase creates a **cleaner linear history**, but it rewrites commit history.

### Important rule

> Avoid rebasing shared/public commits unless you understand the consequences.

---

# 4. Cherry-pick

**Cherry-pick takes a specific commit from another branch and applies it to your current branch.**

Example:

```text
main:     A---B---C

feature:  A---B---D---E
                 ↑
              want D
```

```bash
git switch main
git cherry-pick <commit-hash>
```

Result:

```text
main:     A---B---C---D'
```

Useful when:

* You need one specific fix.
* You don't want to merge the entire feature branch.
* You need to backport a bug fix.

**Remember:**

> Cherry-pick = take a specific commit.

---

# 5. Reset

**Reset moves the current branch's HEAD to another commit.**

Example:

```text
A---B---C---D
        ↑
```

You can move back to `B`.

```bash
git reset --soft B
```

There are three common modes:

### `--soft`

Moves HEAD but keeps changes staged.

```bash
git reset --soft HEAD~1
```

### `--mixed` — default

Moves HEAD and unstages changes, but keeps the files changed.

```bash
git reset HEAD~1
```

### `--hard`

Moves HEAD and discards changes.

```bash
git reset --hard HEAD~1
```

⚠️ Be careful with `--hard`.

### Remember

> **Reset = move/remove commits from your current branch history.**

---

# 6. Revert

**Revert creates a new commit that undoes an earlier commit.**

Suppose:

```text
A---B---C
```

You want to undo `C`.

```bash
git revert C
```

Result:

```text
A---B---C---C'
```

`C'` reverses the changes introduced by `C`.

### Reset vs Revert

This is very important:

**Reset:**

```text
A---B---C
       ↓
A---B
```

Moves history backward.

**Revert:**

```text
A---B---C---C'
```

Keeps history and adds a new commit that undoes the change.

### Interview answer

> "For shared branches like main, I'd generally prefer revert because it doesn't rewrite shared history."

---

# 7. Stash

**Stash temporarily saves uncommitted changes.**

Suppose you're working on:

```text
feature/login
```

but suddenly need to switch branches.

Instead of committing incomplete work:

```bash
git stash
```

Now your working directory is clean.

Switch branches:

```bash
git switch bugfix
```

Later:

```bash
git switch feature/login
git stash pop
```

Your changes come back.

### Useful commands

```bash
git stash
git stash list
git stash pop
git stash apply
```

### `pop` vs `apply`

```text
apply → restore stash but keep stash
pop   → restore stash and remove it
```

**Remember:**

> Stash = temporarily put unfinished changes aside.

---

# 8. Squash

**Squashing combines multiple commits into one commit.**

Suppose your feature has:

```text
A---B---C---D---E
       ↑
     feature
```

Where:

```text
B = added login
C = fixed typo
D = fixed validation
E = final cleanup
```

You may want:

```text
A---B'
```

where `B'` contains the combined changes.

### Why squash?

To create cleaner history.

Common workflow:

```text
Development
 ↓
many small commits
 ↓
Squash
 ↓
one meaningful commit
 ↓
merge/PR
```

### Interview point

> Squashing is usually done to make commit history cleaner and easier to understand.

---

# 9. Conflict Resolution

A conflict happens when Git can't automatically determine which changes to keep.

Example:

Your branch:

```js
const title = "Hello";
```

Other branch:

```js
const title = "Welcome";
```

Git may produce:

```text
<<<<<<< HEAD
const title = "Hello";
=======
const title = "Welcome";
>>>>>>> feature
```

You manually decide:

```js
const title = "Welcome";
```

Then:

```bash
git add .
git commit
```

For a **rebase**:

```bash
git add .
git rebase --continue
```

For a **merge**:

```bash
git add .
git commit
```

### Useful commands

```bash
git status
```

Find conflicted files.

After resolving:

```bash
git add <file>
```

Then continue the operation.

### Abort

If you want to cancel:

```bash
git merge --abort
```

or:

```bash
git rebase --abort
```

**Remember:**

> Conflict resolution = understand both changes, choose/combine the correct code, remove conflict markers, test, then continue.

# 🔥 Most Important Comparisons

## Merge vs Rebase

```text
Merge
→ Combines histories
→ Preserves branch structure
→ Can create merge commit

Rebase
→ Replays commits on top of another branch
→ Creates linear history
→ Rewrites commit history
```

---

## Reset vs Revert

```text
Reset
→ Moves branch pointer
→ Can rewrite history
→ Useful for local/unshared work

Revert
→ Creates a new undo commit
→ Preserves history
→ Safer for shared branches
```

---

## Cherry-pick vs Merge

```text
Cherry-pick
→ Take specific commit(s)

Merge
→ Bring the branch's changes/history together
```

---

# 🧠 1-Minute Revision

```text
Branch
→ Separate line of development

Merge
→ Combine branches

Rebase
→ Replay commits on top of another branch

Cherry-pick
→ Apply a specific commit elsewhere

Reset
→ Move HEAD/branch pointer

Revert
→ Create a new commit that undoes another commit

Stash
→ Temporarily save uncommitted changes

Squash
→ Combine multiple commits into one

Conflict
→ Git can't automatically choose between changes
```

### ⭐ For interviews, remember these 3 especially:

> **Merge vs Rebase** — preserving history vs rewriting for a cleaner history.

> **Reset vs Revert** — reset rewrites/moves history; revert adds an undo commit.

> **Cherry-pick** — selectively take a specific commit without merging the entire branch.
