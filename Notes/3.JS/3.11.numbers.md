# JavaScript - Numbers

Numbers are one of the most frequently used data types in JavaScript. As a React developer, you'll often deal with API responses, form inputs, calculations, pagination, sorting, charts, prices, and validations.

Most interview questions focus on **how strings are converted into numbers**, **precision issues**, and **using the Math object efficiently**.

---

# 1. parseInt()

## What is it?

`parseInt()` converts a **string into an integer**.

It reads characters **from left to right** until it encounters an invalid character.

```javascript
parseInt("123");      // 123
parseInt("123abc");   // 123
parseInt("abc123");   // NaN
```

---

## Syntax

```javascript
parseInt(string, radix)
```

* string → value to convert
* radix → base (2–36)

Always specify radix.

```javascript
parseInt("10", 10); // Decimal -> 10
parseInt("10", 2);  // Binary -> 2
parseInt("10", 16); // Hex -> 16
```

---

## Examples

```javascript
parseInt("45.99");      // 45
parseInt("100px");      // 100
parseInt("  20 ");      // 20
parseInt("-15");        // -15
parseInt("hello");      // NaN
```

---

## Internal Working

1. Removes leading spaces.
2. Reads characters from left.
3. Stops at first invalid character.
4. Returns parsed integer.

Example

```javascript
parseInt("123abc456");
```

Reads

```
1
12
123
(stop at 'a')
```

Returns

```
123
```

---

## Common Mistakes

### Forgetting radix

```javascript
parseInt("10");
```

Better

```javascript
parseInt("10", 10);
```

---

### Expecting rounding

```javascript
parseInt("4.9");
```

Result

```
4
```

It truncates instead of rounding.

Use

```javascript
Math.round(4.9);
```

# 2. parseFloat()

## What is it?

Converts a string into a floating-point number.

```javascript
parseFloat("12.34");
```

Result

```
12.34
```

---

## Examples

```javascript
parseFloat("12.45abc");   // 12.45
parseFloat("100");        // 100
parseFloat("abc12");      // NaN
```

---

## Internal Working

Reads until invalid character.

```javascript
parseFloat("10.5px")
```

Returns

```
10.5
```

---

## Difference from parseInt()

```javascript
parseInt("10.99")
```

returns

```
10
```

while

```javascript
parseFloat("10.99")
```

returns

```
10.99
```

---

# 3. Number()

## What is it?

Converts the **entire value** into a number.

Unlike `parseInt()` and `parseFloat()`, it **does not partially parse**.

---

## Examples

```javascript
Number("123");
```

```
123
```

```javascript
Number("123.45");
```

```
123.45
```

```javascript
Number(true);
```

```
1
```

```javascript
Number(false);
```

```
0
```

```javascript
Number(null);
```

```
0
```

```javascript
Number(undefined);
```

```
NaN
```

---

## Invalid conversion

```javascript
Number("123abc");
```

Result

```
NaN
```

Unlike parseInt()

```javascript
parseInt("123abc");
```

returns

```
123
```

---

## Common Usage

React form input

```javascript
const age = Number(e.target.value);
```

# parseInt vs parseFloat vs Number

| Feature                            | parseInt        | parseFloat    | Number        |
| ---------------------------------- | --------------- | ------------- | ------------- |
| Integer                            | Yes             | No            | Both          |
| Decimal                            | Removes decimal | Keeps decimal | Keeps decimal |
| Stops at invalid chars             | Yes             | Yes           | No            |
| Partial parsing                    | Yes             | Yes           | No            |
| Returns NaN if whole value invalid | No              | No            | Yes           |

Example

```javascript
parseInt("100px")
```

```
100
```

```javascript
parseFloat("100.5px")
```

```
100.5
```

```javascript
Number("100px")
```

```
NaN
```

# Floating Point Precision

JavaScript uses IEEE-754 double-precision floating-point numbers.

Example

```javascript
0.1 + 0.2
```

Result

```
0.30000000000000004
```

Not

```
0.3
```

Reason

Binary floating-point representation cannot exactly represent some decimal fractions.

---

## Solution

```javascript
Number((0.1 + 0.2).toFixed(2))
```

or compare with tolerance

```javascript
Math.abs(a - b) < Number.EPSILON
```

# Best Practices

* Prefer `Number()` when the entire input should be numeric.
* Use `parseInt(str, 10)` when extracting integers from strings like `"100px"`.
* Use `parseFloat()` when decimal values are expected.
* Always provide the radix with `parseInt()`.
* Use `Number.isNaN()` instead of the global `isNaN()`.
* Avoid direct equality checks with floating-point results.
* Prefer `**` over `Math.pow()` in modern JavaScript.
* Use `Math.floor(Math.random() * (max - min + 1)) + min` for random integers in a range.

# Common React Interview Questions (6+ Years)

### 1. What is the difference between `parseInt()`, `parseFloat()`, and `Number()`?

**Answer:** `parseInt()` returns an integer and stops parsing at the first invalid character. `parseFloat()` behaves similarly but preserves decimals. `Number()` requires the entire value to be a valid number; otherwise, it returns `NaN`.

---

### 2. Why should you pass a radix to `parseInt()`?

**Answer:** To explicitly specify the numeral system (commonly base 10) and avoid ambiguity. Use `parseInt(value, 10)`.

---

### 3. Why does `0.1 + 0.2 !== 0.3`?

**Answer:** JavaScript uses IEEE-754 floating-point representation, which cannot exactly represent some decimal fractions, leading to precision errors.

---

### 4. When would you use `Number()` instead of `parseInt()`?

**Answer:** When the entire input must be numeric (e.g., form validation or API data). Use `parseInt()` only when extracting an integer from a mixed string such as `"100px"`.

---

### 5. What is the difference between `Math.floor()`, `Math.ceil()`, `Math.round()`, and `Math.trunc()`?

**Answer:**

* `Math.floor()` → rounds down.
* `Math.ceil()` → rounds up.
* `Math.round()` → rounds to the nearest integer.
* `Math.trunc()` → removes the decimal part without rounding.

---

### 6. How do you generate a random integer between **min** and **max** (inclusive)?

```javascript
Math.floor(Math.random() * (max - min + 1)) + min;
```

---

### 7. Why should you use `Number.isNaN()` instead of the global `isNaN()`?

**Answer:** `Number.isNaN()` checks only whether the value is actually `NaN`, while the global `isNaN()` performs type coercion, which can lead to unexpected results.

---

### 8. How do you sort numbers correctly in JavaScript?

```javascript
numbers.sort((a, b) => a - b);
```

Without the comparator, `sort()` compares values as strings, resulting in incorrect numeric ordering.
