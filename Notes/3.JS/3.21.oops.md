# JavaScript — OOPs (Object-Oriented Programming)

JavaScript supports **OOP using objects, prototypes, and classes**. For interviews, focus on these **4 pillars + JS-specific concepts**.

---

## 1. Object

An **object** is a collection of properties and methods.

```javascript
const user = {
  name: "John",
  age: 30,

  greet() {
    console.log(`Hello ${this.name}`);
  }
};

user.greet();
```

* **Properties** → `name`, `age`
* **Method** → `greet()`
* `this` → refers to the object calling the method.

---

# 2. Four Pillars of OOP

## A. Encapsulation

**Bundling data + methods together** and controlling access to internal data.

### Using private fields

```javascript
class BankAccount {
  #balance = 0;

  deposit(amount) {
    this.#balance += amount;
  }

  getBalance() {
    return this.#balance;
  }
}

const account = new BankAccount();

account.deposit(1000);

console.log(account.getBalance()); // 1000
// console.log(account.#balance);  // Error
```

`#balance` is truly **private**.

### Interview point

Encapsulation helps:

* Hide internal implementation
* Prevent unwanted modification
* Expose controlled APIs

---

## B. Inheritance

A child class **inherits properties and methods from a parent class**.

```javascript
class Animal {
  eat() {
    console.log("Eating");
  }
}

class Dog extends Animal {
  bark() {
    console.log("Barking");
  }
}

const dog = new Dog();

dog.eat();  // inherited
dog.bark();
```

### `super`

Used to call parent constructor/method.

```javascript
class Animal {
  constructor(name) {
    this.name = name;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);
    this.breed = breed;
  }
}
```

**Important:** JavaScript inheritance is fundamentally **prototype-based**, even though `class` provides class-like syntax.

---

# 3. Polymorphism

**Same interface/method name → different behavior.**

### Method overriding

```javascript
class Animal {
  sound() {
    console.log("Some sound");
  }
}

class Dog extends Animal {
  sound() {
    console.log("Bark");
  }
}

class Cat extends Animal {
  sound() {
    console.log("Meow");
  }
}

const animals = [new Dog(), new Cat()];

animals.forEach(animal => animal.sound());

// Bark
// Meow
```

Same `sound()` method, different implementation.

### Common interview definition

> Polymorphism allows objects of different types to be treated through a common interface while providing their own implementation.

---

# 4. Abstraction

**Hide unnecessary implementation details and expose only what is needed.**

JavaScript doesn't have a traditional `abstract` keyword like Java.

A common approach is to define a base class that requires subclasses to implement behavior:

```javascript
class Payment {
  pay() {
    throw new Error("pay() must be implemented");
  }
}

class CreditCardPayment extends Payment {
  pay() {
    console.log("Paid using Credit Card");
  }
}

class UPIPayment extends Payment {
  pay() {
    console.log("Paid using UPI");
  }
}
```

Consumer only cares about:

```javascript
payment.pay();
```

It doesn't need to know the internal payment implementation.

---

# 5. Constructor

A constructor initializes an object.

```javascript
class User {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }
}

const user = new User("John", 30);
```

`new User()` roughly involves:

1. Create a new object
2. Link it to `User.prototype`
3. Execute constructor with `this`
4. Return the object

---

# 6. Prototype — Very Important in JavaScript

JavaScript uses **prototype-based inheritance**.

Objects can inherit properties/methods from another object through the **prototype chain**.

```javascript
const animal = {
  eat() {
    console.log("Eating");
  }
};

const dog = Object.create(animal);

dog.bark = function () {
  console.log("Barking");
};

dog.eat();   // inherited from animal
dog.bark();
```

Prototype chain:

```text
dog
 ↓
animal
 ↓
Object.prototype
 ↓
null
```

### `class` uses prototypes internally

```javascript
class Person {
  greet() {
    console.log("Hello");
  }
}
```

The `greet()` method is stored on:

```javascript
Person.prototype
```

not separately inside every instance.

---

# 7. `this`

`this` refers to the **object/context from which a function is called**.

```javascript
const user = {
  name: "John",

  greet() {
    console.log(this.name);
  }
};

user.greet(); // John
```

But arrow functions don't have their own `this`.

```javascript
const user = {
  name: "John",

  greet: () => {
    console.log(this.name);
  }
};
```

Don't use arrow functions for object methods when you need the object's `this`.

# 8. Composition vs Inheritance

Modern JavaScript/React often prefers **composition over deep inheritance**.

### Inheritance

```javascript
class Dog extends Animal {}
```

### Composition

Combine smaller behaviors:

```javascript
const canWalk = {
  walk() {
    console.log("Walking");
  }
};

const canEat = {
  eat() {
    console.log("Eating");
  }
};

const dog = {
  name: "Tommy",
  ...canWalk,
  ...canEat
};

dog.walk();
dog.eat();
```

### React connection

React strongly favors:

> **Composition over inheritance**

For example:

```jsx
<Card>
  <Button />
</Card>
```

rather than creating large inheritance hierarchies.

# 9. Access Modifiers in JavaScript

JavaScript doesn't have traditional `public/protected/private` keywords like Java.

### Public

```javascript
class User {
  name = "John";
}

const user = new User();
console.log(user.name);
```

### Private

```javascript
class User {
  #password = "1234";

  login() {
    return this.#password;
  }
}
```

`#password` cannot be accessed outside the class.

---

# 10. Static Members

Belong to the **class itself**, not individual instances.

```javascript
class MathUtil {
  static add(a, b) {
    return a + b;
  }
}

console.log(MathUtil.add(10, 20));
```

You cannot do:

```javascript
const obj = new MathUtil();

obj.add(10, 20); // ❌
```

Common examples:

```javascript
Array.isArray([]);
Object.keys({});
Math.max(10, 20);
```

These are static methods.

---

# 11. Getter / Setter

Used to control property access.

```javascript
class User {
  constructor(name) {
    this._name = name;
  }

  get name() {
    return this._name.toUpperCase();
  }

  set name(value) {
    if (!value) throw new Error("Name required");
    this._name = value;
  }
}

const user = new User("John");

console.log(user.name); // JOHN

user.name = "David";
```

# 12. OOP Concepts — Quick Interview Revision

| Concept           | Meaning                                         |
| ----------------- | ----------------------------------------------- |
| **Object**        | Collection of properties and methods            |
| **Class**         | Blueprint for creating objects                  |
| **Encapsulation** | Bundle/hide internal data and behavior          |
| **Inheritance**   | Child reuses parent behavior                    |
| **Polymorphism**  | Same method/interface, different behavior       |
| **Abstraction**   | Hide implementation complexity                  |
| **Constructor**   | Initializes an object                           |
| **Prototype**     | Mechanism behind JS inheritance                 |
| **`this`**        | Depends on how a function is called             |
| **Static**        | Belongs to class, not instance                  |
| **Getter/Setter** | Controlled property access                      |
| **Composition**   | Build functionality by combining smaller pieces |

### ⭐ Most important for a React developer

For interviews, make sure you can clearly explain:

**OOP pillars → `class` → constructor → `this` → `extends`/`super` → prototype → method overriding → private fields → static → composition vs inheritance.**

And remember the key JavaScript-specific point:

> **JavaScript is prototype-based. `class` is syntactic sugar over the prototype system.**
