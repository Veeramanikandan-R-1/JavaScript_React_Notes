# JavaScript OOP (Object-Oriented Programming)

> **Goal:** JavaScript is a **prototype-based language**, not a traditional class-based language like Java or C++. However, ES6 introduced the `class` syntax, making OOP easier to write. As a senior React developer, you should understand both **prototype-based OOP** and **ES6 classes**, since React components, libraries, and many frameworks rely on these concepts.

---

# 1. What is OOP?

Object-Oriented Programming (OOP) is a programming paradigm where data and behavior are grouped into **objects**.

An object contains:

* **Properties (State/Data)**
* **Methods (Behavior/Functions)**

Example

```js
const user = {
  name: "John",

  greet() {
    console.log(`Hello ${this.name}`);
  }
};

user.greet();
```

Output

```
Hello John
```

---

# Why OOP?

Without OOP

```js
const user1Name = "John";
const user1Age = 25;

const user2Name = "Peter";
const user2Age = 30;
```

Lots of duplicated variables.

With OOP

```js
const user = {
  name: "John",
  age: 25
};
```

Data and behavior stay together.

Benefits:

* Code reuse
* Better organization
* Easier maintenance
* Scalability
* Encapsulation of logic

# 3. Objects

```js
const employee = {

  work() {
    console.log("Coding...");
  }

```

Access

```js
employee.name;

employee.work();
```

# 4. Constructor Functions (Before ES6)

Before classes, objects were created using constructor functions.

```js
function Person(name, age) {

    this.name = name;

    this.age = age;

}

const p1 = new Person("John", 25);

console.log(p1.name);
```

`new` performs four things:

1. Creates a new object.
2. Sets its prototype.
3. Binds `this` to the new object.
4. Returns the object.

---

# 5. ES6 Classes

Classes provide cleaner syntax over prototypes.

```js
class Person {

    constructor(name, age){

        this.name = name;

        this.age = age;

    }

    greet(){

        console.log(`Hello ${this.name}`);

    }

}

const user = new Person("John",25);

user.greet();
```

**Important:** Classes are **syntactic sugar** over JavaScript's prototype system. Internally, methods are stored on the prototype, not copied to every instance.

---

# 6. Constructor

The `constructor` initializes object properties.

```js
class User {

    constructor(name){

        this.name = name;

    }

}
```

Runs automatically when using `new`.

# 7. this Keyword

`this` refers to the object that calls the method.

```js
class User {

    constructor(name){

        this.name = name;

    }

    greet(){

        console.log(this.name);

    }

}
```

Output

```
John
```

---

## Common Problem

```js
const obj = {

    name: "John",

    greet() {

        setTimeout(function(){

            console.log(this.name);

        },1000);

    }

};
```

Output

```
undefined
```

Because `this` inside a regular callback refers to the global object (or is `undefined` in strict mode).

Solution

```js
setTimeout(() => {

    console.log(this.name);

},1000);
```

Arrow functions inherit `this` from the surrounding scope.

# 8. Encapsulation

Encapsulation means bundling data and methods together while restricting direct access to internal details.

Example

```js
class BankAccount {

    #balance = 0;

    deposit(amount){

        this.#balance += amount;

    }

    getBalance(){

        return this.#balance;

    }

}

const account = new BankAccount();

account.deposit(1000);

console.log(account.getBalance());
```

Output

```
1000
```

`#balance` is a private field (modern JavaScript).

---

## Older Approach

Before private fields, developers used closures or naming conventions (`_balance`) to indicate privacy.

# 9. Inheritance

Inheritance allows one class to reuse another class's functionality.

```js
class Animal {

    speak(){

        console.log("Animal speaks");

    }

}

class Dog extends Animal {

}

const dog = new Dog();

dog.speak();
```

Output

```
Animal speaks
```

---

## Method Overriding

```js
class Dog extends Animal {

    speak(){

        console.log("Dog barks");

    }

}
```

Output

```
Dog barks
```

## super()

Calls the parent constructor or methods.

```js
class Animal {

    constructor(name){

        this.name = name;

    }

}

class Dog extends Animal {

    constructor(name){

        super(name);

    }

}
```

`super()` must be called before accessing `this` in a derived class constructor.

---

Here's a simple, interview-friendly example of using **`super`** in JavaScript.

## Example: `super()` in Constructor

```js
class Animal {
    constructor(name) {
        this.name = name;
    }

    speak() {
        console.log(`${this.name} makes a sound`);
    }
}

class Dog extends Animal {
    constructor(name, breed) {
        super(name); // Calls Animal's constructor
        this.breed = breed;
    }

    display() {
        console.log(`${this.name} is a ${this.breed}`);
    }
}

const dog = new Dog("Buddy", "Labrador");

dog.display();
dog.speak();
```

**Output**

```text
Buddy is a Labrador
Buddy makes a sound
```

### What happens internally?

```text
new Dog("Buddy", "Labrador")

↓

Dog constructor executes

↓

super(name)

↓

Animal constructor executes

↓

this.name = "Buddy"

↓

Returns to Dog constructor

↓

this.breed = "Labrador"
```

Without `super(name)`:

```js
class Dog extends Animal {
    constructor(name, breed) {
        this.breed = breed; // ❌ Error
    }
}
```

**Error**

```text
ReferenceError: Must call super constructor in derived class before accessing 'this'
```

**Reason:** In a derived class (`extends`), JavaScript doesn't initialize `this` until the parent constructor (`super()`) has run.

---

# Example: `super.method()`

`super` can also call a parent class method.

```js
class Animal {
    speak() {
        console.log("Animal is speaking");
    }
}

class Dog extends Animal {
    speak() {
        super.speak(); // Calls parent's speak()
        console.log("Dog is barking");
    }
}

const dog = new Dog();

dog.speak();
```

**Output**

```text
Animal is speaking
Dog is barking
```

---

## Interview Points

* `super()` calls the **parent class constructor**.
* `super.method()` calls a **parent class method**.
* In a child class constructor, **`super()` must be called before using `this`**.
* `super` is only valid inside classes that use `extends`.

This is the type of example commonly expected in **6+ years React/JavaScript interviews**.

# 10. Polymorphism

Polymorphism means the same method name behaves differently depending on the object.

```js
class Animal {

    speak(){

        console.log("Animal");

    }

}

class Dog extends Animal {

    speak(){

        console.log("Bark");

    }

}

class Cat extends Animal {

    speak(){

        console.log("Meow");

    }

}
```

```js
const animals = [
    new Dog(),
    new Cat()
];

animals.forEach(animal => animal.speak());
```

Output

```
Bark

Meow
```

# 11. Abstraction

Abstraction means exposing only the necessary functionality while hiding implementation details.

Example

```js
class Payment {

    pay(){

        this.validate();

        console.log("Payment Done");

    }

    validate(){

        console.log("Validation");

    }

}
```

The consumer only calls:

```js
payment.pay();
```

The validation logic is hidden inside the class.

Example

## Abstraction in JavaScript

### What is Abstraction?

**Abstraction** means **hiding the internal implementation details and exposing only the necessary functionality** to the user.

The user knows **what** to do, but doesn't need to know **how** it is done.

---

## Real-Life Example

Think about a **car**.

You only do:

```text
Start Car

↓

Drive

↓

Stop Car
```

You don't need to know:

* How the engine starts
* How fuel is injected
* How gears work
* How the ECU operates

Those implementation details are hidden.

---

## JavaScript Example

```js
class CoffeeMachine {
    makeCoffee() {
        this.#boilWater();
        this.#addCoffeePowder();
        this.#pourCoffee();

        console.log("Coffee is ready ☕");
    }

    #boilWater() {
        console.log("Boiling water...");
    }

    #addCoffeePowder() {
        console.log("Adding coffee powder...");
    }

    #pourCoffee() {
        console.log("Pouring coffee...");
    }
}

const machine = new CoffeeMachine();

machine.makeCoffee();
```

### Output

```text
Boiling water...
Adding coffee powder...
Pouring coffee...
Coffee is ready ☕
```

The user only calls:

```js
machine.makeCoffee();
```

They don't know or care about:

* `#boilWater()`
* `#addCoffeePowder()`
* `#pourCoffee()`

These internal implementation details are hidden using **private methods (`#`)**.

---

## Another Interview-Friendly Example

```js
class PaymentService {
    pay(amount) {
        this.#validateCard();
        this.#checkBalance();
        this.#processPayment(amount);

        console.log("Payment Successful");
    }

    #validateCard() {
        console.log("Validating card...");
    }

    #checkBalance() {
        console.log("Checking balance...");
    }

    #processPayment(amount) {
        console.log(`Processing ₹${amount}...`);
    }
}

const payment = new PaymentService();

payment.pay(1000);
```

### Output

```text
Validating card...
Checking balance...
Processing ₹1000...
Payment Successful
```

The caller only knows:

```js
payment.pay(1000);
```

They don't know **how** the payment is processed internally.

# Encapsulation vs Abstraction (Very Common Interview Question)

| Encapsulation                                        | Abstraction                                                                     |
| ---------------------------------------------------- | ------------------------------------------------------------------------------- |
| Bundles data and methods together and protects data. | Hides implementation details and exposes only necessary functionality.          |
| Focuses on **data protection**.                      | Focuses on **hiding complexity**.                                               |
| Achieved using private fields (`#`) or closures.     | Achieved by exposing simple public methods while keeping internal logic hidden. |

### Easy Way to Remember

* **Encapsulation = Protect the data.**
* **Abstraction = Hide the complexity.**

When you use React state:

```jsx
const [count, setCount] = useState(0);
```

You simply call:

```jsx

```

You don't know:

* How React stores the state.
* How it schedules updates.

React **abstracts** all those internal implementation details. You only use the simple public API (`useState` and `setCount`).

In JavaScript, abstraction is commonly achieved by exposing public methods while hiding internal logic using private fields (`#`) or internal helper methods. # 12. Prototypes (Most Important)

Every JavaScript object has a hidden link to another object called its **prototype**.

```
Object

↑

Prototype

↑

Instance
```

Example

```js
function Person(name){

    this.name = name;

}

Person.prototype.greet = function(){

    console.log("Hello");

};

const user = new Person("John");

user.greet();
```

`greet()` is stored once on `Person.prototype`, so all instances share it.

---

# Prototype Chain

```text
user
   ↓
Person.prototype
   ↓
Object.prototype
   ↓
null
```

When JavaScript can't find a property, it looks up the prototype chain until it reaches `null`.

---

# 13. Static Methods

Static methods belong to the class itself, not instances.

```js
class MathUtil {

    static add(a,b){

        return a+b;

    }

}

MathUtil.add(10,20);
```

Cannot call

```js
const obj = new MathUtil();

obj.add();
```

---

# 14. Getters and Setters

Provide controlled access to properties.

```js
class User {

    constructor(name){

        this._name = name;

    }

    get name(){

        return this._name;

    }

    set name(value){

        this._name = value;

    }

}
```

Usage

```js
const user = new User("John");

console.log(user.name);

user.name = "Alex";
```

---

# 15. instanceof

Checks whether an object is an instance of a constructor/class.

```js
const user = new Person("John");

console.log(
user instanceof Person
);
```

Output

```
true
```

### Misunderstanding `this`

Regular functions and arrow functions handle `this` differently.

# Best Practices

* Prefer ES6 `class` syntax for readability when OOP fits the problem.
* Use composition over inheritance where possible (React heavily favors composition).
* Keep methods on the prototype (or use class methods) instead of creating them inside constructors.
* Use private fields (`#`) when encapsulation is needed.
* Use getters/setters only when additional logic is required.
* Avoid deep inheritance hierarchies.

# Frequently Asked Interview Questions (6 Years React)

### 1. Is JavaScript class-based or prototype-based?

**Answer:** JavaScript is **prototype-based**. ES6 classes are syntactic sugar over the prototype system.

---

### 2. What happens internally when you use the `new` keyword?

**Answer:**

1. A new object is created.
2. The object's prototype is linked to the constructor's prototype.
3. `this` is bound to the new object.
4. The constructor executes.
5. The new object is returned (unless another object is explicitly returned).

---

### 3. What is the difference between a constructor function and an ES6 class?

**Answer:** Both create objects and use prototypes internally. Classes provide cleaner syntax, support `extends`, `super`, private fields, and are easier to read, but they are not a new inheritance model.

---

### 4. What is the prototype chain?

**Answer:** It's JavaScript's property lookup mechanism. If a property isn't found on an object, JavaScript searches its prototype, then the prototype's prototype, continuing until `Object.prototype` and finally `null`.

---

### 5. What is the difference between `static` methods and instance methods?

**Answer:** Static methods belong to the class itself and are called using `ClassName.method()`. Instance methods belong to objects created with `new` and are shared through the prototype.

---

### 6. What is the difference between `this` in regular functions and arrow functions?

**Answer:** Regular functions determine `this` based on how they are called. Arrow functions do not have their own `this`; they inherit it lexically from the surrounding scope.

---

### 7. Why does React recommend composition over inheritance?

**Answer:** Composition creates reusable, loosely coupled components and avoids deep inheritance hierarchies. React encourages combining components via `props`, `children`, and custom hooks rather than extending component classes.

---

### 8. What are the four pillars of OOP?

**Answer:**

* **Encapsulation:** Bundle data and behavior; hide internal details.
* **Inheritance:** Reuse functionality from a parent class.
* **Polymorphism:** Same interface, different implementations.
* **Abstraction:** Expose only necessary functionality while hiding implementation details.

---

## Interview Tips for 6+ Years React Developers

For senior frontend interviews, expect deeper questions beyond basic class syntax:

* Explain **how the prototype chain works internally**.
* Describe **what `new` does step by step**.
* Compare **prototype methods vs methods created inside constructors** (memory implications).
* Explain **why React prefers composition over inheritance**.
* Discuss **lexical `this` in arrow functions** and why it solves common callback issues.
* Be able to explain **ES6 classes as syntactic sugar over prototypes**, not a separate inheritance model.
