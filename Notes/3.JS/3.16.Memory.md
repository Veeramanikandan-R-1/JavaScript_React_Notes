# JavaScript - Memory Management

Memory management is an important topic in JavaScript interviews because it directly affects **application performance**, **memory leaks**, and **browser crashes**.

As a React developer, understanding memory helps you write efficient components, avoid leaks in `useEffect`, and optimize large applications.

---

# JavaScript Memory Model

JavaScript mainly uses two memory areas:

```text
Memory
│
├── Stack Memory
│
└── Heap Memory
```

Each serves a different purpose.

---

# 1. Stack Memory

## What is Stack Memory?

The **Stack** is a small, fast memory area used to store:

* Primitive values
* Function calls
* Local variables
* Execution contexts

It follows the **LIFO (Last In, First Out)** principle.

---

## What is Stored in Stack?

Primitive types

* Number
* String
* Boolean
* Undefined
* Null
* Symbol
* BigInt

Example

```javascript
let age = 25;
let name = "John";
let active = true;
```

Stored in Stack

```text
Stack

------------
active=true
------------
name="John"
------------
age=25
------------
```

---

# Function Calls

Every function creates a new **Execution Context**.

Example

```javascript
function one() {
    two();
}

function two() {
    console.log("Hello");
}

one();
```

Call Stack

```text
-------------
two()
-------------
one()
-------------
Global()
-------------
```

After `two()` finishes

```text
-------------
one()
-------------
Global()
-------------
```

Finally

```text
-------------
Global()
-------------
```

---

# Why Stack is Fast?

Because:

* Fixed memory allocation
* Sequential memory
* Push/Pop operations are O(1)

Perfect for temporary data.

---

# 2. Heap Memory

## What is Heap Memory?

Heap stores **reference (non-primitive) values**.

Examples

* Objects
* Arrays
* Functions
* Date
* Map
* Set

Heap is much larger than Stack.

---

Example

```javascript
const user = {
    name: "John",
    age: 25
};
```

Memory

```text
Stack                    Heap

user --------------->   {
                           name:"John",
                           age:25
                        }
```

The Stack stores only the **reference (memory address)**.

Actual object lives in the Heap.

---

# Arrays

```javascript
const arr = [1,2,3];
```

```text
Stack                 Heap

arr ------------->   [1,2,3]
```

---

# Functions

Functions are also objects.

```javascript
function greet() {}
```

Stored in Heap.

---

# Primitive vs Reference

Primitive

```javascript
let a = 10;
let b = a;

b = 20;
```

Result

```text
a = 10
b = 20
```

Each variable has its own value.

---

Reference

```javascript
const obj1 = {
    age: 25
};

const obj2 = obj1;

obj2.age = 30;
```

Result

```text
obj1.age = 30
```

Both variables point to the same Heap object.

---

# Stack vs Heap

| Stack                 | Heap                         |
| --------------------- | ---------------------------- |
| Stores primitives     | Stores objects               |
| Stores references     | Stores actual object data    |
| Fast                  | Slower                       |
| Small                 | Large                        |
| LIFO                  | No fixed order               |
| Automatically managed | Managed by Garbage Collector |

---

# Passing Values

## Primitive

```javascript
let x = 10;

let y = x;

y = 20;
```

Memory

```text
Stack

x = 10

y = 20
```

Independent copies.

---

## Reference

```javascript
const user = {
    age: 20
};

const copy = user;
```

Memory

```text
Stack                   Heap

user -----------\
                 \
copy -------------> {
                     age:20
                  }
```

Shared reference.

---

# Copying Objects

Wrong

```javascript
const copy = user;
```

Creates another reference.

Correct

```javascript
const copy = {
    ...user
};
```

Creates a new object (shallow copy).

---

# Shallow Copy

```javascript
const obj = {
    address: {
        city: "Delhi"
    }
};

const copy = {
    ...obj
};

copy.address.city = "Mumbai";
```

Result

```text
obj.address.city
```

↓

```text
Mumbai
```

Nested object still shares memory.

---

# Deep Copy

Modern approach

```javascript
const clone = structuredClone(obj);
```

Older approach (limitations)

```javascript
JSON.parse(JSON.stringify(obj));
```

# 3. Garbage Collection

## What is Garbage Collection?

JavaScript automatically frees memory that is **no longer reachable**.

Developers do **not** manually free memory.

Unlike C/C++

```cpp
delete ptr;
free(ptr);
```

JavaScript handles this automatically.

---

# Why Garbage Collection?

Without it,

Memory usage would keep increasing.

Eventually

↓

Browser crashes

↓

Application slows

↓

Memory leaks

---

# Reachability

An object is eligible for Garbage Collection when it is **no longer reachable**.

Example

```javascript
let user = {
    name: "John"
};

user = null;
```

Now

```text
Stack

user = null
```

Heap

```text
{
 name:"John"
}
```

No references remain.

↓

Garbage Collector removes it later.

---

# Mark-and-Sweep Algorithm

Modern JavaScript engines use **Mark-and-Sweep**.

Steps

### 1. Mark

Starts from the root.

Marks every reachable object.

```text
Window

↓

App

↓

User

↓

Address
```

---

### 2. Sweep

Removes everything **not marked**.

```text
Reachable → Keep

Unreachable → Delete
```

---

# Memory Leak

A memory leak happens when memory is no longer needed but is still reachable.

Garbage Collector cannot remove it.

---

Example

```javascript
let users = [];

function addUser() {
    users.push(new Array(1000000));
}
```

Calling repeatedly

↓

Memory continuously grows.

---

# React Memory Leaks

## Event Listeners

Wrong

```javascript
useEffect(() => {

    window.addEventListener("resize", handleResize);

}, []);
```

Listener is never removed.

---

Correct

```javascript
useEffect(() => {

    window.addEventListener("resize", handleResize);

    return () => {
        window.removeEventListener("resize", handleResize);
    };

}, []);
```

---

## Timers

Wrong

```javascript
useEffect(() => {

    setInterval(loadData,1000);

}, []);
```

Timer keeps running after unmount.

---

Correct

```javascript
useEffect(() => {

    const id = setInterval(loadData,1000);

    return () => clearInterval(id);

}, []);
```

---

## API Requests

Wrong

Updating state after component unmount.

```javascript
setData(data);
```

Can cause warnings or unnecessary work.

Use cleanup or `AbortController`.

---

## Large Closures

Avoid keeping unnecessary large objects alive.

```javascript
const hugeArray = new Array(1000000);

button.onclick = () => {
    console.log(hugeArray);
};
```

The closure keeps `hugeArray` reachable until the handler is removed.

---

# Best Practices

* Prefer immutable updates.
* Remove event listeners in cleanup.
* Clear timers.
* Abort unnecessary API requests.
* Avoid global variables for temporary data.
* Avoid retaining large objects in closures.
* Use `structuredClone()` when a true deep copy is required.

---

# Common Mistakes

## Thinking Objects Are Stored in Stack

Wrong.

Objects are stored in the Heap.

The Stack stores only references.

---

## Thinking `const` Makes Objects Immutable

```javascript
const user = {
    age: 20
};

user.age = 30;
```

Valid.

`const` protects the reference, not the object's contents.

---

## Confusing Shallow and Deep Copy

```javascript
const copy = {
    ...obj
};
```

Copies only the first level.

Nested objects still share references.

---

## Forgetting Cleanup in React

```javascript
useEffect(() => {

    const id = setInterval(load,1000);

    return () => clearInterval(id);

}, []);
```

Always clean up subscriptions, listeners, and timers.

# Common Interview Questions (6+ Years)

### 1. What is the difference between Stack and Heap memory?

**Answer:** Stack stores primitive values, function execution contexts, and references to objects. Heap stores the actual reference-type data such as objects, arrays, functions, maps, and sets. Stack is fast and follows LIFO; Heap is larger and managed by the Garbage Collector.

---

### 2. Where are objects stored in JavaScript?

**Answer:** Objects are stored in the **Heap**, while the variable in the Stack stores only a reference (memory address) to that object.

---

### 3. Why does changing one object affect another after assignment?

```javascript
const a = { count: 1 };
const b = a;
b.count = 2;
```

**Answer:** Both `a` and `b` reference the same object in Heap memory. Modifying the object through one reference is visible through the other.

---

### 4. What is Garbage Collection?

**Answer:** Garbage Collection is JavaScript's automatic memory management mechanism. It identifies objects that are no longer reachable and frees their memory, typically using the Mark-and-Sweep algorithm.

---

### 5. What is a memory leak?

**Answer:** A memory leak occurs when objects are no longer needed but are still reachable through references, preventing the Garbage Collector from reclaiming their memory.

---

### 6. What are common causes of memory leaks in React?

**Answer:**

* Uncleared `setTimeout`/`setInterval`
* Event listeners not removed
* WebSocket or subscription cleanup missing
* Unaborted API requests
* Large objects retained by closures

---

### 7. What is the difference between a shallow copy and a deep copy?

**Answer:** A shallow copy duplicates only the top-level properties, while nested objects continue to share references. A deep copy recursively copies nested objects so the new object is completely independent.

---

### 8. Why is immutable state important in React?

**Answer:** React detects state changes by comparing object references. Creating a new object (instead of mutating the existing one) allows React to recognize the change and trigger a re-render efficiently.
