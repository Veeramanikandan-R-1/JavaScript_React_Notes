# JavaScript Events — Interview Notes ⭐⭐⭐

Events are actions that happen in the browser, such as **click, input, submit, keydown, mouseover**, etc.

For a 5-year React developer, **event propagation + delegation** are especially important.

---

# 1. Event Bubbling ⭐⭐⭐

When an event happens on a child element, it **bubbles upward** through its ancestors.

```html
<div id="parent">
  <button id="child">Click</button>
</div>
```

```js
parent.addEventListener("click", () => {
  console.log("Parent");
});

child.addEventListener("click", () => {
  console.log("Child");
});
```

Click button:

```text
Child
Parent
```

Flow:

```text
button
  ↑
div
  ↑
body
  ↑
document
```

**Bubbling is the default phase for most event listeners.**

---

# 2. Event Capturing ⭐⭐⭐

Capturing is the **opposite direction**: the event travels from the outer ancestor **down toward the target**.

```text
document
   ↓
  body
   ↓
 parent
   ↓
button (target)
```

To listen during capture:

```js
parent.addEventListener(
  "click",
  () => {
    console.log("Parent");
  },
  true
);
```

Or:

```js
parent.addEventListener("click", handler, {
  capture: true
});
```

### Event flow ⭐

A DOM event generally goes through:

```text
1. Capturing phase
       ↓
2. Target phase
       ↓
3. Bubbling phase
```

---

# 3. Event Delegation ⭐⭐⭐

Instead of attaching listeners to every child, attach **one listener to a parent** and use bubbling to identify the child that triggered the event.

### Without delegation

```js
document.querySelectorAll(".item").forEach(item => {
  item.addEventListener("click", handleClick);
});
```

Potentially many event listeners.

### With delegation

```js
const list = document.querySelector(".list");

list.addEventListener("click", (event) => {
  const item = event.target.closest(".item");

  if (item) {
    console.log(item.textContent);
  }
});
```

### Why use delegation?

* Fewer event listeners
* Useful for large/dynamic lists
* Dynamically added children can work without individually attaching new listeners

### React connection ⭐

React's event system uses **delegated event handling internally**, although the exact implementation details have changed across React versions.

---

# 4. `preventDefault()` ⭐⭐⭐

Prevents the browser's **default action** for an event.

### Example: prevent form submission

```js
form.addEventListener("submit", (event) => {
  event.preventDefault();

  console.log("Submit handled manually");
});
```

Normally, form submission may navigate/reload the page.

### Link example

```js
link.addEventListener("click", (event) => {
  event.preventDefault();
});
```

The link won't follow its normal navigation.

### React

```jsx
<form onSubmit={(e) => {
  e.preventDefault();
  console.log("Custom submit");
}}>
  <button type="submit">Submit</button>
</form>
```

> `preventDefault()` **does NOT stop event propagation**.

---

# 5. `stopPropagation()` ⭐⭐⭐

Stops the event from propagating further through the DOM.

```js
parent.addEventListener("click", () => {
  console.log("Parent");
});

child.addEventListener("click", (event) => {
  event.stopPropagation();

  console.log("Child");
});
```

Click child:

```text
Child
```

Parent doesn't receive that propagated click.

### React

```jsx
<div onClick={() => console.log("Parent")}>
  <button
    onClick={(e) => {
      e.stopPropagation();
    }}
  >
    Click
  </button>
</div>
```

---

# ⭐ `preventDefault()` vs `stopPropagation()`

Very common interview question.

| Method                       | Purpose                                                       |
| ---------------------------- | ------------------------------------------------------------- |
| `preventDefault()`           | Stops **browser's default behavior**                          |
| `stopPropagation()`          | Stops **event propagation**                                   |
| `stopImmediatePropagation()` | Also prevents other listeners on the same target from running |

Example:

```js
event.preventDefault();   // Don't submit/navigate
event.stopPropagation();  // Don't bubble/capture further
```

They solve **different problems**.

# ⭐ Important Example

```html
<div id="parent">
  <button id="child">Click</button>
</div>
```

```js
parent.addEventListener("click", () => {
  console.log("Parent");
});

child.addEventListener("click", (e) => {
  e.preventDefault();
  console.log("Child");
});
```

Output:

```text
Child
Parent
```

Why?

```text
preventDefault()
→ prevents browser default behavior

It does NOT stop propagation.
→ Event still bubbles to Parent.
```

If you use:

```js
e.stopPropagation();
```

then:

```text
Child
```

# 🎯 Quick Revision

```text
Bubbling
→ Target → Parent → Document

Capturing
→ Document → Parent → Target

Event flow
→ Capture → Target → Bubble

Delegation
→ Parent handles events for children

preventDefault()
→ Prevent browser's default action

stopPropagation()
→ Stop event propagation
```

### ⭐ Interview One-Liner

> **Event capturing moves from ancestor to target, bubbling moves from target back to ancestors, and event delegation leverages bubbling to handle events efficiently from a parent. `preventDefault()` stops the browser's default action, while `stopPropagation()` stops the event from propagating further.**
