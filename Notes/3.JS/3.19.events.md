# Events

> **Goal:** Events are one of the most commonly asked JavaScript and React interview topics. As a senior React developer, you should understand **how browser events work internally**, because React's event system is built on top of the DOM event model.

---

# 1. What are Events?

An **event** is an action or occurrence detected by the browser.

Examples:

* Mouse click
* Keyboard press
* Form submit
* Scrolling
* Window resize
* Input change

Example

```html
<button id="btn">Click Me</button>
```

```js
const btn = document.querySelector("#btn");

btn.addEventListener("click", () => {
    console.log("Clicked");
});
```

When the button is clicked, the browser executes the callback function.

---

# Event Flow (Very Important)

Whenever an event occurs, it travels through **three phases**.

```
Document
    ↓
html
    ↓
body
    ↓
div
    ↓
button (Target)
    ↑
div
    ↑
body
    ↑
html
    ↑
Document
```

The phases are:

1. Capturing Phase
2. Target Phase
3. Bubbling Phase

Most interview questions revolve around these phases.

---

# 2. Event Bubbling

## What is Bubbling?

By default, when an event occurs, it starts from the **target element** and moves upward to its ancestors.

```
button
   ↑
div
   ↑
body
   ↑
document
```

Example

```html
<div id="parent">
    <button id="child">Click</button>
</div>
```

```js
document.querySelector("#parent")
.addEventListener("click", () => {
    console.log("Parent");
});

document.querySelector("#child")
.addEventListener("click", () => {
    console.log("Child");
});
```

Click button

Output

```
Child

Parent
```

The event first executes on the button, then bubbles to its parent.

---

## Why Bubbling Exists?

Without bubbling, every parent would need separate logic to know what happened inside it.

Bubbling allows:

* Event Delegation
* Cleaner code
* Better performance

---

## Real-world Example

```
Table

 ├── Row

      ├── Button
```

Instead of adding click handlers to every button, we can add one handler on the table.

---

# 3. Event Capturing

## What is Capturing?

Capturing is the opposite of bubbling.

The event starts from the document and travels down to the target element.

```
Document

↓

html

↓

body

↓

div

↓

button
```

Capturing is disabled by default.

Enable it by passing `true` (or `{ capture: true }`) as the third argument.

```js
parent.addEventListener(
    "click",
    () => console.log("Parent"),
    true
);
```

---

## Example

```js
parent.addEventListener(
    "click",
    () => console.log("Parent"),
    true
);

child.addEventListener(
    "click",
    () => console.log("Child")
);
```

Output

```
Parent

Child
```

Because capturing executes before bubbling.

---

## Modern Syntax

```js
element.addEventListener(
    "click",
    handler,
    {
        capture: true
    }
);
```

Preferred over using `true` because it is more readable and allows other options like `once` and `passive`.

---

# 4. Bubbling vs Capturing

| Bubbling            | Capturing                 |
| ------------------- | ------------------------- |
| Target → Parent     | Parent → Target           |
| Default behavior    | Must enable explicitly    |
| Most commonly used  | Less common               |
| Used for delegation | Used for advanced control |

---

# 5. Event Delegation

## What is Event Delegation?

Instead of attaching event listeners to multiple child elements, attach **one listener to their common parent** and identify which child triggered the event.

Example

Bad

```js
buttons.forEach(button => {
    button.addEventListener("click", handler);
});
```

Good

```js
container.addEventListener("click", handler);
```

---

## Why Event Delegation?

Imagine

```
1000 buttons
```

Without delegation

```
1000 listeners
```

With delegation

```
1 listener
```

Much more memory efficient.

---

## Example

```html
<ul id="list">
    <li>React</li>
    <li>Angular</li>
    <li>Vue</li>
</ul>
```

```js
const list = document.querySelector("#list");

list.addEventListener("click", event => {

    if(event.target.tagName === "LI"){

        console.log(event.target.textContent);

    }

});
```

Click

```
Vue
```

Only one listener handles all list items.

---

## Dynamic Elements

Delegation also works for elements added later.

```js
const li = document.createElement("li");

li.textContent = "Svelte";

list.appendChild(li);
```

No new listener is needed.

---

## Using closest()

Preferred approach

```js
list.addEventListener("click", e => {

    const item = e.target.closest("li");

    if(!item) return;

    console.log(item.textContent);

});
```

Works even if the click happens on nested elements inside the `<li>`.

---

## When to Use

* Tables
* Lists
* Menus
* Cards
* Dynamic UI
* Infinite scrolling
* React-like component trees

---

# 6. preventDefault()

## What does it do?

Stops the browser's **default action** for an event.

Example

```html
<a href="https://google.com">Google</a>
```

```js
link.addEventListener("click", e => {

    e.preventDefault();

});
```

The link will not navigate.

---

## Form Example

```html
<form>

<input>

<button>

Submit

</button>

</form>
```

Without

```js
form.addEventListener("submit", e => {

});
```

The page reloads.

With

```js
form.addEventListener("submit", e => {

    e.preventDefault();

});
```

The page stays as-is.

Very common in React forms.

---

## Common Uses

* Prevent page refresh
* Prevent link navigation
* Prevent context menu
* Prevent drag behavior

---

# 7. stopPropagation()

## What does it do?

Stops the event from moving further through the DOM.

Example

```js
child.addEventListener("click", e => {

    e.stopPropagation();

    console.log("Child");

});

parent.addEventListener("click", () => {

    console.log("Parent");

});
```

Output

```
Child
```

Parent never executes.

---

## Difference

Without

```
Child

Parent
```

With stopPropagation

```
Child
```

---

## stopImmediatePropagation()

Less common but interview-worthy.

Stops:

* Further propagation
* Remaining listeners on the same element

```js
button.addEventListener("click", first);

button.addEventListener("click", second);
```

If the first listener calls:

```js
event.stopImmediatePropagation();
```

The second listener will not execute.

---

# Event Object

Every event handler receives an event object.

```js
button.addEventListener("click", event => {

});
```

Useful properties

| Property                   | Purpose                                  |
| -------------------------- | ---------------------------------------- |
| target                     | Element that triggered the event         |
| currentTarget              | Element where the listener is attached   |
| type                       | Event name                               |
| preventDefault()           | Prevent browser default action           |
| stopPropagation()          | Stop propagation                         |
| stopImmediatePropagation() | Stop propagation and remaining listeners |
| clientX / clientY          | Mouse position                           |

---

# target vs currentTarget (Very Common)

Example

```html
<div id="parent">

<button id="child">

Click

</button>

</div>
```

```js
parent.addEventListener("click", e => {

console.log(e.target);

console.log(e.currentTarget);

});
```

Click button

```
target → button

currentTarget → parent
```

Remember:

* **target** = actual element that triggered the event.
* **currentTarget** = element on which the event listener is registered.

# React and Events

React uses **Synthetic Events**, a cross-browser wrapper around native DOM events.

Example

```jsx
<button onClick={handleClick}>
    Click
</button>
```

Internally, React uses event delegation by attaching a small number of listeners (historically at the `document` level, and in React 17+ at the React root container) and dispatching events through its own event system.

The APIs (`preventDefault()`, `stopPropagation()`, `target`, etc.) behave almost the same as native events.

---

# Common Mistakes

### Forgetting preventDefault()

```js
form.addEventListener("submit", () => {

});
```

The page refreshes unexpectedly.

---

### Stopping propagation unnecessarily

Using `stopPropagation()` everywhere can break parent components that rely on bubbling (e.g., modals, analytics, or delegated listeners). Use it only when needed.

---

### Attaching listeners to every child

Bad

```
1000 listeners
```

Better

```
1 delegated listener
```

---

### Confusing target and currentTarget

A frequent interview question.

---

# Best Practices

* Use event delegation for large or dynamic lists.
* Prefer `closest()` over checking multiple parent nodes manually.
* Call `preventDefault()` only when overriding browser behavior.
* Avoid excessive use of `stopPropagation()`.
* Remove listeners when no longer needed (or let React manage them).
* Use `{ capture: true }` instead of `true` for clarity.

# Frequently Asked Interview Questions (6 Years React)

### 1. Explain the complete event flow in the browser.

**Answer:** Events travel through three phases: **Capturing (document → target)**, **Target**, and **Bubbling (target → document)**. By default, event listeners run during the bubbling phase unless `{ capture: true }` is specified.

---

### 2. What is the difference between event bubbling and capturing?

**Answer:** Bubbling propagates the event from the target element up to its ancestors and is the default behavior. Capturing propagates the event from the document down to the target and must be explicitly enabled.

---

### 3. What is event delegation, and why is it useful?

**Answer:** Event delegation attaches a single listener to a parent element and uses bubbling to handle events from child elements. It improves performance, reduces memory usage, and automatically supports dynamically added elements.

---

### 4. What is the difference between `preventDefault()` and `stopPropagation()`?

**Answer:**

* `preventDefault()` prevents the browser's default action (e.g., submitting a form or following a link).
* `stopPropagation()` prevents the event from propagating to parent elements.

---

### 5. What is the difference between `event.target` and `event.currentTarget`?

**Answer:** `event.target` is the element where the event originated. `event.currentTarget` is the element whose event listener is currently executing.

---

### 6. When would you use the capture phase?

**Answer:** Capture is useful when a parent must intercept an event before it reaches child elements, such as implementing global shortcuts, security checks, or advanced UI behavior.

---

### 7. How does React handle events internally?

**Answer:** React uses a **Synthetic Event** system that normalizes browser differences. It relies on **event delegation**, registering a small number of native listeners on the React root container (React 17+) and dispatching events through React's event system.

---

### 8. Why is event delegation preferred for dynamic lists?

**Answer:** Dynamically created elements don't need individual listeners. A single delegated listener on the parent automatically handles events from existing and newly added child elements, making the application more scalable and efficient.
