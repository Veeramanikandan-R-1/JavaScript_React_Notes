# JavaScript - Modules 

JavaScript Modules allow us to split code into **multiple reusable files** instead of writing everything in a single file.

In React, almost every file is a module:

* Components
* Hooks
* Utility functions
* Constants
* API services
* Redux slices

Understanding modules is essential because every React project relies heavily on the ES Module (ESM) system.

---

# Why Do We Need Modules?

Without modules, all code would exist in one file.

```text
app.js

- Button
- Header
- Footer
- API
- Utils
- Validation
- Theme
```

Problems:

* Hard to maintain
* Difficult to reuse
* Naming conflicts
* Poor scalability

Modules solve these issues by separating code into independent files.

---

# Module System

Example project

```text
src/
│
├── App.js
├── components/
│   ├── Header.js
│   └── Button.js
│
├── utils/
│   └── formatDate.js
│
└── services/
    └── api.js
```

Each file is a **module**.

# 1. export

`export` makes variables, functions, or classes available to other modules.

## Named Export

```javascript
// math.js

export const PI = 3.14;

export function add(a, b) {
    return a + b;
}
```

Import

```javascript
import { PI, add } from "./math.js";

console.log(PI);
console.log(add(2, 3));
```

---

# Multiple Named Exports

```javascript
export const PI = 3.14;

export const TAX = 18;

export function sum() {}

export function multiply() {}
```

Import

```javascript
import {
    PI,
    TAX,
    sum,
    multiply
} from "./math.js";
```

---

# Export Later

```javascript
const PI = 3.14;

function add(a, b) {
    return a + b;
}

export { PI, add };
```

---

# 2. import

`import` allows one module to use code exported from another module.

```javascript
import { add } from "./math.js";
```

---

## Import Multiple

```javascript
import {
    add,
    subtract,
    multiply
} from "./math.js";
```

---

## Import with Alias

Useful when two modules export variables with the same name.

```javascript
import { add as sum } from "./math.js";
```

Now

```javascript
sum(2, 3);
```

---

## Import Everything

```javascript
import * as MathUtils from "./math.js";
```

Usage

```javascript
MathUtils.add(2,3);

MathUtils.PI;
```

---

# 3. Default Export

A file can have **only one default export**.

Example

```javascript
// Button.js

export default function Button() {}
```

Import

```javascript
import Button from "./Button";
```

Notice

No curly braces.

---

## Default Export Example

```javascript
// App.js

export default App;
```

Import

```javascript
import App from "./App";
```

---

# Default Export Can Have Any Name

```javascript
import Main from "./App";

import Home from "./App";
```

Both are valid because the importing module chooses the name.

---

# 4. Named Export

Unlike default exports,

a file can have multiple named exports.

```javascript
export const BASE_URL = "...";

export function fetchUsers() {}

export function fetchOrders() {}
```

Import

```javascript
import {
    BASE_URL,
    fetchUsers,
    fetchOrders
} from "./api";
```

---

# Named vs Default Export

| Feature          | Named Export                | Default Export                |
| ---------------- | --------------------------- | ----------------------------- |
| Exports per file | Multiple                    | One                           |
| Curly braces     | Required                    | Not required                  |
| Import name      | Must match (unless aliased) | Can be any name               |
| Best for         | Utilities, constants        | Main component/class/function |

---

## Example

```javascript
// api.js

export const BASE_URL = "...";

export default fetchUsers;
```

Import

```javascript
import fetchUsers, {
    BASE_URL
} from "./api";
```

---

# Mixing Default and Named Exports

Allowed

```javascript
export default App;

export const VERSION = "1.0";

export const API = "...";
```

Import

```javascript
import App, {
    VERSION,
    API
} from "./App";
```

---

# Re-exporting

Useful in barrel files.

```javascript
export {
    Button
} from "./Button";

export {
    Card
} from "./Card";
```

Then

```javascript
import {
    Button,
    Card
} from "./components";
```

Instead of

```javascript
import Button from "./components/Button";

import Card from "./components/Card";
```

---

# 5. Dynamic Import

Normally imports happen at the beginning of the file.

```javascript
import Button from "./Button";
```

This is called a **static import**.

---

Dynamic import loads modules **only when needed**.

```javascript
const module = await import("./Button");
```

Returns a Promise.

---

# Syntax

```javascript
const module = await import("./utils");
```

Access exports

```javascript
module.add();
```

---

# React Usage

```javascript
const Dashboard =
React.lazy(() => import("./Dashboard"));
```

Dashboard is downloaded only when required.

---

# Why Dynamic Import?

Suppose your application has

```text
Login
Dashboard
Reports
Admin
Charts
Analytics
```

Without dynamic import

↓

All JavaScript downloads immediately.

With dynamic import

↓

Only the required module downloads.

---

Benefits

* Faster initial load
* Smaller bundle
* Better performance
* Code splitting

# React.lazy()

```javascript
const Settings = React.lazy(() =>
    import("./Settings")
);
```

Needs

```jsx
<Suspense fallback={<Loader />}>
    <Settings />
</Suspense>
```

# Module Execution

Modules execute **only once**.

Example

```javascript
// config.js

console.log("Loaded");

export const API = "...";
```

Importing

```javascript
import { API } from "./config";

import { API } from "./config";
```

Output

```text
Loaded
```

Only once.

JavaScript caches modules.

---

# Module Scope

Variables inside a module are private unless exported.

```javascript
const secret = "ABC";

export const API = "...";
```

`secret` cannot be imported.

---

# Circular Dependency

Example

```text
A imports B

↓

B imports A
```

Avoid when possible.

It can produce partially initialized modules.

# Common Mistakes

## Forgetting Curly Braces

Wrong

```javascript
import add from "./math";
```

when

```javascript
export const add = () => {};
```

Correct

```javascript
import { add } from "./math";
```

---

## Using Curly Braces with Default Export

Wrong

```javascript
import { App } from "./App";
```

Correct

```javascript
import App from "./App";
```

---

## Multiple Default Exports

Wrong

```javascript
export default App;

export default Button;
```

Only one default export is allowed per module.

---

## Wrong Import Name

```javascript
export const PI = 3.14;
```

Wrong

```javascript
import { Radius } from "./math";
```

Correct

```javascript
import { PI } from "./math";
```

or

```javascript
import { PI as Radius } from "./math";
```

# Best Practices

* Use **default export** for the main component in a file.
* Use **named exports** for utility functions, hooks, constants, and helpers.
* Group related exports using barrel (`index.js`) files when appropriate.
* Use **dynamic imports** for large, infrequently used modules to reduce bundle size.
* Avoid circular dependencies between modules.

# Common Interview Questions (6+ Years)

### 1. What is the difference between a named export and a default export?

**Answer:**

* A module can have **multiple named exports** but only **one default export**.
* Named exports are imported using curly braces (`import { foo }`).
* Default exports are imported without curly braces (`import Foo`).

---

### 2. When should you use a default export vs a named export?

**Answer:**

* Use a **default export** for the primary entity in a file, such as a React component.
* Use **named exports** for utilities, hooks, constants, helper functions, or when exporting multiple items.

---

### 3. Can a module have both default and named exports?

**Answer:** Yes.

```javascript
export default App;
export const VERSION = "1.0";
```

Import:

```javascript
import App, { VERSION } from "./App";
```

---

### 4. What is a dynamic import?

**Answer:** A dynamic import (`import()`) loads a module at runtime and returns a Promise. It is commonly used for lazy loading and code splitting.

```javascript
const module = await import("./utils");
```

---

### 5. Why is `React.lazy()` used?

**Answer:** `React.lazy()` uses dynamic imports to load components only when they are needed, reducing the initial bundle size and improving application performance.

---

### 6. What is the difference between static and dynamic imports?

| Static Import                        | Dynamic Import                           |
| ------------------------------------ | ---------------------------------------- |
| Loaded during initial module loading | Loaded when executed                     |
| Synchronous syntax                   | Returns a Promise                        |
| Good for always-needed modules       | Good for lazy loading and code splitting |

---

### 7. What happens if you import the same module multiple times?

**Answer:** The module is **executed only once**. JavaScript caches the module after the first import and returns the cached instance for subsequent imports.

---

### 8. What are circular dependencies, and why should they be avoided?

**Answer:** A circular dependency occurs when two modules import each other (A imports B, and B imports A). This can lead to partially initialized modules, unexpected `undefined` values, and maintenance issues. Designing modules with a clear dependency direction helps avoid these problems.
