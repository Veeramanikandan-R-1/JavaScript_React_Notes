# JavaScript Modules — Interview Notes

ES Modules (**ESM**) allow you to split JavaScript code into separate, reusable files.

Main keywords:

```text
export → make something available
import → use something from another module
```

---

## 1. `export` ⭐⭐⭐

Used to expose variables, functions, classes, etc. from a module.

```js
// math.js
export const add = (a, b) => a + b;

export const PI = 3.14;
```

---

# 2. Named Export ⭐⭐⭐

You can export **multiple things** from one file.

```js
// math.js
export const add = (a, b) => a + b;

export const subtract = (a, b) => a - b;
```

Import using the **same exported names**:

```js
// app.js
import { add, subtract } from "./math.js";

console.log(add(10, 5));
console.log(subtract(10, 5));
```

### Rename while importing

```js
import { add as sum } from "./math.js";

sum(10, 5);
```

### Export at the bottom

You can also do:

```js
const add = (a, b) => a + b;
const subtract = (a, b) => a - b;

export { add, subtract };
```

---

# 3. Default Export ⭐⭐⭐

A module can have **only one default export**.

```js
// User.js
export default function User() {
  console.log("User");
}
```

Import:

```js
import User from "./User.js";
```

You can give the imported default export **any name**:

```js
import MyUser from "./User.js";
```

Both are valid.

### Default + Named together

```js
// utils.js
export default function main() {}

export const add = (a, b) => a + b;
```

```js
import main, { add } from "./utils.js";
```

---

# 4. `import` ⭐⭐⭐

Used to consume exported values.

### Named import

```js
import { add } from "./math.js";
```

### Default import

```js
import User from "./User.js";
```

### Import everything

```js
import * as MathUtils from "./math.js";

MathUtils.add(10, 20);
MathUtils.subtract(20, 10);
```

### Side-effect import

You can import a module without importing any specific value:

```js
import "./styles.css";
```

Useful when you only need the module's side effects.

---

# ⭐ Named vs Default Export

| Named Export              | Default Export               |
| ------------------------- | ---------------------------- |
| Multiple allowed          | Only one per module          |
| Import uses `{}`          | No `{}`                      |
| Name generally must match | Import name can be different |
| `export const add`        | `export default add`         |

Example:

```js
// Named
export const add = () => {};

import { add } from "./math.js";
```

```js
// Default
export default add;

import sum from "./math.js";
```

---

# 5. Dynamic `import()` ⭐⭐⭐

Unlike normal static imports, `import()` loads a module **at runtime** and returns a **Promise**.

```js
const module = await import("./math.js");

console.log(module.add(10, 20));
```

Or:

```js
import("./math.js")
  .then(module => {
    console.log(module.add(10, 20));
  });
```

### Why use dynamic imports?

Mainly for **lazy loading / code splitting**.

Instead of loading everything initially:

```text
Initial bundle
├── Home
├── Dashboard
├── Reports
└── Admin
```

Load Admin only when needed:

```js
const Admin = await import("./Admin.js");
```

This can reduce the **initial JavaScript bundle** and improve initial load performance.

---

# ⭐ React Example

Dynamic import is commonly used with `React.lazy()`:

```jsx
import { lazy, Suspense } from "react";

const Dashboard = lazy(() => import("./Dashboard"));

function App() {
  return (
    <Suspense fallback={<div>Loading...</div>}>
      <Dashboard />
    </Suspense>
  );
}
```

The `Dashboard` chunk is loaded when React needs to render it.

# ⭐ Static vs Dynamic Import

### Static

```js
import { add } from "./math.js";
```

* Resolved as part of module loading
* Can be analyzed by bundlers
* Supports tree shaking
* Must be at module top level

### Dynamic

```js
const module = await import("./math.js");
```

* Runtime loading
* Returns a Promise
* Useful for lazy loading/code splitting
* Can be used conditionally

```js
if (isAdmin) {
  const admin = await import("./admin.js");
}
```

# 🎯 React Interview Must Know

```text
export
→ Expose values from a module

import
→ Consume exported values

Named export
→ Multiple per file
→ import { something }

Default export
→ One per file
→ import Something

Dynamic import()
→ Runtime/lazy loading
→ Returns Promise
→ Useful for code splitting
```

### ⭐ Interview One-Liner

> **ES Modules provide a static `import/export` system for organizing dependencies, while dynamic `import()` loads a module asynchronously at runtime and is commonly used for lazy loading and code splitting in React.**
