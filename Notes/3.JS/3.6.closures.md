# JavaScript Closures

Closures are one of the **most frequently asked JavaScript interview topics** for experienced React developers because they are the foundation of:

* React Hooks (`useState`, `useEffect`, `useCallback`)
* Event handlers
* Timers
* Private variables
* Function factories
* Memoization

Understanding closures is essential for writing efficient React applications and debugging stale state issues.

---

# 1. What is a Closure?

A **closure** is created when an **inner function remembers and can access variables from its outer function even after the outer function has finished executing.**

### Definition

> **A closure is a function bundled together with the lexical environment in which it was created.**

---

## Basic Example

```javascript
function outer() {
    let count = 0;

    function inner() {
        count++;
        console.log(count);
    }

    return inner;
}

const counter = outer();

counter();
counter();
counter();
```

Output

```text
1
2
3
```

---

# What Happened?

### Step 1

```javascript
const counter = outer();
```

* `outer()` executes.
* `count` is created.
* `inner()` is returned.

Normally, local variables are destroyed when a function finishes.

But...

`inner()` still needs `count`.

So JavaScript keeps `count` alive.

This is a **closure**.

---

# Visual Representation

```
outer()
│
├── count = 0
│
└── return inner()
          │
          ▼
counter()

counter remembers
count
```

Even after `outer()` finishes, `count` still exists because `inner()` references it.

---

# Closure = Function + Lexical Environment

```
Closure

=

Function

+

Remembered Variables
```

The inner function carries its surrounding variables with it.

---

# Another Example

```javascript
function greet(name) {

    return function () {
        console.log("Hello " + name);
    };
}

const sayHello = greet("John");

sayHello();
```

Output

```text
Hello John
```

Although `greet()` has already finished, `name` is still available.

# Multiple Closures

Each function call creates a **new closure**.

```javascript
function counter() {

    let count = 0;

    return function () {
        count++;
        console.log(count);
    };
}

const c1 = counter();
const c2 = counter();

c1();
c1();

c2();
```

Output

```text
1
2
1
```

Each closure has its own independent `count`.

---

# Closure and Lexical Scope

Closures work because of the **lexical environment**.

```javascript
const x = 10;

function outer() {

    const y = 20;

    function inner() {

        console.log(x);
        console.log(y);
    }

    return inner;
}

const fn = outer();

fn();
```

Output

```text
10
20
```

`inner()` remembers both `x` and `y`.

# Closures in Loops (Very Common Interview Question)

### Problem

```javascript
for (var i = 1; i <= 3; i++) {

    setTimeout(() => {
        console.log(i);
    }, 1000);
}
```

Output

```text
4
4
4
```

---

## Why?

`var` is function-scoped.

All callbacks share the **same** `i`.

By the time `setTimeout` runs,

```
i = 4
```

---

## Solution 1 (Use `let`) ✅

```javascript
for (let i = 1; i <= 3; i++) {

    setTimeout(() => {
        console.log(i);
    }, 1000);
}
```

Output

```text
1
2
3
```

Each iteration gets a new block-scoped variable.

---

## Solution 2 (Closure with IIFE)

```javascript
for (var i = 1; i <= 3; i++) {

    (function (x) {

        setTimeout(() => {
            console.log(x);
        }, 1000);

    })(i);
}
```

Each IIFE creates a separate closure.

# 2. Uses of Closures

Closures are used extensively in JavaScript and React.

---

## 1. Data Privacy (Private Variables)

```javascript
function bankAccount() {

    let balance = 1000;

    return {
        deposit(amount) {
            balance += amount;
        },

        getBalance() {
            return balance;
        }
    };
}

const account = bankAccount();

account.deposit(500);

console.log(account.getBalance());
```

Output

```text
1500
```

`balance` cannot be accessed directly.

```javascript
account.balance
```

Output

```text
undefined
```

This provides **encapsulation**.

---

## 2. Function Factory

Closures allow creating specialized functions.

```javascript
function multiply(multiplier) {

    return function (number) {
        return number * multiplier;
    };
}

const double = multiply(2);
const triple = multiply(3);

console.log(double(5));
console.log(triple(5));
```

Output

```text
10
15
```

---

## 3. React Event Handlers

```jsx
function App() {

    const username = "John";

    function handleClick() {
        alert(username);
    }

    return (
        <button onClick={handleClick}>
            Click
        </button>
    );
}
```

`handleClick` forms a closure over `username`.

---

## 4. Timers

```javascript
function startTimer(message) {

    setTimeout(() => {
        console.log(message);
    }, 1000);
}

startTimer("Completed");
```

The callback remembers `message`.

---

## 5. Memoization

Closures help cache results.

```javascript
function memoSquare() {

    const cache = {};

    return function (num) {

        if (cache[num]) {
            return cache[num];
        }

        cache[num] = num * num;

        return cache[num];
    };
}

const square = memoSquare();

console.log(square(5));
console.log(square(5));
```

The `cache` persists because of the closure.

---

## 6. React Hooks

Hooks rely heavily on closures.

```jsx
function Counter() {

    const [count, setCount] = useState(0);

    function handleClick() {
        console.log(count);
    }

    return (
        <button onClick={handleClick}>
            Click
        </button>
    );
}
```

`handleClick` closes over the current `count` value from that render.

This is why understanding closures is important when working with hooks.

# 3. Memory Implications of Closures

Closures keep referenced variables alive.

Normally,

```
Function ends

↓

Variables removed
```

With a closure,

```
Function ends

↓

Variables still referenced

↓

Memory retained
```

---

## Example

```javascript
function outer() {

    const bigData = new Array(1000000).fill("*");

    return function () {
        console.log(bigData.length);
    };
}

const fn = outer();
```

`bigData` remains in memory because the returned function still references it.

---

# Memory Leak Example

```javascript
function createHandler() {

    const hugeObject = new Array(1000000).fill("*");

    return function () {
        console.log("Clicked");
    };
}
```

Although the returned function never uses `hugeObject`, it may still keep the outer scope alive depending on what is captured and optimization performed by the engine. Retaining unnecessary large objects through closures can increase memory usage.

---

# How to Avoid Memory Problems

### Keep Closures Small

Avoid capturing unnecessary variables.

```javascript
function createHandler(id) {

    return function () {
        console.log(id);
    };
}
```

---

### Remove Event Listeners

```javascript
button.removeEventListener(...);
```

Unused listeners keep closures alive.

---

### Clear Timers

```javascript
clearTimeout(id);

clearInterval(id);
```

---

### Avoid Capturing Large Objects

Instead of

```javascript
const user = hugeObject;
```

Capture only what is needed.

```javascript
const id = user.id;
```

# React Closure Problem (Stale Closure)

A common React interview topic.

```jsx
function Counter() {

    const [count, setCount] = useState(0);

    function handleClick() {

        setTimeout(() => {
            console.log(count);
        }, 3000);
    }

    return (
        <button onClick={handleClick}>
            Click
        </button>
    );
}
```

If `count` changes before the timeout runs, the callback still logs the **value from the render in which it was created**.

This is called a **stale closure**.

### Common Solutions

* Functional state updates

```javascript
setCount(prev => prev + 1);
```

* `useRef` for mutable values
* Correct dependency arrays in `useEffect` and `useCallback`

---

# Common Mistakes

### ❌ Thinking local variables disappear immediately

Closures keep referenced variables alive.

---

### ❌ Confusing Scope with Closure

* **Scope** → Where variables are accessible.
* **Closure** → A function remembering variables from its lexical scope after the outer function has finished.

---

### ❌ Using `var` inside asynchronous loops

```javascript
for (var i = 0; i < 3; i++) {}
```

Usually causes unexpected behavior with callbacks.

Use `let`.

---

### ❌ Capturing Large Objects Unnecessarily

Closures can increase memory usage if they retain references to objects that are no longer needed.

---

# Best Practices

* Use closures for encapsulation and private state.
* Prefer `let` over `var` in loops with asynchronous callbacks.
* Keep closures focused—capture only required variables.
* Clean up event listeners and timers to allow garbage collection.
* Understand stale closures when working with React hooks.

# Common React (6 Years Experience) Interview Questions

### 1. What is a closure?

**Answer:**
A closure is a function that remembers and can access variables from its lexical scope even after the outer function has finished executing.

---

### 2. Why do closures work?

**Answer:**
Because JavaScript uses lexical scoping. Functions remember the environment where they were defined.

---

### 3. Where are closures used in React?

**Answer:**

* Event handlers
* `useState`
* `useEffect`
* `useCallback`
* `useMemo`
* Custom hooks
* Timer callbacks (`setTimeout`, `setInterval`)

---

### 4. What is a stale closure in React?

**Answer:**
A stale closure occurs when a callback captures state or props from an earlier render, causing it to use outdated values later (for example, inside a timeout or effect).

---

### 5. Why does `var` print `4 4 4` in a `setTimeout` loop?

**Answer:**
Because `var` is function-scoped, all callbacks share the same `i`. When the callbacks execute, the loop has already completed and `i` equals `4`.

---

### 6. How do you fix the `var` loop problem?

**Answer:**

* Use `let` (preferred).
* Or create a new closure using an IIFE.

---

### 7. Can closures cause memory leaks?

**Answer:**
Closures themselves do not cause memory leaks, but they can keep objects alive longer than necessary if they retain references to large data or if event listeners/timers are not cleaned up.

---

### 8. How do you avoid memory issues with closures?

**Answer:**

* Capture only required variables.
* Remove event listeners.
* Clear timers.
* Avoid retaining unnecessary large objects.
* Clean up effects properly in React (`useEffect` cleanup).
