# JavaScript Closures — Interview Notes

## 1. Closure ⭐⭐⭐

A **closure** is created when a function **remembers and can access variables from its outer lexical scope even after the outer function has finished executing**.

### Example

```js
function outer() {
  let count = 0;

  return function inner() {
    count++;
    return count;
  };
}

const counter = outer();

console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3
```

What happens:

```text
outer()
  ↓
count = 0
  ↓
returns inner()
  ↓
outer() finishes
  ↓
inner still remembers count
```

That `inner` function + its remembered lexical environment is the **closure**.

### Important ⭐

Closures are based on **lexical scope** — where the function is **defined**, not where it is called.

# 2. Uses of Closures

### ① Data Privacy / Encapsulation

Closures can keep variables private.

```js
function createBankAccount() {
  let balance = 0;

  return {
    deposit(amount) {
      balance += amount;
    },

    getBalance() {
      return balance;
    }
  };
}

const account = createBankAccount();

account.deposit(1000);

console.log(account.getBalance()); // 1000
console.log(account.balance);      // undefined
```

`balance` cannot be directly accessed from outside.

---

### ② Function Factory

Create functions with different configurations.

```js
function multiplyBy(x) {
  return function (num) {
    return num * x;
  };
}

const double = multiplyBy(2);
const triple = multiplyBy(3);

console.log(double(5)); // 10
console.log(triple(5)); // 15
```

---

### ③ Callbacks / Async Code ⭐

Closures are commonly used with callbacks.

```js
function greet(name) {
  setTimeout(() => {
    console.log(`Hello ${name}`);
  }, 1000);
}

greet("John");
```

The callback remembers `name` even after `greet()` has returned.

---

### ④ React

Closures are fundamental to React functional components and hooks.

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  function handleClick() {
    console.log(count);
  }

  return <button onClick={handleClick}>Count: {count}</button>;
}
```

`handleClick` closes over the `count` value from the render in which it was created.

This is also important for understanding **stale closures** in hooks.

# 3. Memory Implications ⭐⭐

A closure keeps references to variables from its outer scope **as long as those variables are reachable through the closure**.

```js
function create() {
  const largeData = new Array(1000000).fill("data");

  return function () {
    console.log(largeData.length);
  };
}

const fn = create();
```

Even though `create()` has finished, `largeData` can remain reachable because `fn` closes over it.

### Potential memory issue

If you unnecessarily keep closures alive:

```js
const handlers = [];

for (let i = 0; i < 100000; i++) {
  handlers.push(() => console.log(i));
}
```

Those functions retain their required lexical data while they remain reachable.

### Important ⭐

A closure **doesn't automatically cause a memory leak**.

Memory can be reclaimed by garbage collection when the closure and the objects it keeps reachable are no longer referenced.

```js
let fn = create();

fn(); 

fn = null; // If nothing else references the closure/data,
           // it can become eligible for garbage collection.
```

### Common causes of closure-related memory leaks

* Long-lived event listeners
* Timers/intervals not cleaned up
* Subscriptions
* Global references
* Large objects accidentally captured by long-lived callbacks

In React, clean up things such as:

```jsx
useEffect(() => {
  const id = setInterval(() => {
    // callback
  }, 1000);

  return () => clearInterval(id);
}, []);
```

### ⭐ Interview One-liner

> **A closure is a function that retains access to variables from its lexical scope even after the outer function has finished executing.**

### Most important interview example

```js
function counter() {
  let count = 0;

  return () => ++count;
}

const c = counter();

c(); // 1
c(); // 2
```

**Why `count` isn't destroyed after `counter()` finishes?**
Because the returned function still has a reference to the lexical environment containing `count`.
