# JavaScript Browser APIs — Interview Notes ⭐⭐⭐

**Browser APIs** are APIs provided by the browser environment that JavaScript can use for storage, networking, DOM observation, etc.

---

## 1. `localStorage` ⭐⭐⭐

Stores data in the browser that **persists even after closing/reopening the browser**.

```js
localStorage.setItem("name", "John");

const name = localStorage.getItem("name");

localStorage.removeItem("name");

// localStorage.clear();
```

⚠️ Values are stored as **strings**.

For objects:

```js
const user = { name: "John", age: 30 };

localStorage.setItem("user", JSON.stringify(user));

const data = JSON.parse(localStorage.getItem("user"));
```

### Important

* Persists until explicitly removed
* String-based
* Synchronous API
* Accessible to JavaScript → **don't store sensitive tokens/secrets here**

---

# 2. `sessionStorage` ⭐⭐⭐

Similar to `localStorage`, but data generally lasts for the **current browser tab/session**.

```js
sessionStorage.setItem("token", "abc");

console.log(sessionStorage.getItem("token"));

sessionStorage.removeItem("token");
```

### Difference

```text
localStorage
→ Persists across browser restarts

sessionStorage
→ Usually cleared when the tab/window session ends
```

Both are generally limited to a few MB per origin, with exact quotas depending on browser.

# 3. Cookies ⭐⭐⭐

Small pieces of data associated with a website/domain and sent with matching HTTP requests.

### Create cookie

```js
document.cookie = "username=John";
```

With options:

```js
document.cookie =
  "sessionId=abc123; Max-Age=3600; Path=/; Secure; SameSite=Lax";
```

### Important cookie attributes ⭐

```text
HttpOnly
→ JavaScript cannot access the cookie

Secure
→ Send only over HTTPS

SameSite
→ Controls cross-site cookie sending
   Strict / Lax / None

Path
→ Controls URL path where cookie applies

Domain
→ Controls applicable domain/subdomains
```

### `HttpOnly` cookie ⭐

```text
Browser
   │
   ├── JavaScript ❌ cannot read
   │
   └── HTTP request → Cookie automatically sent
```

This is why authentication/session cookies are often stored as:

```text
HttpOnly + Secure + appropriate SameSite
```

⚠️ Cookies have small size limits (typically around **4 KB per cookie**).

# 4. `fetch()` ⭐⭐⭐

Used to make HTTP requests.

```js
const response = await fetch("/api/users");

const users = await response.json();

console.log(users);
```

### POST

```js
await fetch("/api/users", {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    name: "John"
  })
});
```

### ⚠️ Important interview point

`fetch()` **doesn't reject the Promise for HTTP errors like 404/500**.

Check `response.ok`:

```js
const response = await fetch("/api/users");

if (!response.ok) {
  throw new Error(`HTTP error: ${response.status}`);
}
```

Network failures/abort generally reject the Promise.

# 5. `AbortController` ⭐⭐⭐

Used to **cancel abortable asynchronous operations**, commonly `fetch()`.

```js
const controller = new AbortController();

fetch("/api/users", {
  signal: controller.signal
});

// Cancel request
controller.abort();
```

### React example ⭐

Very useful inside `useEffect`:

```jsx
useEffect(() => {
  const controller = new AbortController();

  fetch("/api/users", {
    signal: controller.signal
  })
    .then(res => res.json())
    .then(data => setUsers(data))
    .catch(error => {
      if (error.name !== "AbortError") {
        console.error(error);
      }
    });

  return () => controller.abort();
}, []);
```

Prevents an unnecessary in-flight request from continuing when the component unmounts.

# 6. WebSocket — Basics ⭐⭐⭐

WebSocket provides **persistent, two-way communication** between browser and server.

Unlike normal HTTP request/response:

```text
HTTP
Client → Request → Server
Client ← Response ← Server
```

WebSocket:

```text
Client ←──────────────→ Server
        persistent
        two-way
        connection
```

### Example

```js
const socket = new WebSocket("wss://example.com");

socket.onopen = () => {
  socket.send("Hello Server");
};

socket.onmessage = (event) => {
  console.log(event.data);
};

socket.onclose = () => {
  console.log("Disconnected");
};
```

### Use cases

* Chat applications
* Live notifications
* Live dashboards
* Real-time collaboration
* Multiplayer applications

### `ws` vs `wss`

```text
ws://  → WebSocket
wss:// → Secure WebSocket (TLS)
```

# 7. `IntersectionObserver` ⭐⭐⭐

Detects when an element **enters/leaves the viewport or another scroll container**.

```js
const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      console.log("Element is visible");
    }
  });
});

observer.observe(document.querySelector(".target"));
```

### Common use cases

* Lazy loading images
* Infinite scrolling
* Detecting visible sections
* Analytics/view tracking

### React example

```jsx
const ref = useRef(null);

useEffect(() => {
  const observer = new IntersectionObserver(([entry]) => {
    if (entry.isIntersecting) {
      console.log("Visible");
    }
  });

  if (ref.current) observer.observe(ref.current);

  return () => observer.disconnect();
}, []);
```

# 8. `MutationObserver` ⭐⭐

Observes **changes to the DOM**.

It can detect:

```text
child elements added/removed
attributes changed
text/content changes
```

Example:

```js
const observer = new MutationObserver((mutations) => {
  console.log("DOM changed", mutations);
});

observer.observe(document.body, {
  childList: true,
  subtree: true,
  attributes: true
});
```

Stop observing:

```js
observer.disconnect();
```

### Use cases

* Detect DOM changes made by external code
* Integrating with third-party widgets
* Monitoring dynamically generated DOM

⚠️ In React, don't use `MutationObserver` just to track state changes—React state/props should normally be the source of truth.

---

# 9. `ResizeObserver` ⭐⭐⭐

Observes changes to an element's **size**.

```js
const observer = new ResizeObserver((entries) => {
  for (const entry of entries) {
    console.log(entry.contentRect.width);
    console.log(entry.contentRect.height);
  }
});

observer.observe(document.querySelector(".box"));
```

Stop:

```js
observer.disconnect();
```

### Use cases

* Responsive components
* Charts
* Dynamic layouts
* Components that need to react to their own size

---

# ⭐ Intersection vs Mutation vs Resize

| API                    | Observes                |
| ---------------------- | ----------------------- |
| `IntersectionObserver` | Visibility/intersection |
| `MutationObserver`     | DOM changes             |
| `ResizeObserver`       | Element size changes    |

Easy memory trick:

```text
Intersection → "Can I see it?"
Mutation     → "Did DOM change?"
Resize       → "Did its size change?"
```

# ⭐ Storage Comparison

|                                       | localStorage      | sessionStorage     | Cookies                |
| ------------------------------------- | ----------------- | ------------------ | ---------------------- |
| Storage                               | Browser           | Browser            | Browser                |
| Persistence                           | Long-term         | Tab/session        | Configurable           |
| Sent automatically with HTTP requests | ❌                 | ❌                  | ✅                      |
| JS accessible                         | ✅                 | ✅                  | Depends (`HttpOnly` ❌) |
| Size                                  | Few MB            | Few MB             | ~4 KB/cookie           |
| Common use                            | Preferences/cache | Temporary tab data | Sessions/auth          |

> **Browser APIs provide capabilities outside core JavaScript—storage through Web Storage/cookies, networking through Fetch/WebSocket, cancellation through AbortController, and efficient DOM/visibility/size observation through IntersectionObserver, MutationObserver, and ResizeObserver.**
