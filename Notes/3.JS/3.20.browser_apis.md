# JavaScript Browser APIs

> **Goal:** Browser APIs provide capabilities beyond core JavaScript. As a senior React developer, you should know when to use them directly, how React integrates with them, and common interview scenarios.

---

# 1. What are Browser APIs?

Browser APIs are **built-in interfaces provided by the browser** that allow JavaScript to interact with browser features and the user's device.

Examples:

* Storage
* Network requests
* DOM manipulation
* Clipboard
* Geolocation
* Notifications
* WebSockets
* Observers

**Important:** Browser APIs are **not part of JavaScript itself**. They are provided by browsers (Chrome, Firefox, Edge, etc.).

---

# Browser vs JavaScript

| JavaScript | Browser API          |
| ---------- | -------------------- |
| Variables  | localStorage         |
| Arrays     | fetch                |
| Objects    | WebSocket            |
| Functions  | IntersectionObserver |
| Promises   | MutationObserver     |

# 2. localStorage

## What is localStorage?

Stores data **permanently** in the browser until it is manually removed.

* Data survives page refresh.
* Data survives browser restart.
* Shared across tabs of the same origin.

---

## Syntax

```js
localStorage.setItem("theme", "dark");

const theme = localStorage.getItem("theme");

localStorage.removeItem("theme");

localStorage.clear();
```

---

## Example

```js
localStorage.setItem("username", "John");

console.log(localStorage.getItem("username"));
```

Output

```
John
```

---

## Data Type

Stores **only strings**.

Objects must be converted.

```js
const user = {
    name: "John"
};

localStorage.setItem(
    "user",
    JSON.stringify(user)
);
```

Read

```js
const user = JSON.parse(
    localStorage.getItem("user")
);
```

---

## Common Uses

* Theme
* Language
* User preferences
* Cached API data
* Recently viewed items

---

## React Example

```jsx
useEffect(() => {
    localStorage.setItem("theme", theme);
}, [theme]);
```

---

# 3. sessionStorage

Works almost the same as localStorage.

Difference:

Data exists only for the current browser tab.

When the tab closes:

```
Data is removed.
```

---

## Example

```js
sessionStorage.setItem(
    "step",
    "2"
);
```

---

## Use Cases

* Multi-step forms
* Temporary authentication state
* Wizard progress
* Current session data

---

# localStorage vs sessionStorage

| localStorage                 | sessionStorage               |
| ---------------------------- | ---------------------------- |
| Permanent                    | Current tab only             |
| Shared across tabs           | Not shared                   |
| Survives restart             | Removed on tab close         |
| ~5–10 MB (browser-dependent) | ~5–10 MB (browser-dependent) |

# 4. Cookies

Cookies store **small pieces of data** that can be sent to the server with HTTP requests.

Unlike localStorage, cookies can participate in server communication.

---

## Create Cookie

```js
document.cookie =
"username=John";
```

---

## With Expiry

```js
document.cookie =
"theme=dark; expires=Fri, 31 Dec 2027 12:00:00 UTC";
```

---

## Read Cookies

```js
console.log(document.cookie);
```

Returns

```
username=John; theme=dark
```

---

## Why Cookies?

Mainly used for

* Authentication
* Session management
* User tracking
* Preferences

---

## Security Flags (Interview Important)

```
HttpOnly
```

Cannot be accessed from JavaScript.

```
Secure
```

Sent only over HTTPS.

```
SameSite
```

Helps prevent CSRF attacks.

---

## localStorage vs Cookies

| localStorage           | Cookies                          |
| ---------------------- | -------------------------------- |
| Client-side only       | Client + Server                  |
| Large storage          | Small (~4 KB)                    |
| Not sent automatically | Sent with matching HTTP requests |
| Faster access          | Adds network overhead            |

# 5. fetch()

Modern API for making HTTP requests.

Returns a Promise.

---

## GET

```js
fetch("/users")
    .then(res => res.json())
    .then(data => console.log(data));
```

---

## POST

```js
fetch("/users", {
    method: "POST",
    headers: {
        "Content-Type":
        "application/json"
    },
    body: JSON.stringify(user)
});
```

---

## Using async/await

```js
const response =
await fetch("/users");

const data =
await response.json();
```

---

## Error Handling

`fetch()` rejects only on network failures. HTTP errors (404, 500) still resolve the promise.

```js
const response = await fetch("/users");

if (!response.ok) {
    throw new Error("Request failed");
}

const data = await response.json();
```

---

## Common Response Methods

```js
response.json()

response.text()

response.blob()

response.arrayBuffer()

response.formData()
```

# 6. AbortController

Cancels asynchronous operations like `fetch()`.

Very common in React.

---

## Why?

Imagine:

User opens a page.

Request starts.

User navigates away.

Without cancellation:

```
Memory leaks

Unnecessary network traffic

State update after component unmount
```

---

## Example

```js
const controller =
new AbortController();

fetch("/users", {
    signal: controller.signal
});

controller.abort();
```

---

## React Example

```jsx
useEffect(() => {

    const controller =
    new AbortController();

    fetch("/users", {
        signal: controller.signal
    });

    return () => {
        controller.abort();
    };

}, []);
```

# 7. WebSocket (Basics)

HTTP is request-response.

WebSocket enables **full-duplex, persistent communication** between client and server.

Perfect for real-time applications.

---

## Examples

* Chat
* Stock market
* Live dashboards
* Multiplayer games
* Notifications

---

## Create Connection

```js
const socket =
new WebSocket(
    "wss://example.com"
);
```

---

## Events

```js
socket.onopen

socket.onmessage

socket.onerror

socket.onclose
```

---

## Send Data

```js
socket.send("Hello");
```

---

## Receive

```js
socket.onmessage =
event => {

console.log(event.data);

};
```

---

## Close

```js
socket.close();
```

---

## HTTP vs WebSocket

| HTTP                | WebSocket                  |
| ------------------- | -------------------------- |
| Request → Response  | Persistent connection      |
| Stateless           | Stateful                   |
| One-way per request | Two-way communication      |
| Good for REST APIs  | Good for real-time updates |

# 8. IntersectionObserver

Detects when an element enters or leaves the viewport (or another root element).

---

## Why?

Avoid expensive scroll event listeners.

---

## Common Uses

* Infinite scroll
* Lazy loading images
* Analytics (view tracking)
* Trigger animations

---

## Example

```js
const observer =
new IntersectionObserver(entries => {

entries.forEach(entry => {

if(entry.isIntersecting){

console.log("Visible");

}

});

});

observer.observe(element);
```

---

## Stop Observing

```js
observer.unobserve(element);

observer.disconnect();
```

---

## React Use Cases

* Lazy-loaded components
* Image optimization
* Infinite scrolling
* Reveal-on-scroll animations

---

# 9. MutationObserver

Observes changes in the DOM.

Detects

* Elements added
* Elements removed
* Attribute changes
* Text changes

---

## Example

```js
const observer =
new MutationObserver(records => {

console.log(records);

});

observer.observe(
document.body,
{
childList: true,
subtree: true
}
);
```

---

## Use Cases

* Third-party widgets
* Browser extensions
* Analytics
* Monitoring DOM updates outside React

---

## Stop

```js
observer.disconnect();
```

---

# 10. ResizeObserver

Observes element size changes.

Unlike the `window.resize` event, it tracks **individual element** size changes.

---

## Example

```js
const observer =
new ResizeObserver(entries => {

entries.forEach(entry => {

console.log(
entry.contentRect.width
);

});

});

observer.observe(element);
```

---

## Common Uses

* Responsive charts
* Auto-resizing layouts
* Dynamic dashboards
* Canvas resizing

---

## Stop

```js
observer.disconnect();
```

# Browser API Cleanup in React

Many Browser APIs hold resources and should be cleaned up when a component unmounts.

```jsx
useEffect(() => {
    const observer = new ResizeObserver(() => {
        // ...
    });

    observer.observe(ref.current);

    return () => {
        observer.disconnect();
    };
}, []);
```

The same pattern applies to:

* WebSocket (`socket.close()`)
* AbortController (`controller.abort()`)
* IntersectionObserver (`disconnect()`)
* MutationObserver (`disconnect()`)
* Event listeners (`removeEventListener()`)

# Common Mistakes

### Storing objects directly

❌

```js
localStorage.setItem("user", user);
```

✅

```js
localStorage.setItem(
"user",
JSON.stringify(user)
);
```

---

### Forgetting JSON.parse()

Everything comes back as a string.

---

### Not checking `response.ok`

```js
await fetch("/users");
```

404 is **not** automatically treated as an error.

---

### Forgetting to abort fetch

Can cause state updates after unmount in React.

---

### Not disconnecting observers

May lead to memory leaks and unnecessary callbacks.

---

### Using cookies for large data

Cookies are small and sent with HTTP requests. Use localStorage or IndexedDB for larger client-side storage needs.

---

# Best Practices

* Use **localStorage** for persistent client-side preferences.
* Use **sessionStorage** for temporary tab-specific data.
* Use **cookies** only when server communication is required (e.g., auth/session).
* Always check `response.ok` after `fetch()`.
* Cancel pending requests using `AbortController`.
* Prefer `IntersectionObserver` over scroll listeners for visibility detection.
* Disconnect observers in cleanup functions.
* Use secure cookies (`HttpOnly`, `Secure`, `SameSite`) for authentication; avoid storing sensitive tokens in localStorage when possible.

# Frequently Asked Interview Questions (6 Years React)

### 1. What is the difference between `localStorage`, `sessionStorage`, and cookies?

**Answer:**

* `localStorage`: Persistent client-side storage shared across tabs of the same origin.
* `sessionStorage`: Exists only for the current browser tab and is cleared when the tab closes.
* Cookies: Small pieces of data that can be automatically sent with HTTP requests and are commonly used for authentication and session management.

---

### 2. Why is `fetch()` considered better than `XMLHttpRequest`?

**Answer:** `fetch()` is Promise-based, cleaner to use with `async/await`, supports streaming and `AbortController`, and has a simpler API.

---

### 3. Why do we use `AbortController` in React?

**Answer:** To cancel in-flight requests when a component unmounts or when a newer request supersedes an older one, preventing unnecessary work and avoiding state updates on unmounted components.

---

### 4. When would you use a WebSocket instead of `fetch()`?

**Answer:** Use WebSockets for real-time, bidirectional communication such as chat applications, live dashboards, collaborative editing, multiplayer games, or stock price updates. Use `fetch()` for standard request-response APIs.

---

### 5. What is `IntersectionObserver` used for?

**Answer:** It detects when an element enters or exits the viewport. Common use cases include lazy loading images, infinite scrolling, analytics, and scroll-triggered animations.

---

### 6. What is the difference between `MutationObserver` and `ResizeObserver`?

**Answer:** `MutationObserver` detects changes to the DOM structure, attributes, or text. `ResizeObserver` detects changes to an individual element's dimensions.

---

### 7. Why should you disconnect observers in React?

**Answer:** To prevent memory leaks, unnecessary callbacks, and work after the component has been unmounted.

---

### 8. Where should authentication tokens be stored?

**Answer:** For web applications, **HttpOnly + Secure + SameSite cookies** are generally preferred because they cannot be accessed by JavaScript, reducing the risk of XSS attacks. `localStorage` is convenient but should not be used for sensitive tokens unless the security trade-offs are fully understood.
