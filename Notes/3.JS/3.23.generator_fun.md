# JavaScript — Generator Functions

A **Generator Function** is a special function that can **pause its execution and resume later**.

It is declared using `function*` and uses `yield`.

---

## 1. Basic Syntax

```js
function* generator() {
  yield 1;
  yield 2;
  yield 3;
}

const gen = generator();

console.log(gen.next()); // { value: 1, done: false }
console.log(gen.next()); // { value: 2, done: false }
console.log(gen.next()); // { value: 3, done: false }
console.log(gen.next()); // { value: undefined, done: true }
```

### Important

Calling the generator function **doesn't execute its body immediately**.

```js
const gen = generator();
```

It returns a **Generator object** (which is also an iterator).

Execution starts when `.next()` is called.

---

# 2. `yield`

`yield` **pauses** the generator and returns a value.

```js
function* numbers() {
  console.log("Start");

  yield 10;

  console.log("After 10");

  yield 20;

  console.log("After 20");
}

const gen = numbers();

console.log(gen.next());
// Start
// { value: 10, done: false }

console.log(gen.next());
// After 10
// { value: 20, done: false }

console.log(gen.next());
// After 20
// { value: undefined, done: true }
```

Think:

```text
next()
 ↓
execute
 ↓
yield
 ↓
PAUSE
 ↓
next()
 ↓
resume
 ↓
yield
 ↓
PAUSE
```

---

# 3. `yield` Can Receive a Value

This is an important interview concept.

```js
function* test() {
  const value = yield "Hello";

  console.log(value);
}

const gen = test();

console.log(gen.next());
// { value: "Hello", done: false }

console.log(gen.next(100));
// 100
// { value: undefined, done: true }
```

The value passed to:

```js
gen.next(100)
```

becomes the result of the **previous `yield` expression**.

```text
yield "Hello"
      ↑
      |
next(100)
      ↓
value = 100
```

---

# 4. Generator is an Iterator

A generator automatically implements the **iterator protocol**.

```js
function* numbers() {
  yield 1;
  yield 2;
  yield 3;
}

const gen = numbers();

console.log(gen.next());
console.log(gen.next());
```

Each `.next()` returns:

```js
{
  value: ...,
  done: false
}
```

At the end:

```js
{
  value: undefined,
  done: true
}
```

---

# 5. `for...of`

Generators can be consumed using `for...of`.

```js
function* numbers() {
  yield 1;
  yield 2;
  yield 3;
}

for (const num of numbers()) {
  console.log(num);
}
```

Output:

```text
1
2
3
```

`for...of` automatically calls `.next()` until `done === true`.

---

# 6. `yield*`

`yield*` delegates to another iterable/generator.

```js
function* first() {
  yield 1;
  yield 2;
}

function* second() {
  yield* first();
  yield 3;
}

console.log([...second()]);
// [1, 2, 3]
```

Useful for **composing generators**.

---

# 7. Infinite Generator ⭐

Generators can produce values lazily.

```js
function* counter() {
  let i = 1;

  while (true) {
    yield i++;
  }
}

const gen = counter();

console.log(gen.next().value); // 1
console.log(gen.next().value); // 2
console.log(gen.next().value); // 3
```

It doesn't generate all values upfront.

This is called **lazy evaluation**.

---

# 8. Generator vs Normal Function

| Normal Function     | Generator                 |
| ------------------- | ------------------------- |
| Executes normally   | Can pause/resume          |
| Uses `return`       | Uses `yield`              |
| Returns final value | Returns Generator object  |
| Executes once       | Can resume multiple times |
| Eager execution     | Supports lazy execution   |

---

# 9. Generator vs Async/Await

Don't confuse them.

### Generator

```js
function* getData() {
  const data = yield fetch("/api/users");
}
```

Generators themselves **don't automatically handle Promises**.

### Async function

```js
async function getData() {
  const response = await fetch("/api/users");
}
```

`async/await` is specifically designed for asynchronous operations.

Historically, generators were used with libraries such as **Redux-Saga** to manage async workflows.

---

# 10. React / Redux-Saga Connection ⭐

Since you may encounter Redux-Saga:

```js
function* fetchUsers() {
  const response = yield call(api.getUsers);

  yield put({
    type: "USERS_SUCCESS",
    payload: response
  });
}
```

Redux-Saga controls/resumes the generator and interprets the yielded effects.

So:

> **Generator → pause/resume execution → Redux-Saga uses this capability to manage complex async workflows.**

---

# Interview Points ⭐

Remember these:

* Syntax: `function*`
* Uses `yield`
* Calling generator returns a **Generator object**
* Generator execution starts with `.next()`
* `yield` pauses execution.
* `.next()` resumes execution.
* `.next(value)` sends a value back to the previous `yield`.
* Returns `{ value, done }`.
* Generator is an **iterator** and therefore works with `for...of`.
* `yield*` delegates to another iterable/generator.
* Supports **lazy evaluation** and even infinite sequences.
* Generators are **not inherently asynchronous**.
* Redux-Saga heavily uses generators.

### ⭐ Interview one-liner

> **A generator function is a special JavaScript function that can pause and resume execution using `yield`, returning an iterator-like Generator object that produces values through `.next()`.**
