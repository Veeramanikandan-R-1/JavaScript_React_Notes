# JavaScript Functions

Functions are one of the most important JavaScript concepts because React itself is built around **functions** (Function Components, Event Handlers, Hooks, Callbacks, Higher-Order Components, etc.).

Understanding functions is essential for writing reusable, maintainable, and performant React applications.

---

# What is a Function?

A function is a reusable block of code that performs a specific task.

Instead of writing the same code multiple times, we write it once inside a function and call it whenever needed.

```javascript
function greet() {
    console.log("Hello");
}

greet();
```

Output

```text
Hello
```

---

# Types of Functions

* Function Declaration
* Function Expression
* Arrow Function
* Callback Function
* Higher-Order Function (HOF)
* IIFE (Immediately Invoked Function Expression)

---

# 1. Function Declaration

A function declared using the `function` keyword with a name.

## Syntax

```javascript
function functionName() {
    // code
}
```

Example

```javascript
function add(a, b) {
    return a + b;
}

console.log(add(2, 3));
```

Output

```text
5
```

---

## Characteristics

* Has a function name.
* Hoisted completely.
* Can be called before its declaration.

Example

```javascript
sayHello();

function sayHello() {
    console.log("Hello");
}
```

Output

```text
Hello
```

---

## Internal Working

During the creation phase, JavaScript stores the entire function in memory.

```
Creation Phase

sayHello → function
```

So it is available before execution starts.

---

# 2. Function Expression

A function assigned to a variable.

```javascript
const add = function(a, b) {
    return a + b;
};
```

Usage

```javascript
console.log(add(2,3));
```

Output

```text
5
```

---

## Characteristics

* Stored inside a variable.
* Not fully hoisted.
* Cannot be called before initialization.

Example

```javascript
sayHello();

const sayHello = function() {
    console.log("Hello");
};
```

Output

```text
ReferenceError
```

Because only the variable is hoisted (Temporal Dead Zone for `let`/`const`).

---

## Named Function Expression

```javascript
const greet = function sayHello() {
    console.log("Hello");
};
```

Useful for debugging stack traces.

---

# Function Declaration vs Function Expression

| Feature            | Declaration | Expression |
| ------------------ | ----------- | ---------- |
| Hoisted            | ✅ Yes       | ❌ No       |
| Named              | Required    | Optional   |
| Before declaration | ✅ Works     | ❌ Error    |
| Stored in variable | No          | Yes        |

---

# 3. Arrow Function

Introduced in ES6.

Shorter syntax for writing functions.

```javascript
const add = (a, b) => {
    return a + b;
};
```

---

## Implicit Return

If there is only one expression:

```javascript
const add = (a, b) => a + b;
```

No `return` keyword is needed.

---

## Single Parameter

```javascript
const square = n => n * n;
```

---

## No Parameters

```javascript
const greet = () => "Hello";
```

---

# Arrow Function vs Normal Function

## 1. `this`

Normal function

```javascript
const obj = {
    name: "John",
    greet: function () {
        console.log(this.name);
    }
};

obj.greet();
```

Output

```text
John
```

Arrow function

```javascript
const obj = {
    name: "John",
    greet: () => {
        console.log(this.name);
    }
};

obj.greet();
```

Output

```text
undefined
```

Arrow functions do **not** have their own `this`. They inherit it from the surrounding (lexical) scope.

---

## 2. Cannot be Constructors

```javascript
const Person = () => {};

new Person();
```

Output

```text
TypeError
```

Arrow functions cannot be used with `new`.

---

## 3. No `arguments` Object

Normal

```javascript
function demo() {
    console.log(arguments);
}
```

Arrow

```javascript
const demo = () => {
    console.log(arguments);
};
```

Arrow functions don't have their own `arguments`. Use **rest parameters** instead.

```javascript
const demo = (...args) => {
    console.log(args);
};
```

---

# When to Use Arrow Functions

✅ React components

```javascript
const App = () => {
    return <h1>Hello</h1>;
};
```

✅ Event handlers

```javascript
const handleClick = () => {};
```

✅ Array methods

```javascript
users.map(user => user.name);
```

❌ Avoid them as object methods if you need `this`.

---

# 4. Callback Function

A callback is a function passed as an argument to another function.

Example

```javascript
function greet(name, callback) {
    console.log("Hello " + name);

    callback();
}

function done() {
    console.log("Completed");
}

greet("John", done);
```

Output

```text
Hello John
Completed
```

---

## Why Callbacks?

They allow one function to decide **what should happen next**.

---

## Built-in Callback Examples

### setTimeout

```javascript
setTimeout(() => {
    console.log("Executed");
}, 1000);
```

---

### Array map

```javascript
const nums = [1,2,3];

const doubled = nums.map(num => num * 2);
```

---

### filter

```javascript
const even = nums.filter(num => num % 2 === 0);
```

---

### forEach

```javascript
nums.forEach(num => console.log(num));
```

---

# React Callback Examples

Event handler

```jsx
<button onClick={handleClick}>
    Save
</button>
```

`handleClick` is passed as a callback.

---

# Callback Hell

Nested callbacks reduce readability.

```javascript
task1(() => {
    task2(() => {
        task3(() => {
            task4();
        });
    });
});
```

Modern JavaScript prefers **Promises** and **async/await** to avoid callback hell.

---

# 5. Higher-Order Function (HOF)

A Higher-Order Function is a function that:

* Accepts another function as an argument, **or**
* Returns another function.

---

## Accepts Function

```javascript
function calculate(a, b, operation) {
    return operation(a, b);
}

function multiply(a, b) {
    return a * b;
}

console.log(calculate(2, 3, multiply));
```

Output

```text
6
```

---

## Returns Function

```javascript
function greet(message) {
    return function(name) {
        console.log(message + " " + name);
    };
}

const hello = greet("Hello");

hello("John");
```

Output

```text
Hello John
```

---

# Common Higher-Order Functions

```javascript
map()

filter()

reduce()

find()

some()

every()

sort()
```

Example

```javascript
const nums = [1,2,3];

const squared = nums.map(n => n * n);
```

---

# React Examples

## React.memo

```javascript
export default React.memo(Button);
```

Returns an enhanced component.

---

## Higher-Order Components (HOC)

```javascript
withRouter(Component)
```

A function that returns another component.

---

# Callback vs Higher-Order Function

| Callback                     | Higher-Order Function         |
| ---------------------------- | ----------------------------- |
| Passed into another function | Accepts or returns a function |
| `handleClick`                | `map()`                       |
| `setTimeout()` callback      | `filter()`                    |
| Event handler                | `React.memo()`                |

A callback is **the function being passed**. A higher-order function is **the function receiving or returning functions**.

---

# 6. IIFE (Immediately Invoked Function Expression)

An IIFE is a function that executes immediately after it is created.

Syntax

```javascript
(function () {
    console.log("Executed");
})();
```

Output

```text
Executed
```

---

## Arrow IIFE

```javascript
(() => {
    console.log("Executed");
})();
```

---

# Why Use IIFE?

Before ES6 modules and block scope, IIFEs were commonly used to:

* Avoid global variable pollution.
* Create private scope.
* Execute initialization code once.

Example

```javascript
(function () {
    const secret = "ABC";
    console.log(secret);
})();
```

Outside

```javascript
console.log(secret);
```

Output

```text
ReferenceError
```

The variable is private to the IIFE.

---

## Do We Still Use IIFE?

Rarely.

Modern JavaScript uses:

* ES Modules
* `let`
* `const`
* Block scope

However, interviewers still ask about IIFEs because they are part of JavaScript fundamentals.

# Common Mistakes

### ❌ Calling a function expression before initialization

```javascript
sayHi();

const sayHi = function(){};
```

---

### ❌ Using arrow functions where `this` is required

```javascript
const obj = {
    value: 10,
    get: () => this.value
};
```

---

### ❌ Confusing Callback and HOF

```javascript
array.map(callback);
```

* `map()` → Higher-Order Function
* `callback` → Callback Function

---

### ❌ Forgetting `return` in arrow functions with braces

```javascript
const add = (a, b) => {
    a + b;
};
```

Returns `undefined`.

Correct

```javascript
const add = (a, b) => {
    return a + b;
};
```

Or

```javascript
const add = (a, b) => a + b;
```

---

# Best Practices

* Use **Function Declarations** for reusable utility functions.
* Use **Arrow Functions** for React components, event handlers, and array methods.
* Avoid arrow functions for object methods requiring `this`.
* Prefer **Promises/async-await** over deeply nested callbacks.
* Understand that callbacks and HOFs are different but closely related.
* Learn IIFEs for interviews, though they are less common in modern React projects.

# Common React (6 Years Experience) Interview Questions

### 1. What is the difference between a Function Declaration and a Function Expression?

**Answer:** A Function Declaration is fully hoisted and can be called before its declaration. A Function Expression is assigned to a variable and cannot be used before initialization.

---

### 2. What is the difference between an Arrow Function and a Normal Function?

**Answer:**

* Arrow functions have lexical `this`.
* They don't have their own `arguments`.
* They cannot be used as constructors.
* Normal functions have their own `this`, `arguments`, and can be used with `new`.

---

### 3. Why are Arrow Functions widely used in React?

**Answer:** They provide concise syntax, lexical `this`, and work well for function components, event handlers, and array methods.

---

### 4. What is a Callback Function?

**Answer:** A callback is a function passed as an argument to another function, allowing custom behavior to be executed later.

---

### 5. What is a Higher-Order Function?

**Answer:** A function that accepts another function as an argument or returns a function. Examples include `map()`, `filter()`, `reduce()`, and `React.memo()`.

---

### 6. Is every Callback a Higher-Order Function?

**Answer:** No. A **callback** is the function being passed, while a **higher-order function** is the function that accepts or returns functions.

Example:

```javascript
arr.map(callback);
```

* `callback` → Callback
* `map()` → Higher-Order Function

---

### 7. What is an IIFE, and why was it used?

**Answer:** An Immediately Invoked Function Expression executes as soon as it is defined. It was mainly used to create private scope and avoid global variable pollution before ES6 modules and block scope.

---

### 8. When should you avoid using Arrow Functions?

**Answer:** Avoid them for object methods or class methods when you need the function to have its own `this` context.
