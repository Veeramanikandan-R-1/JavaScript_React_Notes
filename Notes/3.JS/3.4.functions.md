# JavaScript Functions — Interview Notes

Functions are **reusable blocks of code** that perform a specific task.

---

## 1. Function Declaration ⭐

A function defined using the `function` keyword with a name.

```js
function add(a, b) {
  return a + b;
}

console.log(add(2, 3)); // 5
```

### Important: Hoisting

Function declarations are **hoisted**, so they can be called before their declaration.

```js
sayHello(); // ✅ Hello

function sayHello() {
  console.log("Hello");
}
```

---

# 2. Function Expression

A function assigned to a variable.

```js
const add = function (a, b) {
  return a + b;
};

console.log(add(2, 3)); // 5
```

### Named function expression

```js
const factorial = function fact(n) {
  if (n <= 1) return 1;
  return n * fact(n - 1);
};
```

### Important ⭐

Function expressions are **not callable before the assignment is executed**.

```js
add(); // ❌ ReferenceError

const add = function () {};
```

---

# 3. Arrow Function ⭐⭐⭐

Shorter syntax introduced in ES6.

```js
const add = (a, b) => {
  return a + b;
};
```

If there is a single expression:

```js
const add = (a, b) => a + b;
```

Single parameter can omit parentheses:

```js
const square = n => n * n;
```

### Key difference: `this` ⭐

Arrow functions **do not have their own `this`**. They capture `this` from the surrounding lexical scope.

```js
const user = {
  name: "John",

  greet() {
    const inner = () => {
      console.log(this.name);
    };

    inner();
  }
};

user.greet(); // John
```

Regular functions have their own `this` depending on how they are called.

### Arrow functions also don't have their own:

* `arguments`
* `prototype`
* `new` capability

```js
const Person = () => {};

new Person(); // ❌ TypeError
```

### React usage ⭐

Arrow functions are very common for callbacks:

```jsx
users.map(user => (
  <div key={user.id}>{user.name}</div>
));
```

---

# 4. Callback Function ⭐⭐⭐

A **callback** is a function passed to another function to be executed later/by that function.

```js
function greet(name, callback) {
  console.log("Hello " + name);
  callback();
}

greet("John", () => {
  console.log("Welcome!");
});
```

### Common JavaScript examples

```js
setTimeout(() => {
  console.log("Done");
}, 1000);
```

```js
[1, 2, 3].map(num => num * 2);
```

Here:

```js
num => num * 2
```

is a callback.

### React example

```jsx
<button onClick={() => handleClick()}>
  Save
</button>
```

The function is provided to React and invoked when the click occurs.

---

# 5. Higher-Order Function ⭐⭐⭐

A **Higher-Order Function (HOF)** is a function that:

1. **Accepts another function as an argument**, OR
2. **Returns a function**

### Accepts a function

```js
function calculate(a, b, operation) {
  return operation(a, b);
}

calculate(10, 5, (a, b) => a + b); // 15
calculate(10, 5, (a, b) => a * b); // 50
```

### Returns a function

```js
function multiplier(x) {
  return function (y) {
    return x * y;
  };
}

const double = multiplier(2);

double(5); // 10
```

### Built-in HOFs ⭐

Common examples:

```js
map()
filter()
reduce()
forEach()
some()
every()
find()
sort()
```

Example:

```js
const numbers = [1, 2, 3, 4];

const result = numbers
  .filter(n => n % 2 === 0)
  .map(n => n * 2);

console.log(result); // [4, 8]
```

### Interview distinction

```text
Callback
→ Function passed to another function

Higher-order function
→ Function that accepts/returns a function
```

A function can be **both** depending on the context.

---

# 6. IIFE ⭐⭐

**IIFE = Immediately Invoked Function Expression**

A function that is **created and executed immediately**.

```js
(function () {
  console.log("Executed immediately");
})();
```

Arrow version:

```js
(() => {
  console.log("Executed immediately");
})();
```

### Why use IIFE?

Historically used to:

* Create a private scope
* Avoid polluting global scope
* Execute initialization code immediately

Example:

```js
(function () {
  const secret = "123";

  console.log(secret);
})();

console.log(secret); // ❌ ReferenceError
```

### Modern JavaScript

With `let`, `const`, ES modules, and module scope, IIFEs are **less commonly required** for encapsulation.

# ⭐ Function Declaration vs Expression vs Arrow

|                    | Declaration        | Expression                 | Arrow                  |
| ------------------ | ------------------ | -------------------------- | ---------------------- |
| Syntax             | `function foo(){}` | `const foo = function(){}` | `const foo = () => {}` |
| Hoisted callable   | ✅                  | ❌                          | ❌                      |
| Own `this`         | ✅                  | ✅                          | ❌                      |
| Own `arguments`    | ✅                  | ✅                          | ❌                      |
| Can use `new`      | ✅                  | ✅                          | ❌                      |
| Common React usage | Good               | Good                       | ⭐ Very common          |

# 🎯 Quick Revision

```text
Function Declaration
→ Named function, hoisted

Function Expression
→ Function stored in variable

Arrow Function
→ Concise syntax + lexical this

Callback
→ Function passed to another function

Higher-Order Function
→ Accepts or returns a function

IIFE
→ Function executed immediately
```

### ⭐ Senior React Interview Takeaway

You should be especially comfortable with:

```js
// Callback
users.map(user => user.name);

// Higher-order function
const double = numbers.map(n => n * 2);

// Arrow function
const add = (a, b) => a + b;

// Function expression
const greet = function () {};

// IIFE
(() => {
  // initialization
})();
```

**Most important interview distinction:**

> **A callback describes how a function is used; a higher-order function describes what a function does with other functions.**
