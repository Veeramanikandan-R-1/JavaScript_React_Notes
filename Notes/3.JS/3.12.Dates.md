# JavaScript - Date

Dates are used everywhere in React applications:

* Showing created/updated timestamps
* Displaying order dates
* Calendar components
* Scheduling
* Countdown timers
* Timezone conversions
* Date formatting for different locales

One of the most common interview topics is **how JavaScript stores dates, handles timezones, and formats dates for users.**

---

# 1. Date API

## What is Date?

The `Date` object represents a **specific point in time**.

Internally, JavaScript stores dates as the **number of milliseconds since January 1, 1970 UTC (Unix Epoch).**

```
1970-01-01T00:00:00.000Z
```

Example

```javascript
const date = new Date();
console.log(date);
```

Output (example)

```
Wed Jul 29 2026 13:30:15 GMT+0530
```

---

# Comparing Dates

Wrong

```javascript
const a = new Date();
const b = new Date();

a === b;
```

Returns

```
false
```

Because objects are compared by reference.

Correct

```javascript
a.getTime() === b.getTime();
```

or

```javascript
+a === +b
```

---

note: new Date() vs Date()

The main difference is that **`new Date()` creates a Date object**, while **`Date()` (without `new`) returns a formatted date string**.

| `new Date()`                               | `Date()`                                               |
| ------------------------------------------ | ------------------------------------------------------ |
| Creates a `Date` object                    | Returns the current date/time as a string              |
| Can use date methods like `getFullYear()`  | Cannot use date methods                                |
| Used for date calculations and comparisons | Mostly used for quickly printing the current date/time |

### Example

```javascript
const d1 = new Date();
console.log(d1);
// Wed Jul 29 2026 ...

console.log(d1.getFullYear());
// 2026
```

```javascript
const d2 = Date();
console.log(d2);
// "Wed Jul 29 2026 13:45:30 GMT+0530 (India Standard Time)"
```

Trying to call a date method on the string will fail:

```javascript
const d = Date();

d.getFullYear(); // ❌ Error: getFullYear is not a function
```

### Internal Reason

* `new Date()` invokes the **Date constructor**, which creates a new `Date` object.
* `Date()` without `new` behaves like a normal function and simply returns the current date/time as a string.

### Interview Answer (Short)

> **`new Date()` returns a `Date` object that supports date operations (`getTime()`, `getFullYear()`, etc.), whereas `Date()` without `new` returns the current date and time as a string and cannot be used for date manipulation.**

# Date API Best Practices

✔ Use ISO strings.

✔ Store UTC in backend.

✔ Convert to local time only for display.

✔ Compare timestamps instead of Date objects.

✔ Use `Date.now()` for timestamps.

# 2. Intl.DateTimeFormat

## What is it?

`Intl.DateTimeFormat` is the **modern internationalization API** for formatting dates according to locale.

Instead of manually formatting:

```
29/07/2026
```

or

```
07/29/2026
```

Use

```javascript
new Intl.DateTimeFormat(locale)
```

---

# Basic Example

```javascript
const formatter = new Intl.DateTimeFormat("en-US");

formatter.format(new Date());
```

Output

```
7/29/2026
```

---

Indian Format

```javascript
new Intl.DateTimeFormat("en-IN")
```

Output

```
29/7/2026
```

---

French

```javascript
new Intl.DateTimeFormat("fr-FR")
```

Output

```
29/07/2026
```

---

Japanese

```javascript
new Intl.DateTimeFormat("ja-JP")
```

Output

```
2026/7/29
```

# Common Interview Questions (6+ Years)

### 1. How does JavaScript internally store dates?

**Answer:** As the number of milliseconds since **January 1, 1970 UTC (Unix Epoch)**.

---

### 2. What is the difference between `getDate()` and `getDay()`?

**Answer:**

* `getDate()` returns the **day of the month (1–31)**.
* `getDay()` returns the **day of the week (0–6, Sunday–Saturday)**.

---

### 3. Why is `getMonth()` confusing?

**Answer:** Months are **zero-based** (`0 = January`, `11 = December`), so developers often forget to adjust when displaying or constructing dates.

---

### 4. Why shouldn't you compare two `Date` objects with `===`?

**Answer:** `Date` objects are compared by reference, not by value. Compare timestamps using `getTime()` instead.

---

### 5. What is the purpose of `toISOString()`?

**Answer:** It converts a date to a standardized **UTC ISO 8601 string**, commonly used for APIs and backend communication.

---

### 6. Why should you use `Intl.DateTimeFormat` instead of manually formatting dates?

**Answer:** It automatically formats dates according to the user's locale, supports different languages, calendars, and time zones, and reduces formatting bugs.

---

### 7. What is the difference between local time and UTC in JavaScript?

**Answer:** Methods like `getHours()` return the local time based on the user's time zone, while `getUTCHours()` returns the corresponding UTC time. The underlying timestamp is the same; only the displayed representation differs.

---

### 8. What are common best practices for handling dates in React applications?

**Answer:**

* Store timestamps or ISO UTC strings in the backend.
* Parse ISO strings with `new Date()`.
* Format dates for display using `Intl.DateTimeFormat`.
* Compare dates using timestamps (`getTime()`).
* Avoid non-ISO date strings to prevent browser parsing inconsistencies.
