# JavaScript `this` Keyword 

The `this` keyword is one of the **most confusing** yet **most frequently asked** JavaScript interview topics.

For React developers, understanding `this` helps explain:

* Class Components
* Event handlers
* Arrow functions
* `bind()`
* `call()`
* `apply()`
* Callback execution

---

# What is `this`?

> **`this` is a special keyword that refers to the object that is executing the current function.**

**Important:**

`this` is **not determined where the function is written**.

It is determined **how the function is called** (except for arrow functions).

---

# Rules of `this`

There are **5 common scenarios**:

1. Global
2. Regular Function
3. Object Method
4. Arrow Function
5. Explicit Binding (`bind`, `call`, `apply`)

---

# 1. Global `this`

In the browser

```javascript
console.log(this);
```

Output

```text
Window
```

Because the global object in browsers is

```text
window
```

---

### Example

```javascript
var name = "John";

console.log(this.name);
```

Output (browser)

```text
John
```

---

### Node.js

In Node.js modules,

```javascript
console.log(this);
```

does **not** refer to the global object. It refers to the current module context (not `globalThis`).

---

# 2. `this` Inside a Regular Function

### Non-Strict Mode (Browser)

```javascript
function greet() {
    console.log(this);
}

greet();
```

Output

```text
Window
```

---

### Strict Mode

```javascript
"use strict";

function greet() {
    console.log(this);
}

greet();
```

Output

```text
undefined
```

This prevents accidental access to the global object.

---

# 3. `this` Inside an Object Method

When a function is called as a method,

`this` refers to **the object before the dot (`.`).**

```javascript
const user = {
    name: "John",

    greet() {
        console.log(this.name);
    }
};

user.greet();
```

Output

```text
John
```

Because

```text
this = user
```

---

### Another Example

```javascript
const car = {
    brand: "BMW",

    show() {
        console.log(this.brand);
    }
};

car.show();
```

Output

```text
BMW
```

---

## Losing `this`

```javascript
const user = {
    name: "John",

    greet() {
        console.log(this.name);
    }
};

const fn = user.greet;

fn();
```

Output (strict mode)

```text
undefined
```

Because

```text
fn()
```

is just a regular function call.

It is **not** called through the object.

---

# 4. `this` Inside Arrow Functions

Arrow functions **do not create their own `this`.**

Instead,

they inherit `this` from their surrounding (lexical) scope.

---

### Example

```javascript
const user = {
    name: "John",

    greet: () => {
        console.log(this.name);
    }
};

user.greet();
```

Output

```text
undefined
```

Why?

Arrow functions don't use

```text
this = user
```

They inherit `this` from the outer scope (global/module scope).

---

## Correct Way

```javascript
const user = {
    name: "John",

    greet() {
        console.log(this.name);
    }
};
```

---

# Why Arrow Functions are Useful

Inside callbacks.

```javascript
const user = {

    name: "John",

    greet() {

        setTimeout(() => {
            console.log(this.name);
        }, 1000);

    }
};

user.greet();
```

Output

```text
John
```

The arrow function inherits

```text
this = user
```

from `greet()`.

---

### Without Arrow Function

```javascript
const user = {

    name: "John",

    greet() {

        setTimeout(function () {
            console.log(this.name);
        }, 1000);

    }
};

user.greet();
```

Output

```text
undefined
```

Because the callback is a regular function and gets its own `this`.

---

# Arrow vs Regular Function

| Feature                 | Regular Function | Arrow Function |
| ----------------------- | ---------------- | -------------- |
| Own `this`              | ✅ Yes            | ❌ No           |
| Own `arguments`         | ✅ Yes            | ❌ No           |
| Can use `new`           | ✅ Yes            | ❌ No           |
| Good for object methods | ✅ Yes            | ❌ Usually No   |
| Good for callbacks      | ❌ Sometimes      | ✅ Yes          |

---

# 5. Explicit Binding

JavaScript provides three methods to manually set `this`.

* `call()`
* `apply()`
* `bind()`

---

# `call()`

Calls the function **immediately**.

Syntax

```javascript
function.call(thisArg, arg1, arg2)
```

Example

```javascript
function greet(city) {
    console.log(this.name, city);
}

const user = {
    name: "John"
};

greet.call(user, "London");
```

Output

```text
John London
```

---

# `apply()`

Almost identical to `call()`.

Difference:

Arguments are passed as an array.

```javascript
function greet(city, country) {
    console.log(this.name, city, country);
}

const user = {
    name: "John"
};

greet.apply(user, ["London", "UK"]);
```

Output

```text
John London UK
```

---

# `bind()`

Does **not execute immediately**.

Returns a **new function**.

```javascript
function greet() {
    console.log(this.name);
}

const user = {
    name: "John"
};

const fn = greet.bind(user);

fn();
```

Output

```text
John
```

---

# Difference Between `call`, `apply`, and `bind`

| Method    | Executes Immediately | Arguments                                                               |
| --------- | -------------------- | ----------------------------------------------------------------------- |
| `call()`  | ✅ Yes                | Individual                                                              |
| `apply()` | ✅ Yes                | Array                                                                   |
| `bind()`  | ❌ No                 | Individual (when creating the bound function or when invoking it later) |

---

# React Connection

## React Class Components

Without binding

```javascript
class App extends React.Component {

    handleClick() {
        console.log(this);
    }

    render() {
        return (
            <button onClick={this.handleClick}>
                Click
            </button>
        );
    }
}
```

`this` becomes undefined because the method is passed as a callback.

---

### Solution 1

```javascript
constructor() {
    super();

    this.handleClick =
        this.handleClick.bind(this);
}
```

---

### Solution 2 (Preferred in Class Components)

```javascript
handleClick = () => {
    console.log(this);
};
```

Arrow functions inherit the class instance's `this`.

> **Note:** Modern React primarily uses Function Components and Hooks, so `bind()` is much less common today. However, interviewers still ask about it because many existing codebases still contain Class Components.

---

# Another React Example

```jsx
<button
    onClick={() => deleteUser(id)}
>
    Delete
</button>
```

Arrow functions capture variables (`id`) from the surrounding scope and don't need manual `this` binding.

# Common Mistakes

### ❌ Using Arrow Functions as Object Methods

```javascript
const user = {

    name: "John",

    greet: () => {
        console.log(this.name);
    }
};
```

Arrow functions don't bind `this` to `user`.

---

### ❌ Forgetting `bind`

```javascript
const fn = user.greet;

fn();
```

`this` is lost because the function is detached from its object.

---

### ❌ Confusing Scope with `this`

Scope determines

```text
Variable access
```

`this` determines

```text
Current execution object
```

They are different concepts.

---

### ❌ Assuming Arrow Functions Always Have `this`

Arrow functions **inherit** `this`; they don't create their own.

---

# Best Practices

* Use regular methods for object methods that rely on `this`.
* Use arrow functions for callbacks (`setTimeout`, promises, event callbacks).
* Use `bind()` only when you need to permanently fix the value of `this`.
* Understand `call()` and `apply()` for function borrowing and explicit context.
* In modern React Function Components, `this` is generally **not used**.

# Common React (6 Years Experience) Interview Questions

### 1. What is the `this` keyword?

**Answer:**
`this` refers to the object that is executing the current function. Its value is determined by how the function is called, except for arrow functions.

---

### 2. What is the difference between `this` in a regular function and an arrow function?

**Answer:**

* **Regular function:** Gets its own `this` based on the call site.
* **Arrow function:** Doesn't have its own `this`; it inherits `this` from the surrounding lexical scope.

---

### 3. Why shouldn't arrow functions generally be used as object methods?

**Answer:**
Because they don't bind `this` to the object. They inherit `this` from the outer scope, which usually isn't the object itself.

---

### 4. What is the difference between `call()`, `apply()`, and `bind()`?

**Answer:**

* `call()` invokes the function immediately with individual arguments.
* `apply()` invokes the function immediately with arguments as an array.
* `bind()` returns a new function with `this` permanently bound and does not execute immediately.

---

### 5. Why was `bind()` commonly used in React Class Components?

**Answer:**
Class methods lose their `this` when passed as callbacks (for example, event handlers). `bind()` ensures `this` always refers to the class instance.

---

### 6. Do React Function Components use `this`?

**Answer:**
No. Function Components use Hooks (`useState`, `useEffect`, etc.) and lexical scope instead of `this`.

---

### 7. Why does `this` become `undefined` when you store an object method in a variable?

```javascript
const fn = user.greet;
fn();
```

**Answer:**
Because the method is no longer called through `user`. It becomes a regular function call, so it loses the object context.

---

### 8. Why do arrow functions work well inside `setTimeout()` callbacks?

**Answer:**
Because they inherit `this` from the surrounding function, avoiding the common problem where regular callback functions get a different `this`.
