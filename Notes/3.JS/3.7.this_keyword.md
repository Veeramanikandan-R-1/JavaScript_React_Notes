# JavaScript `this` Keyword — Interview Notes

`this` refers to the **object/context associated with the current function invocation**.

> ⭐ Key rule: For regular functions, `this` is mainly determined by **how the function is called**, not where it is defined.

---

# 1. `this` in Global Context

In a browser's **non-module script**:

```js
console.log(this);
```

Typically:

```text
window
```

But in **ES modules**, top-level `this` is:

```js
undefined
```

Also, in strict-mode regular functions:

```js
"use strict";

function test() {
  console.log(this);
}

test(); // undefined
```

Without strict mode, a plain function call in a browser typically gets the global object (`window`).

---

# 2. `this` in a Regular Function ⭐

For a regular function, `this` depends on **how the function is called**.

```js
function greet() {
  console.log(this);
}

greet();
```

In strict mode:

```text
undefined
```

In non-strict mode in a browser:

```text
window
```

### Important

```js
const obj = {
  name: "John",

  greet: function () {
    console.log(this.name);
  }
};

obj.greet(); // John
```

Here:

```text
this → obj
```

Because the function is called as:

```js
obj.greet()
```

---

# 3. `this` in an Object ⭐⭐⭐

When a regular method is called through an object:

```js
const user = {
  name: "John",

  greet() {
    console.log(this.name);
  }
};

user.greet(); // John
```

Here:

```text
this → user
```

### ⚠️ Common interview trap

```js
const user = {
  name: "John",

  greet() {
    console.log(this.name);
  }
};

const fn = user.greet;

fn(); // undefined in strict mode
```

Why?

The call is now:

```js
fn()
```

not:

```js
user.greet()
```

So the object context is lost.

---

# 4. Arrow Functions ⭐⭐⭐

Arrow functions **do not have their own `this`**.

They inherit `this` from their **lexical (surrounding) scope**.

```js
const user = {
  name: "John",

  greet() {
    const arrow = () => {
      console.log(this.name);
    };

    arrow();
  }
};

user.greet(); // John
```

The arrow function takes `this` from `greet()`.

### ⚠️ Important

This does **NOT** work as many beginners expect:

```js
const user = {
  name: "John",

  greet: () => {
    console.log(this.name);
  }
};

user.greet(); // ❌ Not "John"
```

Because the arrow doesn't create its own `this`; it inherits it from the surrounding scope.

### React ⭐

Arrow callbacks are useful because they preserve the surrounding `this`:

```js
class Component {
  handleClick = () => {
    console.log(this);
  };
}
```

In **React function components**, however, you generally don't use `this` because function components don't have class-style `this`.

---

# 5. `call()` ⭐⭐⭐

`call()` invokes a function **immediately** with a specified `this` value.

```js
function greet(city) {
  console.log(this.name, city);
}

const user = {
  name: "John"
};

greet.call(user, "Chennai");
// John Chennai
```

Syntax:

```js
function.call(thisArg, arg1, arg2, ...);
```

---

# 6. `apply()` ⭐⭐⭐

`apply()` is similar to `call()`, but arguments are passed as an **array/array-like object**.

```js
function greet(city, country) {
  console.log(this.name, city, country);
}

const user = {
  name: "John"
};

greet.apply(user, ["Chennai", "India"]);
```

### `call` vs `apply`

```js
fn.call(obj, a, b);

fn.apply(obj, [a, b]);
```

| `call()`               | `apply()`                     |
| ---------------------- | ----------------------------- |
| Arguments individually | Arguments as array/array-like |
| `fn.call(obj, 1, 2)`   | `fn.apply(obj, [1, 2])`       |

---

# 7. `bind()` ⭐⭐⭐

`bind()` **doesn't execute the function immediately**.

It returns a **new function with `this` permanently bound** to the specified value.

```js
function greet() {
  console.log(this.name);
}

const user = {
  name: "John"
};

const boundGreet = greet.bind(user);

boundGreet(); // John
```

### With arguments

```js
function greet(city) {
  console.log(this.name, city);
}

const user = {
  name: "John"
};

const greetChennai = greet.bind(user, "Chennai");

greetChennai();
// John Chennai
```

---

# ⭐ `call` vs `apply` vs `bind`

```js
function greet(city) {
  console.log(this.name, city);
}

const user = { name: "John" };

greet.call(user, "Chennai");        // Execute now
greet.apply(user, ["Chennai"]);     // Execute now
const fn = greet.bind(user, "Chennai");
fn();                                // Execute later
```

| Method    | Executes immediately? | Arguments                 |
| --------- | --------------------: | ------------------------- |
| `call()`  |                     ✅ | Individual                |
| `apply()` |                     ✅ | Array                     |
| `bind()`  |                     ❌ | Individual / partial args |

---

# ⭐ Important: Arrow + `call/apply/bind`

`call`, `apply`, and `bind` **cannot change the `this` of an arrow function**.

```js
const greet = () => {
  console.log(this);
};

greet.call({ name: "John" }); // Does NOT make this = { name: "John" }
```

Because arrow functions use **lexical `this`**.

---

# 🎯 `this` Rules — Quick Revision

For **regular functions**:

```text
obj.fn()
   ↓
this = obj
```

```js
fn.call(obj)
fn.apply(obj)
fn.bind(obj)
```

can explicitly control `this`.

For **arrow functions**:

```text
this = inherited from surrounding scope
```

`call/apply/bind` cannot change it.

### ⭐ Interview One-Liner

> **Regular function `this` is determined by how the function is called, while arrow-function `this` is lexically inherited from its surrounding scope. `call()` and `apply()` invoke immediately with a chosen `this`, whereas `bind()` returns a new function with bound `this`.**
