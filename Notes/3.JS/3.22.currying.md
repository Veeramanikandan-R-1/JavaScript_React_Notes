# JavaScript Currying

> **Goal:** Currying is a commonly asked JavaScript interview topic for senior frontend developers. It demonstrates your understanding of **functions, closures, higher-order functions, partial application, and functional programming**. It's also used internally by libraries like **Lodash, Ramda**, and appears in React patterns.

---

# 1. What is Currying?

Currying is the process of **transforming a function that takes multiple arguments into a sequence of functions, each taking one argument.**

Normal Function

```js
function add(a, b, c) {
    return a + b + c;
}

console.log(add(10, 20, 30));
```

Curried Version

```js
function add(a) {
    return function (b) {
        return function (c) {
            return a + b + c;
        };
    };
}

console.log(add(10)(20)(30));
```

Output

```text
60
```

---

# Why Currying?

Suppose you have a function

```js
calculateTax(country, taxRate, amount)
```

If your application always uses the same country and tax rate, you can create a reusable function.

Without Currying

```js
calculateTax("India", 18, 1000);

calculateTax("India", 18, 5000);

calculateTax("India", 18, 7000);
```

With Currying

```js
const indiaTax = calculateTax("India")(18);

indiaTax(1000);

indiaTax(5000);

indiaTax(7000);
```

This avoids repeatedly passing the same values.

# 2. How Currying Works

Normal Function

```js
function multiply(a, b) {
    return a * b;
}
```

Curried

```js
function multiply(a) {

    return function (b) {

        return a * b;

    };

}
```

Usage

```js
multiply(5)(4);
```

Execution

```text
multiply(5)

↓

returns function(b)

↓

function(4)

↓

20
```

# 3. Currying Uses Closures

Currying works because of **closures**.

```js
function add(a){

    return function(b){

        return a + b;

    };

}
```

When

```js
add(5)
```

returns

```js
function(b){

    return 5 + b;

}
```

The inner function remembers `a`.

```js
function greet(greeting){
```

Usage

```js

sayHello("John");

sayHello("Alex");
```

Output

```text

```

The value `"Hello"` is remembered because of closures.

# 8. Partial Application vs Currying (Very Important)

Many developers confuse these concepts.

## Currying

Converts

```text
(a,b,c)
```

into

```text
(a)(b)(c)
```

Example

```js
add(1)(2)(3);
```

---

## Partial Application

Some arguments are fixed, while the function still accepts the remaining arguments together.

Example

```js
function add(a,b,c){

    return a+b+c;

}

const addFive = add.bind(null,5);

addFive(10,20);
```

Equivalent to

```text
add(5,10,20)
```

---

## Difference

| Currying                   | Partial Application                  |
| -------------------------- | ------------------------------------ |
| One argument per function  | Remaining arguments can be multiple  |
| Changes function structure | Doesn't necessarily change structure |
| Uses closures              | Can use `bind()` or closures         |

---

# 9. Generic Currying Function

Interviewers may ask you to implement currying.

```js
function curry(fn){

    return function curried(...args){

        if(args.length >= fn.length){

            return fn(...args);

        }

        return function(...next){

            return curried(
                ...args,
                ...next
            );

        };

    };

}
```

Usage

```js
function sum(a,b,c){

    return a+b+c;

}

const curriedSum =
curry(sum);

console.log(
curriedSum(1)(2)(3)
);

console.log(
curriedSum(1,2)(3)
);

console.log(
curriedSum(1)(2,3)
);

console.log(
curriedSum(1,2,3)
);
```

All produce

```text
6
```

# 11. Currying in React

Currying is often used when creating reusable event handlers.

Example

Instead of

```jsx
<button
onClick={() => deleteUser(id)}
>
```

We can write

```js
const deleteUser =
id =>
() => {

console.log(id);

};
```

Usage

```jsx
<button
onClick={deleteUser(id)}
>
```

The first function receives the `id`.

The second function is the actual event handler.

---

# Another React Example

```js
const handleChange =
field =>
event => {

setForm({

...form,

[field]:
event.target.value

});

};
```

Usage

```jsx
<input
onChange={
handleChange("name")
}
/>

<input
onChange={
handleChange("email")
}
/>
```

This avoids writing separate handlers for every field.

# Common Mistakes

### Confusing currying with closures

Currying **uses** closures, but they are not the same.

* **Closure** → remembers outer variables.
* **Currying** → converts one multi-argument function into nested single-argument functions.

---

### Confusing currying with partial application

They solve similar problems but are different concepts.

---

### Forgetting to return functions

Wrong

```js
function add(a){

a+b;

}
```

Correct

```js
function add(a){

return function(b){

return a+b;

};

}
```

---

### Overusing currying

Don't curry every function.

Use it when:

* Reusability improves
* Readability improves
* Functional composition is useful

Otherwise, a normal function is simpler.

---

# Best Practices

* Use currying for reusable configurations (e.g., loggers, validators).
* Combine currying with closures for elegant reusable functions.
* Prefer arrow function syntax for simple curried functions.
* Avoid deeply nested curried functions when they reduce readability.
* Know the difference between currying and partial application for interviews.

# Frequently Asked Interview Questions (6 Years React)

### 1. What is currying in JavaScript?

**Answer:** Currying is the technique of transforming a function that takes multiple arguments into a sequence of functions that each take a single argument. It improves reusability and supports functional programming patterns.

---

### 2. What is the difference between currying and partial application?

**Answer:**

* **Currying** converts `fn(a, b, c)` into `fn(a)(b)(c)`.
* **Partial application** pre-fills some arguments while allowing the remaining arguments to be passed together.

---

### 3. How does currying work internally?

**Answer:** It works using **closures**. Each returned function retains access to the arguments provided in previous calls until all required arguments are collected.

---

### 4. Why is currying useful?

**Answer:**

* Creates reusable specialized functions.
* Avoids repeatedly passing the same arguments.
* Improves function composition.
* Common in functional programming libraries.

---

### 5. What is `fn.length` and why is it used in a generic curry function?

**Answer:** `fn.length` returns the number of declared parameters of a function. A generic curry implementation uses it to determine when enough arguments have been supplied to execute the original function.

---

### 6. How is currying used in React?

**Answer:** Currying is commonly used to create reusable event handlers and form handlers.

Example:

```jsx
const handleClick = id => () => {
    console.log(id);
};

<button onClick={handleClick(user.id)}>
    Delete
</button>
```

or

```jsx
const handleChange = field => event => {
    setForm({
        ...form,
        [field]: event.target.value
    });
};
```

---

### 7. Is currying the same as closures?

**Answer:** No. Currying is a function transformation technique, while a closure is the JavaScript mechanism that allows inner functions to remember variables from their outer scope. Currying depends on closures but they are different concepts.

---

### 8. When should you avoid currying?

**Answer:** Avoid currying when it makes the code harder to read or when there is no benefit from creating specialized reusable functions. Simple utility functions are often clearer as regular multi-argument functions.
