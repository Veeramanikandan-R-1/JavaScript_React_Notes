# JavaScript — Currying

**Currying** is the technique of converting a function that takes **multiple arguments at once** into a sequence of functions, where each function takes **one argument**.

### Normal function

```js
function add(a, b, c) {
  return a + b + c;
}

add(1, 2, 3); // 6
```

### Curried function

```js
function add(a) {
  return function (b) {
    return function (c) {
      return a + b + c;
    };
  };
}

add(1)(2)(3); // 6
```

---

## Arrow Function Version

```js
const add = a => b => c => a + b + c;

console.log(add(1)(2)(3)); // 6
```

Think of it as:

```text
add(1)
  ↓
function(b)
  ↓
function(c)
  ↓
result
```

---

# Why Currying?

### 1. Reusability / Partial Application

You can fix some arguments and reuse the resulting function.

```js
const multiply = a => b => a * b;

const multiplyBy10 = multiply(10);

multiplyBy10(5); // 50
multiplyBy10(8); // 80
multiplyBy10(3); // 30
```

Here:

```js
multiply(10)
```

returns a new function with `a = 10` remembered through **closure**.

---

# Currying + Closure

Currying commonly relies on **closures**.

```js
const discount = percentage => price =>
  price - (price * percentage) / 100;

const tenPercentOff = discount(10);

console.log(tenPercentOff(1000)); // 900
console.log(tenPercentOff(500));  // 450
```

`tenPercentOff` remembers `percentage = 10`.

# Practical Example

Suppose you want reusable API request configuration:

```js
const createRequest = baseUrl => endpoint => options => {
  return fetch(`${baseUrl}${endpoint}`, options);
};

const api = createRequest("https://api.example.com");

const getUsers = api("/users");

getUsers({ method: "GET" });
```

You configure common values once and reuse them.

---

# Currying vs Partial Application ⭐

They are related but not exactly the same.

### Currying

Transforms:

```js
f(a, b, c)
```

into:

```js
f(a)(b)(c)
```

### Partial Application

Fixes some arguments:

```js
function multiply(a, b) {
  return a * b;
}

const multiplyBy10 = b => multiply(10, b);

multiplyBy10(5); // 50
```

**Interview distinction:**

> Currying changes the function's argument structure; partial application pre-fills some arguments.

# Generic Curry Function ⭐

A common interview question is to implement `curry()`:

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn(...args);
    }

    return (...nextArgs) =>
      curried(...args, ...nextArgs);
  };
}

function add(a, b, c) {
  return a + b + c;
}

const curriedAdd = curry(add);

curriedAdd(1)(2)(3); // 6
curriedAdd(1, 2)(3); // 6
curriedAdd(1)(2, 3); // 6
```

The important idea is:

```text
curry(add)
   ↓
collect arguments
   ↓
enough arguments?
   ↓ yes → execute
   ↓ no  → return another function
```

---

# Important Interview Points

* Currying converts **multi-argument function → chain of single-argument functions**.
* Uses **closures** to remember previously supplied arguments.
* Useful for **reusability, composition, configuration**, and functional programming.
* `add(1)(2)(3)` is the classic example.
* **Currying ≠ partial application**.
* In JavaScript, currying is a **technique**, not a special language feature.
* Libraries such as Lodash provide utilities for currying.

### ⭐ One-line interview answer

> **Currying is a functional programming technique where a function taking multiple arguments is transformed into a sequence of functions, each accepting one argument, allowing arguments to be supplied incrementally and enabling reusable partially configured functions.**
