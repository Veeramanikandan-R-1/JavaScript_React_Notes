# JavaScript - Event Loop (Mandatory)

The **Event Loop** is one of the **most frequently asked JavaScript interview topics**, especially for React developers with 5–8 years of experience.

Interviewers ask this because React itself relies heavily on asynchronous behavior:

* API calls
* Timers
* User events
* Promise handling
* Rendering updates

Understanding the Event Loop helps you debug asynchronous code and predict execution order.

---

# 1. Why Do We Need the Event Loop?

JavaScript is **Single Threaded**.

That means it has **only one Call Stack** to execute code.

```text
JavaScript
     |
One Thread
     |
One Call Stack
```

If JavaScript waited for every slow operation (API calls, timers, file reads), the browser would freeze.

Instead:

* JavaScript executes synchronous code.
* Browser handles asynchronous work.
* Event Loop brings completed tasks back to JavaScript.

---

```text

        +--------------------------+
        |        Call Stack        |
        +--------------------------+
                   ▲
                   |
             Event Loop
            /           \
           /             \

(Promises)          (setTimeout, Events)

            ▲
            |

```

# 2. Call Stack

## What is it?

The **Call Stack** is where JavaScript executes functions.

Functions are pushed onto the stack.

After execution, they are removed.

---

## Example

```javascript
function one() {
    two();
}

function two() {
    console.log("Hello");
}

one();
```

Execution

```text
Call Stack

---------
| two() |
---------
| one() |
---------
|Global |
---------
```

After `two()` finishes

```text
---------
| one() |
---------
|Global |
---------
```

Finally

```text
---------
|Global |
---------
```

---

## Stack follows LIFO

Last In

↓

First Out

# 3. Web APIs

## What are Web APIs?

Web APIs are **provided by the browser**, not JavaScript.

Examples

* setTimeout
* setInterval
* fetch
* DOM Events
* localStorage
* Geolocation
* WebSocket

JavaScript delegates long-running work to Web APIs.

---

## Example

```javascript
console.log("Start");

setTimeout(() => {
    console.log("Timer");
}, 1000);

console.log("End");
```

Execution

```text
Call Stack

console.log("Start")

↓

setTimeout()

↓

Browser Web API

↓

console.log("End")
```

Output

```text
Start
End
Timer
```

---

# Why?

`setTimeout()` is registered with the browser.

JavaScript **does not wait**.

It immediately continues executing the next line.

---

# 4. Callback Queue

After Web APIs complete,

callbacks move into the **Callback Queue**.

Example

```javascript
setTimeout(() => {
    console.log("Done");
},1000);
```

Flow

```text
Call Stack

↓

Web API

↓

Callback Queue

↓

Event Loop

↓

Call Stack
```

---

# Callback Queue contains

* setTimeout
* setInterval
* DOM events
* Mouse click
* Keyboard events

---

# 5. Microtask Queue

Microtasks have **higher priority** than the Callback Queue (Macrotask Queue).

Contains

* Promise.then()
* Promise.catch()
* Promise.finally()
* queueMicrotask()
* MutationObserver

---

## Example

```javascript
console.log("Start");

Promise.resolve()
.then(() => console.log("Promise"));

console.log("End");
```

Output

```text
Start
End
Promise
```

---

## Why?

`.then()` goes into the **Microtask Queue**.

The Event Loop executes all microtasks before moving to macrotasks.

---

# 6. Macrotask Queue (Task Queue)

Contains

* setTimeout
* setInterval
* setImmediate (Node.js)
* MessageChannel
* DOM events

---

Example

```javascript
setTimeout(() => {
    console.log("Timer");
});
```

Moves into

```text
Macrotask Queue
```

---

# Event Loop Rules

The Event Loop repeatedly follows these steps:

### Step 1

Execute all synchronous code.

↓

### Step 2

If Call Stack is empty,

execute **all Microtasks**.

↓

### Step 3

Take one task from the Macrotask Queue.

↓

### Step 4

Repeat forever.

---

# fetch() Example

```javascript
console.log("Start");

fetch("/users")
.then(() => console.log("Fetched"));

console.log("End");
```

Output

```text
Start
End
Fetched
```

`fetch()` starts in the browser (Web API). When the response is ready, the `.then()` callback is placed into the **Microtask Queue**, so it runs after the current synchronous code finishes.

# queueMicrotask()

Explicitly schedules a microtask.

```javascript
console.log("A");

queueMicrotask(() => {
    console.log("B");
});

console.log("C");
```

Output

```text
A
C
B
```

# Does setTimeout(..., 0) Execute Immediately?

No.

```javascript
setTimeout(fn, 0);
```

means

> Execute **after the current Call Stack is empty** and after all pending microtasks have completed.

It does **not** mean "execute instantly."

# Best Practices

* Understand that JavaScript executes synchronous code first.
* Remember that Promise callbacks (`.then()`, `.catch()`, `.finally()`) are microtasks.
* Use `Promise`/`async-await` instead of relying on `setTimeout()` for asynchronous flow.
* Don't assume `setTimeout(..., 0)` runs immediately.
* Keep synchronous code lightweight to avoid blocking the Call Stack.

**Web API vs Mircotask queue**

This is one of the most commonly confused interview topics.

The key point is:

> **Web APIs are not a queue.** They are browser-provided services that perform asynchronous work. **Microtask Queue** is a queue inside the JavaScript runtime that stores callbacks ready to execute.

### Flow

```text
JavaScript
     |
Call Stack
     |
Calls Web API
     |
Web API does async work
     |
Callback is placed into:
    - Microtask Queue (Promises)
    - Macrotask Queue (setTimeout, events)
     |
Event Loop
     |
Call Stack
```

---

## Web APIs

**What are they?**

They are browser features that perform asynchronous work outside the JavaScript engine.

Examples:

* `fetch()`
* `setTimeout()`
* `setInterval()`
* DOM Events
* Geolocation
* WebSocket

Example:

```javascript
fetch("/users");
```

The browser handles the network request. JavaScript continues executing other code.

---

## Microtask Queue

The Microtask Queue stores callbacks that are **ready to execute**.

Examples:

* `Promise.then()`
* `Promise.catch()`
* `Promise.finally()`
* `queueMicrotask()`

Example:

```javascript
Promise.resolve().then(() => {
    console.log("Done");
});
```

The callback is placed in the **Microtask Queue** and runs as soon as the Call Stack is empty.

---

## How They Work Together

Example:

```javascript
fetch("/users")
    .then(() => console.log("Success"));

console.log("End");
```

### Step-by-step

1. `fetch()` is sent to the **Web API** (browser).
2. JavaScript immediately executes `console.log("End")`.
3. When the HTTP request finishes, the Promise is resolved.
4. The `.then()` callback is placed into the **Microtask Queue**.
5. The Event Loop moves the callback to the Call Stack.
6. `"Success"` is printed.

Output:

```text
End
Success
```

---

## Comparison

| Web APIs                                    | Microtask Queue                              |
| ------------------------------------------- | -------------------------------------------- |
| Browser feature                             | JavaScript queue                             |
| Performs async work                         | Stores completed Promise callbacks           |
| Handles timers, network, events             | Holds Promise callbacks ready to run         |
| Doesn't execute JS callbacks directly       | Event Loop executes these callbacks          |
| Examples: `fetch`, `setTimeout`, DOM events | `then`, `catch`, `finally`, `queueMicrotask` |

---

## Easy Way to Remember

Think of a restaurant:

* **Web API** = **Kitchen** 🍳 (prepares the food)
* **Microtask Queue** = **Serving counter** 🍽️ (food is ready to be picked up)
* **Event Loop** = **Waiter** 🚶 (takes ready food to the customer)
* **Call Stack** = **Customer eating** 🍴 (currently executing code)

The kitchen (**Web API**) prepares the work. Once it's ready, the result is placed on the serving counter (**Microtask Queue** or **Macrotask Queue**). The waiter (**Event Loop**) delivers it to the customer (**Call Stack**) when they're free.

---

## Interview Answer (Short)

> **Web APIs perform asynchronous operations like timers, network requests, and DOM events outside the JavaScript engine. Once those operations complete, their callbacks are placed into either the Microtask Queue (for Promise callbacks) or the Macrotask Queue (for timers and events). The Event Loop then executes queued callbacks when the Call Stack becomes empty.**

# Common Interview Questions (6+ Years)

### 1. What is the Event Loop?

**Answer:** The Event Loop is a mechanism that continuously checks whether the Call Stack is empty. If it is, it first executes all pending microtasks, then processes one macrotask, enabling JavaScript to handle asynchronous operations without blocking the main thread.

---

### 2. What is the difference between the Call Stack and the Event Loop?

**Answer:** The Call Stack is where JavaScript executes synchronous functions. The Event Loop monitors the Call Stack and moves completed asynchronous callbacks from the queues into the Call Stack when it becomes empty.

---

### 3. What are Web APIs?

**Answer:** Web APIs are browser-provided features such as `setTimeout`, `fetch`, DOM events, and `localStorage`. JavaScript delegates asynchronous work to these APIs, allowing the Call Stack to remain free.

---

### 4. What is the difference between the Microtask Queue and the Macrotask Queue?

**Answer:** The Microtask Queue contains Promise callbacks (`then`, `catch`, `finally`) and `queueMicrotask()`. The Macrotask Queue contains `setTimeout`, `setInterval`, and DOM events. The Event Loop always processes **all microtasks before the next macrotask**.

---

### 5. What is the output?

```javascript
console.log("1");

setTimeout(() => console.log("2"), 0);

Promise.resolve().then(() => console.log("3"));

console.log("4");
```

**Answer:**

```text
1
4
3
2
```

Because synchronous code runs first, Promise callbacks (microtasks) run next, and timer callbacks (macrotasks) run afterward.

---

### 6. Does `setTimeout(fn, 0)` execute immediately?

**Answer:** No. It schedules the callback as a macrotask. The callback executes only after the current Call Stack is empty and all pending microtasks have been processed.

---

### 7. Why do Promise callbacks execute before `setTimeout` callbacks?

**Answer:** Promise callbacks are placed in the **Microtask Queue**, which has higher priority than the **Macrotask Queue**. The Event Loop always empties the Microtask Queue before executing the next macrotask.

---

### 8. Why is understanding the Event Loop important for React developers?

**Answer:** React applications rely heavily on asynchronous operations such as API requests, timers, user interactions, and state updates. Understanding the Event Loop helps developers predict execution order, avoid race conditions, debug asynchronous issues, and write more efficient, responsive applications.
