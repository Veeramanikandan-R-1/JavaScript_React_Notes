# JavaScript Event Loop — Mandatory ⭐⭐⭐

The **Event Loop** explains how JavaScript handles **synchronous code + asynchronous operations** despite JavaScript being **single-threaded**.

### Basic flow

```text
                JavaScript Runtime
                       │
                ┌──────▼──────┐
                │  Call Stack │
                └──────┬──────┘
                       │
          ┌────────────┴────────────┐
          │                         │
     Web APIs                 Event Loop
          │                         │
   setTimeout/fetch/etc.             │
          │                         │
          ▼                         ▼
     Task queues ───────────→ Call Stack
```

---

# 1. Call Stack ⭐⭐⭐

The **Call Stack** keeps track of currently executing JavaScript functions.

```js
function one() {
  two();
}

function two() {
  console.log("Hello");
}

one();
```

Execution:

```text
Call Stack

one()
  ↓
two()
  ↓
console.log()
  ↓
two() removed
  ↓
one() removed
```

JavaScript executes synchronous code **one operation at a time**.

---

# 2. Web APIs ⭐⭐⭐

Web APIs are provided by the **browser**, not by the JavaScript language itself.

Examples:

```text
setTimeout
fetch
DOM events
setInterval
localStorage
Geolocation
```

Example:

```js
console.log("A");

setTimeout(() => {
  console.log("B");
}, 1000);

console.log("C");
```

`setTimeout()` is handled by the browser's timer API while JavaScript continues executing.

```text
A
C
B
```

> In Node.js, similar functionality is provided by the Node.js runtime rather than browser Web APIs.

---

# 3. Callback Queue / Task Queue ⭐⭐⭐

When an asynchronous callback is ready, it waits in a **task queue** until the Call Stack is empty and the Event Loop allows it to run.

Example:

```js
setTimeout(() => {
  console.log("Timer");
}, 0);

console.log("Hello");
```

Output:

```text
Hello
Timer
```

Even `setTimeout(..., 0)` doesn't execute immediately.

---

# 4. Microtask Queue ⭐⭐⭐

The **Microtask Queue** contains higher-priority asynchronous callbacks.

Common sources:

```text
Promise.then()
Promise.catch()
Promise.finally()
queueMicrotask()
```

Example:

```js
console.log("A");

Promise.resolve().then(() => {
  console.log("B");
});

console.log("C");
```

Output:

```text
A
C
B
```

After the synchronous code finishes, the microtask executes.

---

# 5. Macrotask Queue ⭐⭐⭐

The **Macrotask Queue** (often called the **task queue**) contains tasks such as:

```text
setTimeout
setInterval
DOM events
```

Example:

```js
setTimeout(() => {
  console.log("Timeout");
}, 0);
```

The callback waits in the task/macrotask queue.

---

# ⭐ Microtask vs Macrotask

This is **very important for interviews**.

```js
console.log("1");

setTimeout(() => {
  console.log("2");
}, 0);

Promise.resolve().then(() => {
  console.log("3");
});

console.log("4");
```

Output:

```text
1
4
3
2
```

### Why?

```text
1. Synchronous code
       ↓
   Call Stack
       ↓
   1, 4

2. Microtask Queue
       ↓
   Promise.then()
       ↓
   3

3. Macrotask / Task Queue
       ↓
   setTimeout()
       ↓
   2
```

### Priority

```text
Synchronous code
       ↓
Microtasks
       ↓
Next task/macrotask
       ↓
Microtasks again
       ↓
Next task...
```

**Important:** After a task finishes, the runtime drains the microtask queue before moving to the next task. If microtasks continuously schedule more microtasks, they can delay tasks such as timers.

---

# ⭐ Classic Interview Question

What is the output?

```js
console.log("Start");

setTimeout(() => {
  console.log("Timeout");
}, 0);

Promise.resolve().then(() => {
  console.log("Promise");
});

console.log("End");
```

### Answer

```text
Start
End
Promise
Timeout
```

### Reason

```text
Start / End
     ↓
Synchronous → first

Promise.then()
     ↓
Microtask → second

setTimeout()
     ↓
Task/Macrotask → third
```

# ⭐ `async/await` and Event Loop

`await` also works with Promises.

```js
console.log("A");

async function test() {
  console.log("B");

  await Promise.resolve();

  console.log("C");
}

test();

console.log("D");
```

Output:

```text
A
B
D
C
```

Why?

```text
A → synchronous
B → synchronous
await → continuation scheduled as microtask
D → synchronous
C → microtask
```

# ⭐ React Interview Connection

This is important when debugging:

* API callbacks
* Promise chains
* `async/await`
* timers
* event handlers
* state updates
* UI responsiveness

Example:

```js
useEffect(() => {
  fetch("/api/users")
    .then(res => res.json())
    .then(data => {
      // Promise microtask continuation
    });
}, []);
```

The API request is handled outside the JS call stack, and its continuation runs asynchronously once the response is available.

# 🎯 Complete Mental Model

```text
              JavaScript Runtime
                     │
                     ▼
              ┌─────────────┐
              │ Call Stack  │
              └──────┬──────┘
                     │
              synchronous code
                     │
                     ▼
          ┌─────────────────────┐
          │ Browser / Runtime   │
          │ APIs                │
          │ fetch, timer, DOM   │
          └──────────┬──────────┘
                     │
             callback ready
                     │
          ┌──────────┴──────────┐
          ▼                     ▼
   Microtask Queue        Task Queue
   Promise.then()         setTimeout
   await continuation     DOM events
          │                     │
          └──────────┬──────────┘
                     ▼
                 Event Loop
                     │
          Microtasks are drained
          before next task runs
                     │
                     ▼
                Call Stack
```

### ⭐ One-line interview answer

> **The Event Loop monitors the Call Stack and task queues, allowing asynchronous callbacks to execute when the stack is available; after each task, pending microtasks are drained before the next task is processed.**

### Remember

```text
Call Stack       → executes JS
Web APIs         → handle async browser operations
Microtask Queue  → Promises / await → higher priority
Task Queue       → timers / events
Event Loop       → coordinates when callbacks run
```
