# JavaScript Promises — Interview Notes

Promises are **very important for React/API handling**.

A **Promise** represents the eventual result of an asynchronous operation.

It has 3 states:

```text
Pending → operation in progress
Fulfilled → operation succeeded
Rejected → operation failed
```

---

# 1. Promise ⭐⭐⭐

### Creating a Promise

```js
const promise = new Promise((resolve, reject) => {
  const success = true;

  if (success) {
    resolve("Success");
  } else {
    reject("Failed");
  }
});
```

Consume it using:

```js
promise
  .then(result => console.log(result))
  .catch(error => console.error(error))
  .finally(() => console.log("Done"));
```

### Important methods

```text
.then()     → handles success
.catch()    → handles rejection/error
.finally()  → runs regardless of success/failure
```

### Promise chaining ⭐

```js
fetch("/api/user")
  .then(response => response.json())
  .then(user => {
    console.log(user);
  })
  .catch(error => {
    console.error(error);
  });
```

Each `.then()` can return a value or another Promise.

---

# 2. `async/await` ⭐⭐⭐

`async/await` is syntactic sugar over Promises and makes asynchronous code look synchronous.

### `async`

An `async` function **always returns a Promise**.

```js
async function greet() {
  return "Hello";
}

greet().then(console.log);
// Hello
```

### `await`

`await` waits for a Promise to settle inside an `async` function.

```js
async function getUser() {
  const response = await fetch("/api/user");
  const user = await response.json();

  return user;
}
```

### Error handling ⭐

Use `try/catch`:

```js
async function getUser() {
  try {
    const response = await fetch("/api/user");

    if (!response.ok) {
      throw new Error("Request failed");
    }

    return await response.json();
  } catch (error) {
    console.error(error);
  }
}
```

### Important ⭐

`await` **doesn't block the JavaScript thread**. It pauses the execution of that async function until the Promise settles, allowing other JavaScript work to continue.

---

# 3. `Promise.all()` ⭐⭐⭐

Runs multiple Promises concurrently and waits for **all to fulfill**.

```js
const p1 = fetch("/api/users");
const p2 = fetch("/api/products");

const results = await Promise.all([p1, p2]);
```

Results maintain the **same order as the input**, not completion order.

```js
const result = await Promise.all([
  Promise.resolve("A"),
  Promise.resolve("B"),
  Promise.resolve("C")
]);

console.log(result);
// ["A", "B", "C"]
```

### ⚠️ Fail-fast

If **any Promise rejects**, `Promise.all()` rejects.

```js
await Promise.all([
  Promise.resolve("A"),
  Promise.reject("Error"),
  Promise.resolve("C")
]);

// ❌ rejects with "Error"
```

### Use when:

> All operations are required for the result.

---

# 4. `Promise.allSettled()` ⭐⭐⭐

Waits for **all Promises to finish**, regardless of success or failure.

```js
const results = await Promise.allSettled([
  Promise.resolve("Success"),
  Promise.reject("Failed")
]);

console.log(results);
```

Result:

```js
[
  { status: "fulfilled", value: "Success" },
  { status: "rejected", reason: "Failed" }
]
```

### Use when:

> You want the result of **every operation**, even if some fail.

Example:

```js
const results = await Promise.allSettled([
  fetch("/api/users"),
  fetch("/api/products"),
  fetch("/api/orders")
]);
```

You can process successful and failed requests separately.

---

# 5. `Promise.race()` ⭐⭐⭐

Returns the result of the **first Promise to settle**.

"Settle" means:

```text
fulfilled OR rejected
```

```js
const result = await Promise.race([
  Promise.resolve("First"),
  Promise.resolve("Second")
]);

console.log(result);
// "First"
```

If the fastest Promise rejects:

```js
Promise.race([
  Promise.reject("Failed"),
  Promise.resolve("Success")
])
// → rejects with "Failed"
```

### Common use: timeout pattern

```js
const timeout = new Promise((_, reject) => {
  setTimeout(() => reject(new Error("Timeout")), 5000);
});

await Promise.race([
  fetch("/api/data"),
  timeout
]);
```

⚠️ `Promise.race()` **does not cancel the other Promises**. They may continue running.

---

# 6. `Promise.any()` ⭐⭐⭐

Returns the result of the **first Promise to fulfill**.

Unlike `race()`, rejected Promises are ignored until all Promises reject.

```js
const result = await Promise.any([
  Promise.reject("Error 1"),
  Promise.resolve("Success"),
  Promise.resolve("Success 2")
]);

console.log(result);
// "Success"
```

### If all reject

`Promise.any()` rejects with an **`AggregateError`**.

```js
try {
  await Promise.any([
    Promise.reject("A"),
    Promise.reject("B")
  ]);
} catch (error) {
  console.log(error instanceof AggregateError); // true
}
```

---

# ⭐ `all` vs `allSettled` vs `race` vs `any`

| Method                 | Completes when     | Rejects when                                    |
| ---------------------- | ------------------ | ----------------------------------------------- |
| `Promise.all()`        | All fulfill        | **Any rejects**                                 |
| `Promise.allSettled()` | **All settle**     | Never rejects because of input Promise outcomes |
| `Promise.race()`       | **First settles**  | First settled Promise rejects                   |
| `Promise.any()`        | **First fulfills** | **All reject**                                  |

### Easy way to remember ⭐

```text
all
→ ALL must succeed

allSettled
→ ALL must finish

race
→ FIRST to finish wins

any
→ FIRST successful one wins
```

# ⭐ Important Interview Example

```js
const p1 = new Promise(resolve =>
  setTimeout(() => resolve("A"), 1000)
);

const p2 = new Promise(resolve =>
  setTimeout(() => resolve("B"), 500)
);

const p3 = new Promise(resolve =>
  setTimeout(() => resolve("C"), 1500)
);
```

### `Promise.all`

```js
await Promise.all([p1, p2, p3]);

// ["A", "B", "C"]
```

Even though `B` finishes first, **result order follows input order**.

### `Promise.race`

```js
await Promise.race([p1, p2, p3]);

// "B"
```

Because `p2` settles first.

### `Promise.any`

If `p2` fulfills first:

```js
await Promise.any([p1, p2, p3]);

// "B"
```

If `p2` rejected but `p1` later fulfilled, `any()` would return `"A"`.

# ⭐ React/API Practical Example

Suppose a dashboard needs users, products, and orders:

### All required

```js
const [users, products, orders] =
  await Promise.all([
    getUsers(),
    getProducts(),
    getOrders()
  ]);
```

If one fails → whole `Promise.all()` rejects.

### Independent requests

```js
const results = await Promise.allSettled([
  getUsers(),
  getProducts(),
  getOrders()
]);

results.forEach(result => {
  if (result.status === "fulfilled") {
    console.log(result.value);
  } else {
    console.error(result.reason);
  }
});
```

Useful when **one failed API shouldn't prevent displaying other data**.

---

# ⚠️ Important: Concurrent vs Sequential

Don't unnecessarily do:

```js
const users = await getUsers();
const products = await getProducts();
```

If they're independent, prefer:

```js
const [users, products] = await Promise.all([
  getUsers(),
  getProducts()
]);
```

The second approach allows the operations to be **in flight concurrently**, reducing total waiting time.

# 🎯 Quick Revision

```text
Promise
→ Represents future async result
→ pending / fulfilled / rejected

async
→ Function always returns Promise

await
→ Waits for Promise inside async function

Promise.all()
→ All succeed or fail-fast

Promise.allSettled()
→ Wait for everything, success + failure

Promise.race()
→ First settled wins

Promise.any()
→ First fulfilled wins
→ All rejected → AggregateError
```

### ⭐ Interview one-liner

> **Use `Promise.all()` when all results are required, `allSettled()` when every result matters even if some fail, `race()` when the first settled result should win, and `any()` when the first successful result should win.**
