# JavaScript - Promises

Promises are one of the **most important JavaScript concepts** for React developers.

Almost every React application performs asynchronous operations:

* API calls
* Authentication
* File uploads
* Lazy loading
* Database requests
* Timers

A senior React developer is expected to know **how Promises work internally**, when to use `async/await`, and the differences between `Promise.all()`, `allSettled()`, `race()`, and `any()`.

---

# 1. Promise

## What is a Promise?

A **Promise** is an object that represents the **eventual completion (or failure)** of an asynchronous operation.

Instead of getting the result immediately, a Promise acts as a placeholder for a future value.

Think of it like ordering food online:

* Order placed → Pending
* Food delivered → Fulfilled
* Order cancelled → Rejected

---

## Why do we need Promises?

Before Promises, asynchronous code relied heavily on nested callbacks.

```javascript
login(user, function () {
    getProfile(function () {
        getOrders(function () {
            getNotifications(function () {

            });
        });
    });
});
```

This leads to **Callback Hell**.

Promises solve this by making async code cleaner and chainable.

---

# Promise States

Every Promise has exactly one of these states.

```text
Pending
   |
   |----> Fulfilled
   |
   |----> Rejected
```

Once fulfilled or rejected, a Promise **cannot change again**.

---

# Creating a Promise

```javascript
const promise = new Promise((resolve, reject) => {

    const success = true;

    if (success) {
        resolve("Success");
    } else {
        reject("Failed");
    }

});
```

---

# Consuming a Promise

```javascript
promise
    .then(result => console.log(result))
    .catch(error => console.log(error))
    .finally(() => console.log("Completed"));
```

---

# resolve()

Marks the Promise as successful.

```javascript
resolve(data);
```

---

# reject()

Marks the Promise as failed.

```javascript
reject(error);
```

---

# finally()

Runs regardless of success or failure.

Good for

* Hide loader
* Cleanup
* Close connections

```javascript
fetchData()
    .finally(() => {
        hideSpinner();
    });
```

---

# Promise Chaining

```javascript
login()

.then(getProfile)

.then(getOrders)

.then(showDashboard)

.catch(handleError);
```

Instead of deeply nested callbacks.

---

# Internal Working

When `resolve()` or `reject()` is called,

JavaScript places the callback in the **Microtask Queue**.

The Event Loop executes microtasks **before** macrotasks (`setTimeout`, `setInterval`).

---

# Promise Best Practices

✔ Always handle errors.

✔ Return Promises in `.then()`.

✔ Prefer `async/await` for readability.

✔ Use `.finally()` for cleanup.

---

# 2. async / await

Introduced in ES2017.

Makes asynchronous code look synchronous.

---

# async

Adding `async` to a function means it **always returns a Promise**.

```javascript
async function hello() {
    return "Hello";
}
```

Equivalent to

```javascript
Promise.resolve("Hello");
```

---

# await

Pauses execution until the Promise settles.

```javascript
const result = await fetchData();
```

Only works inside an async function.

---

# Example

Without async/await

```javascript
fetchData()
    .then(data => console.log(data))
    .catch(console.error);
```

With async/await

```javascript
async function load() {

    try {

        const data = await fetchData();

        console.log(data);

    } catch (err) {

        console.log(err);

    }

}
```

Much easier to read.

---

# Error Handling

Always use

```javascript
try {

}
catch {

}
```

Example

```javascript
try {

    const data = await fetchData();

}
catch(error){

}
```

---

# Multiple Awaits

Sequential

```javascript
const user = await getUser();

const posts = await getPosts();
```

Runs one after another.

---

Parallel

```javascript
const [user, posts] = await Promise.all([
    getUser(),
    getPosts()
]);
```

Runs simultaneously.

Much faster.

---

# React Example

```javascript
useEffect(() => {

    async function load() {

        const users = await getUsers();

        setUsers(users);

    }

    load();

}, []);
```

---

# Why Can't useEffect be async?

Wrong

```javascript
useEffect(async () => {

}, []);
```

Because React expects a cleanup function, not a Promise.

Correct

```javascript
useEffect(() => {

    async function load(){}

    load();

}, []);
```

# 3. Promise.all()

Runs multiple Promises **in parallel**.

Returns when **all succeed**.

---

Example

```javascript
const result = await Promise.all([
    getUsers(),
    getOrders(),
    getProducts()
]);
```

Returns

```javascript
[
 users,
 orders,
 products
]
```

---

If one fails

```javascript
Promise.all([
    success(),
    fail(),
    success()
]);
```

Entire Promise rejects immediately.

---

When to use

When every request is required.

Example

Dashboard

* User
* Notifications
* Profile

All must succeed.

---

# 4. Promise.allSettled()

Waits until **every Promise finishes**.

Even if some fail.

---

Example

```javascript
const result = await Promise.allSettled([
    success(),
    fail(),
    success()
]);
```

Returns

```javascript
[
 {status:"fulfilled", value:...},
 {status:"rejected", reason:...},
 {status:"fulfilled", value:...}
]
```

---

When to use

Independent API calls.

Example

Dashboard Widgets

Widget A fails.

Widget B succeeds.

Widget C succeeds.

Still show available widgets.

---

# 5. Promise.race()

Returns whichever Promise settles first.

Success OR Failure.

---

Example

```javascript
Promise.race([
    apiCall(),
    timeout()
]);
```

If timeout finishes first

↓

Promise rejects.

If API finishes first

↓

Promise resolves.

---

Common Usage

Request timeout.

```javascript
await Promise.race([
    fetch(url),
    timeoutPromise
]);
```

---

# 6. Promise.any()

Returns the **first fulfilled Promise**.

Ignores rejected Promises.

---

Example

```javascript
Promise.any([
    rejectFast(),
    server2(),
    server3()
]);
```

Returns first successful server.

---

If all reject

↓

Throws

```text
AggregateError
```

---

Common Usage

Multiple servers.

CDN fallback.

Mirror APIs.

---

# Promise.all vs allSettled vs race vs any

| Method             | Waits For       | Rejects When                          | Returns                    |
| ------------------ | --------------- | ------------------------------------- | -------------------------- |
| Promise.all        | All fulfill     | First rejection                       | Array of values            |
| Promise.allSettled | All settle      | Never                                 | Status of each Promise     |
| Promise.race       | First settled   | First rejection (if it settles first) | First settled value/reason |
| Promise.any        | First fulfilled | All reject                            | First successful value     |

---

example:

*race:*

```js
function getUser() {
  return new Promise((resolve,reject) => {
    setTimeout(() => reject("User Data"), 1000);
  });
}

function getStudent() {
  return new Promise(resolve => {
    setTimeout(() => resolve("Student Data"), 2000);
  });
}

const fetchData = async () => {
    try{
        const resolvedData = await Promise.race([getUser(),getStudent()]);
        console.log(resolvedData);
    }catch(err){
        console.log("err ",err)
    };
}

fetchData(); // err  User Data

*any*

const fetchData = async () => {
    try{
        const resolvedData = await Promise.any([getUser(),getStudent()]);
        console.log(resolvedData);
    }catch(err){
        console.log("err ",err)
    };
}

fetchData(); // Student Data

*all*

const fetchData = async () => {
    try{
        const resolvedData = await Promise.all([getUser(),getStudent()]);
        console.log(resolvedData);
    }catch(err){
        console.log("err ",err)
    };
}

fetchData(); //err  User Data

*all settled*


const fetchData = async () => {
    try{
        const resolvedData = await Promise.allSettled([getUser(),getStudent()]);
        console.log(resolvedData);
    }catch(err){
        console.log("err ",err)
    };
}

fetchData();

//
[
  { status: 'rejected', reason: 'User Data' },
  { status: 'fulfilled', value: 'Student Data' }
]
```

# Promise Execution Order

```javascript
console.log("1");

Promise.resolve().then(() => console.log("2"));

console.log("3");
```

Output

```text
1
3
2
```

Because Promise callbacks execute in the **Microtask Queue** after the current synchronous code completes.

# Common Mistakes

## Forgetting await

Wrong

```javascript
const users = getUsers();
```

Result

```text
Promise { ... }
```

Correct

```javascript
const users = await getUsers();
```

---

## Using await outside async

Wrong

```javascript
const data = await fetchData();
```

Throws

```text
SyntaxError
```

---

## Sequential Instead of Parallel

Wrong

```javascript
const users = await getUsers();

const posts = await getPosts();
```

Better

```javascript
const [users, posts] = await Promise.all([
    getUsers(),
    getPosts()
]);
```

---

## Missing Error Handling

Wrong

```javascript
const data = await fetchData();
```

Correct

```javascript
try {

    const data = await fetchData();

}
catch(err){

}
```

---

## Using Promise.all() for Independent APIs

If one API fails,

Everything fails.

Use

```javascript
Promise.allSettled()
```

instead.

# Best Practices

* Prefer `async/await` over long `.then()` chains for readability.
* Use `Promise.all()` for parallel tasks that all must succeed.
* Use `Promise.allSettled()` when tasks are independent.
* Use `Promise.race()` to implement request timeouts.
* Use `Promise.any()` for fallback strategies.
* Always wrap `await` in `try...catch`.
* Avoid unnecessary sequential `await`s when tasks are independent.

# Common Interview Questions (6+ Years)

### 1. What are the three states of a Promise?

**Answer:** `Pending`, `Fulfilled`, and `Rejected`. A Promise starts as pending and can transition to either fulfilled or rejected only once.

---

### 2. What is the difference between `.then()` and `await`?

**Answer:** Both consume Promises. `.then()` uses callback chaining, while `await` pauses execution inside an `async` function, making asynchronous code easier to read.

---

### 3. Why does an `async` function always return a Promise?

**Answer:** JavaScript automatically wraps the returned value in `Promise.resolve()`. Even if you return a plain value, the function's return type is still a Promise.

---

### 4. What is the difference between `Promise.all()` and `Promise.allSettled()`?

**Answer:** `Promise.all()` resolves only if **all Promises succeed** and rejects immediately if any Promise fails. `Promise.allSettled()` waits for every Promise to complete and returns the outcome (`fulfilled` or `rejected`) of each one.

---

### 5. When would you use `Promise.race()`?

**Answer:** When you need the result of the **first Promise that settles**, regardless of whether it fulfills or rejects. A common use case is implementing API request timeouts.

---

### 6. How is `Promise.any()` different from `Promise.race()`?

**Answer:** `Promise.race()` returns the first Promise to settle (success or failure). `Promise.any()` ignores rejected Promises and returns the first fulfilled one. If every Promise rejects, it throws an `AggregateError`.

---

### 7. Why can't `useEffect` be declared as `async`?

**Answer:** React expects the callback passed to `useEffect` to return either `undefined` or a cleanup function. An `async` function always returns a Promise, which React cannot use as a cleanup function.

---

### 8. Why is `Promise.all()` often faster than awaiting Promises one by one?

**Answer:** `Promise.all()` starts all independent asynchronous operations simultaneously, allowing them to execute in parallel. Sequential `await`s wait for one operation to finish before starting the next, increasing total execution time.
