# 1. What are Data Types?

A **data type** defines the kind of value a variable can store and determines how JavaScript treats that value.

Example:

```javascript
let age = 25;          // Number
let name = "John";     // String
let isAdmin = true;    // Boolean
```

---

# JavaScript has 2 categories of Data Types

```
Data Types
│
├── Primitive
│
└── Reference (Non-Primitive)
```

Understanding this distinction is extremely important because it explains:

* Assignment
* Copying
* Function arguments
* State updates in React
* Equality comparisons

---

# 2. Primitive Data Types

Primitive values are **immutable** and stored **by value**.

JavaScript has **7 primitive data types**.

| Type      | Example                 |
| --------- | ----------------------- |
| String    | `"Hello"`               |
| Number    | `100`, `3.14`           |
| Boolean   | `true`, `false`         |
| Undefined | `undefined`             |
| Null      | `null`                  |
| Symbol    | `Symbol("id")`          |
| BigInt    | `12345678901234567890n` |

Example:

```javascript
let a = 10;
let b = a;

b = 20;

console.log(a); // 10
console.log(b); // 20
```

Because primitives are copied **by value**, changing `b` does not affect `a`.

---

## Primitive Memory

```
Stack

a → 10
b → 20
```

Each variable has its own independent value.

---

## Primitive values are Immutable

Immutable means **the value itself cannot be changed**.

Example:

```javascript
let str = "Hello";

str[0] = "Y";

console.log(str);
```

Output

```
Hello
```

Nothing changes.

Instead,

```javascript
str = "Yellow";
```

A completely new string is created.

# 3. Reference (Non-Primitive) Data Types

Reference values are stored **by reference** (memory address).

Main reference types:

* Object
* Array
* Function
* Date
* Map
* Set
* RegExp
* WeakMap
* WeakSet

Everything that is **not primitive** is a reference type.

Example:

```javascript
const user = {
    name: "Veera"
};
```

---

## Reference Memory

```
Stack

user
 |
 |-------> Heap
            {
               name:"Veera"
            }
```

The actual object lives in the heap.

The variable stores only the address.

---

# Reference Copy Example

```javascript
const obj1 = {
    name: "John"
};

const obj2 = obj1;

obj2.name = "David";

console.log(obj1.name);
```

Output

```
David
```

Why?

Both variables point to the same object.

```
obj1 ----\
          \
           ---> Object
          /
obj2 ----/
```

---

# Array Example

```javascript
const arr1 = [1,2,3];

const arr2 = arr1;

arr2.push(4);

console.log(arr1);
```

Output

```
[1,2,3,4]
```

Again,

Both variables reference the same array.

---

# Function is also an Object

```javascript
function greet() {}

console.log(typeof greet);
```

Output

```
function
```

Internally functions are objects with callable behavior.

# 4. Primitive vs Reference

| Primitive                               | Reference                                         |
| --------------------------------------- | ------------------------------------------------- |
| Stored by value                         | Stored by reference                               |
| Immutable                               | Mutable                                           |
| Copied by value                         | Copied by reference                               |
| Independent copies                      | Shared object                                     |
| Stored directly (conceptually in stack) | Object stored in heap, reference held by variable |

Example

Primitive

```javascript
let a = 10;
let b = a;

b = 20;
```

```
a = 10
b = 20
```

Reference

```javascript
let obj1 = {x:1};
let obj2 = obj1;

obj2.x = 100;
```

```
obj1.x = 100
obj2.x = 100
```

# 5. Mutable vs Immutable

## Immutable

Cannot change the existing value.

Examples:

* String
* Number
* Boolean
* Null
* Undefined
* Symbol
* BigInt

```javascript
let a = "hello";

a = "world";
```

A new string is created.

---

## Mutable

Objects can change after creation.

```javascript
const person = {
    name: "John"
};

person.name = "David";
```

Allowed.

Even though `const` prevents reassignment, it does **not** make the object immutable.

# 7. instanceof Operator

`instanceof` checks whether an object was created from a particular constructor (i.e., whether its prototype chain includes that constructor's `prototype`).

Syntax

```javascript
object instanceof Constructor
```

Example

```javascript
const arr = [];

console.log(arr instanceof Array);
```

Output

```
true
```

---

Example

```javascript
const obj = {};

console.log(obj instanceof Object);
```

Output

```
true
```

---

Example

```javascript
function Person(){}

const p = new Person();

console.log(p instanceof Person);
```

Output

```
true
```

---

Example

```javascript
console.log([] instanceof Object);
```

Output

```
true
```

Because **Array inherits from Object**.

---

## instanceof vs typeof

```javascript
typeof []
```

```
object
```

```javascript
[] instanceof Array
```

```
true
```

This is why `instanceof` is useful for distinguishing arrays from generic objects.

---

## instanceof Limitations

### Primitive values

```javascript
10 instanceof Number
```

```
false
```

Because `10` is a primitive, not a `Number` object.

```javascript
new Number(10) instanceof Number
```

```
true
```

---

### Cross-frame limitation

Objects created in different browser windows/iframes have different global constructors, so:

```javascript
arr instanceof Array
```

may return `false` across frames.

To reliably detect arrays, prefer:

```javascript
Array.isArray(arr);
```

# React Interview Connection

Understanding data types is critical in React because state updates rely on **reference changes**.

❌ Mutating state:

```javascript
const user = state.user;
user.name = "John";

setState(user);
```

React may not detect a meaningful change because the object reference is the same.

✅ Create a new object:

```javascript
setState({
    ...user,
    name: "John"
});
```

The reference changes, allowing React to re-render correctly.

# Common Mistakes

### ❌ Expecting objects to copy independently

```javascript
const a = {x:1};
const b = a;
```

Both point to the same object.

---

### ❌ Using `typeof` for arrays

```javascript
typeof []
```

Returns

```
object
```

Use:

```javascript
Array.isArray([])
```

---

### ❌ Comparing objects with `===`

```javascript
{} === {}
```

```
false
```

Different object references.

---

### ❌ Assuming `const` makes objects immutable

```javascript
const user = {};

user.name = "John";
```

This is valid because only the binding is constant, not the object's contents.

---

# Best Practices

* Use primitives whenever possible for simple values.
* Avoid mutating objects directly; create new objects using the spread operator or other immutable update patterns.
* Use `Array.isArray()` instead of `typeof` or `instanceof` to detect arrays.
* Use `typeof` for primitives and functions.
* Use `instanceof` when checking whether an object is an instance of a specific class or constructor.
* Understand that objects are compared by **reference**, not by value.

# Common React (6 Years Experience) Interview Questions

### 1. How many primitive data types are there in JavaScript?

**Answer:** Seven — `String`, `Number`, `Boolean`, `Undefined`, `Null`, `Symbol`, and `BigInt`.

---

### 2. What is the difference between primitive and reference data types?

**Answer:** Primitives are immutable and copied by value. Reference types are mutable and copied by reference, so multiple variables can point to the same object.

---

### 3. Why does `typeof null` return `"object"`?

**Answer:** It's a historical implementation bug kept for backward compatibility.

---

### 4. Why does `typeof []` return `"object"`?

**Answer:** Arrays are specialized objects in JavaScript. Use `Array.isArray()` to identify arrays.

---

### 5. What is the difference between `typeof` and `instanceof`?

**Answer:** `typeof` returns a type string (best for primitives/functions), while `instanceof` checks whether an object inherits from a specific constructor.

---

### 6. Why are React state updates expected to be immutable?

**Answer:** React relies on reference changes to detect updates efficiently. Mutating the existing object can prevent re-renders or lead to bugs.

---

### 7. Does `const` make an object immutable?

**Answer:** No. It prevents reassignment of the variable, but the object's properties can still be modified.

---

### 8. Why is `Array.isArray()` preferred over `instanceof Array`?

**Answer:** It works reliably across different execution contexts (such as iframes), whereas `instanceof` can fail in those cases.
