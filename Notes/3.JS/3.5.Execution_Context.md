# JavaScript Execution Context — Interview Notes

These concepts explain **how JavaScript executes your code and resolves variables**.

---

# 1. Execution Context ⭐⭐⭐

An **Execution Context** is the environment in which JavaScript code is evaluated and executed.

There are mainly:

```text
1. Global Execution Context (GEC)
2. Function Execution Context (FEC)
3. Eval Execution Context (rarely relevant)
```

### Global Execution Context

Created when JavaScript starts executing a script.

```js
const x = 10;

function greet() {
  console.log("Hello");
}
```

A global execution context is created first.

### Function Execution Context

Every time a function is called, a **new function execution context** is created.

```js
function add(a, b) {
  const result = a + b;
  return result;
}

add(10, 20);
```

Conceptually:

```text
Global Execution Context
        ↓
   add() called
        ↓
Function Execution Context
```

### Two phases ⭐

Execution context is commonly explained in two phases:

**1. Creation phase**

* Creates bindings for variables/functions
* Sets up lexical environment
* Determines `this`
* Function declarations are available
* `let`/`const` bindings exist but are in TDZ until initialized

**2. Execution phase**

* Code executes line by line
* Variables get assigned values
* Functions are called

# 2. Call Stack ⭐⭐⭐

The **Call Stack** is a LIFO (Last In, First Out) stack that tracks currently executing functions.

Example:

```js
function first() {
  second();
}

function second() {
  console.log("Hello");
}

first();
```

Execution:

```text
1. Global Context
       ↓
2. first()
       ↓
3. second()
       ↓
4. console.log()
```

Stack concept:

```text
┌──────────────┐
│   second()   │ ← Top
├──────────────┤
│   first()    │
├──────────────┤
│   Global     │
└──────────────┘
```

After `second()` finishes → removed.

Then `first()` finishes → removed.

### Stack overflow

Infinite recursion can overflow the call stack:

```js
function test() {
  test();
}

test(); // ❌ Maximum call stack size exceeded
```

# 3. Lexical Environment ⭐⭐⭐

A **Lexical Environment** is the structure JavaScript uses to store and resolve **variables/functions based on where the code is written**.

Example:

```js
const name = "John";

function greet() {
  const message = "Hello";

  console.log(name);
  console.log(message);
}
```

The `greet` function's lexical environment contains access to:

```text
greet Lexical Environment
├── message
└── outer environment → Global Lexical Environment
                              └── name
```

### Important: Lexical = where code is written

JavaScript uses **lexical/static scoping**, not where a function happens to be called.

This is the foundation of **closures**.

---

# 4. Scope Chain ⭐⭐⭐

When JavaScript needs to find a variable, it searches:

```text
Current scope
     ↓
Outer scope
     ↓
Outer scope
     ↓
Global scope
```

This is the **scope chain**.

Example:

```js
const a = 10;

function outer() {
  const b = 20;

  function inner() {
    const c = 30;

    console.log(a);
    console.log(b);
    console.log(c);
  }

  inner();
}

outer();
```

When `inner()` looks for variables:

```text
inner scope
   ↓
outer scope
   ↓
global scope
```

So it can access:

```text
c → inner
b → outer
a → global
```

But the reverse is not true:

```js
function outer() {
  function inner() {
    const secret = 123;
  }

  console.log(secret); // ❌
}
```

The outer scope cannot access variables declared inside `inner`.

# ⭐ How They Work Together

Consider:

```js
const x = 10;

function outer() {
  const y = 20;

  function inner() {
    const z = 30;
    console.log(x + y + z);
  }

  inner();
}

outer();
```

### Execution flow

```text
1. Global Execution Context created
          ↓
2. outer() called
          ↓
3. outer Execution Context created
          ↓
4. inner() called
          ↓
5. inner Execution Context created
          ↓
6. inner searches variable
          ↓
   inner → outer → global
          ↓
7. inner() completes
          ↓
8. outer() completes
```

### Call Stack during `inner()`

```text
┌─────────────────┐
│ inner()         │
├─────────────────┤
│ outer()         │
├─────────────────┤
│ Global Context  │
└─────────────────┘
```

# 🎯 Important Interview Distinction

### Execution Context vs Lexical Environment

**Execution Context**

> The complete environment in which JavaScript code executes.

**Lexical Environment**

> The environment responsible for storing/accessing lexical bindings and connecting them to outer environments.

For interview purposes, you can think:

```text
Execution Context
      ↓
contains execution-related state
      +
Lexical Environment
      ↓
variables/functions + outer reference
```

---

diff b/w exec context and lex env

### Execution Context vs Lexical Environment

Think of it simply:

| Execution Context                                                | Lexical Environment                                                        |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **Complete environment for executing code**                      | **Part of the execution context** responsible for variable/function lookup |
| Manages execution-related information                            | Stores lexical bindings (`let`, `const`, functions, etc.)                  |
| Includes `this`, variable environment, lexical environment, etc. | Contains bindings + reference to outer lexical environment                 |
| Created for global/function execution                            | Created based on the lexical structure of the code                         |

### Simple mental model ⭐

```text
Execution Context
├── Lexical Environment
│   ├── variables/functions
│   └── reference to outer environment
├── Variable Environment
└── this binding
```

Example:

```js
const x = 10;

function test() {
  const y = 20;
  console.log(x + y);
}

test();
```

When `test()` runs:

```text
Execution Context for test()
        ↓
Lexical Environment
   y = 20
   ↓
Outer Lexical Environment
   x = 10
```

**Interview one-liner:**

> **Execution Context is the overall environment in which code executes; Lexical Environment is the part that manages lexical variables/functions and their connection to outer scopes.**

# ⭐ Quick Revision

```text
Execution Context
→ Environment in which code executes

Call Stack
→ Tracks active execution contexts
→ LIFO

Lexical Environment
→ Stores lexical bindings and outer reference
→ Based on where code is written

Scope Chain
→ Current scope → outer scope → global
→ Used to resolve variables
```

### ⭐ One-line interview answer

> **When JavaScript executes a function, it creates an execution context and pushes it onto the call stack. The function's lexical environment stores its bindings and references its outer lexical environment, forming the scope chain used for variable lookup.**
