# JavaScript Execution Context

Execution Context is one of the **most important JavaScript concepts**. It explains:

* How JavaScript executes code
* How variables are stored
* How functions are called
* How the call stack works
* Why closures work
* Why hoisting happens

Almost every advanced JavaScript topic (Closures, `this`, Hoisting, Async JS) depends on understanding Execution Context.

---

# 1. What is an Execution Context?

An **Execution Context** is the environment in which JavaScript code is executed.

It contains everything JavaScript needs to execute code:

* Variables
* Functions
* Scope information
* `this` value

Think of it as **a box containing all information required to execute the current code.**

---

## Example

```javascript
let name = "John";

function greet() {
    console.log(name);
}

greet();
```

Before executing this code, JavaScript creates an execution context to keep track of:

* `name`
* `greet`
* Current line being executed
* Scope information

---

# Types of Execution Context

There are mainly **2 types**:

## 1. Global Execution Context (GEC)

Created once when the JavaScript file starts executing.

Contains:

* Global variables
* Global functions
* Global `this`

Example

```javascript
const a = 10;

function add() {}
```

Both belong to the Global Execution Context.

---

## 2. Function Execution Context (FEC)

Created every time a function is called.

Example

```javascript
function greet() {
    console.log("Hello");
}

greet();
```

When `greet()` runs,

JavaScript creates a new execution context only for that function.

When the function finishes,

that execution context is destroyed.

---

# How Execution Context is Created

Every execution context has **2 phases**.

```
1. Creation Phase
2. Execution Phase
```

---

# Phase 1: Creation Phase

JavaScript scans the code before executing it.

During this phase:

* Memory is allocated for variables.
* Functions are stored in memory.
* `this` is determined.

Example

```javascript
console.log(a);

var a = 10;

function greet() {}
```

During creation:

```
a → undefined

greet → function
```

Nothing has executed yet.

---

# Phase 2: Execution Phase

JavaScript executes code line by line.

```
a = 10

console.log(a)
```

Now variables receive actual values.

---

# Execution Context Flow

```text
Start Program
      │
      ▼
Create Global Execution Context
      │
      ▼
Creation Phase
      │
      ▼
Execution Phase
      │
      ▼
Function Call?
      │
     Yes
      │
      ▼
Create Function Execution Context
      │
      ▼
Execute Function
      │
      ▼
Destroy Function Context
```

# 2. Call Stack

The Call Stack is a stack data structure used to manage execution contexts.

It follows

```
LIFO
(Last In First Out)
```

---

## Example

```javascript
function one() {
    two();
}

function two() {
    three();
}

function three() {
    console.log("Done");
}

one();
```

---

### Step 1

```
Call Stack

Global
```

---

### Step 2

```
one()

Global
```

---

### Step 3

```
two()

one()

Global
```

---

### Step 4

```
three()

two()

one()

Global
```

---

### Step 5

`three()` finishes

```
two()

one()

Global
```

---

### Step 6

`two()` finishes

```
one()

Global
```

---

### Step 7

`one()` finishes

```
Global
```

---

## Stack Overflow

If functions call themselves endlessly,

```javascript
function test() {
    test();
}

test();
```

Output

```
Maximum call stack size exceeded
```

The stack becomes full.

# 3. Lexical Environment

A **Lexical Environment** is the environment where a function is **defined**, not where it is called.

It contains:

* Local variables
* Parameters
* Reference to the outer (parent) environment

---

## Example

```javascript
const a = 10;

function outer() {

    const b = 20;

    function inner() {
        console.log(a);
        console.log(b);
    }

    inner();
}

outer();
```

---

### Lexical Environment

```
Global
│
├── a = 10
│
└── outer
      │
      ├── b = 20
      │
      └── inner
```

`inner()` can access both:

* `b`
* `a`

because of the lexical environment.

---

## Important

Lexical means

```
Based on where code is written.
```

NOT

```
Where code is called.
```

---

# 4. Scope Chain

When JavaScript cannot find a variable in the current scope,

it searches upward through parent scopes.

This searching process is called the **Scope Chain**.

---

## Example

```javascript
const a = 10;

function outer() {

    const b = 20;

    function inner() {

        const c = 30;

        console.log(a);
        console.log(b);
        console.log(c);
    }

    inner();
}

outer();
```

---

### Search Order

For `a`

```
inner

↓

outer

↓

global
```

Found.

---

For `b`

```
inner

↓

outer
```

Found.

---

For `c`

```
inner
```

Found immediately.

---

If JavaScript cannot find it

```
ReferenceError
```

---

# Visual Scope Chain

```
Global
│
├── a
│
└── outer
      │
      ├── b
      │
      └── inner
            │
            └── c
```

Searching happens

```
Current

↓

Parent

↓

Global
```

Never downward.

---

# Lexical Environment vs Scope Chain

Many people confuse these.

## Lexical Environment

Describes **where variables belong**.

```
Global

↓

Outer

↓

Inner
```

---

## Scope Chain

Describes **how JavaScript searches variables**.

```
Current

↓

Parent

↓

Global
```

# Common Mistakes

### ❌ Confusing Execution Context with Call Stack

* **Execution Context** → Information required to execute code.
* **Call Stack** → Stores execution contexts.

---

### ❌ Thinking Lexical Environment Depends on Function Calls

```javascript
function outer() {

    function inner() {}

}
```

It depends on **where `inner` is defined**, not where it is called.

---

### ❌ Thinking Variables Are Searched Downward

JavaScript only searches

```
Current

↓

Parent

↓

Global
```

Never

```
Global

↓

Child
```

---

### ❌ Assuming Every Function Shares Variables

Each function gets its own execution context.

Only parent scopes are accessible.

---

# Best Practices

* Understand the two execution context phases: **Creation** and **Execution**.
* Remember that each function invocation creates a **new Function Execution Context**.
* Visualize the **Call Stack** when debugging nested function calls or recursion.
* Think of the **Lexical Environment** as fixed at the time the function is written.
* Remember that the **Scope Chain** searches only upward through parent scopes.

  * Global Execution Context (created once)
  * Function Execution Context (created per function call)

  * Creation
  * Execution

* Stores execution contexts.
* Uses **LIFO**.
* Function finishes → removed from stack.
* Infinite recursion → **Maximum call stack size exceeded**.

---

* Created based on **where a function is defined**.
* Contains:

  * Variables
  * Parameters
  * Reference to parent scope

---

* Variable lookup mechanism.
* Searches:

  * Current scope
  * Parent scope
  * Global scope
* Never searches child scopes.

# Common React (6 Years Experience) Interview Questions

### 1. What is an Execution Context?

**Answer:**
An Execution Context is the environment in which JavaScript executes code. It contains variables, functions, the `this` value, and scope information required to run the code.

---

### 2. What are the phases of an Execution Context?

**Answer:**

1. **Creation Phase**

   * Memory is allocated for variables.
   * Functions are stored in memory.
   * `this` is initialized.

2. **Execution Phase**

   * Code executes line by line.
   * Variables receive actual values.

---

### 3. What is the difference between Global and Function Execution Context?

| Global Execution Context              | Function Execution Context                                        |
| ------------------------------------- | ----------------------------------------------------------------- |
| Created once                          | Created on every function call                                    |
| Exists for the application's lifetime | Destroyed after the function completes                            |
| Holds global variables/functions      | Holds local variables, parameters, and `this` for that invocation |

---

### 4. What is the Call Stack?

**Answer:**
The Call Stack is a LIFO stack that keeps track of active execution contexts. Each function call is pushed onto the stack, and when it finishes, its context is popped off.

---

### 5. What causes **"Maximum call stack size exceeded"**?

**Answer:**
Infinite or uncontrolled recursion repeatedly creates new function execution contexts until the call stack runs out of space.

---

### 6. What is a Lexical Environment?

**Answer:**
A Lexical Environment is the scope where a function is **defined**, containing its local variables, parameters, and a reference to its parent scope.

---

### 7. What is the Scope Chain?

**Answer:**
The Scope Chain is the mechanism JavaScript uses to resolve variables by searching the current scope first, then parent scopes, and finally the global scope.

---

### 8. What is the difference between Lexical Environment and Scope Chain?

**Answer:**

* **Lexical Environment** defines **where variables belong** (based on where the code is written).
* **Scope Chain** defines **how JavaScript searches for variables** (current → parent → global).

---

### 9. Why is understanding Execution Context important in React?

**Answer:**
Every React component is a function. Each render creates a new Function Execution Context, making concepts like closures, hooks, state updates, and event handlers easier to understand and debug.
