# 1. Variables

Variables are used to **store values in memory**.

JavaScript provides three ways to declare variables:

* `var`
* `let`
* `const`

---

## var

Introduced in the initial versions of JavaScript.

```javascript
var name = "John";
```

Characteristics

* Function scoped
* Can be redeclared
* Can be reassigned
* Hoisted and initialized with `undefined`

```javascript
var age = 25;
var age = 30; // Allowed

age = 35; // Allowed
```

---

## let

Introduced in ES6.

```javascript
let age = 25;
```

Characteristics

* Block scoped
* Cannot be redeclared in the same scope
* Can be reassigned
* Hoisted but not initialized

```javascript
let age = 25;

age = 30; // Allowed
```

Not allowed

```javascript
let age = 25;
let age = 30; // Error
```

---

## const

Introduced in ES6.

```javascript
const PI = 3.14;
```

Characteristics

* Block scoped
* Cannot be redeclared
* Cannot be reassigned
* Must be initialized during declaration

```javascript
const name = "React";
```

Wrong

```javascript
const name;
```

---

## Important Interview Question

### Can we modify a const object?

Yes.

`const` protects the **reference**, not the object contents.

```javascript
const user = {
    name: "John"
};

user.name = "Peter"; // Allowed

console.log(user.name);
```

Output

```text
Peter
```

Not allowed

```javascript
user = {};
```

Because the reference changes.

---

# var vs let vs const

| Feature                     | var         | let     | const       |
| --------------------------- | ----------- | ------- | ----------- |
| Scope                       | Function    | Block   | Block       |
| Redeclare                   | ✅           | ❌       | ❌           |
| Reassign                    | ✅           | ✅       | ❌           |
| Hoisted                     | ✅           | ✅       | ✅           |
| Initialized during hoisting | `undefined` | ❌ (TDZ) | ❌ (TDZ)     |
| Preferred                   | ❌           | ✅       | ✅ (default) |

---

## Best Practice

Use

* `const` by default
* `let` if value changes
* Avoid `var`

---

# 2. Scope

Scope determines **where a variable can be accessed**.

There are four important scopes:

* Global Scope
* Function Scope
* Block Scope
* Lexical Scope

---

# Global Scope

Variables declared outside any function.

```javascript
const app = "React";

function show() {
    console.log(app);
}
```

Accessible everywhere.

---

# Function Scope

Variables declared inside a function.

```javascript
function test() {

    var age = 20;

    console.log(age);

}

test();
```

Outside

```javascript
console.log(age);
```

Error.

---

# Block Scope

Created by

```javascript
{

}
```

`let` and `const` are block scoped.

```javascript
if(true){

    let age = 20;

}
```

Outside

```javascript
console.log(age);
```

Error.

---

`var`

is **NOT** block scoped.

```javascript
if(true){

    var age = 20;

}

console.log(age);
```

Output

```text
20
```

---

# Lexical Scope

A function can access variables from its outer scope.

```javascript
const name = "React";

function outer(){

    function inner(){

        console.log(name);

    }

    inner();

}
```

Output

```text
React
```

This is called **Lexical Scope**.

It is also the foundation of **Closures**.

---

# Scope Chain

JavaScript searches variables in this order.

```text
Current Scope
      ↓
Parent Scope
      ↓
Global Scope
      ↓
Not Found → ReferenceError
```

Example

```javascript
const x = 10;

function outer(){

    const y = 20;

    function inner(){

        console.log(x);

        console.log(y);

    }

    inner();

}

outer();
```

---

# 3. Hoisting

Hoisting is JavaScript's behavior of **moving declarations to the top of their scope before execution**.

> **Important:** Only **declarations** are hoisted, not the assignments.

---

## Example with var

```javascript
console.log(age);

var age = 25;
```

Output

```text
undefined
```

Internally

```javascript
var age;

console.log(age);

age = 25;
```

---

## let

```javascript
console.log(age);

let age = 25;
```

Output

```text
ReferenceError
```

---

## const

```javascript
console.log(age);

const age = 25;
```

Output

```text
ReferenceError
```

---

# Temporal Dead Zone (TDZ)

The time between:

* Variable declaration being hoisted
* Variable initialization

During this period, the variable exists but **cannot be accessed**.

```javascript
console.log(age);

let age = 25;
```

The variable is inside the **Temporal Dead Zone**, so accessing it throws a `ReferenceError`.

---

# Function Hoisting

## Function Declaration

```javascript
sayHello();

function sayHello(){

    console.log("Hello");

}
```

Works.

---

## Function Expression

```javascript
sayHello();

const sayHello = function(){

};
```

Error.

Because only the variable is hoisted, not the function assignment.

---

## Arrow Function

```javascript
sayHello();

const sayHello = () => {};
```

Also throws a `ReferenceError`.

---

# Hoisting Summary

| Type                 | Hoisted           | Can Use Before Declaration? |
| -------------------- | ----------------- | --------------------------- |
| `var`                | Yes (`undefined`) | Yes (returns `undefined`)   |
| `let`                | Yes (TDZ)         | ❌                           |
| `const`              | Yes (TDZ)         | ❌                           |
| Function Declaration | Yes               | ✅                           |
| Function Expression  | Variable only     | ❌                           |
| Arrow Function       | Variable only     | ❌                           |

---

# 4. Strict Mode

Strict Mode enables a **safer version of JavaScript** by preventing common mistakes and throwing errors for unsafe code.

Enable it using:

```javascript
"use strict";
```

Example

```javascript
"use strict";

const name = "React";
```

---

## Without Strict Mode

```javascript
age = 25;

console.log(age);
```

Output

```text
25
```

JavaScript automatically creates a global variable.

---

## With Strict Mode

```javascript
"use strict";

age = 25;
```

Output

```text
ReferenceError
```

---

## Prevents Duplicate Parameters

Without strict mode

```javascript
function test(a, a){

}
```

Allowed (legacy behavior).

With strict mode

```javascript
"use strict";

function test(a, a){

}
```

SyntaxError.

---

## Makes `this` Safer

Without strict mode

```javascript
function test(){

    console.log(this);

}

test();
```

Output (browser)

```text
Window
```

With strict mode

```javascript
"use strict";

function test(){

    console.log(this);

}

test();
```

Output

```text
undefined
```

This helps avoid accidental access to the global object.

---

## Why React Developers Should Know This

Modern JavaScript modules (ES Modules) automatically run in **strict mode**, so React applications already benefit from these rules.

# Common Mistakes

### 1. Using `var`

Avoid `var` in modern JavaScript because of function scope and hoisting behavior.

---

### 2. Accessing `let`/`const` Before Declaration

This results in a `ReferenceError` due to the Temporal Dead Zone.

---

### 3. Thinking `const` Makes Objects Immutable

`const` only prevents reassignment of the variable, not modification of object properties.


---
note:

Mutable: An object whose contents can be modified without creating a new object (e.g., Arrays, Objects, Maps, Sets).

Immutable: A value that cannot be modified; any "change" creates a new value (e.g., Strings, Numbers, Booleans).

---

### 4. Forgetting Block Scope

```javascript
if (true) {
    let name = "React";
}

console.log(name); // Error
```

---

### 5. Confusing Function Declaration and Function Expression

```javascript
// ✅ Works
hello();

function hello() {}

// ❌ Error
hi();

const hi = function() {};
```

---

# Best Practices

* Use `const` by default.
* Use `let` only when reassignment is needed.
* Avoid `var`.
* Keep variables in the smallest possible scope.
* Always declare variables before using them.
* Understand hoisting instead of relying on it.
* Remember that ES Modules (used by React) are in strict mode automatically.

# Frequently Asked Interview Questions (6 Years React)

### 1. What is the difference between `var`, `let`, and `const`?

**Answer:**

* `var` is function-scoped, can be redeclared and reassigned, and should generally be avoided.
* `let` is block-scoped, cannot be redeclared in the same scope, but can be reassigned.
* `const` is block-scoped, cannot be redeclared or reassigned, and is the preferred default.

---

### 2. What is hoisting?

**Answer:** Hoisting is JavaScript's process of moving declarations to the top of their scope before execution. Only declarations are hoisted, not assignments.

---

### 3. What is the Temporal Dead Zone (TDZ)?

**Answer:** The TDZ is the period between the start of a scope and the initialization of a `let` or `const` variable. Accessing the variable during this period throws a `ReferenceError`.

---

### 4. Why can a `const` object still be modified?

**Answer:** `const` prevents reassignment of the variable reference, not mutation of the object's properties.

---

### 5. What is lexical scope?

**Answer:** Lexical scope means a function can access variables from its outer (parent) scopes based on where it is defined in the code.

---

### 6. What is the difference between function declarations and function expressions regarding hoisting?

**Answer:** Function declarations are fully hoisted and can be called before they appear in the code. Function expressions (including arrow functions assigned to variables) are not usable before the assignment.

---

### 7. What does Strict Mode do?

**Answer:** Strict Mode enables stricter parsing and error handling. It catches common mistakes (like accidental global variables), disallows certain unsafe behaviors, and makes JavaScript execution more predictable.

---

### 8. Does React use Strict Mode automatically?

**Answer:** React components written as **ES Modules** run under JavaScript's strict mode because ES Modules are strict by default. Additionally, React provides `<React.StrictMode>` in development, which is a React-specific tool that performs extra checks (such as highlighting unsafe lifecycle methods and detecting certain side effects). This is different from JavaScript's `"use strict"` directive.
