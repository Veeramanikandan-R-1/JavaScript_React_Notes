# JavaScript Operators 

Operators are heavily used in React applications for:

* Conditional rendering
* State updates
* Props handling
* API response handling
* Object/Array manipulation
* Function parameters

Understanding these operators is essential because almost every React codebase uses them.

---

# 1. Equality Operators (`==`, `===`, `!=`, `!==`)

Equality operators compare two values.

JavaScript provides two types of equality checks:

| Operator | Name              | Performs Type Conversion? | Recommended |
| -------- | ----------------- | ------------------------- | ----------- |
| `==`     | Loose Equality    | ✅ Yes                     | ❌ Avoid     |
| `!=`     | Loose Inequality  | ✅ Yes                     | ❌ Avoid     |
| `===`    | Strict Equality   | ❌ No                      | ✅ Yes       |
| `!==`    | Strict Inequality | ❌ No                      | ✅ Yes       |

---

# Loose Equality (`==`)

`==` compares values **after converting their types if necessary (type coercion).**

Example:

```javascript
console.log(5 == "5");
```

Output

```javascript
true
```

Internally

```javascript
Number("5") → 5

5 == 5
```

Another example

```javascript
console.log(true == 1);
```

Output

```javascript
true
```

Because

```javascript
true → 1
```

---

## Why is `==` dangerous?

Sometimes JavaScript converts values unexpectedly.

```javascript
console.log("" == 0);           // true
console.log(false == "0");      // true
console.log(null == undefined); // true
```

These comparisons are confusing and often lead to bugs.

**Best Practice**

Avoid `==`.

---

# Strict Equality (`===`)

`===` compares **both value and data type**.

Example

```javascript
console.log(5 === "5");
```

Output

```javascript
false
```

Because

```text
Number !== String
```

Example

```javascript
console.log(5 === 5);
```

Output

```javascript
true
```

---

# Equality with Objects

Objects are compared by **reference**, not by value.

```javascript
const obj1 = { name: "John" };
const obj2 = { name: "John" };

console.log(obj1 === obj2);
```

Output

```javascript
false
```

Although both objects have identical content, they occupy different memory locations.

Example

```javascript
const obj1 = { name: "John" };
const obj2 = obj1;

console.log(obj1 === obj2);
```

Output

```javascript
true
```

Because both variables point to the same object.

---

# Equality Summary

| Expression           | Result  |
| -------------------- | ------- |
| `5 == "5"`           | `true`  |
| `5 === "5"`          | `false` |
| `true == 1`          | `true`  |
| `true === 1`         | `false` |
| `{}` === `{}`        | `false` |
| `[] === []`          | `false` |
| `null == undefined`  | `true`  |
| `null === undefined` | `false` |

---

# React Connection

React relies on **reference equality** to detect changes.

❌ Bad

```javascript
user.name = "David";

setUser(user);
```

Reference didn't change.

React may skip re-rendering.

✅ Correct

```javascript
setUser({
    ...user,
    name: "David"
});
```

New object reference → React detects the update.

# 2. Nullish Coalescing Operator (`??`)

Introduced in **ES2020**.

Returns the right-hand value **only when the left-hand value is `null` or `undefined`.**

Syntax

```javascript
value ?? defaultValue
```

Example

```javascript
const username = null;

console.log(username ?? "Guest");
```

Output

```javascript
Guest
```

---

Example

```javascript
const age = 25;

console.log(age ?? 18);
```

Output

```javascript
25
```

---

# Why not use `||`?

Many developers use

```javascript
||
```

for default values.

Example

```javascript
const count = 0;

console.log(count || 10);
```

Output

```javascript
10
```

This is wrong if `0` is a valid value.

Using `??`

```javascript
console.log(count ?? 10);
```

Output

```javascript
0
```

Correct.

---

# Difference Between `||` and `??`

| Value         | `value || "A"`    | `value ?? "A"`    |
|--------       |----------------   |----------------   |
| `0`           | `"A"`             | `0`               |
| `false`       | `"A"`             | `false`           |
| `""`          | `"A"`             | `""`              |
| `null`        | `"A"`             | `"A"`             |
| `undefined`   | `"A"`             | `"A"`             |

---

# React Example

```javascript
const totalItems = props.count ?? 0;
```

Even if

```javascript
count = 0
```

The value remains `0`.

---

# 3. Optional Chaining (`?.`)

Optional chaining safely accesses nested properties.

Without optional chaining

```javascript
console.log(user.address.city);
```

If `address` is undefined

Output

```text
TypeError
```

---

With optional chaining

```javascript
console.log(user?.address?.city);
```

Output

```javascript
undefined
```

No error occurs.

---

# Optional Chaining with Arrays

```javascript
const users = [];

console.log(users?.[0]);
```

Output

```javascript
undefined
```

---

# Optional Chaining with Functions

```javascript
user?.login?.();
```

The function executes only if it exists.

---

# React Example

Very common when consuming APIs.

```javascript
const image = user?.profile?.image;
```

Instead of

```javascript
user &&
user.profile &&
user.profile.image
```

Much cleaner.

---

# Optional Chaining + Nullish

These are frequently used together.

```javascript
const city =
user?.address?.city ?? "Unknown";
```

Meaning

* Access safely.
* If value doesn't exist, use default.

# 4. Spread Operator (`...`)

Spread expands iterable values or object properties.

Works with

* Arrays
* Objects
* Function arguments

---

# Array Spread

```javascript
const arr1 = [1,2];

const arr2 = [...arr1,3,4];
```

Output

```javascript
[1,2,3,4]
```

---

# Copy an Array

```javascript
const copy = [...arr1];
```

Creates a **new array (shallow copy).**

---

# Merge Arrays

```javascript
const a = [1,2];
const b = [3,4];

const c = [...a,...b];
```

Output

```javascript
[1,2,3,4]
```

---

# Object Spread

```javascript
const user = {
    name:"John"
};

const updated = {
    ...user,
    age:30
};
```

Output

```javascript
{
   name:"John",
   age:30
}
```

---

# Override Existing Properties

```javascript
const updated = {
    ...user,
    name:"David"
};
```

Later values overwrite earlier ones.

---

# Function Arguments

```javascript
const numbers = [1,2,3];

Math.max(...numbers);
```

Equivalent to

```javascript
Math.max(1,2,3);
```

---

# React State Updates

One of the most common React patterns.

```javascript
setUser({
    ...user,
    age:31
});
```

Maintains immutability.

---

# Spread Creates a Shallow Copy

```javascript
const user = {
    address:{
        city:"New York"
    }
};

const copy = {
    ...user
};

copy.address.city = "London";
```

Both objects now contain

```text
London
```

Because only the first level was copied.

Nested objects still share the same reference.

---

Note: Shallow vs Deep

The easiest way to understand this is:

> **Shallow Copy copies only the first level.**
> **Deep Copy copies everything, including nested objects.**

---

# Shallow Copy

A shallow copy creates a **new outer object**, but **nested objects/arrays are still shared**.

### Example

```javascript
const user = {
  name: "John",
  address: {
    city: "New York"
  }
};

const copy = { ...user }; // Shallow copy

copy.name = "David";

console.log(user.name); // John ✅
```

The top-level property (`name`) is independent.

But for nested objects:

```javascript
copy.address.city = "London";

console.log(user.address.city);
```

Output

```text
London
```

Why?

```
user
 ├── name → "John"
 └── address ─────┐
                  │
copy              │
 ├── name → "David"
 └── address ─────┘
```

Both `user` and `copy` share the **same `address` object**.

---

# Deep Copy

A deep copy creates **completely new copies** of all nested objects and arrays.

deep copy we can use 

1. JSON.parse(JSON.stringify(object)) -> but function cannot be copied this way
2. use lodash lib cloneDeep method -> works fine for all

### Example

```javascript
const user = {
  name: "John",
  address: {
    city: "New York"
  }
};

const copy = structuredClone(user); // Deep copy

copy.address.city = "London";

console.log(user.address.city);
```

Output

```text
New York
```

Now both objects are completely independent.

```
user
 ├── name → "John"
 └── address → { city: "New York" }

copy
 ├── name → "John"
 └── address → { city: "London" }
```

No shared references.

---

# Visual Comparison

### Shallow Copy

```
Original
   │
   ▼
{
  name: "John",
  address ───────────┐
}                    │
                     │
Copy                 │
{                    │
  name: "John",      │
  address ───────────┘
}
```

Nested object is shared.

---

### Deep Copy

```
Original
{
  name: "John",
  address → { city: "NY" }
}

Copy
{
  name: "John",
  address → { city: "NY" }
}
```

Everything is copied independently.

# How to Create Them

### Shallow Copy

```javascript
const copy = { ...obj };
const arrCopy = [...arr];
```

or

```javascript
Object.assign({}, obj);
```

---

### Deep Copy (Modern JavaScript)

```javascript
const copy = structuredClone(obj);
```

# React Interview Connection

Suppose your React state is:

```javascript
const user = {
  name: "John",
  address: {
    city: "NY"
  }
};
```

### ❌ Problem with shallow copy

```javascript
const updated = { ...user };

updated.address.city = "LA";
```

`user.address.city` also becomes `"LA"` because `address` is still shared.

### ✅ Correct approach

Copy each nested level that changes:

```javascript
const updated = {
  ...user,
  address: {
    ...user.address,
    city: "LA"
  }
};
```

Now React gets a new reference for both `user` and `address`, making the update immutable.

---

# Quick Cheat Sheet

| Feature                    | Shallow Copy | Deep Copy |
| -------------------------- | ------------ | --------- |
| Copies top-level object    | ✅            | ✅         |
| Copies nested objects      | ❌ (shared)   | ✅         |
| Independent nested changes | ❌            | ✅         |
| Spread (`...`)             | ✅ Shallow    | ❌         |
| `Object.assign()`          | ✅ Shallow    | ❌         |
| `structuredClone()`        | ❌            | ✅         |

### One-line Interview Answer

> **Shallow copy duplicates only the first level, so nested objects still share the same reference. Deep copy recursively duplicates all nested objects and arrays, making the copied object completely independent of the original.**

# 5. Rest Operator (`...`)

The Rest operator collects multiple values into one variable.

Although it uses the same syntax (`...`), it behaves opposite to Spread.

---

# Rest in Function Parameters

```javascript
function sum(...numbers){
    console.log(numbers);
}

sum(1,2,3,4);
```

Output

```javascript
[1,2,3,4]
```

---

# Rest with Objects

```javascript
const user = {
    name:"John",
    age:30,
    city:"London"
};

const { name, ...others } = user;
```

Result

```javascript
name
```

```text
John
```

others

```javascript
{
    age:30,
    city:"London"
}
```

---

# Rest with Arrays

```javascript
const [first,...remaining] = [10,20,30];
```

Result

```text
first = 10

remaining = [20,30]
```

---

# Spread vs Rest

| Spread                     | Rest                                      |
| -------------------------- | ----------------------------------------- |
| Expands values             | Collects values                           |
| Used when sending values   | Used when receiving values                |
| Creates new arrays/objects | Groups remaining values                   |
| Used in function calls     | Used in function parameters/destructuring |

Example

Spread

```javascript
const copy = [...arr];
```

Rest

```javascript
const [first,...others] = arr;
```

# Common Mistakes

### ❌ Using `==`

```javascript
0 == false
```

Returns

```javascript
true
```

Prefer `===`.

---

### ❌ Using `||` Instead of `??`

```javascript
const count = 0;

count || 10;
```

Returns `10`.

Use

```javascript
count ?? 10;
```

---

### ❌ Assuming Spread Performs Deep Copy

```javascript
const copy = {
    ...user
};
```

Nested objects are still shared.

---

### ❌ Forgetting Optional Chaining

```javascript
user.address.city
```

Can throw an error if `address` is missing.

---

### ❌ Confusing Spread and Rest

Remember:

* **Spread expands**
* **Rest collects**

---

# Best Practices

* Always use `===` and `!==`.
* Use `??` instead of `||` for default values when `0`, `false`, or `""` are valid.
* Use `?.` to safely access nested data from APIs.
* Use spread for immutable updates in React.
* Use rest for flexible function parameters and prop forwarding.
* Remember that spread performs only a shallow copy.

# Common React (6 Years Experience) Interview Questions

### 1. What is the difference between `==` and `===`?

**Answer:** `==` performs type coercion before comparison, whereas `===` compares both value and type without coercion. In production code, always prefer `===`.

---

### 2. When should you use `??` instead of `||`?

**Answer:** Use `??` when `0`, `false`, or an empty string are valid values. `??` falls back only for `null` or `undefined`.

---

### 3. What problem does optional chaining solve?

**Answer:** It prevents runtime errors when accessing nested properties or methods on objects that may be `null` or `undefined`.

---

### 4. What is the difference between Spread and Rest operators?

**Answer:**

* **Spread (`...`)** expands arrays, objects, or function arguments.
* **Rest (`...`)** collects remaining values into an array or object during function parameter declaration or destructuring.

---

### 5. Does the spread operator create a deep copy?

**Answer:** No. It creates a **shallow copy**. Nested objects and arrays continue to share references.

---

### 6. Why is the spread operator commonly used in React?

**Answer:** React relies on immutable updates. Using spread creates a new object or array reference, allowing React to detect state changes and re-render efficiently.

---

### 7. Can optional chaining be used with arrays and functions?

**Answer:** Yes.

```javascript
arr?.[0]

obj?.callback?.()
```

---

### 8. If two object spreads contain the same property, which value is used?

```javascript
const result = {
    ...obj1,
    ...obj2
};
```

**Answer:** The property from the **later spread** (`obj2`) overwrites the earlier one.

---

### 9. Why doesn't React re-render when you directly mutate state?

**Answer:** React compares object references. Direct mutation keeps the same reference, so React may not detect the change. Creating a new object with the spread operator changes the reference and triggers a re-render.

---

### 10. When would you use the Rest operator in React?

**Answer:** It's commonly used for:

* Forwarding props (`...props`)
* Collecting remaining object properties
* Accepting a variable number of function arguments
* Destructuring props while separating specific values from the rest
