# JavaScript ES6+

ES6 (ECMAScript 2015) introduced many features that made JavaScript cleaner, more maintainable, and easier to write. Almost every modern React application heavily relies on ES6+ features.

As a React developer, you'll use these features daily in components, hooks, state management, API calls, and utility functions.

---

# 1. let

## What is it?

`let` declares a variable whose value **can be changed later**.

```javascript
let count = 0;
count = 1;
```

---

## Why was let introduced?

Before ES6, JavaScript only had `var`, which caused problems because:

* Function scoped
* Can be redeclared
* Hoisted differently

`let` solves these issues.

---

## Scope

`let` is **Block Scoped**.

```javascript
if (true) {
    let x = 10;
}

console.log(x); // Error
```

The variable exists only inside the block.

---

## Reassignment

Allowed

```javascript
let age = 25;

age = 30;
```

---

## Redeclaration

Not allowed in the same scope.

```javascript
let age = 25;
let age = 30; // Error
```

---

## Hoisting

`let` is hoisted but remains in the **Temporal Dead Zone (TDZ)** until initialized.

```javascript
console.log(a);

let a = 10;
```

Throws

```text
ReferenceError
```

---

## When to use

Use `let` when the variable needs to change.

Example

```javascript
let currentPage = 1;
```

---

# 2. const

## What is it?

Declares a variable whose **binding cannot be reassigned**.

```javascript
const PI = 3.14;
```

---

## Important

People often think const means immutable.

It does **NOT**.

It only means the **reference cannot change**.

Example

```javascript
const user = {
    name: "John"
};

user.name = "Alice"; // Allowed
```

But

```javascript
user = {};
```

Throws an error.

---

## Arrays

Allowed

```javascript
const arr = [1, 2];

arr.push(3);
```

Not allowed

```javascript
arr = [];
```

---

## Scope

Like `let`, it is block scoped.

---

## Hoisting

Also has Temporal Dead Zone.

---

## When to use

Whenever the variable shouldn't be reassigned.

React developers should prefer `const` by default.

---

# let vs const vs var

| Feature   | var      | let       | const     |
| --------- | -------- | --------- | --------- |
| Scope     | Function | Block     | Block     |
| Redeclare | Yes      | No        | No        |
| Reassign  | Yes      | Yes       | No        |
| Hoisted   | Yes      | Yes (TDZ) | Yes (TDZ) |

---

# 3. Template Literals

## What are they?

Strings enclosed by backticks.

```javascript
const name = "John";

console.log(`Hello ${name}`);
```

Output

```text
Hello John
```

---

## Why use them?

Instead of

```javascript
"Hello " + name
```

Use

```javascript
`Hello ${name}`
```

Cleaner and easier to read.

---

## Multi-line Strings

```javascript
const msg = `
Hello
Welcome
`;
```

No need for `\n`.

---

## Expressions

```javascript
const a = 10;
const b = 20;

`${a + b}`
```

Result

```text
30
```

---

## React Usage

```jsx
<h1>{`Welcome ${user.name}`}</h1>
```

---

# 4. Destructuring

## What is it?

Extract values from arrays or objects into variables.

---

# Object Destructuring

Without destructuring

```javascript
const user = {
    name: "John",
    age: 25
};

const name = user.name;
const age = user.age;
```

With destructuring

```javascript
const { name, age } = user;
```

---

## Rename Variable

```javascript
const { name: userName } = user;
```

---

## Default Values

```javascript
const { city = "Chennai" } = user;
```

---

## Nested Destructuring

```javascript
const user = {
    address: {
        city: "Delhi"
    }
};

const {
    address: { city }
} = user;
```

---

# Array Destructuring

```javascript
const arr = [10, 20];

const [a, b] = arr;
```

---

## Skip Values

```javascript
const [a, , c] = [1,2,3];
```

---

## Swap Variables

```javascript
let a = 10;
let b = 20;

[a, b] = [b, a];
```

---

## React Usage

Hooks

```javascript
const [count, setCount] = useState(0);
```

---

# 5. Spread Operator (...)

## What is it?

Expands elements.

Works with

* Arrays
* Objects
* Function arguments

---

## Arrays

```javascript
const a = [1,2];
const b = [...a,3];
```

Result

```text
[1,2,3]
```

---

## Copy Array

```javascript
const copy = [...arr];
```

---

## Merge Arrays

```javascript
const result = [...a,...b];
```

---

## Objects

```javascript
const user = {
    name:"John"
};

const updated = {
    ...user,
    age:25
};
```

---

## Override Properties

```javascript
const obj = {
    name:"John",
    age:20
};

const updated = {
    ...obj,
    age:25
};
```

---

## React State Update

```javascript
setUser({
    ...user,
    age:30
});
```

---

## Shallow Copy

Spread performs a **shallow copy**, not a deep copy.

```javascript
const a = {
    address:{
        city:"Delhi"
    }
};

const b = {...a};

b.address.city="Mumbai";

console.log(a.address.city);
```

Output

```text
Mumbai
```

Nested objects still share references.

---

# 6. Rest Operator (...)

Looks identical to spread but behaves differently.

---

## What is it?

Collects multiple values into one variable.

---

## Function Parameters

```javascript
function sum(...numbers){
    return numbers.reduce((a,b)=>a+b);
}
```

```javascript
sum(1,2,3,4);
```

---

## Object Rest

```javascript
const user = {
    name:"John",
    age:25,
    city:"Delhi"
};

const { name, ...rest } = user;
```

rest

```javascript
{
 age:25,
 city:"Delhi"
}
```

---

## Array Rest

```javascript
const [first,...others] = [1,2,3,4];
```

others

```javascript
[2,3,4]
```

---

# Spread vs Rest

| Spread             | Rest                 |
| ------------------ | -------------------- |
| Expands            | Collects             |
| Used while calling | Used while receiving |

Example

Spread

```javascript
foo(...arr);
```

Rest

```javascript
function foo(...arr){}
```

---

# 7. Modules

Modules split code into reusable files.

---

## Export

Named Export

```javascript
export const PI = 3.14;
```

Import

```javascript
import { PI } from "./math";
```

---

## Default Export

```javascript
export default App;
```

Import

```javascript
import App from "./App";
```

---

# Named vs Default

| Named             | Default      |
| ----------------- | ------------ |
| Multiple per file | One per file |
| Curly braces      | No braces    |
| Name must match   | Any name     |

---

## React Usage

```javascript

import Button from "./Button";

import { formatDate } from "./utils";
```

---


Used for lazy loading.

# 8. Classes

ES6 introduced class syntax.

---

## Example

```javascript
class Person{

    constructor(name){
        this.name = name;
    }

    greet(){
        console.log(this.name);
    }
}
```

---

## Create Object

```javascript
const p = new Person("John");
```

---

## Inheritance

```javascript
class Animal{

    speak(){
        console.log("Animal");
    }

}

class Dog extends Animal{

}

const d = new Dog();

d.speak();
```

---

## super()

Calls parent constructor.

```javascript
class Dog extends Animal{

    constructor(){
        super();
    }

}
```

---

## Why React Developers Should Know Classes?

Modern React uses functional components, but:

* Error Boundaries still require class components (or libraries wrapping them).
* Legacy codebases often use class components.
* Interviewers may ask lifecycle method questions.

---

# ES6 Best Practices

* Prefer `const` over `let`.
* Avoid `var`.
* Use template literals instead of string concatenation.
* Use destructuring for cleaner code.
* Use spread for immutable updates.
* Use rest for variable arguments.
* Use modules to organize code.
* Prefer functional components over class components in React.

---

# Common Mistakes

### Thinking const makes objects immutable

```javascript
const user = {
    name:"John"
};

user.name = "Alice"; // Allowed
```

---

### Confusing Spread and Rest

```javascript
// Spread
foo(...arr);

// Rest
function foo(...arr){}
```

---

### Forgetting Spread is Shallow

```javascript
const copy = {...obj};
```

Nested objects are still shared.

---

### Incorrect Destructuring

```javascript
const { name } = undefined;
```

Throws

```text
TypeError
```

Use optional chaining or defaults when appropriate.

# Common React Interview Questions (6+ Years)

### 1. What is the difference between `let`, `const`, and `var`?

**Answer:** `var` is function-scoped, can be redeclared and reassigned. `let` is block-scoped, can be reassigned but not redeclared. `const` is block-scoped and cannot be reassigned, though object and array contents can still be mutated.

---

### 2. Does `const` make an object immutable?

**Answer:** No. `const` prevents reassignment of the variable reference, but the object's properties or array elements can still be modified.

---

### 3. What is the difference between the spread (`...`) and rest (`...`) operators?

**Answer:** They share the same syntax but different purposes. **Spread** expands elements (e.g., copying arrays or objects, passing function arguments), while **rest** collects multiple values into a single variable (e.g., function parameters or destructuring).

---

### 4. Why is the spread operator commonly used in React state updates?

**Answer:** React state should be treated as immutable. The spread operator creates a new object or array while preserving existing values, allowing safe state updates without mutating the previous state.

---

### 5. What is destructuring and why is it useful?

**Answer:** Destructuring extracts values from objects or arrays into variables. It makes code shorter, improves readability, and is heavily used with React props, hooks, and API responses.

---

### 6. What is the difference between named exports and default exports?

**Answer:** A file can have multiple named exports, which are imported using curly braces (`import { foo } from ...`). It can have only one default export, imported without curly braces (`import Foo from ...`).

---

### 7. What are template literals, and why are they preferred?

**Answer:** Template literals use backticks (`` ` ``) and support string interpolation (`${}`), multi-line strings, and embedded expressions, making string construction cleaner than concatenation.

---

### 8. Do modern React applications still use classes?

**Answer:** Most new React applications use functional components and hooks. However, classes are still relevant for maintaining legacy codebases and understanding concepts like class components and Error Boundaries, which are commonly discussed in interviews.
