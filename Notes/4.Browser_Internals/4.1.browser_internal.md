# Browser Internals — Rendering & Performance

For a React developer, the main thing to understand is:

> **JS/DOM/CSS changes → browser calculates styles → calculates layout → paints pixels → composites layers → displays the frame.**

---

# 1. Rendering Pipeline ⭐

The browser roughly goes through these stages:

```text
HTML
 ↓
DOM
 ↓
CSS
 ↓
CSSOM
 ↓
Style Calculation
 ↓
Layout
 ↓
Paint
 ↓
Composite
 ↓
Screen
```

### Main stages

| Stage                 | What happens                                     |
| --------------------- | ------------------------------------------------ |
| **DOM**               | HTML converted into DOM tree                     |
| **CSSOM**             | CSS converted into CSSOM                         |
| **Style Calculation** | Determines styles for elements                   |
| **Layout**            | Calculates size + position                       |
| **Paint**             | Draws text, colors, borders, images, etc.        |
| **Composite**         | Combines layers and sends final result to screen |

---

# 2. Reflow / Layout ⭐

**Reflow** (also called **layout**) happens when the browser must recalculate the **size or position** of elements.

Example:

```js
element.style.width = "500px";
element.style.height = "200px";
```

Changing these can require layout recalculation.

### Common properties that can trigger layout

```css
width
height
margin
padding
top
left
font-size
display
position
```

Example:

```js
box.style.width = "500px";
```

The browser may need to determine:

```text
How big is the box?
 ↓
Does surrounding content move?
 ↓
Recalculate layout
```

### Why expensive?

A change to one element can cause layout calculations for **many related elements**.

---

# 3. Repaint

After layout, the browser may need to **redraw pixels**.

Example:

```js
element.style.backgroundColor = "red";
```

The element's geometry hasn't changed, but its visual appearance changed.

Common repaint properties:

```css
color
background-color
box-shadow
border-color
visibility
```

### Example

```js
element.style.color = "red";
```

Usually:

```text
Style
 ↓
Paint
 ↓
Composite
```

No layout is required.

---

# 4. Composite ⭐

**Compositing** is the process of combining separately rendered layers into the final image shown on screen.

Some elements can be placed on their own **compositor layers**.

Properties such as:

```css
transform
opacity
```

can often be handled efficiently by the compositor without recalculating layout or repainting the element's pixels.

Example:

```css
.box {
  transform: translateX(100px);
}
```

Animation:

```css
.box {
  transition: transform 0.3s;
}
```

This is generally preferable to:

```css
.box {
  left: 100px;
}
```

because changing `left` can require layout, while `transform` can often be handled during compositing.

> **Important:** `transform`/`opacity` are not guaranteed to be completely free of paint/layout in every situation. Browser implementation and surrounding styles matter.

---

# 5. Reflow vs Repaint vs Composite ⭐

```text
                    DOM/CSS change
                         ↓
                    Style Calculation
                         ↓
              ┌──────────┴──────────┐
              ↓                     ↓
           Layout                 No Layout
              ↓                     ↓
            Paint                Paint
              ↓                     ↓
           Composite           Composite
```

### Performance hierarchy

Generally:

```text
Layout/Reflow  → expensive
Paint          → expensive
Composite      → relatively cheap
```

So, when possible, prefer changes that can be handled by **compositing**.

---

# 6. Critical Rendering Path (CRP) ⭐

**Critical Rendering Path** is the sequence of steps the browser performs to convert resources into pixels on the screen.

Main resources:

```text
HTML
 ↓
DOM

CSS
 ↓
CSSOM

DOM + CSSOM
 ↓
Render Tree
 ↓
Layout
 ↓
Paint
 ↓
Composite
 ↓
Pixels
```

### Render Tree

Render Tree contains the nodes that actually need to be rendered.

For example:

```html
<div>Hello</div>
```

with:

```css
display: none;
```

The element exists in the DOM but isn't included in the rendered output.

---

# 7. Why CSS Can Block Rendering

CSS is generally **render-blocking** because the browser needs styles before safely rendering the page.

```html
<link rel="stylesheet" href="styles.css">
```

The browser needs the stylesheet to determine how elements should look.

### Optimization

Reduce unnecessary CSS:

```text
Large CSS
 ↓
Longer download/parse
 ↓
Delayed rendering
```

Use:

* Minified CSS
* Critical CSS
* Code splitting
* Remove unused CSS

---

# 8. JavaScript and Rendering

JavaScript can modify:

```text
DOM
CSSOM
Styles
Layout
```

Example:

```js
element.style.width = "500px";
```

The browser may need to recalculate layout.

### Avoid layout thrashing ⭐

Bad:

```js
for (let i = 0; i < 1000; i++) {
  element.style.width = `${i}px`;
  console.log(element.offsetWidth);
}
```

You're repeatedly:

```text
Write
 ↓
Read layout
 ↓
Write
 ↓
Read layout
```

This can force synchronous layout calculations.

Better: **batch reads and writes**.

```js
const width = element.offsetWidth;

for (let i = 0; i < 1000; i++) {
  element.style.width = `${i}px`;
}
```

# 9. Rendering Optimization ⭐

## A. Prefer `transform` for animations

Prefer:

```css
transform: translateX(100px);
```

over:

```css
left: 100px;
```

And:

```css
transform: scale(1.2);
opacity: 0.5;
```

are commonly good candidates for compositor-friendly animations.

---

## B. Use `requestAnimationFrame`

For JavaScript-driven visual updates:

```js
requestAnimationFrame(() => {
  element.style.transform = "translateX(100px)";
});
```

`requestAnimationFrame()` schedules visual updates around the browser's rendering cycle.

---

## C. Batch DOM operations

Avoid repeatedly modifying the DOM:

```js
for (...) {
  container.innerHTML += "...";
}
```

Prefer building the content first and making fewer DOM updates.

---

## D. Avoid unnecessary React renders

In React, rendering optimization includes:

```text
React.memo
useMemo
useCallback
proper state placement
code splitting
lazy loading
virtualization
```

Example:

```jsx
const User = React.memo(({ user }) => {
  return <div>{user.name}</div>;
});
```

`React.memo` can skip rendering when props are unchanged.

> Remember: **React render ≠ browser paint.** A React component re-render doesn't necessarily mean the browser performs layout and paint.

---

# 10. Large Lists — Virtualization

Instead of rendering 10,000 DOM nodes:

```text
10,000 items
     ↓
10,000 DOM elements ❌
```

Render only visible items:

```text
10,000 items
     ↓
~20–50 visible DOM elements ✅
```

Libraries/approaches include virtualization such as `react-window`.

---

# 11. Images & Loading Optimization

Use:

```html
<img
  src="large.jpg"
  loading="lazy"
  width="800"
  height="600"
/>
```

Benefits:

* Lazy loading
* Correct dimensions reduce layout shifts
* Optimized image formats/sizes reduce network cost

---

# 12. Web Performance Metrics — Must Know

For modern frontend interviews, know these:

### LCP — Largest Contentful Paint

How quickly the **main/largest visible content** appears.

### INP — Interaction to Next Paint

Measures **interaction responsiveness**.

### CLS — Cumulative Layout Shift

Measures unexpected **visual movement/layout shifts**.

Together, these are the primary **Core Web Vitals**.

### ⭐ Most important interview question

**Q: Which is better for animation — `left` or `transform`?**

```css
/* Prefer */
transform: translateX(100px);

/* Usually avoid for animation */
left: 100px;
```

Because `transform` can often be handled by the **compositor**, avoiding repeated layout work and potentially making animations smoother.
