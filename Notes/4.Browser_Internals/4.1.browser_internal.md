## 1. Rendering Pipeline

The **Rendering Pipeline** is the sequence the browser follows to display a webpage.

```text
HTML
   ↓
DOM

CSS
   ↓
CSSOM

DOM + CSSOM
      ↓
Render Tree
      ↓
Layout (Calculate positions & sizes)
      ↓
Paint (Fill pixels)
      ↓
Composite (Combine layers & display)
```

**Interview Point:** Any DOM or CSS change may trigger some or all of these steps, affecting performance.

---

## 2. Reflow (Layout)

**Reflow** is when the browser recalculates the **size and position** of elements.

Example:

```js
div.style.width = "300px";
```

Since the width changes, surrounding elements may need to move.

**Expensive:** ✅ Yes (one of the most expensive rendering operations)

Triggers:

* Width/height changes
* Margin/padding changes
* Font size changes
* Adding/removing DOM elements
* Window resize

---

## 3. Repaint

**Repaint** happens when an element's **appearance changes** but its layout stays the same.

Example:

```js
div.style.backgroundColor = "red";
```

The browser only redraws the pixels.

**Less expensive than Reflow.**

Triggers:

* Color changes
* Background changes
* Border color changes
* Visibility changes (without affecting layout)

---

## 4. Composite

After painting, the browser **combines different layers** to display the final page on the screen.

Properties like these usually trigger only compositing:

```css
transform: translateX(100px);
opacity: 0.5;
```

These are GPU-friendly and avoid layout recalculation.

**Interview Point:** Prefer `transform` and `opacity` for smooth animations because they usually skip layout and paint, requiring only compositing.

---

## 5. Critical Rendering Path (CRP)

The **Critical Rendering Path** is the sequence of steps the browser follows to render the **first visible content** on the page as quickly as possible.

```text
Download HTML
      ↓
Parse HTML → DOM
      ↓
Download CSS
      ↓
Parse CSS → CSSOM
      ↓
Create Render Tree
      ↓
Layout
      ↓
Paint
      ↓
Display Page
```

**Goal:** Reduce the time until the user sees the page (fast First Contentful Paint).

---

## 6. Rendering Optimization

Rendering optimization means **reducing unnecessary rendering work** to improve performance.

Common techniques:

* Minimize DOM updates.
* Batch multiple DOM changes together.
* Avoid unnecessary reflows.
* Animate using `transform` and `opacity`.
* Lazy load images and components.
* Reduce CSS complexity.
* Use `requestAnimationFrame()` for animations.
* In React, avoid unnecessary re-renders using `React.memo`, `useMemo`, and `useCallback`.

---

# Quick Comparison

| Concept                 | What Happens                           | Performance Cost        |
| ----------------------- | -------------------------------------- | ----------------------- |
| Rendering Pipeline      | Complete browser rendering process     | Depends on changes      |
| Reflow (Layout)         | Recalculates element size and position | 🔴 High                 |
| Repaint                 | Redraws element appearance             | 🟡 Medium               |
| Composite               | Combines painted layers for display    | 🟢 Low                  |
| Critical Rendering Path | Steps to render the first visible page | Important for page load |
| Rendering Optimization  | Techniques to reduce rendering work    | Improves performance    |

---

# 6-Year React Interview Tips

* **Reflow is more expensive than Repaint.**
* **Composite is the cheapest rendering stage.**
* **`transform` and `opacity` are preferred for animations** because they typically trigger only compositing.
* **Changing `width`, `height`, or `margin` usually causes Reflow.**
* **Changing `background-color` usually causes only Repaint.**
* **In React, reducing unnecessary component re-renders also reduces browser rendering work, leading to better UI performance.**
