# React Fundamentals

## 1. Component Types

### Functional Component

A JavaScript function that returns JSX.

```jsx
function User({ name }) {
  return <h2>Hello {name}</h2>;
}
```

With state:

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  return (
    <>
      <p>{count}</p>
      <button onClick={() => setCount(c => c + 1)}>
        Increment
      </button>
    </>
  );
}
```

**Key points**

* Modern React's preferred approach.
* Uses Hooks (`useState`, `useEffect`, `useContext`, etc.).
* No `this`.
* Logic can be reused using **custom Hooks**.
* Components should generally be pure: same props/state → same UI.

---

### Class Component — Basics

```jsx
class User extends React.Component {
  state = {
    count: 0
  };

  render() {
    return <h2>{this.props.name}</h2>;
  }
}
```

State update:

```jsx
this.setState({
  count: this.state.count + 1
});
```

Prefer functional update when depending on previous state:

```jsx
this.setState(prevState => ({
  count: prevState.count + 1
}));
```

### Important class concepts

```text
this.props       → Props
this.state       → Component state
this.setState()  → Update state
render()         → Return UI
```

Common lifecycle methods:

```jsx
componentDidMount() {}
componentDidUpdate() {}
componentWillUnmount() {}
```

**Interview point:** Class components are still supported but are mainly encountered in legacy applications. Modern React uses functional components + Hooks.

---

# 2. Rendering

Rendering means **React calculates what the UI should look like based on the current props/state/context**.

Important distinction:

> **Render ≠ DOM update.**

A component can render again without React changing the actual DOM.

---

## Initial Render

The first time React creates the UI.

```jsx
import { createRoot } from "react-dom/client";

const root = createRoot(document.getElementById("root"));

root.render(<App />);
```

Flow:

```text
root.render(<App />)
        ↓
React calls App
        ↓
Creates React element tree
        ↓
Reconciliation
        ↓
Commit required changes
        ↓
Browser DOM created/updated
```

Example:

```jsx
function App() {
  return <h1>Hello</h1>;
}
```

Initially, React creates the corresponding DOM:

```html
<h1>Hello</h1>
```

---

# 3. Re-render

A **re-render** means React calls a component again to calculate its latest UI.

Common causes:

### 1. State update

```jsx
setCount(count + 1);
```

### 2. Parent re-renders

```jsx
function Parent() {
  const [count, setCount] = useState(0);

  return (
    <>
      <button onClick={() => setCount(count + 1)}>
        {count}
      </button>

      <Child />
    </>
  );
}
```

When `Parent` re-renders, React normally evaluates `Child` as part of rendering the subtree.

### 3. Props change

```jsx
<Child count={count} />
```

### 4. Context value changes

Consumers of the changed context may re-render.

---

## Important: Re-render ≠ DOM update

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  return <h1>{count}</h1>;
}
```

When:

```jsx
setCount(1);
```

React:

```text
State changes
     ↓
Component re-renders
     ↓
New React element tree
     ↓
Compare with previous tree
     ↓
Only necessary DOM changes
```

React does **not** blindly recreate the entire DOM.

---

# 4. Reconciliation

**Reconciliation is React's process of determining what needs to change between the previous rendered tree and the new rendered tree.**

Example:

Previous:

```jsx
<h1>Hello</h1>
```

New:

```jsx
<h1>Hello World</h1>
```

React determines:

```text
<h1> remains
text content changes
```

So the DOM is updated accordingly.

### Reconciliation involves

```text
New React tree
      ↓
Compare with previous tree
      ↓
Determine changes
      ↓
Commit changes to DOM
```

### Important

Reconciliation happens during React's **render/reconciliation phase**; actual DOM mutations happen during the **commit phase**.

---

# 5. Diffing Algorithm

**Diffing** is the comparison process React uses during reconciliation to efficiently identify changes.

React does **not** perform an expensive deep comparison of every possible DOM node combination.

It uses practical heuristics.

---

## Rule 1 — Different element types

Previous:

```jsx
<div>
  <Counter />
</div>
```

New:

```jsx
<section>
  <Counter />
</section>
```

Because:

```text
div ≠ section
```

React treats them as different elements and replaces the old subtree accordingly.

---

## Rule 2 — Same element type

Previous:

```jsx
<div className="old">
  Hello
</div>
```

New:

```jsx
<div className="new">
  Hello
</div>
```

React keeps the same DOM node and updates the changed property:

```text
className: old → new
```

---

## Rule 3 — Component type matters

Previous:

```jsx
<User />
```

New:

```jsx
<Product />
```

Different component types → React treats them as different subtrees.

---

# 6. Keys — Very Important

Keys help React identify **which list item corresponds to which item between renders**.

```jsx
users.map(user => (
  <User key={user.id} user={user} />
));
```

Consider:

```text
Before:
A
B
C

After:
X
A
B
C
```

With stable keys:

```text
X → new
A → existing
B → existing
C → existing
```

React can correctly preserve component/DOM identity.

### ❌ Avoid array index when list can change

```jsx
users.map((user, index) => (
  <User key={index} user={user} />
));
```

If items are inserted, removed, or reordered, index keys can cause incorrect component state/DOM reuse.

### ✅ Prefer stable unique IDs

```jsx
users.map(user => (
  <User key={user.id} user={user} />
));
```

**Important interview point:**

> `key` is used by React for reconciliation. It is not passed to the component as a normal prop.

---

# Rendering vs Reconciliation vs Diffing

| Concept            | Meaning                                                          |
| ------------------ | ---------------------------------------------------------------- |
| **Render**         | React calculates the UI for the current state/props              |
| **Re-render**      | Component is evaluated again because something changed           |
| **Reconciliation** | React determines how the new tree differs from the previous tree |
| **Diffing**        | The comparison/heuristics used during reconciliation             |
| **Commit**         | React applies required changes to the host environment/DOM       |

---

# Complete Flow — Interview Favorite

```text
Initial render
     │
     ▼
React creates element tree
     │
     ▼
Reconciliation / Diffing
     │
     ▼
Commit
     │
     ▼
Browser DOM
```

When state changes:

```text
setState()
   │
   ▼
Update scheduled
   │
   ▼
Component re-renders
   │
   ▼
New element tree
   │
   ▼
Reconciliation / Diffing
   │
   ▼
Commit only necessary changes
   │
   ▼
Browser DOM
```

### One-liner interview answers

* **Initial render:** First rendering of the React application into the host environment.
* **Re-render:** React evaluates a component again to calculate its latest UI.
* **Reconciliation:** Process of determining what changed between previous and new React trees.
* **Diffing:** Efficient comparison strategy used during reconciliation.
* **Commit:** Phase where React applies the calculated changes to the DOM.
* **Key:** Stable identity used primarily for efficiently reconciling lists.

**Most important distinction to remember:**
**A component re-rendering does NOT mean the entire DOM is recreated.** React re-renders/evaluates the relevant component tree, reconciles the result, and commits only the necessary host-environment changes.
