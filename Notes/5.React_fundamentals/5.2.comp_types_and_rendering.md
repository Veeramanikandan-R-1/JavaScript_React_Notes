# React Fundamentals – Component Types & Rendering 

> **Goal:** For a **6-year React interview**, you're expected to understand not only **how React renders components**, but also **what happens internally when state changes**, **why reconciliation exists**, and **how the diffing algorithm optimizes updates**.

---

# Part 1: Component Types

# 1. Functional Components (Modern React)

## What are Functional Components?

A Functional Component is a **JavaScript function** that returns JSX.

Example

```jsx
function Welcome() {
    return <h1>Hello React</h1>;
}
```

Usage

```jsx
<Welcome />
```

---

## Why Functional Components?

Before Hooks, functional components were called **stateless components** because they couldn't manage state.

React Hooks (React 16.8+) introduced:

* State
* Lifecycle
* Context
* Refs
* Side effects

Now they support almost everything class components do.

Example

```jsx
import { useState } from "react";

function Counter() {

    const [count, setCount] = useState(0);

    return (
        <>
            <h2>{count}</h2>

            <button
                onClick={() => setCount(count + 1)}
            >
                Increment
            </button>
        </>
    );
}
```

---

## Advantages

* Less boilerplate
* Easier to read
* Hooks support
* Better code reuse with Custom Hooks
* Preferred by React team
* Better tree-shaking and optimization

---

# 2. Class Components (Basics)

## What are Class Components?

Class Components are ES6 classes that extend `React.Component`.

Example

```jsx
class Welcome extends React.Component {

    render() {

        return <h1>Hello React</h1>;

    }

}
```

---

## State

```jsx
class Counter extends React.Component {

    state = {
        count: 0
    };

    render() {

        return (
            <h2>{this.state.count}</h2>
        );

    }

}
```

Update

```jsx
this.setState({
    count: this.state.count + 1
});
```

---

## Lifecycle Methods

Common ones

```text
constructor()

componentDidMount()

componentDidUpdate()

componentWillUnmount()
```

Hooks replaced most lifecycle methods.

---

## Why Class Components Are Less Preferred

* More boilerplate
* `this` binding issues
* Harder to reuse logic
* Lifecycle methods are more complex
* Hooks provide a simpler alternative

---

# Functional vs Class Components

| Functional                  | Class                          |
| --------------------------- | ------------------------------ |
| JavaScript function         | ES6 class                      |
| Uses Hooks                  | Uses lifecycle methods         |
| Less code                   | More boilerplate               |
| No `this` keyword           | Uses `this`                    |
| Preferred in modern React   | Mostly legacy                  |
| Better for new applications | Maintained for older codebases |

# Part 2: Rendering

# What is Rendering?

Rendering means **React converts components into React elements and updates the UI in the browser.**

Rendering **does not always mean updating the Real DOM**.

Sometimes React renders, compares changes, and decides that no DOM update is needed.

---

# React Rendering Flow

```text
Component

↓

JSX

↓

React Elements

↓

Virtual DOM

↓

Diffing

↓

Reconciliation

↓

Real DOM Update

↓

Browser Paint
```

---

# 3. Initial Render

## What is Initial Render?

The first time React renders the application.

Example

```jsx
root.render(<App />);
```

Flow

```text
App Component

↓

JSX Created

↓

Virtual DOM Created

↓

Real DOM Created

↓

Browser Displays UI
```

---

## Example

```jsx
function App() {

    return <h1>Hello React</h1>;

}
```

Initial Render

```text
Virtual DOM

↓

Real DOM

↓

Display
```

---

# 4. Re-render

## What is Re-render?

A re-render occurs when React executes the component again to calculate what the UI should look like after a change.

React creates a **new Virtual DOM**, compares it with the previous one, and updates only the changed parts.

---

## What Causes Re-render?

### 1. State Change

```jsx
setCount(count + 1);
```

Most common.

---

### 2. Props Change

```jsx
<User
name={username}
/>
```

When `username` changes, `User` re-renders.

---

### 3. Parent Re-render

```text
App

↓

Header

↓

Button
```

If App re-renders, children usually re-render too unless optimized.

---

### 4. Context Change

```jsx
<ThemeProvider>
```

Consumers re-render when the context value changes.

---

### 5. Force Update (Rare)

```jsx
this.forceUpdate();
```

Mostly for class components.

---

# What Does NOT Cause Re-render?

Changing a normal variable

```jsx
let count = 0;

count++;
```

React doesn't track normal variables.

---

Changing `useRef`

```jsx
ref.current = 100;
```

Does not trigger a re-render.

---

# Rendering Example

```jsx
function Counter(){

    const [count,setCount]=
    useState(0);

    console.log("Rendered");

    return (
        <button
        onClick={() =>
        setCount(count+1)}
        >
        {count}
        </button>
    );

}
```

Every click

```text
Rendered
```

The component function executes again.

# 5. Reconciliation (Most Important)

## What is Reconciliation?

Reconciliation is React's process of comparing the **old Virtual DOM** with the **new Virtual DOM** and determining the minimum changes needed to update the Real DOM.

---

## Why Reconciliation?

Without reconciliation

```text
State Change

↓

Destroy Entire DOM

↓

Create Everything Again
```

Very slow.

With reconciliation

```text
State Change

↓

Compare Trees

↓

Update Only Changed Nodes
```

---

## Example

Old

```jsx
<h1>Hello</h1>
```

New

```jsx
<h1>Hello John</h1>
```

Only text changes.

React updates only:

```text
Hello

↓

Hello John
```

---

# Reconciliation Steps

```text
State Changes

↓

New Virtual DOM

↓

Compare Old vs New

↓

Find Difference

↓

Update Real DOM
```

---

# React Fiber

Modern reconciliation is implemented using the **React Fiber architecture**.

Fiber enables:

* Incremental rendering
* Prioritizing updates
* Interruptible rendering
* Concurrent features (React 18+)

You don't need to know Fiber internals, but you should know it powers modern reconciliation.

---

# 6. Diffing Algorithm

## What is Diffing?

Diffing is the algorithm React uses during reconciliation to compare two Virtual DOM trees.

Instead of comparing every node deeply (which would be expensive), React uses heuristics.

---

## Why?

Comparing two complete trees is an O(n³) problem.

React simplifies this to approximately O(n) using assumptions.

---

## Rule 1

Different element types

Old

```jsx
<div>
```

New

```jsx
<section>
```

React destroys the old subtree and creates a new one.

---

## Rule 2

Same element type

Old

```jsx
<h1>Hello</h1>
```

New

```jsx
<h1>Welcome</h1>
```

Only the text updates.

---

## Rule 3

Children

React compares children in order.

Example

Old

```jsx
<li>A</li>

<li>B</li>
```

New

```jsx
<li>A</li>

<li>C</li>
```

Only second item updates.

---

# Keys (Interview Favorite)

Without keys

```jsx
[
A,
B,
C
]
```

Insert at beginning

```jsx
[
X,
A,
B,
C
]
```

React thinks everything changed.

---

With keys

```jsx
<li key="1">A</li>

<li key="2">B</li>

<li key="3">C</li>
```

React knows exactly which item moved or was inserted.

---

## Why Keys Matter

Good keys:

```jsx
id
```

Bad keys

```jsx
index
```

If list order changes, index keys can cause:

* Incorrect DOM reuse
* Input value mix-ups
* Performance issues

Use stable, unique IDs whenever possible.

# Common Mistakes

### Thinking Re-render = DOM Update

Not always.

React may re-render, compare Virtual DOMs, and decide no Real DOM update is needed.

---

### Using index as key

Bad

```jsx
key={index}
```

Good

```jsx
key={user.id}
```

---

### Mutating State

```jsx
user.name = "Alex";
```

React may not detect the change correctly.

Create new objects instead.

---

### Assuming Child Components Never Re-render

By default, if a parent re-renders, its child components also re-render unless optimized with techniques like `React.memo`.

---

# Best Practices

* Prefer Functional Components with Hooks.
* Avoid unnecessary state.
* Keep components small and reusable.
* Use stable, unique keys for lists.
* Avoid mutating state directly.
* Use `React.memo`, `useMemo`, and `useCallback` where appropriate to reduce unnecessary re-renders (after measuring performance).

# Frequently Asked Interview Questions (6 Years React)

### 1. What is the difference between Functional and Class Components?

**Answer:**

| Functional                | Class                  |
| ------------------------- | ---------------------- |
| Uses Hooks                | Uses lifecycle methods |
| No `this`                 | Uses `this`            |
| Less boilerplate          | More boilerplate       |
| Preferred in modern React | Mainly for legacy code |

---

### 2. What causes a React component to re-render?

**Answer:**

* State updates
* Props changes
* Parent component re-renders
* Context value changes
* Force updates (rare)

---

### 3. Does every re-render update the Real DOM?

**Answer:** No. Every re-render creates a new Virtual DOM and performs diffing. React updates the Real DOM **only if differences are found**.

---

### 4. What is Reconciliation?

**Answer:** Reconciliation is React's process of comparing the previous and current Virtual DOM trees to determine the minimum number of changes needed for the Real DOM.

---

### 5. What is the Diffing Algorithm?

**Answer:** Diffing is the algorithm used during reconciliation to compare two Virtual DOM trees efficiently. React uses heuristics to reduce the comparison complexity from O(n³) to approximately O(n).

---

### 6. Why are `key` props important?

**Answer:** Keys uniquely identify list items so React can correctly match old and new elements during reconciliation. Stable keys improve performance and prevent issues such as incorrect DOM reuse or losing input state.

---

### 7. What happens if you use the array index as a key?

**Answer:** If items are inserted, removed, or reordered, React may incorrectly reuse DOM nodes, causing bugs such as incorrect input values or unnecessary re-renders. Use stable unique IDs whenever possible.

---

### 8. What is React Fiber?

**Answer:** React Fiber is the internal rendering engine introduced in React 16. It powers reconciliation and enables features such as interruptible rendering, update prioritization, and the concurrent rendering capabilities introduced in React 18.

---

## 6+ Years Interview Tips

* Clearly distinguish **Render**, **Re-render**, **Reconciliation**, and **Diffing**—they are related but not the same.
* Explain that **re-rendering a component does not necessarily mean updating the Real DOM**.
* Mention that **React Fiber** is the modern reconciliation engine.
* Be prepared to explain **why stable keys are important** and why using array indexes as keys can cause bugs.
* Emphasize that **Functional Components with Hooks** are the standard for modern React development.
