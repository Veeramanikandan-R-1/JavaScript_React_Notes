# Redux-Saga — Quick Revision Notes

## 1. What is Redux-Saga?

**Redux-Saga is a middleware used to handle side effects in Redux applications.**

Side effects include:

```text
API calls
Timers
WebSocket events
Async operations
Browser interactions
Complex workflows
```

Without Saga:

```text
Component
   ↓
dispatch(action)
   ↓
Reducer
```

With Saga:

```text
Component
   ↓
dispatch(action)
   ↓
Saga Middleware
   ↓
API / async operation
   ↓
dispatch(success/failure)
   ↓
Reducer
   ↓
UI
```

### Interview one-liner

> Redux-Saga is Redux middleware that uses generator functions to manage asynchronous operations and other side effects in a structured way.

---

# 2. Why Redux-Saga?

Suppose you have:

```text
Login
 ↓
API call
 ↓
Save token
 ↓
Fetch user
 ↓
Redirect
```

This workflow can become complicated if handled entirely inside components.

Saga lets you move this orchestration outside React components.

```text
React
 ↓
dispatch(loginRequest)
 ↓
Saga
 ↓
login API
 ↓
fetch user
 ↓
success/failure action
```

# 3. Basic Setup ⭐

You typically have:

```text
Redux Store
     ↓
Saga Middleware
     ↓
Root Saga
     ↓
Individual Sagas
```

Example:

```js
import { configureStore } from "@reduxjs/toolkit";
import createSagaMiddleware from "redux-saga";
import rootSaga from "./sagas";

const sagaMiddleware = createSagaMiddleware();

const store = configureStore({
  reducer: {
    // reducers
  },
  middleware: (getDefaultMiddleware) =>
    getDefaultMiddleware({
      thunk: false
    }).concat(sagaMiddleware)
});

sagaMiddleware.run(rootSaga);

export default store;
```

# 4. Root Saga

Root Saga combines multiple sagas.

```js
import { all, fork } from "redux-saga/effects";

import { watchUser } from "./userSaga";
import { watchProduct } from "./productSaga";

export default function* rootSaga() {
  yield all([
    fork(watchUser),
    fork(watchProduct)
  ]);
}
```

Think:

```text
Root Saga
   ├── User Saga
   ├── Product Saga
   └── Order Saga
```

# 5. Generator Functions ⭐⭐⭐

Saga heavily uses JavaScript generators.

Syntax:

```js
function* mySaga() {
  yield something();
}
```

The `*` means generator function.

Example:

```js
function* exampleSaga() {
  yield console.log("Hello");
}
```

You don't need to master generators for basic Saga interviews.

Remember:

> **Saga uses generators to pause/resume asynchronous workflows.**

# 6. `yield`

Saga uses `yield` to describe what should happen.

Example:

```js
function* fetchUsers() {
  const response = yield call(api.getUsers);

  yield put({
    type: "USERS_SUCCESS",
    payload: response
  });
}
```

Think:

```text
yield call()
    ↓
Pause saga
    ↓
Operation completes
    ↓
Resume saga
```

# 7. `call()` ⭐⭐⭐

`call()` is used to invoke a function, commonly an API function.

```js
const response = yield call(api.getUsers);
```

Instead of:

```js
api.getUsers();
```

Why?

Saga middleware controls the effect.

### Example

```js
function* fetchUsersSaga() {
  try {
    const users = yield call(fetchUsers);

    yield put({
      type: "USERS_SUCCESS",
      payload: users
    });
  } catch (error) {
    yield put({
      type: "USERS_FAILURE",
      payload: error.message
    });
  }
}
```

---

# 8. `put()` ⭐⭐⭐

`put()` dispatches a Redux action.

```js
yield put({
  type: "USERS_SUCCESS",
  payload: users
});
```

Equivalent conceptually to:

```js
dispatch({
  type: "USERS_SUCCESS",
  payload: users
});
```

So:

```text
call()
→ call function/API

put()
→ dispatch Redux action
```

# 9. `takeLatest()` ⭐⭐⭐

One of the most important Saga effects.

```js
yield takeLatest(
  "SEARCH_REQUEST",
  searchSaga
);
```

Meaning:

> If multiple actions arrive, cancel the previous running task and keep the latest one.

Perfect for search.

```text
User types:
iphone
iphone 1
iphone 14

SEARCH_REQUEST
     ↓
SEARCH_REQUEST
     ↓
SEARCH_REQUEST
```

`takeLatest` ensures the latest search is the one that matters.

### Typical use cases

```text
Search
Autocomplete
Filter
User profile refresh
```

---

# 10. `takeEvery()` ⭐⭐⭐

Runs a saga for **every action**.

```js
yield takeEvery(
  "SEND_ANALYTICS",
  analyticsSaga
);
```

If 5 actions arrive:

```text
Action 1 → Saga
Action 2 → Saga
Action 3 → Saga
Action 4 → Saga
Action 5 → Saga
```

Useful when every event needs to be processed.

### Examples

```text
Analytics
Logging
Independent API operations
```

---

# 11. `takeLatest` vs `takeEvery`

Very common interview question.

| `takeLatest`            | `takeEvery`                   |
| ----------------------- | ----------------------------- |
| Keeps latest            | Runs all                      |
| Previous task cancelled | Previous tasks continue       |
| Search                  | Analytics                     |
| Autocomplete            | Multiple independent requests |

### Easy memory trick

> **Search → takeLatest**

> **Every event matters → takeEvery**

# 12. `take()` ⭐⭐

Waits for a specific action.

```js
const action = yield take("LOGIN_SUCCESS");
```

Saga pauses until that action occurs.

Conceptually:

```text
Saga
 ↓
take(LOGIN_SUCCESS)
 ↓
WAIT
 ↓
LOGIN_SUCCESS dispatched
 ↓
Continue
```

Useful for complex workflows.

# 13. `fork()` ⭐⭐

Starts a saga task without blocking the current saga.

```js
yield fork(watchUsers);
yield fork(watchProducts);
```

Think:

```text
fork
→ Start task independently
```

Compare:

```js
yield call(task);
```

vs

```js
yield fork(task);
```

### `call`

Blocking.

```text
Start task
 ↓
Wait
 ↓
Continue
```

### `fork`

Non-blocking.

```text
Start task
 ↓
Continue immediately
```

# 14. `join()` ⭐⭐

Waits for a forked task to complete.

Think:

```text

 ↓

 ↓
do other work
 ↓
join
 ↓
```

# 17. `select()` ⭐⭐⭐

Gets data from the Redux store inside a Saga.

```js

  state => state.user

```

Conceptually:

```text
Saga
 ↓
select()
 ↓
Redux Store
 ↓
Current state
```

# 18. `all()` ⭐⭐

Runs multiple effects together.

```js
yield all([
  call(fetchUsers),
  call(fetchProducts)
]);
```

Conceptually:

```text
         all()
        /     \

        \     /
         ↓
      Continue
```

Useful when requests are independent and can run concurrently.

# 19. `race()` ⭐⭐

Runs multiple effects and takes the result of whichever finishes first.

```js
const { response, timeout } = yield race({
  response: call(fetchData),
  timeout: delay(5000)
});
```

Concept:

```text
             race
            /    \
       API call  5 sec
           ↓       ↓
        First one wins
```

Useful for:

* API timeout
* User interaction vs timeout
* Competing async operations

# 20. `cancelled()` ⭐⭐

Can check whether a Saga was cancelled.

```js
import { cancelled } from "redux-saga/effects";

function* worker() {
  try {
    yield call(api);
  } finally {
    if (yield cancelled()) {
      console.log("Saga cancelled");
    }
  }
}
```

Mostly useful for cleanup.

You don't need to go deep unless specifically asked.

# 25. Saga Debouncing ⭐⭐

Redux Saga has a `debounce` effect.

```js
import {
  debounce,
  call,
  put
} from "redux-saga/effects";

function* searchSaga(action) {
  const result = yield call(
    searchProducts,
    action.payload
  );

  yield put({
    type: "SEARCH_SUCCESS",
    payload: result
  });
}

function* watchSearch() {
  yield debounce(
    500,
    "SEARCH_REQUEST",
    searchSaga
  );
}
```

Meaning:

```text
User types
 ↓
wait 500ms
 ↓
If another action arrives → reset timer
 ↓
No action for 500ms
 ↓
API request
```

### `debounce` vs `takeLatest`

Don't confuse them.

**takeLatest**

> Starts tasks but keeps the latest task and cancels the previous running task.

**debounce**

> Waits until actions stop arriving for a specified period before starting the worker.

Concept:

```text
API

Wait 1 sec
 ↓
Retry
 ↓
Fail
 ↓
Wait
 ↓
Retry
```

Useful for temporary network failures.

# 29. Saga vs Redux Thunk ⭐⭐⭐

Very common interview question.

### Redux Thunk

Allows dispatching functions:

```js
const fetchUsers = () => async dispatch => {
  const users = await api.getUsers();

  dispatch({
    type: "USERS_SUCCESS",
    payload: users
  });
};
```

### Saga

Uses generator functions and effects:

```js
function* fetchUsersSaga() {
  const users = yield call(api.getUsers);

  yield put({
    type: "USERS_SUCCESS",
    payload: users
  });
}
```

### Simple comparison

| Thunk                   | Saga                                   |
| ----------------------- | -------------------------------------- |
| Simpler                 | More powerful                          |
| Functions               | Generator functions                    |
| Good for basic async    | Good for complex workflows             |
| Easier to learn         | Steeper learning curve                 |
| Less boilerplate        | More concepts                          |
| Common in Redux Toolkit | Used in complex legacy/enterprise apps |

### Interview answer

> "For simple API calls, Redux Thunk or Redux Toolkit's async patterns are usually sufficient. Saga becomes useful when the application has complex asynchronous workflows, cancellation, retries, debouncing, polling, or coordination between multiple effects."

# 🔥 Most Important Interview Questions

### What is Redux Saga?

> Middleware for managing side effects using generator functions.

### Why use Saga?

> To handle complex asynchronous workflows such as API orchestration, cancellation, retries, polling, debouncing and coordination between multiple async operations.

### What is `call()`?

> Executes a function/API as a Saga effect.

### What is `put()`?

> Dispatches a Redux action.

### What is `select()`?

> Reads data from Redux state.

### `takeLatest` vs `takeEvery`?

> `takeLatest` keeps the latest task and cancels the previous one; `takeEvery` runs a task for every action.

### `call` vs `fork`?

> `call` is blocking; `fork` starts a non-blocking task.

### `all` vs `race`?

> `all` waits for multiple effects; `race` resolves based on whichever effect wins first.

### Why generators?

> Generators allow Saga to pause and resume asynchronous workflows using `yield`.

### Saga vs Thunk?

> Thunk is simpler and sufficient for many basic async operations. Saga is more suitable for complex workflows involving cancellation, retries, polling, debouncing and coordination.

## Practical Example

Yes. In a **modern React application**, you can use **Redux Toolkit + Redux-Saga** together.

The important point is:

> **Redux Toolkit manages the Redux store/reducers/actions, while Redux-Saga handles complex asynchronous workflows.**

Here is a complete simple example.

### 1. Install

```bash
npm install @reduxjs/toolkit react-redux redux-saga
```

### 2. `userSlice.js`

Redux Toolkit creates the actions and reducer for us.

```js
import { createSlice } from "@reduxjs/toolkit";

const userSlice = createSlice({
  name: "users",

  initialState: {
    users: [],
    loading: false,
    error: null,
  },

  reducers: {
    fetchUsersRequest: (state) => {
      state.loading = true;
      state.error = null;
    },

    fetchUsersSuccess: (state, action) => {
      state.loading = false;
      state.users = action.payload;
    },

    fetchUsersFailure: (state, action) => {
      state.loading = false;
      state.error = action.payload;
    },
  },
});

export const {
  fetchUsersRequest,
  fetchUsersSuccess,
  fetchUsersFailure,
} = userSlice.actions;

export default userSlice.reducer;
```

---

### 3. `userSaga.js`

This is where the **generator function** is used.

```js
import { call, put, takeLatest } from "redux-saga/effects";

import {
  fetchUsersRequest,
  fetchUsersSuccess,
  fetchUsersFailure,
} from "./userSlice";

const fetchUsersApi = () =>
  fetch("https://jsonplaceholder.typicode.com/users")
    .then((response) => response.json());

function* fetchUsers() {
  try {
    const users = yield call(fetchUsersApi);

    yield put(fetchUsersSuccess(users));
  } catch (error) {
    yield put(fetchUsersFailure(error.message));
  }
}

export default function* userSaga() {
  yield takeLatest(fetchUsersRequest.type, fetchUsers);
}
```

Notice this:

```js
function* fetchUsers() {
```

That's the **generator function**.

And:

```js
const users = yield call(fetchUsersApi);
```

Saga pauses here until the API call completes.

Then:

```js
yield put(fetchUsersSuccess(users));
```

dispatches the Redux Toolkit action.

---

### 4. `rootSaga.js`

```js
import { all } from "redux-saga/effects";
import userSaga from "./userSaga";

export default function* rootSaga() {
  yield all([
    userSaga(),
  ]);
}
```

---

### 5. `store.js`

With Redux Toolkit, we use `configureStore`.

```js
import { configureStore } from "@reduxjs/toolkit";
import createSagaMiddleware from "redux-saga";

import userReducer from "./userSlice";
import rootSaga from "./rootSaga";

const sagaMiddleware = createSagaMiddleware();

const store = configureStore({
  reducer: {
    users: userReducer,
  },

  middleware: (getDefaultMiddleware) =>
    getDefaultMiddleware({
      thunk: false,
    }).concat(sagaMiddleware),
});

sagaMiddleware.run(rootSaga);

export default store;
```

---

### 6. `App.jsx`

```jsx
import { useDispatch, useSelector } from "react-redux";
import { fetchUsersRequest } from "./userSlice";

function App() {
  const dispatch = useDispatch();

  const { users, loading, error } = useSelector(
    (state) => state.users
  );

  const handleFetchUsers = () => {
    dispatch(fetchUsersRequest());
  };

  return (
    <div>
      <h1>Users</h1>

      <button onClick={handleFetchUsers}>
        Fetch Users
      </button>

      {loading && <p>Loading...</p>}

      {error && <p>Error: {error}</p>}

      <ul>
        {users.map((user) => (
          <li key={user.id}>
            {user.name} - {user.email}
          </li>
        ))}
      </ul>
    </div>
  );
}

export default App;
```

### 7. `main.jsx`

```jsx
import React from "react";
import ReactDOM from "react-dom/client";
import { Provider } from "react-redux";

import App from "./App";
import store from "./store";

ReactDOM.createRoot(document.getElementById("root")).render(
  <Provider store={store}>
    <App />
  </Provider>
);
```

## Understand the flow

When you click **Fetch Users**:

```text
Button
   ↓
dispatch(fetchUsersRequest())
   ↓
Redux Toolkit
   ↓
Saga sees FETCH_USERS_REQUEST
   ↓
fetchUsers() generator starts
   ↓
yield call(fetchUsersApi)
   ↓
API response
   ↓
yield put(fetchUsersSuccess(users))
   ↓
Redux Toolkit reducer
   ↓
state.users updated
   ↓
React UI updates
```

### The 3 most important Saga functions

| Saga           | Meaning                        |
| -------------- | ------------------------------ |
| `call()`       | Call an API/function           |
| `put()`        | Dispatch a Redux action        |
| `takeLatest()` | Handle only the latest request |

### Redux Toolkit vs Saga

```text
Redux Toolkit
├── configureStore()
├── createSlice()
├── reducers
└── actions

Redux-Saga
├── call()
├── put()
├── takeLatest()
└── generator functions
```

**Interview answer:**

> "Redux Toolkit simplifies Redux state management using slices and `configureStore`, while Redux-Saga uses generator functions and effects like `call`, `put`, and `takeLatest` to handle complex asynchronous operations."
