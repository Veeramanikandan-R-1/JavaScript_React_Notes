# React Fundamentals – React Performance

> **Interview Focus (6 Years):**
> Companies expect you to know **why components re-render**, **how to optimize them**, and **when NOT to optimize**. Performance optimization should be **measured**, not applied everywhere.

---

# 1. React.memo

## What is it?

`React.memo` is a **Higher Order Component (HOC)** that prevents a functional component from re-rendering if its **props haven't changed**.

```jsx
const Child = React.memo(({ name }) => {
  console.log("Child Rendered");
  return <h2>{name}</h2>;
});
```

Parent

```jsx
function App() {
  const [count, setCount] = useState(0);

  return (
    <>
      <button onClick={() => setCount(count + 1)}>Increment</button>
      <Child name="John" />
    </>
  );
}
```

Clicking the button:

* Parent re-renders ✅
* Child does NOT re-render ✅ (props unchanged)

---

## Internal Working

React performs a **shallow comparison** of previous and current props.

```text
Previous Props
↓

Shallow Compare

↓

Same?
   Yes → Skip render
   No  → Render
```

---

## When to use

* Expensive components
* Large lists
* Dashboard widgets
* Charts
* Tables

---

## Don't use when

* Component is very small
* Props change every render

---

# 2. useMemo

## What is it?

Caches (memoizes) the **result of an expensive calculation**.

Without

```jsx
const sortedUsers = users.sort(sortFn);
```

Runs on every render.

With

```jsx
const sortedUsers = useMemo(() => {
    return users.sort(sortFn);
}, [users]);
```

Runs only when `users` changes.

---

## Syntax

```jsx
const value = useMemo(() => {
    return expensiveFunction();
}, [dependencies]);
```

---

## Real Example

```jsx
const filteredUsers = useMemo(() => {
    return users.filter(user => user.active);
}, [users]);
```

---

## Don't use for

Simple calculations like

```jsx
const fullName = first + last;
```

The overhead isn't worth it.

---

# 3. useCallback

## What is it?

Memoizes a **function reference**.

Without

```jsx
const handleClick = () => {};
```

New function created every render.

With

```jsx
const handleClick = useCallback(() => {
    console.log("Clicked");
}, []);
```

Same function reference reused.

---

## Why?

Useful with `React.memo`.

Without

```jsx
<Child onClick={() => {}} />
```

Every render creates a new function.

Child re-renders.

Better

```jsx
const handleClick = useCallback(() => {}, []);

<Child onClick={handleClick} />
```

---

## useMemo vs useCallback

| useMemo        | useCallback       |
| -------------- | ----------------- |
| Memoizes value | Memoizes function |
| Returns value  | Returns function  |

---

# 4. Lazy Loading

## What is it?

Load a component **only when needed**.

Instead of downloading everything initially,

download when user visits that page.

---

Without Lazy Loading

```text
Login
Dashboard
Settings
Reports

↓

Downloaded together
```

---

With Lazy Loading

```text
Login

↓

Only Login downloaded

↓

User opens Dashboard

↓

Dashboard downloaded
```

---

## Syntax

```jsx
const Dashboard = React.lazy(() => import("./Dashboard"));
```

---

# 5. Suspense

Used with Lazy Loading.

Shows fallback UI until component loads.

```jsx
<Suspense fallback={<h2>Loading...</h2>}>
    <Dashboard />
</Suspense>
```

---

Complete Example

```jsx
const Dashboard = React.lazy(() => import("./Dashboard"));

function App() {
    return (
        <Suspense fallback={<Spinner />}>
            <Dashboard />
        </Suspense>
    );
}
```

---

# 6. Code Splitting

## What is it?

Breaking one large JavaScript bundle into **smaller bundles**.

Instead of

```text
bundle.js
20 MB
```

Split into

```text
Home.js
Dashboard.js
Reports.js
Settings.js
```

Browser downloads only what's needed.

---

## Benefits

* Faster initial load
* Better Lighthouse score
* Less network usage

---

## Common Ways

* React.lazy
* Dynamic import
* Route-based splitting
* Component-based splitting

---

# 7. Dynamic Import

ES Module feature.

Normal import

```jsx
import Dashboard from "./Dashboard";
```

Loaded immediately.

Dynamic

```jsx
const Dashboard = await import("./Dashboard");
```

Loaded only when needed.

React.lazy internally uses dynamic imports.

---

Example

```jsx
button.onclick = async () => {
    const module = await import("./utils");
};
```

---

# 8. Windowing

Large lists are expensive.

Example

```text
50,000 rows
```

Don't render all.

Render only visible rows.

```text
Visible

1
2
3
4
5
6
```

As user scrolls,

old rows removed,

new rows added.

---

Popular Library

```
react-window
```

---

# 9. Virtualization

Windowing and Virtualization are often used interchangeably.

Idea:

Only visible DOM nodes exist.

Instead of

```
100000 DOM elements
```

Render

```
20 DOM elements
```

Huge performance improvement.

---

## Real-world Example

* Gmail
* Facebook feed
* Chat applications
* Data tables

# 10. Memoization

## What is it?

Caching results to avoid repeating work.

Instead of

```text
calculate()

calculate()

calculate()
```

Do

```text
calculate()

↓

Cache

↓

Reuse
```

---

React provides memoization using

* React.memo
* useMemo
* useCallback

# 11. Stable References

## Problem

Objects and arrays create new references every render.

```jsx
const user = {
    name: "John"
};
```

Every render

```
New Object
```

React.memo thinks props changed.

Child re-renders.

---

Better

```jsx
const user = useMemo(() => ({
    name: "John"
}), []);
```

---

Functions

Bad

```jsx
const handleClick = () => {};
```

Good

```jsx
const handleClick = useCallback(() => {}, []);
```

---

Arrays

Bad

```jsx
const items = [1,2,3];
```

Good

```jsx
const items = useMemo(() => [1,2,3], []);
```

---

# 12. Prevent Unnecessary Renders

## Common Reasons

### Parent re-render

```
Parent

↓

Child
```

Child also re-renders.

Solution

```
React.memo
```

---

### New object props

Bad

```jsx
<Child user={{name:"John"}} />
```

Good

```jsx
const user = useMemo(() => ({
    name:"John"
}), []);

<Child user={user} />
```

---

### New callback

Bad

```jsx
<Child onClick={() => {}} />
```

Good

```jsx
const handleClick = useCallback(() => {}, []);

<Child onClick={handleClick} />
```

---

### Context Updates

Every consumer re-renders when the Provider value changes.

Solution

* Split contexts
* Memoize Provider value

---

### Large Lists

Use

* react-window
* Virtualization
* Pagination

---

### Expensive Computation

Use

```
useMemo
```

# Choosing the Right Optimization

| Problem                          | Solution                   |
| -------------------------------- | -------------------------- |
| Child re-renders with same props | React.memo                 |
| Expensive calculation            | useMemo                    |
| Function recreated every render  | useCallback                |
| Large initial bundle             | Code Splitting             |
| Component should load on demand  | React.lazy                 |
| Loading UI                       | Suspense                   |
| Import only when needed          | Dynamic Import             |
| Large list rendering             | Windowing / Virtualization |
| Repeated expensive work          | Memoization                |
| New object/function references   | Stable References          |

---

# Best Practices

✔ Measure performance before optimizing (React DevTools Profiler).

✔ Use `React.memo` only for components that benefit from it.

✔ Use `useMemo` for expensive calculations, not simple expressions.

✔ Use `useCallback` mainly when passing callbacks to memoized children.

✔ Split bundles using `React.lazy` and route-based code splitting.

✔ Virtualize long lists instead of rendering thousands of DOM nodes.

✔ Keep object, array, and function references stable when passing them as props.

✔ Avoid creating inline objects/functions inside JSX for memoized components.

# Common Interview Questions (6 Years)

### 1. What causes a React component to re-render?

* State updates
* Parent re-render
* Props change
* Context value change
* Force update

---

### 2. Explain `React.memo`.

It memoizes a functional component and skips rendering if its props are shallowly equal to the previous render.

---

### 3. Difference between `useMemo` and `useCallback`.

* `useMemo` caches a computed **value**.
* `useCallback` caches a **function** reference.

---

### 4. Can `React.memo` prevent all re-renders?

No. It only skips renders caused by unchanged props. State changes inside the component or context updates will still trigger re-renders.

---

### 5. What is the difference between Lazy Loading and Code Splitting?

* **Code Splitting** is the technique of splitting the JavaScript bundle into smaller chunks.
* **Lazy Loading** is loading those chunks only when they are actually needed.

---

### 6. Why is `Suspense` required with `React.lazy`?

`React.lazy` loads components asynchronously. `Suspense` provides a fallback UI (like a spinner) while the component is being downloaded.

---

### 7. What are stable references, and why are they important?

Objects, arrays, and functions get a new reference on every render. Stable references (`useMemo`/`useCallback`) prevent unnecessary re-renders in memoized child components.

---

### 8. How would you optimize a page rendering 50,000 rows?

* Use virtualization/windowing (`react-window` or `react-virtualized`).
* Add pagination or infinite scrolling if appropriate.
* Memoize row components when beneficial.

---

### 9. How do you identify performance bottlenecks?

Use **React DevTools Profiler**, browser Performance tools, and measure before applying optimizations.

---

### 10. What's a common mistake with `useMemo` and `useCallback`?

Using them everywhere. They also have a cost, so use them only when they reduce more work than they introduce.
