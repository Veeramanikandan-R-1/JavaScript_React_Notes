# React JS — Performance

### Goal

React performance optimization mainly means:

1. **Avoid unnecessary renders**
2. **Avoid expensive calculations**
3. **Reduce initial JavaScript**
4. **Reduce DOM nodes for large lists**

---

# 1. `React.memo`

`React.memo` prevents a functional component from re-rendering when its **props haven't changed**.

```jsx
const User = React.memo(function User({ name }) {
  console.log("User rendered");

  return <div>{name}</div>;
});
```

```jsx
<User name="John" />
```

React performs a **shallow comparison** of props.

### Important

```jsx
<User data={{ name: "John" }} />
```

This can still re-render because a **new object reference** is created.

### When useful?

* Expensive child components
* Components that receive the same props frequently
* Large component trees

### Don't use everywhere

`React.memo` itself has comparison overhead. **Measure before optimizing.**

---

# 2. `useMemo`

`useMemo` memoizes an **expensive calculated value**.

```jsx
const filteredUsers = useMemo(() => {
  return users.filter(user => user.active);
}, [users]);
```

The calculation runs again only when dependencies change.

### Use for

* Expensive calculations
* Maintaining stable object/array references when necessary

### Don't use for

Simple calculations:

```jsx
const fullName = firstName + lastName;
```

No need for `useMemo`.

---

# 3. `useCallback`

`useCallback` memoizes a **function reference**.

```jsx
const handleDelete = useCallback((id) => {
  deleteUser(id);
}, []);
```

Useful when passing callbacks to memoized children:

```jsx
const UserList = React.memo(({ onDelete }) => {
  // ...
});
```

```jsx
<UserList onDelete={handleDelete} />
```

### Key difference ⭐

```text
useMemo     → memoizes a VALUE
useCallback → memoizes a FUNCTION
React.memo  → memoizes a COMPONENT'S rendering
```

---

# 4. Lazy Loading

Load a component **only when it is required**.

```jsx
const Reports = lazy(() => import("./Reports"));
```

Instead of loading `Reports` during the initial application load, its code can be loaded when React needs it.

### Good candidates

* Routes/pages
* Large modals
* Admin modules
* Rarely used features

---

# 5. Suspense

`Suspense` provides a **fallback UI while lazy content is loading**.

```jsx
<Suspense fallback={<Spinner />}>
  <Reports />
</Suspense>
```

Flow:

```text
Reports required
      ↓
JS chunk loading
      ↓
Suspense fallback
      ↓
Chunk loaded
      ↓
Reports rendered
```

### Important ⭐

`Suspense` **doesn't perform code splitting**.

It handles the UI while something is suspended/loading.

---

# 6. Code Splitting

Code splitting breaks a large JavaScript bundle into **smaller chunks**.

### Without

```text
main.js
 ├── Home
 ├── Dashboard
 ├── Reports
 └── Admin
```

### With

```text
main.js
dashboard.chunk.js
reports.chunk.js
admin.chunk.js
```

Only necessary chunks need to be loaded.

### Benefit

🚀 **Smaller initial bundle → faster initial loading**

---

# 7. Dynamic Import

JavaScript provides:

```jsx
import("./Reports")
```

instead of:

```jsx
import Reports from "./Reports";
```

Dynamic imports return a **Promise**.

```jsx
const loadReports = async () => {
  const module = await import("./Reports");
};
```

With React:

```jsx
const Reports = lazy(() => import("./Reports"));
```

### Relationship ⭐

```text
Dynamic import
      ↓
Code splitting
      ↓
Lazy loading
      ↓
Suspense handles loading UI
```

# 8. Windowing

**Windowing** means rendering only the portion of a large list that is currently visible.

Example:

```text
10,000 records
       ↓
Only visible ~30 records
       ↓
Render those 30
```

Instead of creating 10,000 DOM nodes.

---

# 9. Virtualization

**Virtualization** is the technique of maintaining a small set of DOM elements while scrolling through a large dataset.

Example:

```text
10,000 items
      ↓
┌─────────────────┐
│ Item 101        │
│ Item 102        │
│ Item 103        │
│ ...             │
│ Item 120        │
└─────────────────┘
```

As you scroll:

```text
Old visible items → removed/reused
New visible items → rendered
```

### Windowing vs Virtualization

These terms are often used interchangeably in React.

> **Windowing/virtualization = render only the visible portion of a large collection.**

Libraries such as `react-window` and `react-virtualized` implement this pattern.

### Use for

* Large tables
* 1,000+ item lists
* Chat history
* Logs
* Large search results

---

# 10. Memoization

**Memoization** = cache a previous computation/result and reuse it when the input hasn't changed.

Example:

```jsx
const result = useMemo(() => {
  return expensiveCalculation(data);
}, [data]);
```

Conceptually:

```text
Input A → calculate → Result A
Input A → cache hit → Result A
Input B → calculate → Result B
```

### Important

Memoization is an **optimization, not a default requirement**.

It has its own memory/comparison overhead.

---

# 11. Stable References

Objects, arrays and functions are reference types.

```jsx
{} === {} // false
```

This means:

```jsx
function App() {
  const options = { theme: "dark" };

  return <Child options={options} />;
}
```

`options` gets a **new reference on every render**.

This can cause unnecessary work for memoized children or effects.

### Stable reference

```jsx
const options = useMemo(() => ({
  theme: "dark"
}), []);
```

For functions:

```jsx
const handleClick = useCallback(() => {
  // ...
}, []);
```

### Other good approach

Move constants outside the component:

```jsx
const OPTIONS = {
  theme: "dark"
};

function App() {
  return <Child options={OPTIONS} />;
}
```

# 12. Prevent Unnecessary Renders

### 1. Keep state close to where it is needed

❌ Putting frequently changing state at the top-level can cause many descendants to render.

Prefer:

```text
App
 ├── Header
 ├── Search ← search state
 └── ProductList
```

instead of unnecessarily keeping search state in `App`.

---

### 2. Avoid unnecessary state

Don't store values that can be calculated:

❌

```jsx
const [fullName, setFullName] = useState("");

useEffect(() => {
  setFullName(firstName + lastName);
}, [firstName, lastName]);
```

Prefer:

```jsx
const fullName = firstName + lastName;
```

---

### 3. Avoid unstable props

❌

```jsx
<Child config={{ theme: "dark" }} />
```

❌

```jsx
<Child onClick={() => handleClick()} />
```

These create new references on each render.

Use stable references **when it actually matters**, especially with memoized children.

---

### 4. Split Contexts

Avoid putting everything into one frequently-changing Context:

```text
AppContext
 ├── auth
 ├── theme
 ├── cart
 ├── notifications
 └── search
```

Prefer separate contexts when appropriate:

```text
AuthContext
ThemeContext
CartContext
```

A context update can cause its consumers to re-render.

---

### 5. Use list keys correctly

```jsx
users.map(user => (
  <User key={user.id} user={user} />
))
```

Stable keys help React correctly reconcile list items.

---

# Performance Optimization Strategy ⭐

Think in **4 layers**:

```text
                    React Performance
                           │
        ┌──────────────────┼──────────────────┐
        ↓                  ↓                  ↓
   Render work        Bundle size         DOM size
        │                  │                  │
 React.memo          Code splitting      Virtualization
 useMemo             Lazy loading        Windowing
 useCallback          Dynamic import
 Stable references    Suspense
        │
 Avoid unnecessary
 renders
```

# Interview Quick Revision ⭐

| Concept           | Main Purpose                                   |
| ----------------- | ---------------------------------------------- |
| `React.memo`      | Skip component render when props are unchanged |
| `useMemo`         | Cache calculated value                         |
| `useCallback`     | Cache function reference                       |
| Lazy Loading      | Load code only when required                   |
| Suspense          | Show fallback while suspended content loads    |
| Code Splitting    | Divide bundle into smaller chunks              |
| Dynamic Import    | Load module asynchronously                     |
| Windowing         | Render visible portion of large list           |
| Virtualization    | Minimize DOM nodes for large collections       |
| Memoization       | Cache previous computation                     |
| Stable References | Keep object/function identity stable           |
| Prevent renders   | Reduce unnecessary React work                  |

### ⭐ Most important interview distinction

> **`React.memo` → component rendering optimization**
> **`useMemo` → value optimization**
> **`useCallback` → function-reference optimization**
> **Code splitting → bundle optimization**
> **Lazy loading → load code when needed**
> **Suspense → fallback while suspended content is unavailable**
> **Virtualization/windowing → DOM optimization for large lists**
