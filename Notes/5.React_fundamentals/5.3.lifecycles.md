# React Fundamentals – Lifecycle

React component lifecycle describes **the different stages a component goes through from creation until removal from the DOM.**

Think of it like a person's life:

* **Born → Mount**
* **Grow → Update**
* **Die → Unmount**

Understanding lifecycle is important because many interview questions revolve around **when API calls happen, when cleanup should occur, and how React re-renders components.**

---

# 1. Mount Phase

## What is Mounting?

Mounting means:

> **A component is created for the first time and inserted into the DOM.**

This happens only once during the component's lifetime.

Example:

```jsx
<App />
```

When `<App />` renders for the first time, it mounts.

---

## Functional Component

```jsx
function User() {
  console.log("Rendered");

  return <h1>User</h1>;
}
```

The component is mounted once.

If we need to perform side effects after mounting:

```jsx
useEffect(() => {
    console.log("Mounted");
}, []);
```

Output

```
Rendered
Mounted
```

The empty dependency array (`[]`) means:

> Run only after the first render.

---

## Class Component Lifecycle

During mounting, React calls these methods:

```
constructor()
↓

render()
↓

componentDidMount()
```

Example

```jsx
class User extends React.Component {

  constructor() {
    super();
    console.log("Constructor");
  }

  componentDidMount() {
    console.log("Mounted");
  }

  render() {
    console.log("Render");
    return <h1>User</h1>;
  }
}
```

Output

```
Constructor
Render
Mounted
```

---

## What should happen during Mount?

Usually we perform:

* API calls
* Initial state setup
* Subscribe to events
* Start timers
* Initialize third-party libraries

Example

```jsx
useEffect(() => {
    fetchUsers();
}, []);
```

---

# 2. Update Phase

## What is Updating?

Updating happens whenever the component needs to render again.

Common reasons:

* State changes
* Props change
* Parent component re-renders
* Context value changes
* Force update (class components)

---

Example

```jsx
const [count, setCount] = useState(0);

<button onClick={() => setCount(count + 1)}>
```

Every click causes:

```
Update
↓

Render again
```

---

## Functional Component

```jsx
useEffect(() => {
    console.log("Count changed");
}, [count]);
```

Runs whenever:

```
count changes
```

---

Another example

```jsx
useEffect(() => {
    console.log("User changed");
}, [user]);
```

Runs only when `user` changes.

---

## Class Component

During update:

```
render()

↓

componentDidUpdate()
```

Example

```jsx
componentDidUpdate(prevProps, prevState) {

    if(prevState.count !== this.state.count){
        console.log("Count Updated");
    }

}
```

Always compare previous values before calling `setState()` inside `componentDidUpdate()`, otherwise it can create an infinite update loop.

---

## What triggers Update?

### State

```jsx
setCount(count + 1);
```

---

### Props

```jsx
<User age={25} />
```

Later

```jsx
<User age={26} />
```

Component updates because props changed.

---

### Parent Re-render

```jsx
<Parent>
   <Child />
</Parent>
```

If Parent re-renders,

Child also re-renders by default.

To avoid unnecessary renders:

```
React.memo()
```

---

### Context Change

```jsx
const theme = useContext(ThemeContext);
```

Whenever ThemeContext changes,

the component updates.

---

# 3. Unmount Phase

## What is Unmounting?

Unmount means:

> Component is removed from the DOM.

Example

```jsx
{
   show && <User />
}
```

Initially

```
show = true
```

Later

```
show = false
```

React removes:

```
<User />
```

from DOM.

---

## Functional Component

Cleanup function

```jsx
useEffect(() => {

    console.log("Mounted");

    return () => {
        console.log("Unmounted");
    };

}, []);
```

Output

```
Mounted

(Unmount)

Unmounted
```

The returned function is called:

* Before component unmounts
* Before the effect runs again when dependencies change

---

## Class Component

```jsx
componentWillUnmount(){

    console.log("Cleanup");

}
```

---

## What should happen during Unmount?

Usually:

* Remove event listeners
* Clear timers
* Abort API requests
* Close WebSocket connections
* Cancel subscriptions
* Dispose third-party libraries

Example

```jsx
useEffect(() => {

    const timer = setInterval(() => {

    },1000);

    return () => {
        clearInterval(timer);
    }

}, []);
```

Without cleanup:

Memory leak.

# Important Notes About useEffect

## Mount only

```jsx
useEffect(() => {

}, []);
```

Runs once.

---

## Every render

```jsx
useEffect(() => {

});
```

Runs after every render.

---

## Dependency changes

```jsx
useEffect(() => {

}, [count]);
```

Runs whenever `count` changes.

---

## Cleanup

```jsx
useEffect(() => {

   return () => {

   }

}, []);
```

Runs on unmount.

# React 18 Strict Mode Behavior (Very Important)

During development, React Strict Mode intentionally mounts, unmounts, and mounts components again to help detect side effects.

Example:

```jsx
useEffect(() => {
  console.log("Mounted");

  return () => {
    console.log("Cleanup");
  };
}, []);
```

In development with `<React.StrictMode>` you may see:

```
Mounted
Cleanup
Mounted
```

This is expected **only in development**. In production, it runs once.

# Real-world Example

Fetching users

```jsx
useEffect(() => {
    const controller = new AbortController();

    fetch("/users", { signal: controller.signal });

    return () => {
        controller.abort();
    };
}, []);
```

Why?

If the component unmounts before the API completes:

* Prevents unnecessary state updates
* Cancels the request
* Avoids memory leaks and wasted network usage

---

# Common Mistakes

### Forgetting cleanup

```jsx
setInterval(() => {},1000);
```

Never cleared.

Memory leak.

---

### Missing dependency

```jsx
useEffect(() => {
   fetchUser(id);
}, []);
```

If `id` changes, the effect won't rerun because it's missing from the dependency array.

Correct:

```jsx
useEffect(() => {
   fetchUser(id);
}, [id]);
```

---

### Infinite loop

```jsx
useEffect(() => {
    setCount(count + 1);
}, [count]);
```

Every update changes `count`, causing the effect to run again indefinitely.

---

### Calling `setState()` in `componentDidUpdate()` without checking previous values

```jsx
componentDidUpdate() {
  this.setState({ count: this.state.count + 1 });
}
```

This causes an infinite render loop. Always compare `prevProps` or `prevState` first.

---

# Best Practices

* Perform API calls inside `useEffect`, not during rendering.
* Always clean up timers, event listeners, subscriptions, and sockets.
* Keep dependency arrays accurate; don't suppress lint warnings without understanding them.
* Use `AbortController` for canceling fetch requests when appropriate.
* Use `React.memo`, `useMemo`, and `useCallback` to reduce unnecessary updates where beneficial.
* Prefer functional components and Hooks for new development.

# Common React Interview Questions (6 Years Experience)

### 1. What are the lifecycle phases of a React component?

**Answer:** Mount, Update, and Unmount.

---

### 2. How do functional components replace lifecycle methods?

**Answer:** Using Hooks:

* `componentDidMount` → `useEffect(() => {}, [])`
* `componentDidUpdate` → `useEffect(() => {}, [dependencies])`
* `componentWillUnmount` → Cleanup function returned from `useEffect`.

---

### 3. What triggers a component re-render?

**Answer:** State updates, prop changes, parent re-renders, context updates, and `forceUpdate()` in class components.

---

### 4. Why is cleanup important in `useEffect`?

**Answer:** It prevents memory leaks by removing timers, event listeners, subscriptions, aborting requests, and closing connections.

---

### 5. Why does `useEffect` run twice in development?

**Answer:** React 18 Strict Mode intentionally mounts, cleans up, and remounts components in development to detect unsafe side effects. This does not happen in production.

---

### 6. What is the difference between rendering and mounting?

**Answer:** Mounting is the first time a component is added to the DOM. Rendering is the process of generating the UI and can happen multiple times during updates.

---

### 7. When should you make API calls in React?

**Answer:** In `componentDidMount()` for class components or `useEffect(() => {}, [])` for functional components.

---

### 8. What happens if you omit the dependency array in `useEffect`?

**Answer:** The effect runs after every render.

---

### 9. Why should you compare `prevProps` or `prevState` in `componentDidUpdate()`?

**Answer:** To avoid unnecessary updates and infinite render loops when calling `setState()`.

---

### 10. What is the difference between `useEffect` and the component lifecycle?

**Answer:** `useEffect` is a Hook that can model mount, update, and unmount behaviors depending on its dependency array and cleanup function, replacing multiple class lifecycle methods.

---

# Complete React Class Component Lifecycle

```
Mount Phase

constructor()
        ↓
static getDerivedStateFromProps()
        ↓
render()
        ↓
componentDidMount()

--------------------------------------

Update Phase

static getDerivedStateFromProps()
        ↓
shouldComponentUpdate()
        ↓
render()
        ↓
getSnapshotBeforeUpdate()
        ↓
componentDidUpdate()

--------------------------------------

Unmount Phase

componentWillUnmount()

--------------------------------------

Error Handling

static getDerivedStateFromError()
componentDidCatch()
```

---

# 1. constructor()

### Purpose

Initialize state and bind methods.

### Runs

* Only once during mounting
* Before render

### Example

```jsx
constructor(props) {
  super(props);

  this.state = {
    count: 0
  };
}
```

### Use for

* Initial state
* Method binding (`this.handleClick = this.handleClick.bind(this)`)

Avoid API calls here.

---

# 2. static getDerivedStateFromProps()

### Purpose

Synchronize state with incoming props.

### Runs

* Before every render
* During both Mount and Update

### Signature

```jsx
static getDerivedStateFromProps(props, state) {
    return null;
}
```

### Returns

* New state object
* or `null`

### Example

```jsx
static getDerivedStateFromProps(props, state) {

    if(props.value !== state.value){
        return {
            value: props.value
        };
    }

    return null;
}
```

### Interview Note

Rarely used. Most logic can be handled using props directly or Hooks.

---

# 3. render()

### Purpose

Returns JSX to display UI.

### Runs

* Mount
* Every Update

### Example

```jsx
render() {
    return <h1>Hello</h1>;
}
```

### Important

* Must be pure.
* Don't call `setState()`.
* Don't make API calls.

---

# 4. componentDidMount()

### Purpose

Runs after the component is added to the DOM.

### Runs

Only once after first render.

### Example

```jsx
componentDidMount() {
    fetchUsers();
}
```

### Common Uses

* API calls
* Timers
* Event listeners
* Third-party library initialization

---

# 5. shouldComponentUpdate()

### Purpose

Decides whether React should re-render the component.

### Runs

Before every update.

### Returns

* `true` → Continue rendering
* `false` → Skip rendering

### Example

```jsx
shouldComponentUpdate(nextProps, nextState) {
    return nextState.count !== this.state.count;
}
```

### Why?

Performance optimization.

Equivalent in functional components:

* `React.memo`
* `useMemo`
* `useCallback`

---

# 6. getSnapshotBeforeUpdate()

### Purpose

Capture DOM information before React updates it.

### Runs

After `render()`, but before the DOM is updated.

### Example

```jsx
getSnapshotBeforeUpdate(prevProps, prevState) {
    return window.scrollY;
}
```

The returned value is passed to `componentDidUpdate()`.

### Common Uses

* Preserve scroll position
* Measure DOM before update

Rarely used.

---

# 7. componentDidUpdate()

### Purpose

Runs after the DOM has been updated.

### Runs

After every update.

### Example

```jsx
componentDidUpdate(prevProps, prevState) {

    if(prevState.count !== this.state.count){
        console.log("Updated");
    }

}
```

### Common Uses

* API calls based on prop/state changes
* DOM updates
* Analytics

Always compare previous values before calling `setState()`.

---

# 8. componentWillUnmount()

### Purpose

Cleanup before removing the component.

### Runs

Only once.

### Example

```jsx
componentWillUnmount() {
    clearInterval(this.timer);
}
```

### Common Uses

* Remove event listeners
* Clear timers
* Close WebSocket
* Cancel subscriptions

---

# 9. static getDerivedStateFromError()

### Purpose

Update UI when a child component throws an error.

### Runs

When an error occurs.

### Example

```jsx
static getDerivedStateFromError(error) {
    return {
        hasError: true
    };
}
```

Usually used in an **Error Boundary**.

---

# 10. componentDidCatch()

### Purpose

Log or report errors.

### Example

```jsx
componentDidCatch(error, info) {
    logError(error);
}
```

Used for:

* Sentry
* Datadog
* Crash reporting

---

# Interview Cheat Sheet

| Method                       | Phase          | Purpose                        |
| ---------------------------- | -------------- | ------------------------------ |
| `constructor()`              | Mount          | Initialize state, bind methods |
| `getDerivedStateFromProps()` | Mount & Update | Sync state from props (rare)   |
| `render()`                   | Mount & Update | Return JSX                     |
| `componentDidMount()`        | Mount          | API calls, subscriptions       |
| `shouldComponentUpdate()`    | Update         | Decide whether to re-render    |
| `getSnapshotBeforeUpdate()`  | Update         | Capture DOM info before update |
| `componentDidUpdate()`       | Update         | Perform work after update      |
| `componentWillUnmount()`     | Unmount        | Cleanup resources              |
| `getDerivedStateFromError()` | Error          | Update UI on error             |
| `componentDidCatch()`        | Error          | Log/report errors              |

## Interview Tip (6 Years Experience)

While class lifecycle methods are still asked, interviewers usually expect you to **map them to Hooks**:

| Class Lifecycle              | Functional Component                                                                                 |
| ---------------------------- | ---------------------------------------------------------------------------------------------------- |
| `constructor()`              | `useState` initialization                                                                            |
| `componentDidMount()`        | `useEffect(() => {}, [])`                                                                            |
| `componentDidUpdate()`       | `useEffect(() => {}, [deps])`                                                                        |
| `componentWillUnmount()`     | Cleanup function in `useEffect`                                                                      |
| `shouldComponentUpdate()`    | `React.memo`, `useMemo`, `useCallback`                                                               |
| `getDerivedStateFromProps()` | Usually derive values directly from props or use `useEffect` only if syncing state is truly required |
| `getSnapshotBeforeUpdate()`  | `useLayoutEffect` (closest equivalent for DOM measurements)                                          |

> **Note:** Methods like `UNSAFE_componentWillMount`, `UNSAFE_componentWillReceiveProps`, and `UNSAFE_componentWillUpdate` are deprecated and should generally only be mentioned if asked about legacy React codebases.
