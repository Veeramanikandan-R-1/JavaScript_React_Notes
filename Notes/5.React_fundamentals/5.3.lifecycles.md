# React Lifecycle

A component's lifecycle describes what happens from **creation → updates → removal**.

```text
Mount → Update → Unmount
```

For modern React, think in terms of **functional components + Hooks**. Class lifecycle methods are important mainly for legacy code and interviews.

---

# 1. Mounting

**Mounting = component is created and added to the DOM for the first time.**

Example:

```jsx
function User() {
  return <h1>User</h1>;
}
```

When `<User />` first appears, it mounts.

---

## Functional Component — Mount

There are no explicit `componentDidMount` methods.

Use:

```jsx
useEffect(() => {
  console.log("Mounted");
}, []);
```

### Common use cases

* API calls
* Event listeners
* Subscriptions
* Timers
* Initial side effects

Example:

```jsx
function User() {
  useEffect(() => {
    console.log("Component mounted");

    fetch("/api/user")
      .then(res => res.json())
      .then(data => console.log(data));

    return () => {
      console.log("Cleanup");
    };
  }, []);

  return <h1>User</h1>;
}
```

`[]` means the Effect does not re-run because of prop/state dependencies after the initial setup.

> **Important:** In development Strict Mode, React may run an Effect's setup and cleanup an extra time to help detect bugs. Don't use this as proof that production runs the effect twice.

---

# 2. Updating

**Update = component renders again because its inputs changed.**

Common causes:

```text
State changes
Props change
Context changes
Parent re-renders
```

Example:

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      {count}
    </button>
  );
}
```

Calling `setCount()` causes an update.

---

## Functional Component — Update

Use `useEffect` with dependencies when you need a side effect related to a value.

```jsx
useEffect(() => {
  console.log("Count changed");
}, [count]);
```

This runs after a commit when `count` changes.

### Example

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    console.log("Count updated:", count);
  }, [count]);

  return (
    <button onClick={() => setCount(c => c + 1)}>
      {count}
    </button>
  );
}
```

### Important

The component function itself runs during rendering:

```jsx
function Counter() {
  console.log("Render");

  // ...
}
```

Don't treat `useEffect` as "the update lifecycle." Effects are for **synchronizing with external systems after commit**.

---

# 3. Unmounting

**Unmounting = component is removed from the DOM.**

Example:

```jsx
{showUser && <User />}
```

When:

```jsx
setShowUser(false);
```

`User` unmounts.

---

## Functional Component — Unmount

Use the cleanup function returned from `useEffect`.

```jsx
useEffect(() => {
  const timer = setInterval(() => {
    console.log("Running");
  }, 1000);

  return () => {
    clearInterval(timer);
  };
}, []);
```

Cleanup happens when the component unmounts.

Also, if dependencies change, React runs the previous cleanup before running the new Effect setup.

```text
Effect setup
     ↓
Dependency changes
     ↓
Cleanup previous Effect
     ↓
Run new Effect
```

---

# Class Components

Class components have explicit lifecycle methods grouped into **three main phases**.

```text
Mounting
Updating
Unmounting
```

---

# 4. Class — Mounting Cycle

### 4.1 `constructor()`

Called when the component instance is created.

```jsx
class User extends React.Component {
  constructor(props) {
    super(props);

    this.state = {
      name: "John"
    };
  }

  render() {
    return <h1>{this.state.name}</h1>;
  }
}
```

Used for:

* Initial state
* Binding methods
* Initialization

```jsx
this.handleClick = this.handleClick.bind(this);
```

---

### 4.2 `static getDerivedStateFromProps()`

Called before rendering when React is updating the component.

```jsx
static getDerivedStateFromProps(props, state) {
  return {
    // updated state
  };
}
```

Used to derive state from props in specific cases.

**Usually avoid it** because derived state often indicates unnecessary complexity.

---

### 4.3 `render()`

Required method that returns JSX.

```jsx
render() {
  return <h1>Hello</h1>;
}
```

**Important:**

`render()` should be pure.

Avoid:

```jsx
render() {
  // ❌ API call
  // ❌ setState()
  // ❌ side effects

  return <h1>Hello</h1>;
}
```

---

### 4.4 `componentDidMount()`

Called after the component is mounted.

```jsx
componentDidMount() {
  console.log("Mounted");

  fetch("/api/users");
}
```

Common use cases:

* API calls
* DOM operations
* Event subscriptions
* Timers

### Mount order

```text
constructor()
      ↓
getDerivedStateFromProps()
      ↓
render()
      ↓
DOM commit
      ↓
componentDidMount()
```

---

# 5. Class — Updating Cycle

An update can happen because of:

```text
New props
State update
Context changes
```

### 5.1 `static getDerivedStateFromProps()`

Runs before `render()` during updates too.

```jsx
static getDerivedStateFromProps(props, state) {
  return null;
}
```

---

### 5.2 `shouldComponentUpdate()`

Controls whether the component should re-render.

```jsx
shouldComponentUpdate(nextProps, nextState) {
  return nextProps.id !== this.props.id;
}
```

* `true` → continue rendering
* `false` → skip rendering/update lifecycle

Used for performance optimization.

> `React.PureComponent` provides shallow prop/state comparison automatically.

---

### 5.3 `render()`

Calculates the next UI.

```jsx
render() {
  return <h1>{this.props.name}</h1>;
}
```

---

### 5.4 `getSnapshotBeforeUpdate()`

Called **right before React commits DOM changes**.

Useful when you need information from the DOM before it changes.

Example: preserving scroll position.

```jsx
getSnapshotBeforeUpdate(prevProps, prevState) {
  return this.listRef.current.scrollHeight;
}
```

Its return value is passed to `componentDidUpdate`.

---

### 5.5 `componentDidUpdate()`

Called after the update has been committed.

```jsx
componentDidUpdate(prevProps, prevState) {
  if (prevProps.id !== this.props.id) {
    fetch(`/api/users/${this.props.id}`);
  }
}
```

**Always be careful with `setState()` here**, otherwise you can create an infinite update loop.

### Update order

```text
getDerivedStateFromProps()
          ↓
shouldComponentUpdate()
          ↓
render()
          ↓
getSnapshotBeforeUpdate()
          ↓
DOM commit
          ↓
componentDidUpdate()
```

If `shouldComponentUpdate()` returns `false`, the later update lifecycle doesn't proceed normally for that component.

---

# 6. Class — Unmounting Cycle

### `componentWillUnmount()`

Called immediately before the component is removed.

```jsx
componentWillUnmount() {
  clearInterval(this.timer);

  window.removeEventListener(
    "resize",
    this.handleResize
  );
}
```

Used for cleanup:

* Timers
* Event listeners
* Subscriptions
* WebSocket connections
* Other external resources

### Unmount order

```text
componentWillUnmount()
        ↓
DOM removed
```

---

# Functional vs Class Lifecycle Mapping

| Lifecycle need     | Functional                        | Class                      |
| ------------------ | --------------------------------- | -------------------------- |
| Initialization     | `useState`, normal initialization | `constructor`              |
| Mount side effect  | `useEffect(..., [])`              | `componentDidMount`        |
| Update side effect | `useEffect(..., [deps])`          | `componentDidUpdate`       |
| Cleanup            | `useEffect` return function       | `componentWillUnmount`     |
| Skip update        | `React.memo`                      | `shouldComponentUpdate`    |
| Before DOM update  | No direct equivalent              | `getSnapshotBeforeUpdate`  |
| Derive state       | Usually avoid                     | `getDerivedStateFromProps` |

**Don't memorize this as a strict 1:1 mapping.** Functional Effects are a different programming model from class lifecycle methods.

---

# Complete Lifecycle Comparison

### Functional

```jsx
function Component({ userId }) {
  const [user, setUser] = useState(null);

  // Render
  console.log("Render");

  // Mount + userId changes + cleanup
  useEffect(() => {
    let ignore = false;

    fetch(`/api/users/${userId}`)
      .then(res => res.json())
      .then(data => {
        if (!ignore) setUser(data);
      });

    return () => {
      ignore = true;
    };
  }, [userId]);

  return <h1>{user?.name}</h1>;
}
```

Conceptually:

```text
Render
  ↓
Commit
  ↓
Effect setup
  ↓
Dependency changes
  ↓
Cleanup
  ↓
Render
  ↓
Commit
  ↓
New Effect setup
  ↓
Unmount
  ↓
Cleanup
```

---

### Class

```jsx
class User extends React.Component {
  constructor(props) {
    super(props);

    this.state = {
      user: null
    };
  }

  componentDidMount() {
    this.loadUser();
  }

  componentDidUpdate(prevProps) {
    if (prevProps.userId !== this.props.userId) {
      this.loadUser();
    }
  }

  componentWillUnmount() {
    // cleanup
  }

  loadUser() {
    fetch(`/api/users/${this.props.userId}`)
      .then(res => res.json())
      .then(user => this.setState({ user }));
  }

  render() {
    return <h1>{this.state.user?.name}</h1>;
  }
}
```

# ⭐ Interview Must-Know

### Mount

> Component is created and inserted into the DOM.

**Class:**

```text
constructor
→ getDerivedStateFromProps
→ render
→ componentDidMount
```

**Function:**

```text
render
→ commit
→ useEffect
```

### Update

> Component renders again due to changed props, state, or context.

**Class:**

```text
getDerivedStateFromProps
→ shouldComponentUpdate
→ render
→ getSnapshotBeforeUpdate
→ commit
→ componentDidUpdate
```

**Function:**

```text
render
→ reconciliation
→ commit
→ relevant Effects
```

### Unmount

> Component is removed from the UI.

**Class:**

```text
componentWillUnmount()
→ DOM removal
```

**Function:**

```text
useEffect cleanup
→ DOM removal
```

### Most important distinction

> **Render phase calculates UI; commit phase applies changes. Effects run after commit.**

And for a senior-level interview, remember: **`useEffect` is not simply "componentDidMount/componentDidUpdate replacement."** It is primarily a mechanism for synchronizing a component with external systems, with cleanup for undoing that synchronization.
