# React JS — Redux Toolkit

> **Interview focus:** Redux Toolkit (RTK) is the recommended way to write Redux. It reduces boilerplate and provides good defaults for immutability, middleware, and DevTools.

---

## 1. `createSlice`

`createSlice()` creates:

* **Slice state**
* **Action creators**
* **Action types**
* **Reducers**

### Example

```js
import { createSlice } from "@reduxjs/toolkit";

const counterSlice = createSlice({
  name: "counter",

  initialState: {
    value: 0,
  },

  reducers: {
    increment: (state) => {
      state.value += 1;
    },

    decrement: (state) => {
      state.value -= 1;
    },

    incrementBy: (state, action) => {
      state.value += action.payload;
    },
  },
});

export const { increment, decrement, incrementBy } =
  counterSlice.actions;

export default counterSlice.reducer;
```

### Important

RTK allows code like:

```js
state.value += 1;
```

even though Redux state should be treated as immutable.

This works because RTK uses **Immer**, which internally produces an immutable state update.

### Action

```js
dispatch(incrementBy(5));
```

Generated action:

```js
{
  type: "counter/incrementBy",
  payload: 5
}
```

### Interview point

> `createSlice` automatically generates action creators and action types from the reducers defined inside the slice.

# 2. `configureStore`

Creates the Redux store with sensible defaults.

It automatically configures:

* Redux DevTools
* Middleware
* Thunk middleware
* Serializable-state checks
* Reducer combination

### Example

```js
import { configureStore } from "@reduxjs/toolkit";
import counterReducer from "./counterSlice";
import userReducer from "./userSlice";

export const store = configureStore({
  reducer: {
    counter: counterReducer,
    user: userReducer,
  },
});
```

Store structure:

```text
store
 ├── counter
 │    └── value
 └── user
      └── data
```

### Connect with React

```jsx
import { Provider } from "react-redux";
import { store } from "./store";

<Provider store={store}>
  <App />
</Provider>
```

### Component

```jsx
import { useDispatch, useSelector } from "react-redux";
import { increment } from "./counterSlice";

function Counter() {
  const count = useSelector((state) => state.counter.value);
  const dispatch = useDispatch();

  return (
    <>
      <p>{count}</p>
      <button onClick={() => dispatch(increment())}>
        +
      </button>
    </>
  );
}
```

# 3. `createAsyncThunk`

Used for **async operations**, commonly API calls.

It automatically generates three lifecycle states:

```text
pending
fulfilled
rejected
```

### Example

```js
import { createAsyncThunk } from "@reduxjs/toolkit";

export const fetchUsers = createAsyncThunk(
  "users/fetchUsers",
  async () => {
    const response = await fetch("/api/users");
    return response.json();
  }
);
```

Dispatch:

```js
dispatch(fetchUsers());
```

Redux automatically dispatches:

```text
users/fetchUsers/pending
users/fetchUsers/fulfilled
users/fetchUsers/rejected
```

### Handling states

Usually handled using `extraReducers`.

```js
const userSlice = createSlice({
  name: "users",

  initialState: {
    data: [],
    loading: false,
    error: null,
  },

  reducers: {},

  extraReducers: (builder) => {
    builder
      .addCase(fetchUsers.pending, (state) => {
        state.loading = true;
        state.error = null;
      })

      .addCase(fetchUsers.fulfilled, (state, action) => {
        state.loading = false;
        state.data = action.payload;
      })

      .addCase(fetchUsers.rejected, (state, action) => {
        state.loading = false;
        state.error = action.error.message;
      });
  },
});
```

### `rejectWithValue`

Useful when you want to return a custom API error payload:

```js
export const login = createAsyncThunk(
  "auth/login",
  async (credentials, { rejectWithValue }) => {
    try {
      const response = await api.login(credentials);
      return response.data;
    } catch (error) {
      return rejectWithValue(error.response.data);
    }
  }
);
```

Then:

```js
.addCase(login.rejected, (state, action) => {
  state.error = action.payload;
});
```

### Interview point

`createAsyncThunk` is useful for **one-off async workflows**, but for API data fetching/caching, **RTK Query is generally preferred**.

# 4. `extraReducers`

Used when a slice needs to respond to **actions generated outside its own `reducers` section**.

Common use cases:

* `createAsyncThunk`
* Actions from another slice
* Global actions

### Example

```js
const userSlice = createSlice({
  name: "user",

  initialState: {
    user: null,
    loading: false,
  },

  reducers: {
    logout: (state) => {
      state.user = null;
    },
  },

  extraReducers: (builder) => {
    builder
      .addCase(fetchUser.pending, (state) => {
        state.loading = true;
      })
      .addCase(fetchUser.fulfilled, (state, action) => {
        state.loading = false;
        state.user = action.payload;
      });
  },
});
```

### `reducers` vs `extraReducers`

| `reducers`                           | `extraReducers`                  |
| ------------------------------------ | -------------------------------- |
| Handles actions defined by the slice | Handles external actions         |
| Generates action creators            | Doesn't generate action creators |
| `increment`, `logout`                | `fetchUser.fulfilled`            |
| Local slice logic                    | Cross-slice / async logic        |

**Interview answer:**

> `reducers` defines the slice's own actions, while `extraReducers` allows the slice to respond to actions created elsewhere.

# 5. RTK Query — Basics

**RTK Query** is Redux Toolkit's data-fetching and caching solution.

It handles many things automatically:

* API requests
* Loading state
* Error state
* Caching
* Request deduplication
* Cache invalidation
* Refetching
* Generated React hooks

Instead of manually writing:

```text
API call
   ↓
pending
   ↓
fulfilled/rejected
   ↓
store data
   ↓
loading/error state
   ↓
cache management
```

RTK Query handles much of this for you.

---

## `createApi`

```js
import { createApi, fetchBaseQuery } from "@reduxjs/toolkit/query/react";

export const usersApi = createApi({
  reducerPath: "usersApi",

  baseQuery: fetchBaseQuery({
    baseUrl: "/api",
  }),

  endpoints: (builder) => ({
    getUsers: builder.query({
      query: () => "/users",
    }),

    getUser: builder.query({
      query: (id) => `/users/${id}`,
    }),
  }),
});

export const {
  useGetUsersQuery,
  useGetUserQuery,
} = usersApi;
```

### Add API reducer to store

```js
const store = configureStore({
  reducer: {
    [usersApi.reducerPath]: usersApi.reducer,
  },

  middleware: (getDefaultMiddleware) =>
    getDefaultMiddleware().concat(usersApi.middleware),
});
```

---

## Using generated hook

```jsx
function Users() {
  const {
    data,
    isLoading,
    isError,
    error,
  } = useGetUsersQuery();

  if (isLoading) return <p>Loading...</p>;

  if (isError) return <p>Error: {error.message}</p>;

  return (
    <ul>
      {data?.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```

RTK Query automatically manages the request state.

---

## Query vs Mutation

### Query → GET/read data

```js
getUsers: builder.query({
  query: () => "/users",
})
```

### Mutation → POST/PUT/PATCH/DELETE

```js
addUser: builder.mutation({
  query: (user) => ({
    url: "/users",
    method: "POST",
    body: user,
  }),
})
```

Generated hook:

```js
const [addUser, { isLoading }] = useAddUserMutation();

await addUser({
  name: "John",
});
```

---

## Cache invalidation

RTK Query supports tags:

```js
createApi({
  tagTypes: ["Users"],

  endpoints: (builder) => ({
    getUsers: builder.query({
      query: () => "/users",
      providesTags: ["Users"],
    }),

    addUser: builder.mutation({
      query: (user) => ({
        url: "/users",
        method: "POST",
        body: user,
      }),
      invalidatesTags: ["Users"],
    }),
  }),
});
```

After `addUser` succeeds, the users query can automatically refetch because its cache was invalidated.

# Redux Toolkit — Quick Architecture

```text
                 Redux Store
                     │
          ┌──────────┴──────────┐
          │                     │
       Slice A               Slice B
          │                     │
     reducers             extraReducers
          │                     │
          └──────────┬──────────┘
                     │
                  Dispatch
                     │
              Async operations
                     │
             createAsyncThunk
                     │
                   API
```

For API-heavy applications:

```text
React
  │
  ├── useSelector/useDispatch
  │
  ├── createSlice
  │
  └── RTK Query
        │
        ├── API requests
        ├── Cache
        ├── Loading/Error
        └── Invalidation
```

## ⭐ Interview Cheat Sheet

| Concept              | Purpose                               |
| -------------------- | ------------------------------------- |
| `createSlice`        | Creates state + reducers + actions    |
| `configureStore`     | Creates/configures Redux store        |
| `createAsyncThunk`   | Handles async workflows               |
| `extraReducers`      | Handles external/async actions        |
| RTK Query            | API fetching + caching solution       |
| `builder.addCase()`  | Handle specific action                |
| `builder.query()`    | Read/fetch API data                   |
| `builder.mutation()` | Create/update/delete API data         |
| `providesTags`       | Identifies cached data                |
| `invalidatesTags`    | Invalidates/refetches cached data     |
| Immer                | Allows mutable-looking reducer code   |
| Thunk                | Middleware used for async dispatching |

**Key interview distinction:**

> **`createAsyncThunk`** is for custom async logic/workflows. **RTK Query** is purpose-built for server-state fetching, caching, synchronization, and invalidation.
