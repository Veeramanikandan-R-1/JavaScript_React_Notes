# React Fundamentals - Redux Toolkit

Redux Toolkit (RTK) is the official and recommended way to write Redux code. It removes boilerplate, provides good defaults, and makes Redux much easier to maintain.

Instead of manually creating actions, reducers, and store configuration, RTK provides utilities to do everything with less code.

---

# 1. configureStore()

## What is it?

`configureStore()` creates the Redux store.

It automatically:

* Combines reducers
* Adds Redux DevTools
* Adds useful middleware (Thunk)
* Enables good defaults

Instead of:

```javascript
createStore(rootReducer, applyMiddleware(thunk))
```

Use:

```javascript
import { configureStore } from "@reduxjs/toolkit";
import counterReducer from "./counterSlice";

const store = configureStore({
  reducer: {
    counter: counterReducer
  }
});

export default store;
```

---

## Why use configureStore?

Without RTK

* createStore()
* combineReducers()
* applyMiddleware()
* composeWithDevTools()

With RTK

One function does everything.

---

## Adding Multiple Reducers

```javascript
const store = configureStore({
  reducer: {
    auth: authReducer,
    user: userReducer,
    products: productReducer
  }
});
```

State becomes

```javascript
{
    auth:{},
    user:{},
    products:{}
}
```

Access

```javascript
const user = useSelector(state => state.user);
```

# 2. createSlice()

## What is Slice?

A slice represents one part of your Redux state.

Example

```
Application

|
|-- User Slice
|-- Auth Slice
|-- Cart Slice
|-- Product Slice
```

Each slice contains

* initialState
* reducers
* actions

---

## Syntax

```javascript
import { createSlice } from "@reduxjs/toolkit";

const counterSlice = createSlice({
    name: "counter",

    initialState: {
        value: 0
    },

    reducers: {
        increment(state) {
            state.value++;
        },

        decrement(state) {
            state.value--;
        },

        incrementByAmount(state, action) {
            state.value += action.payload;
        }
    }
});

export const {
    increment,
    decrement,
    incrementByAmount
} = counterSlice.actions;

export default counterSlice.reducer;
```

---

## Using Slice

Dispatch

```javascript
dispatch(increment());

dispatch(incrementByAmount(5));
```

Read state

```javascript
const count = useSelector(state => state.counter.value);
```

---

## Why can we mutate state?

Normally Redux requires immutable updates.

Instead of

```javascript
return {
    ...state,
    value: state.value + 1
}
```

RTK allows

```javascript
state.value++;
```

Because internally RTK uses **Immer**.

Immer converts mutable-looking code into immutable updates.

You are NOT actually mutating Redux state.

---

## Slice contains

```
createSlice

|

|-- initialState

|-- reducers

|-- actions (generated automatically)

|-- reducer (exported)
```

# 3. createAsyncThunk()

Used for handling async operations.

Examples

* API calls
* Login
* Fetch Users
* Upload File
* Delete Item

---

## Why?

Instead of writing

```
Loading

Success

Failure

actions manually
```

RTK generates them automatically.

---

## Syntax

```javascript
import { createAsyncThunk } from "@reduxjs/toolkit";

export const fetchUsers = createAsyncThunk(
    "users/fetchUsers",

    async () => {
        const response = await fetch("/api/users");
        return response.json();
    }
);
```

Generated actions automatically

```
fetchUsers.pending

fetchUsers.fulfilled

fetchUsers.rejected
```

---

# 4. extraReducers

Reducers handle actions defined inside the same slice.

extraReducers handle:

* Async thunks
* Actions from other slices
* External actions

---

Example

```javascript
const userSlice = createSlice({

    name: "users",

    initialState: {
        users: [],
        loading: false,
        error: null
    },

    reducers: {},

    extraReducers: (builder) => {

        builder

        .addCase(fetchUsers.pending, (state) => {
            state.loading = true;
        })

        .addCase(fetchUsers.fulfilled, (state, action) => {
            state.loading = false;
            state.users = action.payload;
        })

        .addCase(fetchUsers.rejected, (state, action) => {
            state.loading = false;
            state.error = action.error.message;
        });

    }

});
```

---

## Flow

```
dispatch(fetchUsers())

↓

API Call

↓

Pending

↓

Loading=true

↓

API Success

↓

Fulfilled

↓

Store updated

↓

UI rerenders
```

Failure

```
dispatch(fetchUsers())

↓

Pending

↓

Rejected

↓

Error stored

↓

Show error message
```

# 6. Payload in createAsyncThunk

Passing parameters

```javascript
export const fetchUser = createAsyncThunk(

    "users/fetch",

    async (id) => {

        const response = await fetch(`/users/${id}`);

        return response.json();

    }

);
```

Dispatch

```javascript
dispatch(fetchUser(10));
```

# 7. Error Handling

```javascript
export const login = createAsyncThunk(

    "auth/login",

    async (credentials, thunkAPI) => {

        try {

            const response = await api.login(credentials);

            return response.data;

        } catch (error) {

            return thunkAPI.rejectWithValue(error.response.data);

        }

    }

);
```

Rejected

```javascript
builder.addCase(login.rejected, (state, action) => {

    state.error = action.payload;

});
```

Using `rejectWithValue()` lets you pass custom error payloads instead of generic error messages.

# 8. reducers vs extraReducers

| reducers                        | extraReducers             |
| ------------------------------- | ------------------------- |
| Handles own actions             | Handles external actions  |
| Generates actions automatically | Doesn't generate actions  |
| Mostly synchronous              | Mostly async              |
| Used for local state changes    | Used for createAsyncThunk |

Example

```javascript
reducers: {

    increment(){}

}
```

```javascript
extraReducers(builder){

builder.addCase(fetchUsers.fulfilled)

}
```

# 9. RTK Query (Basics)

RTK Query is Redux Toolkit's built-in data fetching and caching solution.

Instead of writing

* createAsyncThunk
* loading
* error
* reducers
* extraReducers

RTK Query handles everything automatically.

---

## Without RTK Query

```
Component

↓

dispatch(fetchUsers())

↓

Thunk

↓

API

↓

Reducer

↓

Store

↓

Component
```

Lots of boilerplate.

---

## With RTK Query

```
Component

↓

useGetUsersQuery()

↓

Automatic fetch

↓

Automatic cache

↓

Automatic loading

↓

Automatic error handling
```

Much simpler.

---

## Create API

```javascript
import { createApi, fetchBaseQuery } from "@reduxjs/toolkit/query/react";

export const api = createApi({
  reducerPath: "api",

  baseQuery: fetchBaseQuery({
    baseUrl: "/api",
  }),

  endpoints: (builder) => ({
    getUsers: builder.query({
      query: () => "/users",
    }),
  }),
});
```

---

## Configure Store

```javascript
import { configureStore } from "@reduxjs/toolkit";
import { api } from "./api";

const store = configureStore({
  reducer: {
    [api.reducerPath]: api.reducer,
  },

  middleware: (getDefaultMiddleware) =>
    getDefaultMiddleware().concat(api.middleware),
});
```

---

## Generated Hook

```javascript
const {
    data,
    error,
    isLoading
} = useGetUsersQuery();
```

No dispatch needed.

---

## Mutation

```javascript
addUser: builder.mutation({

    query: (user) => ({

        url: "/users",

        method: "POST",

        body: user

    })

})
```

Usage

```javascript
const [addUser] = useAddUserMutation();

addUser({
    name: "John"
});
```

## RTK Query Features

* Automatic caching
* Automatic refetching
* Request deduplication
* Loading state
* Error state
* Polling
* Pagination support
* Optimistic updates
* Cache invalidation using **tags** (`providesTags` / `invalidatesTags`)
* Auto-generated hooks

# When should you use what?

| Scenario                    | Use              |
| --------------------------- | ---------------- |
| Local UI state              | useState         |
| Global shared state         | Redux Toolkit    |
| Complex synchronous updates | createSlice      |
| Async API calls             | createAsyncThunk |
| CRUD APIs with caching      | RTK Query        |

---

# Best Practices

* Keep one feature per slice (e.g., `authSlice`, `userSlice`, `cartSlice`).
* Keep reducers pure; avoid side effects inside reducers.
* Use `createAsyncThunk` for custom async workflows.
* Prefer **RTK Query** for most REST API fetching/caching.
* Normalize large collections when needed (e.g., with `createEntityAdapter`).
* Keep only global/shared state in Redux; use local component state for UI-specific data.
* Use selectors to read state instead of directly accessing nested objects across components.

---

# Common Mistakes

❌ Creating one huge slice for the entire application.

❌ Mutating state outside Redux Toolkit.

❌ Storing temporary UI state (modal open, input values) globally when it belongs in a component.

❌ Writing API calls inside reducers.

❌ Forgetting to add the slice reducer to `configureStore`.

❌ Forgetting to add `api.middleware` and `api.reducer` when using RTK Query.

# Common React (6 Years Experience) Interview Questions

### 1. Why is Redux Toolkit preferred over traditional Redux?

**Answer:** It reduces boilerplate, includes Immer, configures the store automatically, adds default middleware, and improves maintainability.

---

### 2. Why can we write `state.count++` inside `createSlice`?

**Answer:** Redux Toolkit uses **Immer**, which tracks mutations and produces a new immutable state internally.

---

### 3. What is the difference between `reducers` and `extraReducers`?

**Answer:** `reducers` define and generate actions for the slice. `extraReducers` respond to actions created elsewhere, especially async thunk lifecycle actions.

---

### 4. Explain the lifecycle of `createAsyncThunk`.

**Answer:** `dispatch(thunk)` → `pending` → API call → `fulfilled` (success) or `rejected` (failure).

---

### 5. What problem does RTK Query solve?

**Answer:** It eliminates boilerplate around API calls by providing built-in fetching, caching, request deduplication, cache invalidation, loading/error states, and auto-generated hooks.

---

### 6. When would you choose `createAsyncThunk` over RTK Query?

**Answer:** Use `createAsyncThunk` for custom async workflows (multiple dependent requests, complex business logic, non-HTTP async tasks). Use RTK Query for standard CRUD/data-fetching scenarios.

---

### 7. What middleware does `configureStore` add by default?

**Answer:** It includes Redux Thunk and development middleware such as immutable state and serializable state checks (enabled in development).

---

### 8. What is cache invalidation in RTK Query?

**Answer:** After a mutation, you can invalidate specific cache tags so related queries automatically refetch fresh data, keeping the UI synchronized with the server.

---

### 9. Can one slice respond to actions from another slice?

**Answer:** Yes. Use `extraReducers` to handle actions created by other slices or async thunks.

---

### 10. How would you structure Redux Toolkit in a large React application?

**Answer:** Organize by feature (feature-based folders), keep one slice per domain, use selectors, keep API logic in RTK Query where possible, and avoid storing local UI state in Redux.
