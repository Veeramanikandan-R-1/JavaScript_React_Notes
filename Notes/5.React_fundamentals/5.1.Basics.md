# React Fundamentals — Basics

For a **5-year experienced React developer**, focus on understanding **what happens, why it exists, and interview-level differences**, rather than memorizing definitions.

---

## 1. Virtual DOM

### What is it?

The **Virtual DOM (VDOM)** is an in-memory JavaScript representation of the UI.

When state/props change:

```text
State/Props change
       ↓
Component re-renders
       ↓
New Virtual DOM
       ↓
Reconciliation / Diffing
       ↓
Only required DOM changes
       ↓
Browser renders UI
```

### Example

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  return <h1>{count}</h1>;
}
```

When `count` changes from `0 → 1`, React creates a new element tree and compares it with the previous one.

React determines that only the text inside `<h1>` needs updating.

### Important

* Virtual DOM is **not a direct copy of the browser DOM**.
* React uses **reconciliation** to compare the previous and new element trees.
* `key` helps React identify list items efficiently.

```jsx
{users.map(user => (
  <User key={user.id} user={user} />
))}
```

### Interview point

> Virtual DOM doesn't automatically make every React app fast. Efficient reconciliation, component structure, avoiding unnecessary renders, and minimizing expensive work are what matter.

# 2. React DOM

**React DOM** is the package that allows React to interact with the **browser DOM**.

Modern React:

```jsx
import { createRoot } from "react-dom/client";

const root = createRoot(document.getElementById("root"));

root.render(<App />);
```

### React vs React DOM

| React                                      | React DOM                   |
| ------------------------------------------ | --------------------------- |
| Core React library                         | Browser DOM integration     |
| Components, hooks, reconciliation concepts | Renders React tree into DOM |
| Platform-independent concepts              | Web-specific                |

React itself can target different platforms, while `react-dom` is specifically for web browsers.

### Interview point

```text
React → defines UI/component model
React DOM → connects React with browser DOM
```

# 3. JSX

JSX is a **syntax extension for JavaScript** that allows you to write HTML-like UI inside JavaScript.

```jsx
const element = <h1>Hello World</h1>;
```

It is transformed into JavaScript React element creation.

Conceptually:

```jsx
<h1>Hello</h1>
```

becomes something equivalent to:

```js
jsx("h1", {
  children: "Hello"
});
```

### JSX expressions

Use `{}` for JavaScript expressions:

```jsx
const name = "John";
const age = 25;

return (
  <div>
    <h1>Hello {name}</h1>
    <p>{age}</p>
  </div>
);
```

### JSX rules

```jsx
// class → className
<div className="container" />

// for → htmlFor
<label htmlFor="email">Email</label>

// JavaScript expression
<p>{user.name}</p>

// Conditional rendering
{isLoggedIn && <Dashboard />}
```

### Expression vs statement

This works:

```jsx
{isLoggedIn ? <Home /> : <Login />}
```

This doesn't directly work:

```jsx
{/* ❌ statement */}
{if (isLoggedIn) ...}
```

### Interview point

> JSX is not HTML. It is syntax that gets transformed into JavaScript expressions that create React elements.

# 4. Components

A component is an independent, reusable piece of UI.

### Functional component

```jsx
function Welcome() {
  return <h1>Hello</h1>;
}
```

Usage:

```jsx
<Welcome />
```

### Component with props

```jsx
function User({ name }) {
  return <h2>Hello {name}</h2>;
}

<User name="John" />
```

### Component composition

Instead of creating huge components, compose smaller components:

```jsx
function App() {
  return (
    <Page>
      <Header />
      <Sidebar />
      <Content />
      <Footer />
    </Page>
  );
}
```

This is a major React design principle:

> **Composition over inheritance**

### Component must return

A component returns a React element/tree:

```jsx
function App() {
  return (
    <>
      <Header />
      <Content />
    </>
  );
}
```

Fragment `<>...</>` avoids adding an unnecessary DOM element.

### Important concepts

* Components should ideally be **small and reusable**.
* Keep components focused on a clear responsibility.
* Component names should start with uppercase.
* Avoid unnecessary state inside components.
* Prefer composition for reuse.

# 5. Props

**Props = inputs passed from parent to child.**

```jsx
function User({ name, age }) {
  return (
    <div>
      {name} - {age}
    </div>
  );
}

function App() {
  return <User name="John" age={30} />;
}
```

Data flow:

```text
Parent
  ↓ props
Child
```

### Props are read-only

Child should not modify props directly.

```jsx
function Child({ name }) {
  // ❌ Don't do this
  // name = "Bob";
}
```

If child needs to communicate with parent, pass a callback:

```jsx
function Parent() {
  const handleClick = () => {
    console.log("Clicked");
  };

  return <Child onClick={handleClick} />;
}

function Child({ onClick }) {
  return <button onClick={onClick}>Click</button>;
}
```

### Props can contain anything

```jsx
<User
  name="John"
  age={30}
  isAdmin={true}
  skills={["React", "JS"]}
  user={{ id: 1 }}
  onClick={handleClick}
/>
```

### `children` prop

```jsx
function Card({ children }) {
  return <div className="card">{children}</div>;
}

<Card>
  <h2>Hello</h2>
  <p>Content</p>
</Card>
```

`children` is especially important for **component composition**.

# 6. State

State is **data owned by a component that can change over time and trigger a re-render**.

```jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <>
      <h1>{count}</h1>
      <button onClick={() => setCount(count + 1)}>
        +
      </button>
    </>
  );
}
```

### `useState`

```jsx
const [state, setState] = useState(initialValue);
```

* `state` → current value
* `setState` → updates state
* `initialValue` → initial state

### State update causes re-render

```text
setCount()
   ↓
State update scheduled
   ↓
Component renders again
   ↓
New React element tree
   ↓
Reconciliation
   ↓
DOM updated if necessary
```

### Never mutate state directly

❌ Wrong:

```jsx
const [user, setUser] = useState({
  name: "John",
  age: 30
});

user.age = 31;
```

✅ Correct:

```jsx
setUser(prev => ({
  ...prev,
  age: 31
}));
```

### Functional state update

Important when the new state depends on the previous state:

```jsx
setCount(prev => prev + 1);
setCount(prev => prev + 1);
```

This correctly increments twice.

Prefer:

```jsx
setCount(prev => prev + 1);
```

over:

```jsx
setCount(count + 1);
```

when depending on previous state.

# Props vs State

| Props                                 | State                        |
| ------------------------------------- | ---------------------------- |
| Passed by parent                      | Owned/managed by component   |
| Read-only                             | Can be updated               |
| Used to configure component           | Used for changing data       |
| Parent → Child                        | Internal component data      |
| Changes when parent passes new values | Changes through state setter |

Example:

```jsx
function User({ name }) {          // Props
  const [age, setAge] = useState(20); // State

  return (
    <>
      <h1>{name}</h1>
      <p>{age}</p>
    </>
  );
}
```

# Must-Know Interview Summary

### Virtual DOM

> In-memory representation of the UI that React uses during reconciliation to determine necessary DOM updates.

### React DOM

> Web-specific package that renders React elements into the browser DOM.

### JSX

> JavaScript syntax extension for describing UI; it gets transformed into JavaScript/React element creation.

### Component

> Reusable, independent UI building block.

### Props

> Read-only inputs passed from parent to child.

### State

> Mutable component-owned data that, when updated through React's state mechanism, causes the component to render again.

### Core React flow

```text
Props / State
     ↓
Component Render
     ↓
React Elements
     ↓
Reconciliation
     ↓
DOM updates
     ↓
Browser Paint
```

**One important correction for interviews:** don't say *"React updates the Virtual DOM and then directly replaces the real DOM."* React compares the new element tree with the previous one and commits the necessary changes to the host environment (the browser DOM for `react-dom`).
