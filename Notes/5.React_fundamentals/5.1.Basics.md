# React Fundamentals – Basics

> **Goal:** These are the core building blocks of React. For a **6-year React interview**, you should not only know *what* they are, but also *why React introduced them*, *how they work internally*, and *their performance implications*.

---

# 1. What is React?

React is an **open-source JavaScript library** developed by **Meta (Facebook)** for building **interactive, reusable, and efficient user interfaces**, especially Single Page Applications (SPAs).

React follows a **component-based architecture**, where the UI is split into independent, reusable pieces.

Example

```jsx
function App() {
    return <h1>Hello React</h1>;
}
```

---

## Why React?

Before React:

* Manual DOM manipulation
* Difficult state management
* Poor code reusability
* Frequent UI bugs
* Performance issues in large applications

React solves these by introducing:

* Components
* Virtual DOM
* Declarative UI
* Efficient rendering
* One-way data flow

## React vs Angular (Short Interview Answer)

| React                                                      | Angular                                                                     |
| ---------------------------------------------------------- | --------------------------------------------------------------------------- |
| **Library** for building UI                                | **Complete framework** for building applications                            |
| Developed by **Meta (Facebook)**                           | Developed by **Google**                                                     |
| Uses **JavaScript/TypeScript**                             | Primarily **TypeScript**                                                    |
| Uses **Virtual DOM**                                       | Uses **Real DOM** with change detection                                     |
| Flexible (choose your own routing, state management, etc.) | Comes with built-in routing, forms, HTTP client, dependency injection, etc. |
| Easier to learn                                            | Steeper learning curve                                                      |
| Better for highly interactive UIs                          | Better for large enterprise applications with opinionated architecture      |
| Smaller bundle size                                        | Larger bundle size                                                          |

---

* Reduces expensive DOM manipulations.

### 2. Reusable Components

### 3. Declarative UI

### 4. Easy State Management

* Single Page Applications (SPA)
* Dashboards

---

## Interview Answer (1 Minute)

> **React is a UI library, whereas Angular is a complete frontend framework. React focuses only on building the user interface and gives developers the flexibility to choose libraries for routing, state management, and other features. Angular provides most of these features out of the box, making it more opinionated. React uses a Virtual DOM to efficiently update only the changed parts of the UI, resulting in better performance for interactive applications. Its component-based architecture, reusable components, large ecosystem, and support for React Native make it a popular choice for modern web development. Angular, on the other hand, is often preferred for large enterprise applications where a complete, structured framework is beneficial.**

### React Interview Tip (6+ Years)

If asked **"Why did your project choose React over Angular?"**, a strong answer is:

> *"Our application required a highly interactive UI with frequent state updates. React's Virtual DOM, component-based architecture, flexibility in choosing libraries, and excellent ecosystem made it easier to build, optimize, and maintain the application. It also aligned well with our team's expertise and performance requirements."*

# 2. Virtual DOM (Most Important)

## What is Virtual DOM?

The **Virtual DOM (VDOM)** is a **lightweight JavaScript representation of the Real DOM**.

Instead of updating the browser DOM directly, React:

1. Creates a Virtual DOM.
2. Compares it with the previous Virtual DOM.
3. Updates only the changed parts in the Real DOM.

---

## Why Virtual DOM?

Updating the Real DOM is expensive because it may trigger:

* Layout (Reflow)
* Paint
* Composite

React minimizes these expensive operations.

---

## How Virtual DOM Works

Imagine:

Initial UI

```jsx
<h1>Hello</h1>
```

Virtual DOM

```text
App

↓

h1

↓

"Hello"
```

User changes state

```jsx
<h1>Hello John</h1>
```

React creates another Virtual DOM.

```text
Old VDOM          New VDOM

Hello      →      Hello John
```

React compares both trees (**Diffing**) and finds only the text changed.

Only the `<h1>` text is updated in the Real DOM.

---

## Virtual DOM Process

```text
State Changes

↓

Create New Virtual DOM

↓

Diffing Algorithm

↓

Find Differences

↓

Update Only Changed Nodes

↓

Real DOM Updated
```

---

## Benefits

* Faster UI updates
* Fewer DOM operations
* Better performance
* Predictable rendering

---

## Interview Point

> Virtual DOM itself doesn't make React fast. **The performance gain comes from reducing unnecessary Real DOM updates using reconciliation and batching.**

---

# 3. React DOM

## What is ReactDOM?

`react-dom` is the package responsible for connecting React with the browser DOM.

It takes the Virtual DOM and updates the Real DOM.

Example

```jsx
import { createRoot } from "react-dom/client";

const root = createRoot(
    document.getElementById("root")
);

root.render(<App />);
```

---

## Responsibilities

* Rendering React components
* Updating the Real DOM
* Event delegation
* Hydration (SSR)
* Managing the React root

---

## React vs ReactDOM

| React              | ReactDOM                  |
| ------------------ | ------------------------- |
| Core library       | Browser renderer          |
| Creates components | Updates browser DOM       |
| Hooks, JSX         | `createRoot()`, rendering |

---

## Interview Point

React can work on multiple platforms.

Examples:

* React DOM → Web
* React Native → Mobile
* React Three Fiber → 3D
* Ink → CLI

Only the renderer changes.

# 4. JSX

## What is JSX?

JSX (**JavaScript XML**) is a syntax extension that lets us write HTML-like code inside JavaScript.

Example

```jsx
const element =
<h1>Hello React</h1>;
```

---

## Why JSX?

Without JSX

```jsx
React.createElement(
    "h1",
    null,
    "Hello"
);
```

With JSX

```jsx
<h1>Hello</h1>
```

Much easier to read.

---

## JSX Compilation

JSX is **not understood by browsers**.

Babel converts

```jsx
<h1>Hello</h1>
```

into

```jsx
React.createElement(
    "h1",
    null,
    "Hello"
);
```

---

## JSX Rules

### One parent element

Wrong

```jsx
<h1>Hello</h1>

<p>React</p>
```

Correct

```jsx
<>
    <h1>Hello</h1>

    <p>React</p>
</>
```

---

### Close every tag

```jsx
<img src="logo.png" />
```

---

### class becomes className

```jsx
<div className="box">
```

---

### JavaScript inside `{}`

```jsx
const name = "John";

<h1>{name}</h1>
```

---

### Expressions only

Allowed

```jsx
{5+5}
```

Not allowed

```jsx
if(){}
```

Use ternary instead.

---

# 5. Components

## What is a Component?

A component is an independent, reusable piece of UI.

Think of it like a JavaScript function that returns JSX.

Example

```jsx
function Button() {

    return <button>Save</button>;

}
```

Usage

```jsx
<Button />
```

---

## Types of Components

### Functional Components (Preferred)

```jsx
function Header(){

    return <h1>React</h1>;

}
```

---

### Class Components (Legacy)

```jsx
class Header extends React.Component{

    render(){

        return <h1>React</h1>;

    }

}
```

Modern React prefers functional components with Hooks.

---

## Why Components?

Without components

Large HTML file.

With components

```text
App

├── Header

├── Sidebar

├── Content

└── Footer
```

Reusable and maintainable.

---

## Component Naming

Must start with Capital Letter

Correct

```jsx
<UserCard />
```

Wrong

```jsx
<userCard />
```

Lowercase names are treated as HTML tags.

---

# 6. Props

## What are Props?

Props (**Properties**) are inputs passed from a parent component to a child component.

Props are **read-only (immutable)**.

---

Example

Parent

```jsx
<User
    name="John"
/>
```

Child

```jsx
function User(props){

    return <h1>

        {props.name}

    </h1>;

}
```

Output

```text
John
```

---

## Destructuring

Preferred

```jsx
function User({name}){

    return <h1>{name}</h1>;

}
```

---

## Multiple Props

```jsx
<User

name="John"

age={25}

city="London"

/>
```

---

## Passing Functions

```jsx
<Button

onClick={handleClick}

/>
```

---

## Props are Immutable

Wrong

```jsx
props.name = "Alex";
```

Never modify props.

---

## Data Flow

React follows **One-Way Data Flow**.

```text
Parent

↓

Props

↓

Child
```

Child cannot modify parent props directly.

---

# 7. State

## What is State?

State is data owned and managed by a component.

Unlike props, state **can change**, and when it changes, React re-renders the component.

---

Example

```jsx
const [count,setCount] =
useState(0);
```

Update

```jsx
setCount(1);
```

---

## Why State?

Without state

```jsx
let count = 0;
```

Changing it

```jsx
count++;
```

UI won't update.

With state

```jsx
setCount(count+1);
```

React re-renders automatically.

---

## State Lifecycle

```text
User Click

↓

setState()

↓

State Updated

↓

Virtual DOM Created

↓

Diffing

↓

Real DOM Updated

↓

UI Changes
```

---

## Rules

Never

```jsx
count++;
```

Always

```jsx
setCount(count+1);
```

Or

```jsx
setCount(prev => prev+1);
```

Preferred when the next state depends on the previous one.

---

## Props vs State

| Props                   | State                |
| ----------------------- | -------------------- |
| Passed from parent      | Managed by component |
| Read-only               | Mutable via setter   |
| External data           | Internal data        |
| Component cannot modify | Component can update |

---

# Virtual DOM vs Real DOM

| Virtual DOM            | Real DOM                    |
| ---------------------- | --------------------------- |
| JavaScript object      | Browser DOM                 |
| Fast to update         | Expensive to update         |
| React manages it       | Browser manages it          |
| Compared using Diffing | Updated only when necessary |

---

# Common Mistakes

### Modifying Props

```jsx
props.user="Alex";
```

Never modify props.

---

### Mutating State

Wrong

```jsx
state.user.name="John";
```

Create a new object instead.

---

### Using State for Constants

```jsx
const [title] =
useState("React");
```

If it never changes, use:

```jsx
const title =
"React";
```

---

### Forgetting Key Difference

* Props → Parent owns them.
* State → Component owns it.

---

# Best Practices

* Keep components small and reusable.
* Use props for communication between parent and child.
* Keep state as local as possible.
* Don't mutate props or state directly.
* Prefer functional components with Hooks.
* Lift state up only when multiple components need to share it.

# Frequently Asked Interview Questions (6 Years React)

### 1. What is the Virtual DOM, and how does it improve performance?

**Answer:** The Virtual DOM is a lightweight JavaScript representation of the Real DOM. When state or props change, React creates a new Virtual DOM, compares it with the previous one using the diffing algorithm, and updates only the changed nodes in the Real DOM. This minimizes expensive DOM operations and improves rendering performance.

---

### 2. What is the difference between React and ReactDOM?

**Answer:** `react` contains the core React APIs such as components, hooks, and JSX support. `react-dom` is the renderer responsible for mounting React applications and synchronizing the Virtual DOM with the browser's Real DOM.

---

### 3. What is JSX? Is it HTML?

**Answer:** JSX is a syntax extension for JavaScript that looks like HTML but isn't HTML. It is compiled (typically by Babel) into `React.createElement()` calls that create React elements.

---

### 4. What is the difference between Props and State?

| Props                  | State                         |
| ---------------------- | ----------------------------- |
| Passed from parent     | Managed by the component      |
| Read-only              | Updated with setter functions |
| Used for configuration | Used for dynamic data         |
| External               | Internal                      |

---

### 5. Why shouldn't we mutate state directly?

**Answer:** React detects updates by comparing references. Direct mutation may not create a new reference, so React may not detect the change correctly, leading to missed re-renders and bugs.

---

### 6. Why are functional components preferred over class components?

**Answer:** Functional components are simpler, support Hooks for state and side effects, have less boilerplate, and are the standard approach in modern React. Class components are mainly maintained for legacy codebases.

---

### 7. What causes a React component to re-render?

**Answer:** A component re-renders when:

* Its **state** changes.
* Its **props** change.
* Its **parent** re-renders (unless rendering is optimized with techniques like `React.memo`).
* A **context** value it consumes changes.

---

### 8. Explain React's rendering flow after a state update.

**Answer:**

```text
setState() / setCount()
        ↓
State updated
        ↓
New Virtual DOM created
        ↓
Diffing (Reconciliation)
        ↓
Changed nodes identified
        ↓
ReactDOM updates only those nodes
        ↓
Browser repaints the affected UI
```

---

## 6+ Years Interview Tips

* Know the difference between **React Element**, **Component**, **Virtual DOM**, and **ReactDOM**.
* Be able to explain **why Virtual DOM is useful**, not just what it is.
* Understand **one-way data flow** and why React keeps props immutable.
* Explain **what triggers a re-render** and how React minimizes browser DOM updates.
* Mention that **React 18's `createRoot()`** enables the new concurrent rendering capabilities, replacing the legacy `ReactDOM.render()`.
