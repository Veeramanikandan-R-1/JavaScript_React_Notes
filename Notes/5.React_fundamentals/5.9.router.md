# React JS — React Router

**React Router** is used for **client-side routing** in React applications — mapping URLs to UI without a full browser page reload.

> Interview focus: understand **route matching, nested layouts, navigation, URL parameters, and data loading**.

---

# 1. `BrowserRouter`

`BrowserRouter` enables routing using the browser's **History API**.

```jsx
import { BrowserRouter } from "react-router-dom";

function App() {
  return (
    <BrowserRouter>
      <AppRoutes />
    </BrowserRouter>
  );
}
```

Example URL:

```text
/products/123
```

The server sees the same application entry point, while React Router decides which component to render.

### Important

`BrowserRouter` uses **clean URLs**:

```text
/products
/products/123
```

Unlike `HashRouter`:

```text
#/products
```

### Production consideration ⭐

With `BrowserRouter`, the server must be configured to serve `index.html` for application routes; otherwise directly refreshing `/products` can result in a **404**.

---

# 2. `Routes`

`Routes` is the container for your route definitions.

```jsx
<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/about" element={<About />} />
</Routes>
```

React Router finds the route that matches the current URL and renders its element.

---

# 3. `Route`

`Route` maps a URL pattern to a React element.

```jsx
<Route path="/users" element={<Users />} />
```

Examples:

```jsx
<Route path="/" element={<Home />} />
<Route path="/login" element={<Login />} />
<Route path="/users" element={<Users />} />
<Route path="/about" element={<About />} />
```

### Dynamic route

```jsx
<Route path="/users/:id" element={<UserDetails />} />
```

URL:

```text
/users/101
```

`id` becomes:

```text
101
```

---

# 4. Nested Routes

Nested routes allow a parent route to contain child routes.

Example:

```jsx
<Routes>
  <Route path="/dashboard" element={<Dashboard />}>
    <Route path="profile" element={<Profile />} />
    <Route path="settings" element={<Settings />} />
  </Route>
</Routes>
```

URLs:

```text
/dashboard
/dashboard/profile
/dashboard/settings
```

### Why use nested routes?

Useful for layouts such as:

```text
Dashboard
 ├── Profile
 ├── Settings
 └── Reports
```

The `Dashboard` layout remains while the child content changes.

---

# 5. `Outlet`

`Outlet` defines **where the child route should render**.

```jsx
function Dashboard() {
  return (
    <>
      <nav>Dashboard Navigation</nav>

      <Outlet />
    </>
  );
}
```

With:

```jsx
<Route path="/dashboard" element={<Dashboard />}>
  <Route path="profile" element={<Profile />} />
  <Route path="settings" element={<Settings />} />
</Route>
```

Visiting:

```text
/dashboard/profile
```

renders:

```text
Dashboard
  ↓
<Outlet />
  ↓
Profile
```

### Interview ⭐

> **Nested Route defines the child route; `Outlet` defines where that child route is rendered.**

---

# 6. `Navigate`

`Navigate` performs a **declarative redirect**.

```jsx
import { Navigate } from "react-router-dom";

function ProtectedPage() {
  const isAuthenticated = false;

  if (!isAuthenticated) {
    return <Navigate to="/login" replace />;
  }

  return <Dashboard />;
}
```

### `replace`

```jsx
<Navigate to="/login" replace />
```

Replaces the current history entry instead of adding another one.

Useful for authentication redirects.

---

# 7. `useNavigate`

`useNavigate` performs navigation **programmatically**.

```jsx
import { useNavigate } from "react-router-dom";

function Login() {
  const navigate = useNavigate();

  const handleLogin = () => {
    // login success
    navigate("/dashboard");
  };

  return <button onClick={handleLogin}>Login</button>;
}
```

### Go back

```jsx
navigate(-1);
```

### Go forward

```jsx
navigate(1);
```

### Replace current URL

```jsx
navigate("/dashboard", { replace: true });
```

### `Navigate` vs `useNavigate`

| `Navigate`                      | `useNavigate`               |
| ------------------------------- | --------------------------- |
| Component                       | Hook                        |
| Declarative                     | Programmatic                |
| `<Navigate to="/login" />`      | `navigate("/login")`        |
| Good for redirects in rendering | Good for event/action logic |

---

# 8. `useParams`

Gets **dynamic URL parameters**.

Route:

```jsx
<Route path="/users/:id" element={<User />} />
```

Component:

```jsx
function User() {
  const { id } = useParams();

  return <h1>User ID: {id}</h1>;
}
```

URL:

```text
/users/123
```

Result:

```text
id = "123"
```

### Important ⭐

Route params are **strings**.

If you need a number:

```jsx
const userId = Number(id);
```

---

# 9. `useLocation`

Returns information about the **current URL/location**.

```jsx
const location = useLocation();

console.log(location.pathname);
console.log(location.search);
console.log(location.hash);
console.log(location.state);
```

For:

```text
/products?page=2#reviews
```

you get roughly:

```text
pathname → /products
search   → ?page=2
hash     → #reviews
```

### Common use cases

* Track page views
* React to URL changes
* Read navigation state
* Access query string before parsing it

Example:

```jsx
useEffect(() => {
  console.log("Page changed:", location.pathname);
}, [location]);
```

For query parameters, prefer `useSearchParams` when appropriate.

# 10. Loaders — React Router v6.4+

A **loader** loads route data **before the route element renders**.

Example:

```jsx
const router = createBrowserRouter([
  {
    path: "/users/:id",
    element: <User />,
    loader: async ({ params }) => {
      const response = await fetch(`/api/users/${params.id}`);
      return response.json();
    }
  }
]);
```

Inside the component:

```jsx
import { useLoaderData } from "react-router-dom";

function User() {
  const user = useLoaderData();

  return <h2>{user.name}</h2>;
}
```

### Flow

```text
Navigate to /users/10
        ↓
Route matches
        ↓
loader()
        ↓
Fetch data
        ↓
Route renders
        ↓
useLoaderData()
```

### Why loaders?

They move route-level data fetching **out of the component**.

Instead of:

```jsx
useEffect(() => {
  fetchUser();
}, []);
```

you can define the data dependency at the route level.

### Loader with error handling

React Router supports route-level error handling:

```jsx
{
  path: "/users/:id",
  loader: userLoader,
  element: <User />,
  errorElement: <ErrorPage />
}
```

### Important ⭐

Loaders are part of React Router's **data router APIs**, commonly configured using:

```jsx
createBrowserRouter()
```

and rendered with:

```jsx
<RouterProvider router={router} />
```

# 11. Protected Routes

Protected routes restrict access based on authentication/authorization.

Typical requirement:

```text
Not logged in
     ↓
/dashboard
     ↓
/login
```

### Simple pattern

```jsx
function ProtectedRoute({ children }) {
  const isAuthenticated = useAuth();

  if (!isAuthenticated) {
    return <Navigate to="/login" replace />;
  }

  return children;
}
```

Usage:

```jsx
<Route
  path="/dashboard"
  element={
    <ProtectedRoute>
      <Dashboard />
    </ProtectedRoute>
  }
/>
```

---

## Better Nested Protected Layout

For multiple protected pages:

```jsx
function ProtectedLayout() {
  const isAuthenticated = useAuth();

  if (!isAuthenticated) {
    return <Navigate to="/login" replace />;
  }

  return <Outlet />;
}
```

Routes:

```jsx
<Routes>
  <Route path="/login" element={<Login />} />

  <Route element={<ProtectedLayout />}>
    <Route path="/dashboard" element={<Dashboard />} />
    <Route path="/profile" element={<Profile />} />
    <Route path="/settings" element={<Settings />} />
  </Route>
</Routes>
```

Now authentication is checked once at the layout level.

### Authentication vs Authorization ⭐

**Authentication:**

> "Who are you?"

```text
Is user logged in?
```

**Authorization:**

> "What are you allowed to access?"

```text
Is user an ADMIN?
Can user access /admin?
```

Protected routes can handle both.

# 12. Complete Routing Structure

A real application might look like:

```jsx
<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/login" element={<Login />} />

  <Route element={<ProtectedLayout />}>
    <Route path="/dashboard" element={<Dashboard />} />

    <Route path="/users" element={<Users />}>
      <Route path=":id" element={<UserDetails />} />
    </Route>

    <Route path="/settings" element={<Settings />} />
  </Route>
</Routes>
```

URL:

```text
/users/123
```

Flow:

```text
BrowserRouter
     ↓
Routes
     ↓
/users/:id
     ↓
Users
     ↓
Outlet
     ↓
UserDetails
     ↓
useParams() → { id: "123" }
```

 ↓

**Senior-level point:** Don't treat React Router as just a URL-to-component library. Modern React Router (v6.4+) also provides **data loading, actions, pending states, error boundaries, and route-level layouts**, making routing closely integrated with application data flow.
