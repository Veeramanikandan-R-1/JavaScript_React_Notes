# React Fundamentals - React Router (React Router v6+)

> React Router is used to build **Single Page Applications (SPA)** where navigation happens without refreshing the page.

---

# 1. BrowserRouter

## What is it?

`BrowserRouter` enables routing using the browser's History API.

It should wrap your entire application.

```jsx
import { BrowserRouter } from "react-router-dom";

root.render(
  <BrowserRouter>
    <App />
  </BrowserRouter>
);
```

### Internally

* Uses HTML5 History API
* Updates URL without page reload
* React renders matching component

Example:

```
/home
/about
/profile
```

Page changes without refreshing the browser.

---

# 2. Routes

## What is it?

`Routes` contains all route definitions.

It checks the current URL and renders the first matching Route.

```jsx
<Routes>
   <Route path="/" element={<Home />} />
   <Route path="/about" element={<About />} />
</Routes>
```

Think of it as

```
Current URL
      ↓
Routes
      ↓
Find Matching Route
      ↓
Render Component
```

```jsx
<Routes>
```

# 4. Nested Routes

Used when pages share the same layout.

Example

```
Dashboard
    |
    |-- Profile
    |-- Settings
    |-- Reports
```

```jsx
<Routes>
   <Route path="/dashboard" element={<Dashboard />}>
      <Route path="profile" element={<Profile />} />
      <Route path="settings" element={<Settings />} />
   </Route>
</Routes>
```

URL

```
/dashboard/profile

/dashboard/settings
```

---

# 5. Outlet

`Outlet` is the placeholder where nested child routes render.

Example

```jsx
function Dashboard() {
   return (
      <>
         <Sidebar />

         <Outlet />
      </>
   );
}
```

Without `Outlet`, child routes never appear.

Visual

```
Dashboard

Sidebar
Header

Outlet
   ↓
Profile Component
```

# 6. Navigate

Redirect component.

Example

```jsx
<Navigate to="/login" />
```

Common usage

After logout

```jsx
if (!user) {
   return <Navigate to="/login" />;
}
```

Equivalent to redirecting user.

---

# Replace Navigation

```jsx
<Navigate
   to="/login"
   replace
/>
```

`replace` removes the current page from browser history.

Useful after login/logout.

# 7. useNavigate()

Used for **programmatic navigation**.

```jsx
const navigate = useNavigate();
```

Navigate

```jsx
navigate("/dashboard");
```

Go back

```jsx
navigate(-1);
```

Go forward

```jsx
navigate(1);
```

Replace history

```jsx
navigate("/login", {
   replace: true
});
```

Passing state

```jsx
navigate("/profile", {
   state: {
      name: "John"
   }
});
```

Receiving

```jsx
const location = useLocation();

console.log(location.state);
```



```

id
```

# 9. useLocation()

Returns information about current URL.

```jsx
const location = useLocation();

console.log(location.pathname);
console.log(location.search);
console.log(location.state);
```

Suppose URL

```
/users?id=10
```

```
pathname → /users

search → ?id=10
```

Common uses

* Active menu
* Analytics
* Breadcrumbs
* Reading navigation state

---

# Query Parameters

```jsx
import { useSearchParams } from "react-router-dom";

const [params] = useSearchParams();

params.get("id");
```

URL

```
/users?id=25
```

Output

```
25
```

> **Difference**
>
> `useParams()` → Route parameters (`/users/:id`)
>
> `useSearchParams()` → Query parameters (`?id=25`)

# 10. Loaders (React Router v6.4+ Basics)

Before v6.4

```
Component loads

↓

useEffect

↓

API call

↓

Render
```

With Loaders

```
Navigate

↓

Loader runs

↓

Data fetched

↓

Component renders
```

Example

```jsx
const router = createBrowserRouter([
  {
    path: "/users",
    loader: async () => {
      return fetch("/api/users");
    },
    element: <Users />
  }
]);
```

Inside component

```jsx
const users = useLoaderData();
```

Advantages

* Data available before rendering
* Cleaner code
* Centralized fetching
* Better UX (less loading flicker)

# 11. Protected Routes

Restrict access to authenticated users.

Example

```
Logged In?

      Yes
       ↓
Dashboard

      No
       ↓
Login
```

Implementation

```jsx
function ProtectedRoute({ children }) {
   const user = useAuth();

   if (!user) {
      return <Navigate to="/login" />;
   }

   return children;
}
```

Usage

```jsx
<Route
   path="/dashboard"
   element={
      <ProtectedRoute>
         <Dashboard />
      </ProtectedRoute>
   }
/>
```

# Route Configuration (Large Applications)

Instead of defining all routes in one file:

```
src/

routes/
    appRoutes.js

pages/
components/
layouts/
```

Example

```jsx
const routes = [
   {
      path: "/",
      element: <Home />
   },
   {
      path: "/dashboard",
      element: <Dashboard />
   }
];
```

This improves maintainability in enterprise projects.

# React Router Best Practices (Senior Level)

* Keep route configuration centralized.
* Use nested routes for shared layouts.
* Protect private pages with a wrapper.
* Lazy load route components.
* Use `replace` after login/logout.
* Prefer Loaders for route-level data fetching (v6.4+).
* Use `useSearchParams` for filters and pagination.
* Create a 404 page using `path="*"`.
* Avoid deeply nested routes unless necessary.
* Split routes by feature in large projects.

# Frequently Asked Interview Questions (6 Years Experience)

### 1. BrowserRouter vs HashRouter?

**BrowserRouter**

* Uses HTML5 History API.
* Clean URLs (`/users`).
* Requires server configuration for deep links.

**HashRouter**

* Uses URL hash (`/#/users`).
* No server configuration needed.
* Mostly used for static hosting or legacy apps.

---

### 2. Why do we use Outlet?

It is the placeholder where nested child routes are rendered. Without it, child routes won't appear.

---

### 3. `useNavigate()` vs `<Navigate />`

* **`useNavigate()`**: Imperative/programmatic navigation (e.g., after form submission).
* **`<Navigate />`**: Declarative redirect during rendering (e.g., redirect unauthenticated users).

---

### 4. `useParams()` vs `useSearchParams()`

* **`useParams()`** → Route params (`/users/:id`)
* **`useSearchParams()`** → Query params (`/users?id=10`)

---

### 5. What are Loaders?

Loaders fetch route-level data **before** rendering the component, reducing loading flicker and centralizing data fetching.

---

### 6. How do you implement Protected Routes?

Wrap the protected component in a custom component that checks authentication and returns `<Navigate to="/login" />` if the user is not authenticated.

---

### 7. How do nested routes improve application design?

They allow multiple pages to share a common layout (header, sidebar, footer) while rendering different content through `<Outlet />`.

---

### 8. What are common routing optimizations in enterprise React applications?

* Route-based code splitting with `React.lazy()`
* Lazy loading pages
* Centralized route configuration
* Protected routes
* Route-level loaders
* 404 fallback route
* Feature-based route organization
