# Additional React Hooks (Interview Notes)

These hooks are less frequently used than the core hooks, but for a **6+ years React interview**, you should know **what they do, when to use them, and one practical example**.

---

# 1. useId

## What is it?

Generates a **unique, stable ID** for accessibility (`id`, `htmlFor`, ARIA attributes).

It prevents ID conflicts, especially in reusable components and during SSR (Server-Side Rendering).

### Example

```jsx
import { useId } from "react";

function LoginForm() {
  const id = useId();

  return (
    <>
      <label htmlFor={id}>Username</label>
      <input id={id} />
    </>
  );
}
```

### Use Cases

* Forms
* Accessibility
* Reusable components
* SSR-safe IDs

---

# 2. useTransition

`useTransition` is one of the most confusing hooks, but the core idea is actually simple.

# What is useTransition?

`useTransition` tells React:

> **"This update is not urgent. If the user is interacting with the UI, keep the UI responsive first and do this update in the background."**

It is mainly used when **a state update causes expensive rendering**.

---

# Problem Without useTransition

Imagine you have **50,000 users**.

Every time the user types:

```text
A

↓

Update input

↓

Filter 50,000 users

↓

Render list
```

Because filtering is expensive, typing becomes **slow and laggy**.

---

# Solution With useTransition

Now React separates the updates into two priorities.

```text
User types

↓

Update input immediately ✅

↓

Filter users later (background)
```

The input stays smooth while the list updates shortly afterward.

---

# Example

```jsx
import { useState, useTransition } from "react";

function Search() {
  const [text, setText] = useState("");
  const [users, setUsers] = useState([]);
  const [isPending, startTransition] = useTransition();

  function handleChange(e) {
    const value = e.target.value;

    // High priority (urgent)
    setText(value);

    // Low priority (non-urgent)
    startTransition(() => {
      setUsers(heavySearch(value));
    });
  }

  return (
    <>
      <input
        value={text}
        onChange={handleChange}
      />

      {isPending && <p>Searching...</p>}

      {users.map(user => (
        <div key={user.id}>{user.name}</div>
      ))}
    </>
  );
}
```

---

# What Happens Internally?

### Without useTransition

```
Typing

↓

Update Input

↓

Heavy Search

↓

Render

(User feels lag)
```

---

### With useTransition

```
Typing

↓

Update Input Immediately ✅

↓

React schedules heavy search

↓

Render results later
```

The user experiences **smooth typing**, even if the search is expensive.

---

# What are `startTransition` and `isPending`?

### `startTransition()`

Marks updates inside it as **low priority**.

```jsx
startTransition(() => {
  setUsers(heavySearch(value));
});
```

---

### `isPending`

Indicates whether the transition is still in progress.

```jsx
{isPending && <p>Loading...</p>}
```

This lets you show a loading indicator while the background update completes.

---

# Real-World Use Cases

Use `useTransition` for:

* Searching large datasets
* Filtering thousands of records
* Large tables
* Complex dashboards
* Heavy chart rendering
* Expensive UI updates

---

# When NOT to Use It

Don't use it for simple updates like:

```jsx
setCount(count + 1);
setName("John");
setOpen(true);
```

These updates are already fast, so `useTransition` adds no benefit.

---

# Interview Answer (6 Years Experience)

> **"`useTransition` is used to mark non-urgent state updates. It allows React to prioritize urgent updates, such as user typing or clicking, while scheduling expensive rendering work in the background. This improves UI responsiveness without changing the application logic."**

### Easy Way to Remember

* **Normal `setState`** → Update **now** (high priority)
* **`startTransition(setState)`** → Update **later if needed** (low priority)

Think of it like this:

> **Typing in the input is urgent. Updating a huge search result list is not. `useTransition` tells React to prioritize the typing experience.**

# 3. useDeferredValue

`useDeferredValue` is easier to understand if you think of it as **a delayed copy of a value**.

# What is useDeferredValue?

`useDeferredValue` returns a **deferred (slightly delayed) version of a value**.

> **It allows the UI to update immediately while expensive rendering uses the delayed value.**

---

# Problem Without useDeferredValue

Imagine you have a search box with **50,000 users**.

Every keystroke:

```text
Type "J"

↓

search = "J"

↓

Filter 50,000 users

↓

Render results
```

Typing becomes slow because filtering happens on every key press.

---

# Solution With useDeferredValue

Instead of filtering with the latest value:

```jsx
const deferredSearch = useDeferredValue(search);
```

Now:

```text
Type "J"

↓

search updates immediately ✅

↓

Input stays smooth

↓

deferredSearch updates slightly later

↓

Filter users

↓

Render results
```

The input never lags.

---

# Example

```jsx
import { useState, useDeferredValue, useMemo } from "react";

function Search() {
  const [search, setSearch] = useState("");

  const deferredSearch = useDeferredValue(search);

  const filteredUsers = useMemo(() => {
    console.log("Filtering...");
    return heavySearch(deferredSearch);
  }, [deferredSearch]);

  return (
    <>
      <input
        value={search}
        onChange={(e) => setSearch(e.target.value)}
      />

      {filteredUsers.map(user => (
        <div key={user.id}>{user.name}</div>
      ))}
    </>
  );
}
```

---

# What Happens Internally?

### Without useDeferredValue

```text
Type

↓

search changes

↓

Heavy filtering

↓

UI becomes slow
```

---

### With useDeferredValue

```text
Type

↓

search changes immediately ✅

↓

Input updates instantly

↓

deferredSearch changes later

↓

Heavy filtering

↓

Results update
```

---

# Difference Between `search` and `deferredSearch`

Suppose the user types quickly:

```text
Typing:

J
Jo
Joh
John
```

Immediately:

```text
search = "John"
```

But for a short moment:

```text
deferredSearch = "Joh"
```

React delays updating `deferredSearch` until it has time, so expensive filtering doesn't block typing.

---

# Real-World Use Cases

Use `useDeferredValue` for:

* Search boxes
* Large tables
* Expensive filtering
* Dashboard reports
* Large lists
* Heavy charts

---

# useTransition vs useDeferredValue

| useTransition                               | useDeferredValue                              |
| ------------------------------------------- | --------------------------------------------- |
| Defers a **state update**                   | Defers a **value**                            |
| You wrap updates inside `startTransition()` | You wrap the value with `useDeferredValue()`  |
| Control when an update is low priority      | React provides a delayed version of the value |

### Example

**useTransition**

```jsx
startTransition(() => {
  setUsers(heavySearch(text));
});
```

You're saying:

> "This **state update** is low priority."

---

**useDeferredValue**

```jsx
const deferredSearch = useDeferredValue(search);
```

You're saying:

> "Give me a **delayed version of this value**, and I'll use it for expensive work."

---

# Easy Way to Remember

Imagine Google Search:

* Whatever you type appears **immediately** in the input.
* The search results update **a fraction later**.

```text
Input

H
He
Hel
Hell
Hello      ✅ Instant

Results

H
He
Hel
Hello      ⏳ Slightly delayed
```

This is exactly what `useDeferredValue` is designed for.

---

# Interview Answer (6 Years Experience)

> **"`useDeferredValue` returns a deferred version of a value. It's useful when a rapidly changing value, like search text, triggers expensive rendering. The input updates immediately, while React delays rendering based on the deferred value, keeping the UI responsive."**

# 4. useLayoutEffect

## What is it?

Like `useEffect`, but runs **synchronously after the DOM updates and before the browser paints**.

Useful when you need to **measure or modify the DOM before the user sees it**.

### Example

```jsx
import { useLayoutEffect, useRef } from "react";

function Box() {
  const boxRef = useRef();

  useLayoutEffect(() => {
    console.log(boxRef.current.getBoundingClientRect());
  }, []);

  return <div ref={boxRef}>Hello</div>;
}
```

### Use Cases

* Measuring element size
* Scroll positioning
* Preventing layout flicker

### Difference

| useEffect               | useLayoutEffect                |
| ----------------------- | ------------------------------ |
| After paint             | Before paint                   |
| Doesn't block rendering | Blocks painting until finished |

# 5. useImperativeHandle

## What is it?

Allows a child component to **control what the parent can access through a ref**.

Usually used with `forwardRef` (or React's ref forwarding APIs).

### Example

```jsx
import {
  forwardRef,
  useImperativeHandle,
  useRef
} from "react";

const Input = forwardRef((props, ref) => {
  const inputRef = useRef();

  useImperativeHandle(ref, () => ({
    focus() {
      inputRef.current.focus();
    }
  }));

  return <input ref={inputRef} />;
});
```

Parent:

```jsx
const ref = useRef();

<Input ref={ref} />

<button onClick={() => ref.current.focus()}>
  Focus
</button>
```

### Use Cases

* Expose `focus()`
* Reset forms
* Open/close modal APIs

---

# 6. useSyncExternalStore

## What is it?

Safely subscribes React components to **external stores** (outside React state).

Introduced to support concurrent rendering.

### Example

```jsx
const value = useSyncExternalStore(
  store.subscribe,
  store.getSnapshot
);
```

Whenever the external store changes, React updates the component.

### Use Cases

* Redux internals
* Zustand
* Browser APIs
* Custom global stores

Most application developers rarely use it directly.

---

# 7. useInsertionEffect

## What is it?

Runs **before any DOM mutations** and is mainly intended for **CSS-in-JS libraries** to inject styles before layout calculations.

### Example

```jsx
useInsertionEffect(() => {
  // Insert dynamic CSS
});
```

### Use Cases

* Emotion
* Styled Components
* CSS-in-JS libraries

Application developers almost never need this hook directly.

---

# Quick Comparison

| Hook                   | Purpose                        | Common Use                    |
| ---------------------- | ------------------------------ | ----------------------------- |
| `useId`                | Stable unique IDs              | Forms, accessibility          |
| `useTransition`        | Defer non-urgent state updates | Search, heavy UI updates      |
| `useDeferredValue`     | Defer a value                  | Large lists, filtering        |
| `useLayoutEffect`      | Read/update DOM before paint   | Measurements, scrolling       |
| `useImperativeHandle`  | Customize exposed ref methods  | Focus, modal APIs             |
| `useSyncExternalStore` | Subscribe to external stores   | Redux, Zustand, custom stores |
| `useInsertionEffect`   | Insert CSS before DOM updates  | CSS-in-JS libraries           |

# Common Interview Questions

### 1. What is the difference between `useEffect` and `useLayoutEffect`?

**Answer:** `useEffect` runs after the browser paints, while `useLayoutEffect` runs synchronously after DOM updates but before painting. Use `useLayoutEffect` only when you need to measure or modify the DOM before it's displayed.

---

### 2. `useTransition` vs `useDeferredValue`?

| `useTransition`                     | `useDeferredValue`                                               |
| ----------------------------------- | ---------------------------------------------------------------- |
| Defers a state update               | Defers a value                                                   |
| Uses `startTransition()`            | Uses `useDeferredValue(value)`                                   |
| Best for marking non-urgent updates | Best for delaying expensive computations based on changing input |

---

### 3. When would you use `useImperativeHandle`?

To expose a controlled imperative API (such as `focus()`, `reset()`, or `open()`) from a child component instead of exposing the entire DOM node.

---

### 4. Why was `useSyncExternalStore` introduced?

To provide a consistent and safe way for React to subscribe to external stores in Concurrent React, avoiding issues like inconsistent snapshots during rendering.

---

### 5. Should application developers use `useInsertionEffect`?

Generally **no**. It is designed for authors of CSS-in-JS libraries. Most React applications should use `useEffect` or `useLayoutEffect` instead.
