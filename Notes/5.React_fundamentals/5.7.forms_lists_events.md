# React Fundamentals

This section covers React Forms, Lists, and Events. These are frequently asked in React interviews because they test whether you understand how React handles UI updates efficiently.

---

# 1. Forms

Forms in React are different from normal HTML forms because React prefers controlling form values through state.

There are **two ways** to manage forms:

* Controlled Components
* Uncontrolled Components

---

# Controlled Components

## What?

A controlled component is an input whose value is controlled by **React State**.

React becomes the **single source of truth**.

```jsx
import { useState } from "react";

function App() {
  const [name, setName] = useState("");

  return (
    <input
      value={name}
      onChange={(e) => setName(e.target.value)}
    />
  );
}
```

---

## How it works

```
User Types
      ↓
onChange Event
      ↓
setState()
      ↓
Component Re-renders
      ↓
Input receives updated value
```

---

## Why use Controlled Components?

* Easy validation
* Easy formatting
* Easy conditional rendering
* Easy API submission
* State always available

Example

```jsx
if(name.length < 3){
   showError();
}
```

No DOM lookup required.

---

## Advantages

✔ React controls everything

✔ Easy validation

✔ Instant UI updates

✔ Predictable behavior

✔ Works well with dynamic forms

---

## Disadvantages

Every keystroke causes

```
Input
 ↓
State Update
 ↓
Re-render
```

For very large forms this can affect performance.

---

## Real Example

```jsx
const [email,setEmail]=useState("");

<input
   value={email}
   onChange={(e)=>setEmail(e.target.value)}
/>
```

---

# Uncontrolled Components

## What?

The input manages its own value.

React does **not** store every character in state.

Instead we use **ref** to read the value.

```jsx
import { useRef } from "react";

function App(){

 const inputRef = useRef();

 function submit(){
    console.log(inputRef.current.value);
 }

 return (
   <>
      <input ref={inputRef}/>
      <button onClick={submit}>Submit</button>
   </>
 );
}
```

---

## How it works

```
User Types
      ↓
Browser stores value
      ↓
React doesn't know
      ↓
Read using ref when needed
```

---

## Advantages

* Fewer re-renders
* Better performance for simple forms
* Easier integration with non-React libraries

---

## Disadvantages

* Harder validation
* Less predictable
* React state doesn't know current value

---

# Controlled vs Uncontrolled

| Feature         | Controlled       | Uncontrolled                      |
| --------------- | ---------------- | --------------------------------- |
| Source of Truth | React State      | DOM                               |
| Uses State      | Yes              | No                                |
| Uses Ref        | Optional         | Yes                               |
| Validation      | Easy             | Hard                              |
| Performance     | More re-renders  | Better                            |
| Recommended     | Yes (most cases) | Small/simple forms or file inputs |

---

## File Input

`<input type="file">` is **always uncontrolled** because browsers do not allow JavaScript to set its value for security reasons.

```jsx
const fileRef = useRef();

<input type="file" ref={fileRef} />
```

# React Hook Form Basics

One of the most popular form libraries.

Website

```
react-hook-form.com
```

---

## Why React Hook Form?

Instead of storing every field inside React state,

it stores values using refs internally.

Benefits

* Very fast
* Minimal re-renders
* Easy validation
* Small bundle size

---

## Installation

```bash
npm install react-hook-form
```

---

## Basic Example

```jsx
import { useForm } from "react-hook-form";

function App(){

 const { register, handleSubmit } = useForm();

 const onSubmit = data =>{
     console.log(data);
 }

 return(
    <form onSubmit={handleSubmit(onSubmit)}>

      <input
          {...register("username")}
      />

      <button>Submit</button>

    </form>
 )
}
```

---

## Important APIs

### register()

Registers input

```jsx
<input {...register("email")} />
```

---

### handleSubmit()

Handles validation + submit.

```jsx
<form onSubmit={handleSubmit(onSubmit)}>
```

---

### formState.errors

Validation errors.

```jsx
const {
 register,
 handleSubmit,
 formState:{errors}
}=useForm();
```

Validation

```jsx
<input
 {...register("email",{
    required:"Email Required"
 })}
/>

<p>{errors.email?.message}</p>
```

---

### reset()

Reset form

```jsx
reset();
```

---

### watch()

Observe field values.

```jsx
const password = watch("password");
```

Useful for confirm password fields.

---

## Why companies use React Hook Form?

* Better performance
* Cleaner code
* Easy validation
* Less boilerplate
* Supports dynamic forms

# 2. Lists

React renders lists using JavaScript array methods like `map()`.

```jsx
const users = ["John","Bob","Alice"];

return users.map(user=>(
    <p>{user}</p>
));
```

---

# Key

## What?

A key uniquely identifies each item in a list.

```jsx
users.map(user=>(
   <li key={user.id}>
      {user.name}
   </li>
))
```

---

## Why Key?

During reconciliation React compares

```
Old List

↓

New List
```

Keys help React know

* Which item changed
* Which item moved
* Which item was deleted
* Which item is new

Without keys React may recreate unnecessary DOM nodes.

---

## Good Keys

Use

```
Database ID

UUID

Unique Identifier
```

Example

```jsx
key={employee.id}
```

---

## Bad Keys

Avoid

```jsx
key={Math.random()}
```

Changes every render.

Avoid

```jsx
key={Date.now()}
```

Changes every render.

Avoid index when items are reordered.

```jsx
key={index}
```

Using index can cause state bugs when inserting, deleting, or sorting items.

**When is index acceptable?**

* Static lists that never reorder
* Read-only lists

---

# Fragment

Sometimes React requires one parent element.

Instead of unnecessary divs,

use Fragment.

```jsx
<>
   <h1>Hello</h1>
   <p>World</p>
</>
```

Equivalent

```jsx
<React.Fragment>

</React.Fragment>
```

---

## Why Fragment?

Without Fragment

```jsx
<div>
   ...
</div>
```

Extra DOM node.

With Fragment

No extra DOM element.

Useful inside tables.

```jsx
<>
   <td>Name</td>
   <td>Age</td>
</>
```

---

## Keyed Fragment

When mapping multiple sibling elements, a shorthand fragment (`<>...</>`) cannot take a key.

```jsx
users.map(user => (
  <React.Fragment key={user.id}>
    <h3>{user.name}</h3>
    <p>{user.email}</p>
  </React.Fragment>
));
```

# Conditional Rendering

Show UI based on condition.

---

## if-else

```jsx
if(isLoggedIn){
   return <Home/>
}
return <Login/>
```

---

## Ternary Operator

```jsx
{
 isLoggedIn
 ? <Home/>
 : <Login/>
}
```

Most common.

---

## Logical AND

```jsx
{
 isAdmin && <AdminPanel/>
}
```

Render only when true.

---

## Logical OR / Nullish Coalescing

Useful for fallbacks.

```jsx
{username || "Guest"}
{username ?? "Guest"}
```

`||` treats `0`, `false`, and `""` as falsy, while `??` only falls back for `null` or `undefined`.

---

## Return null

Hide component.

```jsx
if(!visible){
   return null;
}
```

# 3. Events

React events look like DOM events but are handled differently.

---

# Synthetic Events

## What?

React wraps native browser events inside **SyntheticEvent**.

```
Browser Event

↓

SyntheticEvent

↓

React Handler
```

---

## Why?

React provides

* Cross-browser compatibility
* Consistent behavior
* Better abstraction

Regardless of browser,

```jsx
onClick
onChange
onBlur
```

behave consistently.

---

## Example

```jsx
function App(){

 function clickHandler(e){
    console.log(e.type);
 }

 return (
   <button onClick={clickHandler}>
      Click
   </button>
 )
}
```

---

## Access Native Event

```jsx
function handle(e){
   console.log(e.nativeEvent);
}
```

Use only if browser-specific APIs are needed.

---

## Event Naming

HTML

```html
onclick
```

React

```jsx
onClick
```

CamelCase.

---

## Prevent Default

```jsx
function submit(e){
   e.preventDefault();
}
```

---

## Stop Propagation

```jsx
function click(e){
   e.stopPropagation();
}
```

Prevents event bubbling.

---

# Event Pooling (Historical Context)

### Before React 17

React reused (`pooled`) `SyntheticEvent` objects for performance.

After the event handler finished, event properties were cleared.

```jsx
function handle(e){
   setTimeout(()=>{
      console.log(e.target.value); // ❌ Older React: null/error
   },1000);
}
```

Developers had to call:

```jsx
e.persist();
```

to keep the event object.

---

### React 17+

Event pooling was **removed**.

Now this works without `e.persist()`:

```jsx
function handle(e){
   setTimeout(()=>{
      console.log(e.target.value); // ✅ Works
   },1000);
}
```

**Interview point:** Mention that event pooling is a historical optimization. Modern React (17+) no longer pools events.

# Best Practices

### Forms

* Prefer controlled components for most forms.
* Use React Hook Form for large or complex forms.
* Validate inputs before submission.
* Keep validation logic reusable.
* Use uncontrolled inputs only when appropriate (e.g., file inputs or simple integrations).

### Lists

* Always use stable unique keys.
* Never use `Math.random()` or `Date.now()` as keys.
* Avoid index as key if the list changes order.
* Use Fragments to avoid unnecessary DOM elements.

### Events

* Use Synthetic Events instead of native listeners in React components.
* Call `preventDefault()` for form submissions when needed.
* Use `stopPropagation()` only when necessary.
* Avoid relying on `nativeEvent` unless required.

# Short Revision Notes (Cheat Sheet)

### Forms

* Controlled = React State controls input.
* Uncontrolled = DOM controls input (`useRef`).
* Controlled → Easy validation.
* Uncontrolled → Better performance for simple cases.
* File input is always uncontrolled.
* React Hook Form uses refs internally to minimize re-renders.
* Important APIs: `register`, `handleSubmit`, `watch`, `reset`, `formState.errors`.

---

### Lists

* Render lists using `map()`.
* Every list item needs a stable unique `key`.
* Keys help React reconcile efficiently.
* Avoid index as key for dynamic lists.
* Fragment (`<>...</>`) avoids extra DOM nodes.
* Use `React.Fragment` when you need to provide a `key`.
* Conditional rendering: `if`, ternary, `&&`, `??`, `return null`.

---

### Events

* React uses `SyntheticEvent`.
* Same event API across browsers.
* `preventDefault()` → Stops default browser action.
* `stopPropagation()` → Stops bubbling.
* `nativeEvent` gives access to the original browser event.
* Event pooling existed before React 17 and was removed in React 17+.

# Common React Interview Questions (6 Years Experience)

### 1. Controlled vs Uncontrolled Components?

**Answer:** Controlled components use React state as the source of truth, making validation and UI synchronization easier. Uncontrolled components let the DOM manage values and are accessed using refs.

---

### 2. Why is React Hook Form faster than controlled forms?

**Answer:** It relies primarily on refs and subscriptions instead of updating React state on every keystroke, resulting in fewer re-renders and better performance.

---

### 3. Why should keys be unique and stable?

**Answer:** Keys allow React's reconciliation algorithm to correctly identify which items were added, removed, or updated. Unstable keys can cause incorrect UI updates and lost component state.

---

### 4. Why should we avoid using array index as a key?

**Answer:** If items are inserted, removed, or reordered, indices change. React may reuse the wrong component instance, leading to incorrect state or UI behavior.

---

### 5. What is a Fragment?

**Answer:** A Fragment groups multiple elements without adding an extra DOM node. Use `React.Fragment` instead of the shorthand when you need to assign a `key`.

---

### 6. What is a SyntheticEvent?

**Answer:** It is React's cross-browser wrapper around native browser events that provides a consistent event API across browsers.

---

### 7. What was event pooling?

**Answer:** Before React 17, SyntheticEvent objects were reused for performance, requiring `e.persist()` for asynchronous access. React 17 removed event pooling.

---

### 8. When would you choose uncontrolled components?

**Answer:** For file inputs, integrating with third-party non-React libraries, or very simple forms where React doesn't need to track every input value.

---

### 9. Which conditional rendering approach do you prefer?

**Answer:** Use `if` for complex logic, ternary for choosing between two UIs, `&&` for optional rendering, and `return null` when the component should render nothing.

---

### 10. How do you optimize large forms in React?

**Answer:** Use React Hook Form (or similar libraries), avoid unnecessary controlled state where possible, split forms into smaller components, memoize expensive child components, and validate efficiently.
