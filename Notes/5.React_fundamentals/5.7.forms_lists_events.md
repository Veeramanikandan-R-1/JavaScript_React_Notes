# React JS — Forms, Lists & Events

For a **5-year React developer**, focus on the concepts, trade-offs, and interview points rather than just syntax.

---

# 1. Forms

## Controlled Components

In a **controlled component**, React state is the **source of truth** for the input value.

```jsx
function Login() {
  const [email, setEmail] = useState("");

  return (
    <input
      value={email}
      onChange={(e) => setEmail(e.target.value)}
    />
  );
}
```

### Flow

```text
User types
   ↓
onChange
   ↓
setState
   ↓
React re-renders
   ↓
value updated
```

### Advantages

* Easy validation
* Easy conditional UI
* Input value available in React state
* Good for dynamic forms
* Predictable

### Disadvantages

* More boilerplate
* Every change updates React state
* Large forms can require more optimization

### Interview point ⭐

> Controlled = **React controls the input value**.

---

# 2. Uncontrolled Components

In an **uncontrolled component**, the **DOM maintains the input value** instead of React state.

Use `ref` to access the value.

```jsx
function Login() {
  const emailRef = useRef();

  const handleSubmit = (e) => {
    e.preventDefault();
    console.log(emailRef.current.value);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input ref={emailRef} />
      <button>Submit</button>
    </form>
  );
}
```

Here:

```text
DOM → owns input value
React → accesses it using ref
```

### Advantages

* Less code
* No state update on every keystroke
* Useful for simple forms
* Useful when integrating with non-React code

### Disadvantages

* Validation/control can be less straightforward
* Harder to manage complex dynamic UI

### Interview point ⭐

> Uncontrolled = **DOM controls the input value**, React accesses it through refs.

---

## Controlled vs Uncontrolled

|                 | Controlled               | Uncontrolled              |
| --------------- | ------------------------ | ------------------------- |
| Source of truth | React state              | DOM                       |
| Access          | State                    | `ref`                     |
| Validation      | Easy                     | More manual               |
| Boilerplate     | More                     | Less                      |
| Dynamic UI      | Better                   | Less convenient           |
| Performance     | Can require optimization | Often fewer React updates |

**Rule of thumb:**

> Complex/dynamic form → Controlled or form library
> Simple form → Uncontrolled can be sufficient

# 3. React Hook Form Basics

**React Hook Form (RHF)** is a popular form library designed to simplify form handling while minimizing unnecessary React re-renders.

Typical setup:

```jsx
import { useForm } from "react-hook-form";

function Login() {
  const {
    register,
    handleSubmit,
    formState: { errors }
  } = useForm();

  const onSubmit = (data) => {
    console.log(data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input
        {...register("email", {
          required: "Email is required"
        })}
      />

      {errors.email && <p>{errors.email.message}</p>}

      <button type="submit">Login</button>
    </form>
  );
}
```

### Important APIs

#### `register()`

Registers an input with React Hook Form.

```jsx
<input {...register("email")} />
```

---

#### `handleSubmit()`

Handles form submission and provides validated form data.

```jsx
<form onSubmit={handleSubmit(onSubmit)}>
```

---

#### `formState.errors`

Contains validation errors.

```jsx
errors.email?.message
```

---

#### Validation

```jsx
register("email", {
  required: "Email is required",
  pattern: {
    value: /^\S+@\S+\.\S+$/,
    message: "Invalid email"
  }
})
```

### `Controller`

Used mainly when integrating **controlled/custom components** that don't work naturally with `register`.

```jsx
<Controller
  name="country"
  control={control}
  render={({ field }) => (
    <Select {...field} />
  )}
/>
```

### Interview ⭐

> React Hook Form primarily uses an **uncontrolled approach with refs**, which helps reduce unnecessary re-renders. `Controller` is useful for controlled third-party/custom components.

# 4. Lists

React commonly renders lists using `.map()`.

```jsx
const users = [
  { id: 1, name: "John" },
  { id: 2, name: "Alex" }
];

function Users() {
  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>
          {user.name}
        </li>
      ))}
    </ul>
  );
}
```

---

# 5. `key`

`key` uniquely identifies elements in a list.

```jsx
users.map(user => (
  <User key={user.id} user={user} />
))
```

React uses keys during **reconciliation** to determine which items were:

* Added
* Removed
* Moved
* Updated

### Good key

```jsx
key={user.id}
```

### Avoid

```jsx
key={Math.random()} // ❌
```

Because it changes every render.

### Avoid array index when possible

```jsx
key={index} // ⚠️
```

Index can cause incorrect component state/DOM reuse when items are:

* Inserted
* Removed
* Reordered

Index is acceptable when the list is **static and never reordered/changed**.

### Important ⭐

`key` is a **special React prop** and isn't available inside the child:

```jsx
<User key={user.id} />
```

If the child needs the ID:

```jsx
<User key={user.id} id={user.id} />
```

# 6. Fragment

Fragments let you return multiple elements **without adding an extra DOM element**.

```jsx
<>
  <h1>Hello</h1>
  <p>Welcome</p>
</>
```

Equivalent:

```jsx
<React.Fragment>
  <h1>Hello</h1>
  <p>Welcome</p>
</React.Fragment>
```

### Why?

Avoid unnecessary DOM wrappers:

```jsx
<div>
  <h1>Hello</h1>
  <p>Welcome</p>
</div>
```

Fragment produces **no extra DOM node**.

### Keyed Fragment

Short syntax `<>` cannot receive a `key`.

For lists:

```jsx
items.map(item => (
  <React.Fragment key={item.id}>
    <dt>{item.term}</dt>
    <dd>{item.description}</dd>
  </React.Fragment>
))
```

# 7. Conditional Rendering

React supports several approaches.

### `if`

```jsx
if (loading) {
  return <Spinner />;
}

return <Dashboard />;
```

Best for complex conditions/early returns.

---

### Ternary

```jsx
{isLoggedIn ? <Dashboard /> : <Login />}
```

Good for **if/else UI**.

---

### `&&`

```jsx
{isAdmin && <AdminPanel />}
```

Good when rendering something only if a condition is true.

### Gotcha ⭐

```jsx
{count && <p>Hello</p>}
```

If `count = 0`, React can render `0`.

Safer:

```jsx
{count > 0 && <p>Hello</p>}
```

---

### Null

Render nothing:

```jsx
{isLoading ? <Spinner /> : null}
```

# 8. Events — Synthetic Events

React provides **SyntheticEvent**, a wrapper around the browser's native event system.

```jsx
function Button() {
  const handleClick = (event) => {
    console.log(event.type);
  };

  return <button onClick={handleClick}>Click</button>;
}
```

React event:

```jsx
event
```

provides a consistent interface across browsers.

Common events:

```jsx
onClick
onChange
onSubmit
onFocus
onBlur
onKeyDown
onMouseEnter
```

---

## Event Naming

React uses **camelCase**:

```jsx
onClick={handleClick}
```

Not:

```html
onclick="handleClick()"
```

Also, pass the function rather than calling it:

```jsx
onClick={handleClick}     // ✅
```

Not:

```jsx
onClick={handleClick()}   // ❌
```

---

## `preventDefault()`

Prevents the browser's default behavior.

```jsx
function Form() {
  const handleSubmit = (e) => {
    e.preventDefault();

    // custom submit logic
  };

  return <form onSubmit={handleSubmit}>...</form>;
}
```

---

## `stopPropagation()`

Stops an event from propagating to parent elements.

```jsx
const handleButtonClick = (e) => {
  e.stopPropagation();
};
```

# 9. Event Pooling — Historical Context ⭐

In **older React versions (before React 17)**, React used **SyntheticEvent pooling**.

After an event handler finished, React could reuse the event object.

Therefore this could cause problems:

```jsx
function handleClick(e) {
  setTimeout(() => {
    console.log(e.target);
  }, 1000);
}
```

Historically, you might need:

```jsx
e.persist();
```

to keep the event available asynchronously.

### Modern React

**Event pooling was removed in React 17.**

So:

```jsx
setTimeout(() => {
  console.log(e.target); // ✅
}, 1000);
```

works without `e.persist()`.

> `e.persist()` is effectively unnecessary in modern React.

### Interview answer ⭐

> **Event pooling was a performance optimization in older React versions where SyntheticEvent objects were reused after the event handler. React 17 removed event pooling, so `event.persist()` is no longer necessary.**

# Quick Interview Revision ⭐

```text
Forms
 ├── Controlled → React state owns value
 ├── Uncontrolled → DOM owns value + ref
 └── React Hook Form → efficient form management, validation, refs

Lists
 ├── key → stable identity during reconciliation
 ├── Fragment → group elements without extra DOM node
 └── Conditional rendering → if / ternary / && / null

Events
 ├── SyntheticEvent → React's event abstraction
 ├── preventDefault() → stop browser default
 ├── stopPropagation() → stop event propagation
 └── Event pooling → historical; removed in React 17
```
