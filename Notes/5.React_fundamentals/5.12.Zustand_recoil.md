# React JS — Zustand & Recoil

> For a 5-year React developer, focus on **when to use them, core API, re-render behavior, and how they differ from Redux**.

---

# 1. Zustand — Basics

**Zustand** is a lightweight state-management library based on a **store + hooks** approach.

### Why Zustand?

Compared with Redux, Zustand generally requires:

* Less boilerplate
* No reducers/actions/dispatch ceremony
* Simple React hook-based API
* Selective subscriptions → components can subscribe to specific state

---

## Creating a Store

```js
import { create } from "zustand";

const useCounterStore = create((set) => ({
  count: 0,

  increment: () =>
    set((state) => ({
      count: state.count + 1,
    })),

  decrement: () =>
    set((state) => ({
      count: state.count - 1,
    })),
}));
```

### Using in Component

```jsx
function Counter() {
  const count = useCounterStore((state) => state.count);
  const increment = useCounterStore((state) => state.increment);

  return (
    <>
      <p>{count}</p>
      <button onClick={increment}>+</button>
    </>
  );
}
```

### Important

Unlike Redux:

```text
Redux:
Component → dispatch → action → reducer → store → component

Zustand:
Component → store action → state update → component
```

No `Provider` is required for the normal Zustand store.

---

## Updating Multiple Values

```js
const useUserStore = create((set) => ({
  user: null,
  isLoggedIn: false,

  login: (user) =>
    set({
      user,
      isLoggedIn: true,
    }),

  logout: () =>
    set({
      user: null,
      isLoggedIn: false,
    }),
}));
```

---

## Async Actions

Zustand doesn't require a separate `createAsyncThunk`.

```js
const useUserStore = create((set) => ({
  users: [],
  loading: false,

  fetchUsers: async () => {
    set({ loading: true });

    try {
      const response = await fetch("/api/users");
      const users = await response.json();

      set({
        users,
        loading: false,
      });
    } catch (error) {
      set({ loading: false });
    }
  },
}));
```

Use:

```js
const fetchUsers = useUserStore((state) => state.fetchUsers);

useEffect(() => {
  fetchUsers();
}, [fetchUsers]);
```

---

## Selectors — Important

Prefer selecting only what the component needs:

```js
const count = useStore((state) => state.count);
```

instead of:

```js
const store = useStore();
```

Selective subscriptions help avoid unnecessary re-renders.

---

## Zustand Middleware

Common middleware/features:

* `persist` → localStorage/sessionStorage persistence
* `devtools` → Redux DevTools integration
* `immer` → Immer-based updates
* `subscribeWithSelector` → advanced subscriptions

Example:

```js
import { persist } from "zustand/middleware";

const useStore = create(
  persist(
    (set) => ({
      theme: "dark",
      setTheme: (theme) => set({ theme }),
    }),
    {
      name: "app-storage",
    }
  )
);
```

---

## Zustand Interview Points

* Lightweight alternative to Redux.
* Store is created using `create()`.
* Components access state through hooks.
* **No Provider required** for the normal usage.
* Supports async actions directly.
* Selectors allow fine-grained subscriptions.
* Middleware supports persistence, DevTools, Immer, etc.
* Good for simple-to-medium global client state.

# 2. Recoil — Basics

**Recoil** is a state-management library designed specifically for React.

Its main concepts are:

```text
Atom
  ↓
Selector
  ↓
Component
```

> **Note:** Recoil's GitHub repository was archived by Meta in January 2025, so it is generally not a first-choice option for a new production project today.

---

## Atom

An **atom** is a piece of shared state.

```js
import { atom } from "recoil";

export const countState = atom({
  key: "countState",
  default: 0,
});
```

---

## RecoilRoot

Your application needs `RecoilRoot`.

```jsx
import { RecoilRoot } from "recoil";

function App() {
  return (
    <RecoilRoot>
      <Counter />
    </RecoilRoot>
  );
}
```

---

## Reading & Updating Atom

```jsx
import { useRecoilState } from "recoil";
import { countState } from "./state";

function Counter() {
  const [count, setCount] = useRecoilState(countState);

  return (
    <>
      <p>{count}</p>

      <button onClick={() => setCount(count + 1)}>
        +
      </button>
    </>
  );
}
```

Other useful hooks:

### Read only

```js
const count = useRecoilValue(countState);
```

### Write only

```js
const setCount = useSetRecoilState(countState);
```

This can help avoid subscribing to state when the component only needs to update it.

---

# 3. Recoil Selectors

A **selector** represents derived state based on atoms/selectors.

```js
import { selector } from "recoil";

export const doubleCountState = selector({
  key: "doubleCountState",

  get: ({ get }) => {
    const count = get(countState);

    return count * 2;
  },
});
```

Use it:

```jsx
const doubleCount = useRecoilValue(doubleCountState);
```

If:

```text
count = 5
```

then:

```text
doubleCount = 10
```

### Selector can also be writable

```js
const fullNameState = selector({
  key: "fullName",

  get: ({ get }) => {
    const first = get(firstNameState);
    const last = get(lastNameState);

    return `${first} ${last}`;
  },

  set: ({ set }, newValue) => {
    // update underlying atoms
  },
});
```

---

# 4. Async Selectors — Basic Concept

Recoil selectors can also derive data asynchronously.

```js
const userSelector = selector({
  key: "userSelector",

  get: async () => {
    const response = await fetch("/api/user");
    return response.json();
  },
});
```

This allows components to consume async derived state, often with React `Suspense` patterns.

# Zustand vs Recoil

|                        | Zustand                               | Recoil                                     |
| ---------------------- | ------------------------------------- | ------------------------------------------ |
| Main concept           | Store                                 | Atoms + Selectors                          |
| React Provider         | ❌ Normally not required               | ✅ `RecoilRoot`                             |
| Boilerplate            | Very low                              | Low                                        |
| Async logic            | Direct async functions                | Async selectors                            |
| Derived state          | Store selectors                       | Selectors                                  |
| Architecture           | Central store                         | Distributed atoms                          |
| Current recommendation | More commonly considered for new apps | **Avoid for new projects** due to archival |
| Redux alternative      | Yes                                   | Yes                                        |

# Zustand vs Redux Toolkit

For interview discussions:

### Redux Toolkit

```text
Global State
    ↓
Actions
    ↓
Reducers
    ↓
Store
```

Best when you need:

* Large application architecture
* Strict predictable state flow
* Complex state transitions
* Extensive middleware/devtools ecosystem
* RTK Query for server state

### Zustand

```text
Component
    ↓
Zustand Store
    ↓
State + Actions
```

Best when:

* You want minimal boilerplate
* Global client state is relatively simple
* You don't need Redux's architecture

### Most important interview question

**Q: Zustand vs Redux?**

> Zustand is much simpler and has less boilerplate, while Redux Toolkit provides a more structured and scalable architecture with explicit reducers/actions and a larger ecosystem. For complex enterprise applications, RTK is often preferred; for lightweight global client state, Zustand can be a very good choice.

**Q: Would you choose Recoil for a new project?**

> Generally no. Recoil's repository was archived in 2025, so I'd choose a currently maintained solution such as Redux Toolkit, Zustand, or another appropriate state-management approach.
