# React JS — Custom Hooks

Custom Hooks are **reusable JavaScript functions that use React Hooks** (`useState`, `useEffect`, `useContext`, etc.) to extract and share **stateful logic** between components.

> A Custom Hook shares **logic**, not state. Each component calling the hook gets its **own state**.

---

## 1. Rules of Custom Hooks

Custom Hooks follow the same **Rules of Hooks**.

### Rule 1 — Name must start with `use`

```jsx
function useCounter() {
  const [count, setCount] = useState(0);
  return { count, setCount };
}
```

✅ `useCounter`
❌ `counterHook`

React uses the `use` naming convention to identify functions that may contain Hooks.

---

### Rule 2 — Call Hooks only at the top level

Don't call Hooks inside:

* `if/else`
* loops
* nested functions
* callbacks
* `try/catch`

❌

```jsx
function useUser(isLoggedIn) {
  if (isLoggedIn) {
    const [user, setUser] = useState(null); // ❌
  }
}
```

✅

```jsx
function useUser(isLoggedIn) {
  const [user, setUser] = useState(null);

  if (!isLoggedIn) {
    // normal logic
  }
}
```

---

### Rule 3 — Custom Hooks can call other Hooks

```jsx
function useCounter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    console.log(count);
  }, [count]);

  return { count, setCount };
}
```

---

### Rule 4 — Call Custom Hooks only from React functions

✅ Component:

```jsx
function App() {
  const { count } = useCounter();
}
```

✅ Another Custom Hook:

```jsx
function useSomething() {
  const { count } = useCounter();
}
```

❌ Normal utility function:

```jsx
function calculate() {
  const [count] = useState(0); // ❌
}
```

# 2. Basic Custom Hook Example

### Without Custom Hook

Two components may duplicate this logic:

```jsx
const [count, setCount] = useState(0);

const increment = () => setCount(c => c + 1);
const decrement = () => setCount(c => c - 1);
```

### Extract into Custom Hook

```jsx
function useCounter(initialValue = 0) {
  const [count, setCount] = useState(initialValue);

  const increment = () => setCount(c => c + 1);
  const decrement = () => setCount(c => c - 1);
  const reset = () => setCount(initialValue);

  return { count, increment, decrement, reset };
}
```

Usage:

```jsx
function Counter() {
  const { count, increment, decrement, reset } = useCounter(10);

  return (
    <>
      <p>{count}</p>
      <button onClick={increment}>+</button>
      <button onClick={decrement}>-</button>
      <button onClick={reset}>Reset</button>
    </>
  );
}
```

### Key point

If 2 components use:

```jsx
useCounter()
```

they **do not share the same `count`**.

Each gets an independent state instance.

# 3. Reusability

Custom Hooks are useful when **the same stateful behavior is needed in multiple components**.

### Example: `useDebounce`

```jsx
function useDebounce(value, delay = 500) {
  const [debouncedValue, setDebouncedValue] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => {
      setDebouncedValue(value);
    }, delay);

    return () => clearTimeout(timer);
  }, [value, delay]);

  return debouncedValue;
}
```

Usage:

```jsx
function Search() {
  const [search, setSearch] = useState("");

  const debouncedSearch = useDebounce(search, 500);

  useEffect(() => {
    if (debouncedSearch) {
      // API call
    }
  }, [debouncedSearch]);

  return (
    <input
      value={search}
      onChange={e => setSearch(e.target.value)}
    />
  );
}
```

Now the same debounce logic can be reused in:

```jsx
SearchUsers
SearchProducts
SearchOrders
```

# 4. Best Practices

### 1. Keep hooks focused

❌ One huge hook:

```jsx
useUserEverything()
```

Prefer smaller hooks:

```jsx
useUser()
useAuth()
usePermissions()
useUserPreferences()
```

**Single responsibility** makes hooks easier to test and maintain.

---

### 2. Return only what consumers need

❌

```jsx
return {
  state,
  setState,
  internalTimer,
  internalFunction,
  ...
};
```

Prefer:

```jsx
return {
  data,
  loading,
  error,
  refetch
};
```

---

### 3. Don't create a Custom Hook for simple calculations

❌ Unnecessary:

```jsx
function useAdd(a, b) {
  return a + b;
}
```

Just use:

```jsx
const result = a + b;
```

Custom Hooks are mainly valuable for **reusable stateful/side-effect logic**.

---

### 4. Keep API logic reusable

```jsx
function useUsers() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);

  useEffect(() => {
    // fetch users
  }, []);

  return { users, loading, error };
}
```

Component focuses on UI:

```jsx
function UserList() {
  const { users, loading, error } = useUsers();

  if (loading) return <p>Loading...</p>;
  if (error) return <p>Error</p>;

  return users.map(user => (
    <div key={user.id}>{user.name}</div>
  ));
}
```

**Separation of concerns:**

```text
Component → UI
Custom Hook → Stateful/business logic
API service → HTTP communication
```

---

### 5. Follow dependency rules

When using `useEffect` inside a Custom Hook, maintain correct dependencies.

```jsx
useEffect(() => {
  fetchUser(userId);
}, [userId]);
```

Don't intentionally omit dependencies just to silence ESLint.

---

### 6. Avoid unnecessary abstraction

Don't create a Custom Hook just because you can.

Use one when:

* Logic is reused
* Component logic is becoming complex
* Stateful logic needs separation
* Side-effect logic needs to be encapsulated

---

# 5. Custom Hook vs Utility Function

| Custom Hook                           | Utility Function             |
| ------------------------------------- | ---------------------------- |
| Can use React Hooks                   | Cannot use React Hooks       |
| Name starts with `use`                | No naming requirement        |
| Stateful logic                        | Usually pure/stateless logic |
| Can use `useState`, `useEffect`, etc. | Normal JS                    |
| Used inside React components/hooks    | Can be used anywhere         |

Example:

```jsx
// Custom Hook
function useWindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);
  // ...
}
```

```jsx
// Utility
function formatCurrency(amount) {
  return `$${amount.toFixed(2)}`;
}
```

# 6. Important Interview Points ⭐

**Q: What is a Custom Hook?**

> A JavaScript function starting with `use` that encapsulates reusable stateful React logic.

**Q: Does a Custom Hook share state?**

> No. It shares **logic**, while each invocation gets its own state.

**Q: Can a Custom Hook call another Custom Hook?**

> Yes.

```jsx
function useAuthUser() {
  const user = useUser();
  const permissions = usePermissions();

  return { user, permissions };
}
```

**Q: When should you create a Custom Hook?**

> When stateful logic, effects, subscriptions, event handling, fetching, etc. need to be reused or isolated from UI components.

**Q: Custom Hook vs HOC?**

> Custom Hooks reuse **logic inside components**; HOCs reuse **component behavior by wrapping components**. For modern React, Custom Hooks are generally preferred for logic reuse.

### One-line revision

> **Custom Hook = reusable stateful logic + Rules of Hooks + starts with `use` + each call has independent state.**
