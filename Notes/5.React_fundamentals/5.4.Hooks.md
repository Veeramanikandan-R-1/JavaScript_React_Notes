# React Hooks — Core Hooks

For a **5-year React developer**, know for each Hook: **purpose → when to use → common mistake → simple example**.

> **Hooks let functional components use React features such as state, context, refs, and Effects.**

### Rules of Hooks

Hooks must:

1. Be called **only at the top level** of a component/custom Hook.
2. Not be called inside `if`, loops, nested functions, etc.
3. Be called from **React components or custom Hooks**.

```jsx
// ❌ Wrong
if (isLoggedIn) {
  useState(0);
}

// ✅ Correct
const [count, setCount] = useState(0);
```

React relies on the **consistent order of Hook calls**.

---

# 1. `useState`

Used for **local component state**.

```jsx
const [count, setCount] = useState(0);
```

* `count` → current state
* `setCount` → updates state
* State update schedules a re-render

### Example

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  return (
    <>
      <p>{count}</p>
      <button onClick={() => setCount(c => c + 1)}>
        Increment
      </button>
    </>
  );
}
```

### Functional update

Use when the new value depends on the previous value:

```jsx
setCount(prev => prev + 1);
```

### Object state

```jsx
const [user, setUser] = useState({
  name: "John",
  age: 25
});

setUser(prev => ({
  ...prev,
  age: 26
}));
```

❌ Don't mutate:

```jsx
user.age = 26;
```

### Lazy initialization

For expensive initial calculation:

```jsx
const [data, setData] = useState(() => expensiveCalculation());
```

The initializer is used to calculate the initial state rather than doing the calculation on every render.

### Interview point

> State updates are scheduled; don't assume `setState` immediately changes the current state variable within the same render.

# 2. `useEffect`

Used to **synchronize a component with external systems** such as:

* API/network requests
* Event listeners
* Timers
* WebSockets
* Subscriptions
* Browser APIs

```jsx
useEffect(() => {
  // Effect
}, [dependencies]);
```

### Mount-style Effect

```jsx
useEffect(() => {
  console.log("Effect ran");
}, []);
```

### Dependency-based Effect

```jsx
useEffect(() => {
  fetchUser(userId);
}, [userId]);
```

Runs when `userId` changes.

### Cleanup

```jsx
useEffect(() => {
  const timer = setInterval(() => {
    console.log("Running");
  }, 1000);

  return () => {
    clearInterval(timer);
  };
}, []);
```

Cleanup happens when the component unmounts and before the Effect re-runs because its dependencies changed.

### Important misconception

Don't say:

> "`useEffect` is for componentDidMount."

Better:

> **`useEffect` synchronizes with external systems after a commit and can optionally clean up that synchronization.**

Also, if something can be calculated during rendering, you usually **don't need an Effect**.

```jsx
// ❌ Unnecessary
useEffect(() => {
  setFullName(firstName + " " + lastName);
}, [firstName, lastName]);

// ✅
const fullName = `${firstName} ${lastName}`;
```

# 3. `useContext`

Used to **read values from React Context** without passing props through every intermediate component.

### Create context

```jsx
const ThemeContext = createContext();
```

### Provider

Modern React supports:

```jsx
<ThemeContext value="dark">
  <App />
</ThemeContext>
```

You may also encounter the older/common form:

```jsx
<ThemeContext.Provider value="dark">
  <App />
</ThemeContext.Provider>
```

### Consume

```jsx
function Button() {
  const theme = useContext(ThemeContext);

  return <button className={theme}>Click</button>;
}
```

### Common use cases

* Theme
* Authentication/user context
* Locale
* App-level configuration

### Important performance point

When the context value changes, consumers reading that context can re-render.

Avoid putting frequently changing large objects into a single global context unnecessarily.

```jsx
// Potentially causes consumers to update whenever
// any field in this value changes
<AuthContext value={{ user, permissions, settings }}>
```

For complex/global state, dedicated state-management solutions or carefully split contexts may be more appropriate.

# 4. `useReducer`

Useful for **complex state logic**, especially when multiple state transitions are related.

```jsx
const [state, dispatch] = useReducer(reducer, initialState);
```

### Example

```jsx
const initialState = {
  count: 0
};

function reducer(state, action) {
  switch (action.type) {
    case "increment":
      return {
        ...state,
        count: state.count + 1
      };

    case "decrement":
      return {
        ...state,
        count: state.count - 1
      };

    default:
      return state;
  }
}
```

Component:

```jsx
function Counter() {
  const [state, dispatch] = useReducer(
    reducer,
    initialState
  );

  return (
    <>
      <p>{state.count}</p>

      <button onClick={() => dispatch({ type: "increment" })}>
        +
      </button>

      <button onClick={() => dispatch({ type: "decrement" })}>
        -
      </button>
    </>
  );
}
```

### Flow

```text
User action
    ↓
dispatch(action)
    ↓
reducer(state, action)
    ↓
new state
    ↓
re-render
```

### `useState` vs `useReducer`

| `useState`               | `useReducer`                          |
| ------------------------ | ------------------------------------- |
| Simple state             | Complex state logic                   |
| Direct setter            | `dispatch(action)`                    |
| Less boilerplate         | More structured                       |
| Good for isolated values | Good for multiple related transitions |

# 5. `useRef`

Stores a **mutable value that persists across renders without causing a re-render when changed**.

```jsx
const ref = useRef(initialValue);
```

Access:

```jsx
ref.current
```

## Use case 1 — DOM reference

```jsx
function Input() {
  const inputRef = useRef(null);

  const focusInput = () => {
    inputRef.current.focus();
  };

  return (
    <>
      <input ref={inputRef} />
      <button onClick={focusInput}>
        Focus
      </button>
    </>
  );
}
```

## Use case 2 — Store mutable value

```jsx
const timerRef = useRef(null);

timerRef.current = setInterval(...);
```

### Important

Changing:

```jsx
ref.current = value;
```

**does not trigger a re-render.**

### `useState` vs `useRef`

```text
useState → value changes → re-render
useRef   → value changes → no re-render
```

### Interview point

> `useRef` is useful for DOM references and persistent mutable values that don't need to participate in rendering.

# 6. `useMemo`

Used to **cache the result of an expensive calculation** between renders.

```jsx
const result = useMemo(
  () => expensiveCalculation(data),
  [data]
);
```

### Example

```jsx
function ProductList({ products, search }) {
  const filteredProducts = useMemo(() => {
    return products.filter(product =>
      product.name
        .toLowerCase()
        .includes(search.toLowerCase())
    );
  }, [products, search]);

  return <ProductListView products={filteredProducts} />;
}
```

React can reuse the memoized result when dependencies haven't changed.

### Don't overuse it

❌ Don't blindly do:

```jsx
const name = useMemo(() => user.name, [user]);
```

For cheap calculations, `useMemo` can add unnecessary complexity.

### Interview point

> `useMemo` is a **performance optimization**, not a correctness mechanism.

---

# 7. `useCallback`

Used to **cache a function reference** between renders.

```jsx
const handleClick = useCallback(() => {
  // logic
}, [dependencies]);
```

### Why?

Every render normally creates a new function:

```jsx
const handleClick = () => {
  console.log("clicked");
};
```

With `useCallback`:

```jsx
const handleClick = useCallback(() => {
  console.log("clicked");
}, []);
```

React can reuse the same function reference until dependencies change.

### Common use case — `React.memo`

```jsx
const Child = React.memo(function Child({ onClick }) {
  console.log("Child render");

  return <button onClick={onClick}>Click</button>;
});

function Parent() {
  const handleClick = useCallback(() => {
    console.log("Clicked");
  }, []);

  return <Child onClick={handleClick} />;
}
```

Without `useCallback`, `Parent` creates a new `handleClick` function on each render, potentially causing the memoized `Child` to re-render.

### Don't overuse

`useCallback` itself has a cost and adds complexity.

Use it when **referential equality actually matters**, commonly with memoized children or hook dependencies.

# `useMemo` vs `useCallback`

This is a very common interview question.

```jsx
useMemo(
  () => calculateValue(),
  [deps]
);
```

→ **memoizes a value**

```jsx
useCallback(
  () => doSomething(),
  [deps]
);
```

→ **memoizes a function**

Conceptually:

```jsx
useCallback(fn, deps)
```

is similar to:

```jsx
useMemo(() => fn, deps)
```

# ⭐ Quick Revision Table

| Hook          | Purpose                                 | Causes re-render when changed?                                 |
| ------------- | --------------------------------------- | -------------------------------------------------------------- |
| `useState`    | Local state                             | ✅ Yes                                                          |
| `useEffect`   | External synchronization / side effects | ❌ Effect itself doesn't cause one; state updates inside it can |
| `useContext`  | Read context                            | Context changes can re-render consumers                        |
| `useReducer`  | Complex state management                | ✅ Yes                                                          |
| `useRef`      | DOM ref / persistent mutable value      | ❌ No                                                           |
| `useMemo`     | Memoize calculated value                | ❌ No                                                           |
| `useCallback` | Memoize function reference              | ❌ No                                                           |

# 🧠 Senior-Level Mental Model

```text
                React Component
                      │
       ┌──────────────┼──────────────┐
       ↓              ↓              ↓
   useState       useReducer      useContext
       │              │              │
       └──────────────┼──────────────┘
                      ↓
                 Re-render
                      │
          ┌───────────┴───────────┐
          ↓                       ↓
      useMemo                 useCallback
   memoize value            memoize function
          │                       │
          └───────────┬───────────┘
                      ↓
                  useRef
             persistent mutable
               value / DOM ref
                      │
                      ↓
                  useEffect
           synchronize with external
                 systems
```

## 🔥 Interview Must-Know

1. **`useState`** → simple local state.
2. **`useReducer`** → complex state transitions.
3. **`useEffect`** → synchronize with external systems; cleanup when necessary.
4. **`useContext`** → consume context and avoid prop drilling.
5. **`useRef`** → persistent value/DOM reference without triggering render.
6. **`useMemo`** → memoize an expensive/computational value.
7. **`useCallback`** → memoize a function reference.
8. **Never use `useMemo`/`useCallback` blindly**—they are optimizations, not default requirements.
9. **Hooks must be called in the same order**; never conditionally call Hooks.
10. **A Hook doesn't automatically prevent re-renders.** `useMemo`/`useCallback` help only in specific optimization scenarios.
