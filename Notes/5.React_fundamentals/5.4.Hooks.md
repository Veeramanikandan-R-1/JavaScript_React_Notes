# React Fundamentals – Core Hooks

Hooks were introduced in **React 16.8** to allow **functional components** to use state, lifecycle features, context, refs, and other React capabilities **without writing class components**.

## Why Hooks?

Before Hooks:

* State → Only class components
* Lifecycle methods → Only class components
* Reusing stateful logic → Difficult (HOCs, Render Props)

After Hooks:

* Functional components can do everything class components can.
* Logic becomes reusable using **custom hooks**.
* Code is easier to read, test, and maintain.

---

# 1. useState

## What is useState?

`useState` lets a functional component store and update state.

Think of it as the component's **memory**.

```jsx
const [count, setCount] = useState(0);
```

* `count` → current state
* `setCount()` → updates state
* `0` → initial value

---

## Syntax

```jsx
const [state, setState] = useState(initialValue);
```

---

## Example 1 – Counter

```jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <>
      <h2>{count}</h2>

      <button onClick={() => setCount(count + 1)}>
        Increment
      </button>
    </>
  );
}
```

---

## Example 2 – Object State

```jsx
const [user, setUser] = useState({
  name: "John",
  age: 25
});

setUser({
  ...user,
  age: 26
});
```

Always spread the previous object because `useState` **replaces** the entire value.

---

## Example 3 – Functional Update

```jsx
setCount(prev => prev + 1);
```

Preferred when the next state depends on the previous state.

---

## Common Mistake

```jsx
setCount(count + 1);
setCount(count + 1);
```

Result:

```text
count + 1
```

Not:

```text
count + 2
```

Correct:

```jsx
setCount(prev => prev + 1);
setCount(prev => prev + 1);
```

Result:

```text
count + 2
```

---

## When to use

* Form fields
* Counters
* Toggle
* Modal open/close
* Local UI state

---

# 2. useEffect

## What is useEffect?

`useEffect` performs **side effects** after rendering.

Examples:

* API calls
* Timers
* Event listeners
* Local Storage
* WebSocket
* Analytics

---

## Syntax

```jsx
useEffect(() => {

}, []);
```

---

## Example 1 – API Call

```jsx
useEffect(() => {
  fetch("/users")
    .then(res => res.json())
    .then(setUsers);
}, []);
```

Runs only once after mounting.

---

## Example 2 – Dependency

```jsx
useEffect(() => {
  console.log("Count changed");
}, [count]);
```

Runs whenever `count` changes.

---

## Example 3 – Cleanup

```jsx
useEffect(() => {
  const timer = setInterval(() => {
    console.log("Running");
  }, 1000);

  return () => {
    clearInterval(timer);
  };
}, []);
```

Cleanup prevents memory leaks.

---

## Dependency Behavior

```jsx
useEffect(() => {});
```

Runs after every render.

---

```jsx
useEffect(() => {}, []);
```

Runs once.

---

```jsx
useEffect(() => {}, [count]);
```

Runs whenever `count` changes.

---

## When to use

* API requests
* Subscriptions
* DOM listeners
* Timers
* Cleanup

---

# 3. useContext

## What is useContext?

Allows components to consume shared data **without prop drilling**.

Without Context:

```text
App
 ↓
Parent
 ↓
Child
 ↓
GrandChild
```

Every component passes props.

With Context:

```text
App

↓

Context

↓

Any Component
```

---

## Create Context

```jsx
import { createContext } from "react";

export const ThemeContext = createContext();
```

---

## Provide Context

```jsx
<ThemeContext.Provider value="dark">
  <App />
</ThemeContext.Provider>
```

---

## Consume Context

```jsx
const theme = useContext(ThemeContext);

return <h1>{theme}</h1>;
```

---

## Real Example

```jsx
const UserContext = createContext();

<UserContext.Provider value={{ name: "John" }}>
  <Dashboard />
</UserContext.Provider>
```

```jsx
function Dashboard() {
  const user = useContext(UserContext);

  return <h1>{user.name}</h1>;
}
```

---

## When to use

* Theme
* Logged-in user
* Language
* Authentication
* Global settings

---

# 4. useReducer

## What is useReducer?

Alternative to `useState`.

Best for:

* Complex state
* Multiple state updates
* Predictable state transitions

Very similar to Redux.

---

## Syntax

```jsx
const [state, dispatch] = useReducer(reducer, initialState);
```

---

## Reducer

```jsx
function reducer(state, action) {

  switch(action.type){

    case "increment":
      return { count: state.count + 1 };

    case "decrement":
      return { count: state.count - 1 };

    default:
      return state;
  }

}
```

---

## Component

```jsx
const initialState = {
  count: 0
};

function Counter() {

  const [state, dispatch] = useReducer(reducer, initialState);

  return (
    <>
      <h2>{state.count}</h2>

      <button
        onClick={() => dispatch({ type: "increment" })}
      >
        +
      </button>

      <button
        onClick={() => dispatch({ type: "decrement" })}
      >
        -
      </button>
    </>
  );
}
```

---

## Why useReducer?

Instead of:

```jsx
setUser(...)
setCart(...)
setLoading(...)
setError(...)
```

Centralize logic:

```text
Action

↓

Reducer

↓

New State
```

---

## When to use

* Shopping cart
* Forms
* Wizard steps
* Authentication
* Complex state

---

# 5. useRef

## What is useRef?

Stores a mutable value **without causing re-renders**.

Also used to access DOM elements.

---

## Syntax

```jsx
const inputRef = useRef(null);
```

---

## Example 1 – Focus Input

```jsx
function Login() {

  const inputRef = useRef();

  const focusInput = () => {
    inputRef.current.focus();
  };

  return (
    <>
      <input ref={inputRef} />

      <button onClick={focusInput}>
        Focus
      </button>
    </>
  );
}
```

---

## Example 2 – Previous Value

```jsx
const prevCount = useRef();

useEffect(() => {
  prevCount.current = count;
}, [count]);

return (
  <>
    Current: {count}

    Previous: {prevCount.current}
  </>
);
```

---

## Example 3 – Timer ID

```jsx
const timerRef = useRef();

timerRef.current = setInterval(...);

clearInterval(timerRef.current);
```

---

## Difference

```text
useState

Update

↓

Re-render
```

```text
useRef

Update

↓

No Re-render
```

---

## When to use

* DOM access
* Previous values
* Timer IDs
* Mutable values

---

# 6. useMemo

## What is useMemo?

Caches an **expensive calculated value**.

Without useMemo:

Every render recalculates.

With useMemo:

Calculation happens only when dependencies change.

---

## Syntax

```jsx
const value = useMemo(() => {

}, [dependencies]);
```

---

## Example

```jsx
const sortedUsers = useMemo(() => {

  console.log("Sorting");

  return [...users].sort(
    (a, b) => a.age - b.age
  );

}, [users]);
```

Sorting only runs when `users` changes.

---

## Another Example

```jsx
const total = useMemo(() => {

  return products.reduce(
    (sum, p) => sum + p.price,
    0
  );

}, [products]);
```

---

## Don't use for

```jsx
const fullName = useMemo(() => first + last, [first, last]);
```

Simple string concatenation doesn't need memoization.

---

## When to use

* Expensive calculations
* Sorting
* Filtering
* Large datasets


A **good interview example** for `useMemo` is **filtering a large list of users**. Without `useMemo`, the filtering runs on **every render**, even when the user list hasn't changed.

---

# Without useMemo (Expensive calculation runs every render)

```jsx
import { useState } from "react";

function App() {
  const [search, setSearch] = useState("");
  const [count, setCount] = useState(0);

  // Imagine this contains 10,000 users
  const users = [
    "John",
    "Alice",
    "Bob",
    "David",
    "Alex",
    "Johnny"
  ];

  console.log("Filtering users...");

  const filteredUsers = users.filter(user =>
    user.toLowerCase().includes(search.toLowerCase())
  );

  return (
    <>
      <input
        value={search}
        onChange={(e) => setSearch(e.target.value)}
        placeholder="Search user"
      />

      <button onClick={() => setCount(count + 1)}>
        Counter: {count}
      </button>

      <ul>
        {filteredUsers.map(user => (
          <li key={user}>{user}</li>
        ))}
      </ul>
    </>
  );
}
```

### Problem

Clicking the **Counter** button prints:

```
Filtering users...
Filtering users...
Filtering users...
```

Even though the **user list** and **search text** didn't change.

The expensive filtering is executed on **every render**.

---

# With useMemo (Optimized)

```jsx
import { useMemo, useState } from "react";

function App() {
  const [search, setSearch] = useState("");
  const [count, setCount] = useState(0);

  const users = [
    "John",
    "Alice",
    "Bob",
    "David",
    "Alex",
    "Johnny"
  ];

  const filteredUsers = useMemo(() => {
    console.log("Filtering users...");

    return users.filter(user =>
      user.toLowerCase().includes(search.toLowerCase())
    );
  }, [search]);

  return (
    <>
      <input
        value={search}
        onChange={(e) => setSearch(e.target.value)}
        placeholder="Search user"
      />

      <button onClick={() => setCount(count + 1)}>
        Counter: {count}
      </button>

      <ul>
        {filteredUsers.map(user => (
          <li key={user}>{user}</li>
        ))}
      </ul>
    </>
  );
}
```

---

# What Happens?

### Initial Render

```
Filtering users...
```

### Click Counter

```
(No filtering)
```

Because only `count` changed.

### Change Search

```
Filtering users...
```

Because `search` is in the dependency array.

---

# How `useMemo` Works Internally

```
Render
   │
   ▼
Has dependency changed?
        │
   ┌────┴─────┐
   │          │
 No         Yes
   │          │
Return      Recalculate
cached      value
value
```

# Real-World Scenarios

`useMemo` is useful for:

* Filtering **10,000+ records**
* Sorting large tables
* Calculating dashboard statistics
* Building chart data
* Grouping or aggregating API responses

# Interview Answer (6 Years Experience)

> **"I use `useMemo` to memoize expensive computed values, such as filtering or sorting large datasets. It prevents recalculating the value on every render and recomputes it only when its dependencies change. However, I don't use it for trivial calculations because memoization itself has a small overhead."**

This is the kind of explanation interviewers typically expect from a senior React developer.

# 7. useCallback

## What is useCallback?

Caches a **function reference**.

Useful when passing callbacks to memoized child components.

---

## Without useCallback

```jsx
const handleClick = () => {
  console.log("Clicked");
};
```

A new function is created on every render.

---

## With useCallback

```jsx
const handleClick = useCallback(() => {
  console.log("Clicked");
}, []);
```

The same function reference is reused until dependencies change.

---

## Solid Example

### Child

```jsx
const Child = React.memo(({ onSave }) => {
  console.log("Child Render");

  return (
    <button onClick={onSave}>
      Save
    </button>
  );
});
```

---

### Parent (Without useCallback)

```jsx
function Parent() {

  const [count, setCount] = useState(0);

  const handleSave = () => {
    console.log("Saved");
  };

  return (
    <>
      <button onClick={() => setCount(count + 1)}>
        Count
      </button>

      <Child onSave={handleSave} />
    </>
  );
}
```

Every click recreates `handleSave`, so `Child` re-renders even though nothing relevant changed.

---

### Parent (With useCallback)

```jsx
const handleSave = useCallback(() => {
  console.log("Saved");
}, []);
```

Now `Child` does **not** re-render unnecessarily because `handleSave` keeps the same reference.

---

## When to use

* Event handlers passed to `React.memo` components
* Stable callback references
* Performance optimization

---

# useMemo vs useCallback

| Hook          | Memoizes | Returns         |
| ------------- | -------- | --------------- |
| `useMemo`     | Value    | Cached value    |
| `useCallback` | Function | Cached function |

```jsx
const total = useMemo(() => calculateTotal(items), [items]);

const handleSave = useCallback(() => saveUser(), []);
```

---

# Best Practices

* Use `useState` for simple local state.
* Use `useReducer` for complex or related state updates.
* Always specify correct dependencies in `useEffect`.
* Use `useRef` for mutable values and DOM access, not UI state.
* Don't overuse `useMemo` or `useCallback`; use them only after identifying unnecessary recalculations or re-renders.
* Keep Context focused; avoid putting frequently changing large objects in a single context to reduce unnecessary re-renders.

---

# Revision Notes (5-Minute Cheat Sheet)

| Hook          | Purpose              | Typical Use                                |
| ------------- | -------------------- | ------------------------------------------ |
| `useState`    | Local state          | Counter, forms, toggles                    |
| `useEffect`   | Side effects         | API, timers, listeners                     |
| `useContext`  | Shared state         | Theme, auth, language                      |
| `useReducer`  | Complex state        | Forms, cart, workflows                     |
| `useRef`      | Mutable value/DOM    | Focus input, timers, previous value        |
| `useMemo`     | Cache computed value | Sorting, filtering, expensive calculations |
| `useCallback` | Cache function       | Stable callbacks for memoized children     |

### Remember

```jsx
// State
const [state, setState] = useState();

// Side effects
useEffect(() => {}, []);

// Shared data
const value = useContext(Context);

// Complex state
const [state, dispatch] = useReducer(reducer, initialState);

// DOM reference
const ref = useRef();

// Memoized value
const value = useMemo(() => expensiveFn(), [deps]);

// Memoized function
const fn = useCallback(() => {}, [deps]);
```

# Common React Interview Questions (6 Years Experience)

### 1. When would you choose `useReducer` over `useState`?

**Answer:** Use `useState` for simple independent state. Use `useReducer` when state is complex, multiple values change together, or updates depend on action types, making the logic easier to maintain.

---

### 2. What is the difference between `useMemo` and `useCallback`?

**Answer:** `useMemo` memoizes the **result of a computation**, while `useCallback` memoizes the **function itself**.

---

### 3. Does `useMemo` improve performance in every case?

**Answer:** No. Memoization has its own overhead. It should only be used for expensive calculations or when preserving referential equality provides a measurable benefit.

---

### 4. Why doesn't updating `useRef.current` trigger a re-render?

**Answer:** React does not track changes to `ref.current` as part of its rendering process. `useRef` is intended for mutable values that should persist across renders without affecting the UI.

---

### 5. What happens if you forget dependencies in `useEffect`?

**Answer:** The effect may use stale values (stale closures), fail to rerun when expected, or produce bugs. The `react-hooks/exhaustive-deps` ESLint rule helps identify missing dependencies.

---

### 6. Can `useContext` replace Redux?

**Answer:** For small to medium global state (theme, authentication, locale), yes. For large applications with complex state management, middleware, devtools, caching, and advanced debugging, Redux (or similar libraries) is often a better fit.

---

### 7. When should you use `React.memo` with `useCallback`?

**Answer:** When a memoized child component receives callback props. `useCallback` keeps the callback reference stable, allowing `React.memo` to skip unnecessary child re-renders.

---

### 8. Why are Hooks required to be called at the top level?

**Answer:** React relies on the order of Hook calls to associate Hook state with the correct component. Calling Hooks conditionally or inside loops changes that order and breaks React's internal bookkeeping.

---

### 9. What is a stale closure in React Hooks?

**Answer:** A stale closure occurs when a Hook captures an old value from a previous render because the dependency array is incomplete or incorrect.

---

### 10. What is the order of execution during the initial render?

**Answer:** Component function executes → JSX is rendered → DOM is committed → `useEffect` callbacks run (or `useLayoutEffect` before the browser paints). Understanding this order is important for debugging rendering and side effects.
