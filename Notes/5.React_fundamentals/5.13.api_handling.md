# 1. fetch

`fetch()` is the browser's built-in API for making HTTP requests.

No external library is required.

```javascript
fetch("/api/users")
  .then(res => res.json())
  .then(data => console.log(data));
```

Using async/await

```javascript
const getUsers = async () => {
    const response = await fetch("/api/users");

    if (!response.ok) {
        throw new Error("API Failed");
    }

    return await response.json();
};
```

# 1. Axios (Recommended)

Axios has built-in timeout support.

```javascript
import axios from "axios";

const api = axios.create({
  baseURL: "/api",
  timeout: 5000, // 5 seconds
});

try {
  const response = await api.get("/users");
  console.log(response.data);
} catch (error) {
  if (error.code === "ECONNABORTED") {
    console.log("Request timed out");
  } else {
    console.log(error.message);
  }
}
```

If the server doesn't respond within **5 seconds**, Axios aborts the request.

---

# 2. fetch() using AbortController

`fetch` doesn't have a built-in timeout, so use `AbortController`.

```javascript
const controller = new AbortController();

setTimeout(() => {
  controller.abort();
}, 5000);

try {
  const response = await fetch("/api/users", {
    signal: controller.signal,
  });

  const data = await response.json();
  console.log(data);
} catch (err) {
  if (err.name === "AbortError") {
    console.log("Request timed out");
  }
}
```

---

# 3. Reusable fetch with timeout (Production)

```javascript
async function fetchWithTimeout(url, options = {}, timeout = 5000) {
  const controller = new AbortController();

  const timeoutId = setTimeout(() => {
    controller.abort();
  }, timeout);

  try {
    const response = await fetch(url, {
      ...options,
      signal: controller.signal,
    });

    return response;
  } finally {
    clearTimeout(timeoutId); // Prevent unnecessary timer execution
  }
}
```

Usage:

```javascript
const response = await fetchWithTimeout("/api/users");
const data = await response.json();
```

---

# 4. Axios Request-Level Timeout

You can also override the timeout for a specific request.

```javascript
await axios.get("/users", {
  timeout: 10000, // 10 seconds
});
```

# Interview Answer (6 Years Experience)

**Q: How do you implement API timeout in React?**

**Answer:**

* **Axios:** Use the built-in `timeout` option in the Axios instance or per request. Handle timeout errors by checking `error.code === "ECONNABORTED"`.
* **fetch:** Since it doesn't support timeouts natively, use `AbortController` with `setTimeout()` to abort the request after the desired duration.
* In production, create a reusable API utility or Axios instance with a default timeout and handle timeout errors globally using interceptors or centralized error handling.

This demonstrates not only how to implement timeouts but also how to standardize them across a large React application.

# 4. Interceptors

Interceptors run **before request** or **after response**.

Used for

* Adding token
* Logging
* Global error handling
* Refresh token
* Retry failed requests

---

## Request Interceptor

```javascript
api.interceptors.request.use(config => {

    config.headers.Authorization =
        `Bearer ${token}`;

    return config;
});
```

Every request automatically gets the token.

---

## Response Interceptor

```javascript
api.interceptors.response.use(
    response => response,

    error => {
        console.log(error);

        return Promise.reject(error);
    }
);
```

# 7. JWT (JSON Web Token)

JWT is a token used for stateless authentication.

Flow

```

↓

↓

↓

↓

↓

```

---

JWT contains

* Header
* Payload
* Signature

Do **not** store sensitive information (like passwords) in the payload—it is only encoded, not encrypted.

# 10. Retry

Sometimes requests fail because of

* Network issue
* Temporary server issue
* Timeout
* Rate limiting (429)

Retry example

```
API

↓

Failed

↓

Retry

↓

Success
```

Example

```javascript
async function fetchUsers(retry = 3) {
    try {
        return await api.get("/users");
    } catch (err) {
        if (retry > 0) {
            return fetchUsers(retry - 1);
        }
        throw err;
    }
}
```

**Best Practice:** Use **exponential backoff** (e.g., wait 1s, then 2s, then 4s) instead of retrying immediately to avoid overloading the server.

Do **not** retry requests for client errors like `400` or `401` unless there's a specific recovery flow (such as refreshing a token).

# 11. Cancellation

Suppose user searches

```

ab

```

Old requests may still be running.

Need cancellation.

---

Using AbortController (fetch)

```javascript
const controller = new AbortController();

fetch("/users", {
    signal: controller.signal
});

controller.abort();
```

---

Axios (modern versions)

```javascript
const controller = new AbortController();

axios.get("/users", {
    signal: controller.signal
});

controller.abort();
```

---

React Example

```javascript
useEffect(() => {
    const controller = new AbortController();

    fetch("/users", {
        signal: controller.signal
    });

    return () => controller.abort();

}, []);
```

This prevents memory leaks and avoids updating state after the component unmounts.

# Best Practices

* Create a single Axios instance.
* Store `baseURL` in environment variables.
* Use request/response interceptors.
* Keep API calls in a dedicated service layer.
* Never hardcode URLs or tokens.
* Handle errors globally.
* Cancel unnecessary requests.
* Implement refresh token flow for expired access tokens.
* Retry only transient failures (e.g., network issues, 429, 503) with exponential backoff.
* Use loading and error states for better UX.
* Validate API responses before updating UI.

# Common React Interview Questions (6 Years Experience)

### 1. Why do most React projects prefer Axios over fetch?

**Answer:** Axios provides automatic JSON parsing, better error handling, interceptors, timeout support, request cancellation, and easier configuration with base URLs.

---

### 2. What is the difference between Authentication and Authorization?

**Answer:**

* Authentication verifies **who the user is**.
* Authorization determines **what the user is allowed to access**.

---

### 3. What is the difference between PUT and PATCH?

**Answer:**

* `PUT` replaces the entire resource.
* `PATCH` updates only specific fields.

---

### 4. What are Axios interceptors?

**Answer:** Interceptors allow you to modify requests before they are sent (e.g., attach JWT) and process responses globally (e.g., refresh expired tokens, log errors).

---

### 5. How do you handle expired JWT tokens?

**Answer:** When an API returns `401 Unauthorized`, use the refresh token to request a new access token, update the stored token, and retry the original request.

---

### 6. How do you cancel an API request in React?

**Answer:** Use `AbortController` and call `controller.abort()` in the cleanup function of `useEffect` to cancel pending requests.

---

### 7. Why shouldn't you store JWT in localStorage?

**Answer:** `localStorage` is accessible to JavaScript, making it vulnerable to XSS attacks. HttpOnly secure cookies are generally safer for storing authentication tokens.

---

### 8. How do you organize API calls in a large React application?

**Answer:** Create a reusable Axios instance, keep API logic in a dedicated `api/` or `services/` layer, use interceptors for common behavior, and avoid calling APIs directly from UI components.

---

### 9. When should you retry a failed API request?

**Answer:** Retry only transient failures like network issues, `429`, or temporary server errors (`503`). Avoid retrying client errors like `400` unless there's a specific recovery strategy.

---

### 10. What happens if you don't cancel pending requests when a component unmounts?

**Answer:** The request may complete after the component is unmounted, leading to unnecessary work and potentially attempting to update stale state. Cancelling requests helps avoid these issues and conserves resources.
