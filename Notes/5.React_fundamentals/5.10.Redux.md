# React JS — Redux

**Redux** is a predictable state-management library used to manage **shared application state** in a centralized store.

### Core flow ⭐

```text
UI
 ↓
dispatch(action)
 ↓
Reducer
 ↓
Store updates
 ↓
UI reads updated state
```

> **Action describes what happened → Reducer calculates the new state → Store holds the state → Selector reads the state → Dispatch sends the action.**

---

# 1. Store

The **Store** holds the application's Redux state.

With modern Redux, you normally create it using **Redux Toolkit**:

```jsx
import { configureStore } from "@reduxjs/toolkit";
import counterReducer from "./counterSlice";

const store = configureStore({
  reducer: {
    counter: counterReducer
  }
});
```

State structure:

```text
store
 └── counter
      ├── value
      └── ...
```

### React integration

Wrap your application with `Provider`:

```jsx
import { Provider } from "react-redux";

<Provider store={store}>
  <App />
</Provider>
```

Now components can access the Redux store.

### Important ⭐

> **Store is the single centralized container for Redux state.**

In larger applications, the store usually contains multiple **slices** rather than one huge reducer.

---

# 2. Actions

An **action** describes **what happened**.

An action is a plain object containing a required `type`.

```jsx
{
  type: "counter/increment"
}
```

Action with data:

```jsx
{
  type: "counter/incrementBy",
  payload: 5
}
```

### Example

Using Redux Toolkit:

```jsx
const incrementBy = (amount) => ({
  type: "counter/incrementBy",
  payload: amount
});
```

### Important

An action should describe an **event**, not directly modify state.

```text
❌ "change count to 10"
✅ "user incremented counter"
```

---

# 3. Reducers

A **reducer** is a function that determines the **new state based on the current state and action**.

Conceptually:

```jsx
(previousState, action) => newState
```

Example:

```jsx
function counterReducer(state = { value: 0 }, action) {
  switch (action.type) {
    case "counter/increment":
      return {
        ...state,
        value: state.value + 1
      };

    default:
      return state;
  }
}
```

### Reducer rules ⭐

A reducer should be:

* Predictable
* Synchronous
* Free of side effects
* Not directly mutate state in traditional Redux

❌

```jsx
state.value++;
return state;
```

✅ Traditional Redux:

```jsx
return {
  ...state,
  value: state.value + 1
};
```

### Redux Toolkit difference

Redux Toolkit uses **Immer**, so this is safe inside an RTK reducer:

```jsx
const counterSlice = createSlice({
  name: "counter",
  initialState: { value: 0 },
  reducers: {
    increment(state) {
      state.value++;
    }
  }
});
```

Immer internally produces the immutable update.

# 4. Dispatch

`dispatch()` sends an action to Redux.

```jsx
const dispatch = useDispatch();

dispatch({
  type: "counter/increment"
});
```

With Redux Toolkit:

```jsx
dispatch(increment());
```

With payload:

```jsx
dispatch(incrementBy(5));
```

### Flow

```text
dispatch(action)
      ↓
Redux Store
      ↓
Reducer receives action
      ↓
New state
      ↓
Subscribed components update
```

### Example

```jsx
function Counter() {
  const dispatch = useDispatch();

  return (
    <button onClick={() => dispatch(increment())}>
      Increment
    </button>
  );
}
```

---

# 5. Selectors

A **selector** is a function used to **read/derive data from Redux state**.

Simple selector:

```jsx
const selectCount = (state) => state.counter.value;
```

Use it:

```jsx
const count = useSelector(selectCount);
```

### Why selectors?

Instead of components depending directly on the entire state structure:

```jsx
const count = useSelector(
  state => state.counter.value
);
```

you can centralize the state access:

```jsx
const selectCount = state => state.counter.value;
```

Then:

```jsx
const count = useSelector(selectCount);
```

### Derived data

Selectors can calculate data:

```jsx
const selectCompletedTodos = (state) =>
  state.todos.filter(todo => todo.completed);
```

For expensive derived calculations, **memoized selectors** can be created using tools such as Reselect/RTK's selector utilities.

### Important ⭐

> **Selectors read state; they don't modify state.**

# Complete Example

Using **Redux Toolkit**, which is the recommended modern Redux approach:

### `counterSlice.js`

```jsx
import { createSlice } from "@reduxjs/toolkit";

const counterSlice = createSlice({
  name: "counter",

  initialState: {
    value: 0
  },

  reducers: {
    increment(state) {
      state.value += 1;
    },

    decrement(state) {
      state.value -= 1;
    },

    incrementBy(state, action) {
      state.value += action.payload;
    }
  }
});

export const {
  increment,
  decrement,
  incrementBy
} = counterSlice.actions;

export default counterSlice.reducer;
```

### Store

```jsx
const store = configureStore({
  reducer: {
    counter: counterReducer
  }
});
```

### Selector

```jsx
const selectCount = state => state.counter.value;
```

### Component

```jsx
function Counter() {
  const count = useSelector(selectCount);
  const dispatch = useDispatch();

  return (
    <>
      <p>{count}</p>

      <button onClick={() => dispatch(increment())}>
        +
      </button>

      <button onClick={() => dispatch(incrementBy(5))}>
        +5
      </button>
    </>
  );
}
```

# Redux Architecture ⭐

```text
                 ┌──────────────┐
                 │     Store    │
                 │              │
                 │  Redux State │
                 └──────▲───────┘
                        │
                        │ new state
                        │
                 ┌──────┴───────┐
                 │   Reducer    │
                 └──────▲───────┘
                        │
                        │ Action
                        │
UI ── dispatch() ───────┘

UI ── useSelector() ──→ Store
```

### One-way data flow

```text
User interaction
      ↓
dispatch(action)
      ↓
Reducer
      ↓
Store state changes
      ↓
Selector
      ↓
Component re-renders
```

# Quick Interview Revision ⭐

| Concept      | Purpose                       |
| ------------ | ----------------------------- |
| **Store**    | Holds centralized Redux state |
| **Action**   | Describes what happened       |
| **Reducer**  | Calculates new state          |
| **Dispatch** | Sends action to Redux         |
| **Selector** | Reads/derives state           |

### ⭐ One-line definitions

**Store:**

> Central container that holds Redux state.

**Action:**

> Plain object describing an event/change.

**Reducer:**

> Pure logic that calculates the next state from current state + action.

**Dispatch:**

> Mechanism used to send an action to the Redux store.

**Selector:**

> Function that reads or derives data from Redux state.

### Most important flow to remember

```text
Action → Dispatch → Reducer → Store → Selector → UI
```

> **For modern projects, prefer Redux Toolkit (`configureStore`, `createSlice`, `createAsyncThunk`, RTK Query) instead of writing traditional Redux boilerplate manually.**
