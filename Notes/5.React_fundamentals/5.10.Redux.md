# React Fundamentals - Redux (Core Concepts)

> Redux is a **predictable state management library** used to manage **global/shared state** across the application.

---

# Why Redux?

Without Redux:

```
App
 ├── Header
 ├── Sidebar
 ├── ProductList
 └── Cart
```

Suppose **Cart Count** is needed in:

* Header
* Product Page
* Checkout
* Payment

Passing state through multiple components (**prop drilling**) becomes difficult.

Redux stores shared state in one place.

```
             Redux Store
                 │
     ┌───────────┼───────────┐
 Header      Product      Checkout
```

---

# Redux Flow (Most Important)

```
User Click

     ↓

dispatch(action)

     ↓

Reducer

     ↓

New State

     ↓

Store Updates

     ↓

UI Re-renders
```

Remember this flow for interviews.

---

# Redux Principles

### 1. Single Source of Truth

Entire application state is stored in one store.

```
Store
 ├── auth
 ├── users
 ├── products
 └── cart
```

---

### 2. State is Read-only

Never modify state directly.

❌ Wrong

```js
state.count++;
```

✅ Correct

```js
return {
  ...state,
  count: state.count + 1
};
```

---

### 3. Changes happen through Reducers

Reducer decides how state changes.

---

# 1. Store

## What is Store?

Store holds the complete application state.

Think of it as a **central database in memory**.

```
Store

{
   user:{},
   cart:[],
   products:[],
   theme:"dark"
}
```

Creating store (Redux Toolkit)

```js
import { configureStore } from "@reduxjs/toolkit";

const store = configureStore({
  reducer: {
    cart: cartReducer,
    auth: authReducer
  }
});
```

Provide store to React

```jsx
import { Provider } from "react-redux";

<Provider store={store}>
   <App />
</Provider>
```

Without `Provider`, React components cannot access Redux.

---

# 2. Actions

## What is Action?

An action describes **what happened**.

It is a plain JavaScript object.

Example

```js
{
   type: "cart/addItem"
}
```

With payload

```js
{
   type: "cart/addItem",
   payload: product
}
```

Think of actions as **events**.

Examples

```
User Logged In

Product Added

Logout

Theme Changed

Language Changed
```

Redux Toolkit automatically creates action creators.

Example

```js
cartSlice.actions.addItem(product);
```

---

# 3. Reducers

## What is Reducer?

Reducer is a **pure function** that receives

* Current State
* Action

Returns

* New State

```
Current State

      +

Action

      ↓

Reducer

      ↓

New State
```

Example

```js
function counterReducer(state, action) {

   switch(action.type){

      case "increment":
         return {
            ...state,
            count: state.count + 1
         };

      default:
         return state;
   }

}
```

Redux Toolkit (recommended)

```js
const counterSlice = createSlice({
  name: "counter",
  initialState: {
    count: 0
  },
  reducers: {
    increment(state) {
      state.count++;
    }
  }
});
```

> **Why is mutation (`state.count++`) allowed here?**
>
> Redux Toolkit uses **Immer** internally. It lets you write mutable-looking code but produces a new immutable state behind the scenes.

---

# Pure Function (Interview Question)

Reducers must be pure.

Same input → Same output

❌ Wrong

```js
state.count = Math.random();
```

```js
fetch("/users");
```

```js
new Date();
```

These introduce side effects.

✅ Correct

```js
return {
   ...state,
   count: state.count + 1
};
```

---

# 4. Dispatch

## What is Dispatch?

Dispatch sends an action to Redux.

```
dispatch(action)
```

Example

```js
const dispatch = useDispatch();

dispatch(addItem(product));
```

Internally

```
dispatch()

      ↓

Reducer Executes

      ↓

Store Updated

      ↓

React Re-renders
```

Another example

```js
dispatch(removeItem(id));
```

---

# 5. Selectors

Selectors read data from Redux Store.

Example

```js
const cart = useSelector(
   state => state.cart.items
);
```

Another example

```js
const username = useSelector(
   state => state.auth.user.name
);
```

Selectors are **read-only**.

They never update state.

---

# Why Selectors?

Without selector

```
Store

↓

Entire Store

↓

Component
```

Component receives unnecessary data.

With selector

```
Store

↓

Only Cart Count

↓

Header
```

Less unnecessary rendering.

---

# Derived Selectors

Selectors can compute values.

Example

```js
const totalPrice = useSelector(state =>
   state.cart.items.reduce(
      (sum, item) => sum + item.price,
      0
   )
);
```

For expensive calculations or reusable logic, use **Reselect** (`createSelector`) to memoize selectors.

```
Button Click

      ↓
```

# Redux Toolkit (Modern Redux)

Modern React projects use **Redux Toolkit (RTK)** instead of writing Redux manually.

Benefits

* Less boilerplate
* Built-in Immer
* Better developer experience
* Easier configuration
* Recommended by Redux team

Main APIs

```js
configureStore()

createSlice()

createAsyncThunk()

useDispatch()

useSelector()
```

# Common Mistakes

### 1. Mutating state (Plain Redux)

❌

```js
state.items.push(product);
```

Use immutable updates in plain Redux. (In Redux Toolkit reducers, Immer safely handles this pattern.)

---

### 2. Updating Store directly

❌

```js
store.cart.push(item);
```

Always dispatch an action.

---

### 3. Keeping local UI state in Redux

Wrong

```
Modal Open

Input Value

Tooltip Visible
```

Keep these in component state (`useState`).

Use Redux only for **shared/global state**.

---

### 4. Fetching API inside Reducer

Reducers must stay pure.

Use

* `createAsyncThunk`
* RTK Query
* Middleware (Thunk)

---

### 5. Selecting Entire Store

❌

```js
const store = useSelector(state => state);
```

This causes unnecessary re-renders.

Select only what the component needs.

---

# When to Use Redux?

Use Redux when:

* Authentication state
* Shopping cart
* User profile
* Theme
* Language
* Notifications
* Shared filters
* Data shared across many components

Avoid Redux for:

* Input fields
* Modal visibility (unless shared globally)
* Local form state
* Component-specific UI state

---

# React State vs Redux

| React State (`useState`) | Redux                          |
| ------------------------ | ------------------------------ |
| Local state              | Global state                   |
| One component            | Multiple components            |
| Simple updates           | Complex application state      |
| No Provider needed       | Requires Store & Provider      |
| Best for UI state        | Best for shared business state |

---

# Revision Notes

| Concept       | Purpose                        |
| ------------- | ------------------------------ |
| Store         | Holds global application state |
| Action        | Describes what happened        |
| Reducer       | Updates state based on action  |
| Dispatch      | Sends action to Redux          |
| Selector      | Reads data from store          |
| Provider      | Makes store available to React |
| Redux Toolkit | Modern way to write Redux      |

# Cheat Sheet

```js
// Read state
const cart = useSelector(
  state => state.cart.items
);

// Dispatch action
const dispatch = useDispatch();

dispatch(addItem(product));

// Store
configureStore({
  reducer: {
    cart: cartReducer
  }
});

// Slice
createSlice({
  name: "cart",
  initialState,
  reducers: {
    addItem(state, action) {}
  }
});
```

## Middleware (Short Interview Explanation)

A **middleware** is a function that sits **between `dispatch(action)` and the reducer**.

It can **intercept actions** to perform extra work before they reach the reducer.

```text
Component
    ↓
dispatch(action)
    ↓
Middleware
    ↓
Reducer
    ↓
Store Updated
```

### Why do we need Middleware?

Reducers must be **pure** and cannot perform side effects like:

* API calls
* Logging
* Async operations
* Analytics
* Authentication checks

Middleware handles these tasks.

---

## Example

Without middleware:

```js
dispatch(fetchUsers());
```

Middleware:

```text
Receive Action
      ↓
Call API
      ↓
Success
      ↓
dispatch(usersLoaded(data))
      ↓
Reducer Updates Store
```

---

## Common Redux Middlewares

* **Redux Thunk** → Handles asynchronous logic (most common).
* **Redux Saga** → Complex async workflows.
* **RTK Query** → Data fetching and caching (recommended with Redux Toolkit).

---

## Easy Interview Definition

> **Middleware is a function that intercepts dispatched actions before they reach the reducer, allowing you to perform side effects such as API calls, logging, authentication, or asynchronous operations.**

# Common Interview Questions (6 Years Experience)

### 1. Explain the Redux flow.

```
UI Event
   ↓
dispatch(action)
   ↓
Reducer
   ↓
Store Updates
   ↓
useSelector gets new state
   ↓
React Re-renders
```

---

### 2. What is the difference between Redux and Context API?

| Redux                                        | Context API                                            |
| -------------------------------------------- | ------------------------------------------------------ |
| State management library                     | React feature for passing data                         |
| Optimized updates with selectors             | Can cause wider re-renders if not structured carefully |
| Includes DevTools, middleware, async support | No built-in middleware or DevTools                     |
| Better for large, complex apps               | Good for simple shared state (theme, locale, auth)     |

---

### 3. What is a Reducer?

A pure function that takes the current state and an action, then returns the next state.

---

### 4. Why are reducers called pure functions?

Because they:

* Produce the same output for the same input.
* Do not mutate state.
* Do not perform side effects (API calls, timers, random values, etc.).

---

### 5. What is the purpose of `dispatch()`?

It sends an action to the Redux store, triggering the reducer to calculate the next state.

---

### 6. What is the difference between `useSelector()` and `useDispatch()`?

* `useSelector()` reads data from the store.
* `useDispatch()` sends actions to update the store.

---

### 7. Why is Redux Toolkit recommended over plain Redux?

* Less boilerplate.
* Simpler APIs (`configureStore`, `createSlice`).
* Built-in Immer for immutable updates.
* Better defaults and developer experience.

---

### 8. When should you avoid using Redux?

Avoid Redux for component-specific UI state such as form inputs, dropdown visibility, or modal open/close state. Use `useState` or `useReducer` for those scenarios.
