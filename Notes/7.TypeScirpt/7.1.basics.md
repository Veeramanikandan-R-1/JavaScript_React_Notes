# TypeScript — Senior React Developer Notes

For a **5-year React developer**, focus less on basic syntax and more on **type modeling, generics, utility types, React typing, narrowing, and real-world patterns**.

---

## 1. What is TypeScript?

**TypeScript (TS)** is a statically typed superset of JavaScript.

```text
TypeScript
    ↓ compile/transpile
JavaScript
    ↓
Browser / Node.js
```

TypeScript does **not run directly in the browser**.

### Benefits

* Compile-time type checking
* Better IDE/autocomplete
* Safer refactoring
* Better documentation
* Detects many bugs before runtime
* Excellent for large React applications

---

# 2. Type Inference ⭐

TS can automatically determine the type.

```ts
let name = "John";     // string
let age = 25;          // number
let active = true;     // boolean
```

You don't always need explicit types.

```ts
const count: number = 10;
```

Prefer inference when the type is obvious.

---

# 3. Basic Types

```ts
let name: string = "John";
let age: number = 25;
let isAdmin: boolean = true;

let value: null = null;
let data: undefined = undefined;
```

Arrays:

```ts
const names: string[] = ["John", "Sam"];
const numbers: Array<number> = [1, 2, 3];
```

---

# 4. `any` vs `unknown` ⭐⭐⭐

### `any`

Disables type checking.

```ts
let value: any = "hello";

value.foo.bar(); // TypeScript won't complain
```

Avoid `any` whenever possible.

### `unknown`

Safe alternative.

```ts
let value: unknown = "hello";
```

You must narrow it before using it:

```ts
if (typeof value === "string") {
  console.log(value.toUpperCase());
}
```

### Interview answer

> `any` disables type safety, whereas `unknown` requires type checking before performing operations.

---

# 5. `void`

Usually used for functions that don't return a value.

```ts
function logMessage(message: string): void {
  console.log(message);
}
```

---

# 6. `never` ⭐⭐

Represents a value that **never occurs**.

Common example:

```ts
function throwError(message: string): never {
  throw new Error(message);
}
```

Also useful for exhaustive checks:

```ts
type Status = "loading" | "success" | "error";

function handleStatus(status: Status) {
  switch (status) {
    case "loading":
      return "Loading";
    case "success":
      return "Success";
    case "error":
      return "Error";
    default:
      return assertNever(status);
  }
}

function assertNever(value: never): never {
  throw new Error(`Unexpected value: ${value}`);
}
```

```ts
type User = {
  id: number;

const user: User = {
  id: 1,
  name: "John",
  email: "john@test.com"

```

# 8. Interface ⭐⭐⭐

Commonly used for object contracts.

```ts
interface User {
  id: number;
  name: string;
  email: string;
}
```

Usage:

```ts
const user: User = {
  id: 1,
  name: "John",
  email: "john@test.com"
};
```

### Interface extension

```ts
interface Admin extends User {
  permissions: string[];
}
```

---

# 9. `type` vs `interface` ⭐⭐⭐

Both can describe object shapes.

### Interface

```ts
interface User {
  name: string;
}
```

### Type

```ts
type User = {
  name: string;
};
```

`type` is more flexible for:

* Union types
* Intersection types
* Tuples
* Mapped types
* Conditional types

```ts
type ID = string | number;
```

Interfaces support declaration merging:

```ts
interface User {
  name: string;
}

interface User {
  age: number;
}
```

Result:

```ts
// User has name + age
```

### Practical rule

> Use either consistently. `interface` is common for object contracts; `type` is especially useful when composing types.

# 10. Optional Properties

```ts
interface User {
  id: number;
  name: string;
  age?: number;
}
```

Valid:

```ts
const user: User = {
  id: 1,
  name: "John"
};
```

`age` is effectively:

```ts
number | undefined
```

---

# 11. Readonly

Prevent reassignment.

```ts
interface User {
  readonly id: number;
  name: string;
}

const user: User = {
  id: 1,
  name: "John"
};

user.name = "Sam"; // OK
user.id = 2;       // Error
```

---

# 12. Union Types ⭐⭐⭐

A value can be one of several types.

```ts
let id: string | number;

id = 10;
id = "ABC";
```

Very useful in React:

```ts
type Status = "loading" | "success" | "error";
```

```ts
function getMessage(status: Status) {
  // ...
}
```

---

# 13. Intersection Types

Combines multiple types.

```ts
type Person = {
  name: string;
};

type Employee = {
  employeeId: number;
};

type EmployeeDetails = Person & Employee;
```

Now:

```ts
const employee: EmployeeDetails = {
  name: "John",
  employeeId: 101
};
```

Think:

```text
Union        → A OR B
Intersection → A AND B
```

---

# 14. Literal Types ⭐⭐

Restrict values to specific literals.

```ts
type Direction = "left" | "right" | "up" | "down";
```

```ts
let direction: Direction;

direction = "left";  // OK
direction = "hello"; // Error
```

Excellent for React state:

```ts
const [status, setStatus] =
  useState<"idle" | "loading" | "success" | "error">("idle");
```

---

# 15. Function Types

```ts
type Add = (a: number, b: number) => number;

const add: Add = (a, b) => a + b;
```

Or:

```ts
function add(a: number, b: number): number {
  return a + b;
}
```

Callback:

```ts
function processUser(
  user: User,
  callback: (user: User) => void
) {
  callback(user);
}
```

---

# 16. Type Narrowing ⭐⭐⭐

TypeScript can narrow a union based on runtime checks.

```ts
function printValue(value: string | number) {
  if (typeof value === "string") {
    console.log(value.toUpperCase());
  } else {
    console.log(value.toFixed(2));
  }
}
```

Common narrowing techniques:

```ts
typeof
instanceof
in
=== / !==
Array.isArray()
```

---

# 17. Type Guards ⭐⭐⭐

Custom function that tells TypeScript what type something is.

```ts
interface User {
  name: string;
}

function isUser(value: unknown): value is User {
  return (
    typeof value === "object" &&
    value !== null &&
    "name" in value
  );
}
```

Then:

```ts
if (isUser(data)) {
  console.log(data.name);
}
```

---

# 18. Type Assertion

Tell TypeScript that you know the type.

```ts
const input =
  document.getElementById("email") as HTMLInputElement;
```

Alternative:

```ts
const input =
  <HTMLInputElement>document.getElementById("email");
```

In React/TSX, prefer `as`.

### Important

Type assertion **doesn't perform runtime conversion**.

```ts
const value = "123" as unknown as number;
```

It doesn't actually convert the string to a number.

# 19. Enums

```ts
enum Role {
  ADMIN,
  USER,
  GUEST
}
```

```ts
const role = Role.ADMIN;
```

String enum:

```ts
enum Status {
  Loading = "LOADING",
  Success = "SUCCESS",
  Error = "ERROR"
}
```

### Modern practical approach

Often prefer union literals:

```ts
type Status = "loading" | "success" | "error";
```

They are lightweight and work very well with React.

---

# 20. Tuples

Fixed number/order of elements.

```ts
const user: [string, number] = ["John", 25];
```

Wrong:

```ts
const user: [string, number] = [25, "John"];
```

Named tuple:

```ts
type User = [name: string, age: number];
```

---

# 21. Generics ⭐⭐⭐⭐⭐

One of the most important TypeScript concepts.

Generics allow reusable code while preserving type information.

```ts
function identity<T>(value: T): T {
  return value;
}

const name = identity("John");
// string

const age = identity(25);
// number
```

Without generic:

```ts
function identity(value: any): any {
  return value;
}
```

`any` loses type safety.

---

# 22. Generic Constraints

Restrict what types can be passed.

```ts
function getLength<T extends { length: number }>(
  value: T
) {
  return value.length;
}
```

Valid:

```ts
getLength("Hello");
getLength([1, 2, 3]);
```

---

# 23. Generic Interfaces

```ts
interface ApiResponse<T> {
  data: T;
  success: boolean;
  message?: string;
}
```

Usage:

```ts
type UserResponse = ApiResponse<User>;
```

```ts
type ProductResponse = ApiResponse<Product>;
```

Very common for API response typing.

# 24. Utility Types ⭐⭐⭐⭐⭐

Extremely important for real projects.

### `Partial<T>`

Makes all properties optional.

```ts
type UserUpdate = Partial<User>;
```

Equivalent:

```ts
{
  id?: number;
  name?: string;
  email?: string;
}
```

Useful for PATCH/update objects.

---

### `Required<T>`

Makes everything required.

```ts
type RequiredUser = Required<User>;
```

---

### `Readonly<T>`

```ts
type ReadonlyUser = Readonly<User>;
```

---

### `Pick<T, K>`

Select properties.

```ts
type UserPreview = Pick<User, "id" | "name">;
```

---

### `Omit<T, K>`

Remove properties.

```ts
type CreateUser = Omit<User, "id">;
```

Very common:

```ts
type User = {
  id: number;
  name: string;
  email: string;
};

type CreateUser = Omit<User, "id">;
```

---

### `Record<K, T>`

Creates an object type with specific keys.

```ts
type UserRoles = Record<string, string[]>;
```

```ts
const roles: UserRoles = {
  john: ["admin"],
  sam: ["user"]
};
```

---

### `ReturnType<T>`

Gets a function's return type.

```ts
function getUser() {
  return {
    id: 1,
    name: "John"
  };
}

type User = ReturnType<typeof getUser>;
```

---

### `Parameters<T>`

Gets function parameter types as a tuple.

```ts
function login(email: string, password: string) {}

type LoginParams = Parameters<typeof login>;
// [email: string, password: string]
```

---

# 25. `keyof` ⭐⭐⭐

Gets the keys of a type.

```ts
interface User {
  id: number;
  name: string;
}

type UserKey = keyof User;
```

Result:

```ts
"id" | "name"
```

Useful:

```ts
function getValue<T, K extends keyof T>(
  obj: T,
  key: K
) {
  return obj[key];
}
```

---

# 26. `typeof`

Gets the TypeScript type of a value.

```ts
const user = {
  id: 1,
  name: "John"
};

type User = typeof user;
```

Useful combination:

```ts
type UserKey = keyof typeof user;
```

---

# 27. Mapped Types ⭐⭐⭐

Transform properties of an existing type.

```ts
type Optional<T> = {
  [K in keyof T]?: T[K];
};
```

Usage:

```ts
type PartialUser = Optional<User>;
```

This is essentially the concept behind utility types like `Partial`.

---

# 28. Conditional Types ⭐⭐⭐

Type-level `if/else`.

```ts
type IsString<T> =
  T extends string ? true : false;
```

```ts
type A = IsString<string>; // true
type B = IsString<number>; // false
```

Mostly encountered when building advanced reusable TypeScript types/libraries.

# 29. `extends` Has Multiple Meanings

Important interview point.

### Generic constraint

```ts
function getName<T extends User>(user: T) {}
```

### Interface inheritance

```ts
interface Admin extends User {}
```

### Conditional type

```ts
type Result<T> =
  T extends string ? string : number;
```

Same keyword, different contexts.

# 34. React `useReducer`

```tsx
type State = {
  count: number;
};

type Action =
  | { type: "increment" }
  | { type: "decrement" }
  | { type: "reset"; payload: number };

function reducer(
  state: State,
  action: Action
): State {
  switch (action.type) {
    case "increment":
      return { count: state.count + 1 };

    case "decrement":
      return { count: state.count - 1 };

    case "reset":
      return { count: action.payload };

    default:
      return state;
  }
}
```

Discriminated unions make reducer actions type-safe.

---

# 35. Discriminated Unions ⭐⭐⭐⭐

Very useful in React/Redux.

```ts
type Action =
  | { type: "ADD"; payload: number }
  | { type: "REMOVE"; payload: number }
  | { type: "RESET" };
```

Now TypeScript knows the payload based on `type`.

```ts
function reducer(action: Action) {
  if (action.type === "ADD") {
    action.payload; // number
  }

  if (action.type === "RESET") {
    // payload doesn't exist
  }
}
```

# 37. React Component Types

```tsx
const Component: React.FC<Props> = ({
  name
}) => {
  return <div>{name}</div>;
};
```

However, you don't have to use `React.FC`.

Often preferred:

```tsx
function Component({ name }: Props) {
  return <div>{name}</div>;
}
```

### Practical recommendation

Prefer explicitly typing props rather than using `React.FC` by default.

# 38. API Response Typing ⭐⭐⭐⭐⭐

Define API models:

```ts

  name: string;
  email: string;
```

```ts
const response = await getUsers();

response.data.forEach(user => {
  console.log(user.name);

```

# 41. Optional Chaining & Nullish Coalescing

These are JavaScript features but heavily used with TypeScript.

### Optional chaining

```ts
user?.profile?.name;
```

### Nullish coalescing

```ts
const name = user.name ?? "Guest";
```

Difference from `||`:

```ts
0 ?? 10   // 0
0 || 10   // 10
```

# 42. Non-null Assertion `!`

Tells TS:

> I guarantee this isn't null/undefined.

```ts

  document.getElementById("root")!;
```

Avoid excessive use.

Prefer:

```ts
element?.focus();
```

when appropriate.

# 47. Type vs Runtime ⭐⭐⭐

Important concept:

```ts
interface User {
  id: number;
}
```

The interface disappears after compilation.

TypeScript types provide **compile-time safety**, not runtime validation.

Therefore API data can still be invalid:

```text
Backend
   ↓
JSON
   ↓
Runtime data
   ↓
TypeScript does NOT automatically validate it
```

For untrusted external data, runtime validation libraries such as Zod can complement TypeScript.

---

# 48. `unknown` + API Data

For external/untrusted data:

```ts
const data: unknown = await response.json();
```

Then validate/narrow it before trusting it.

This is safer than:

```ts
const data: any = await response.json();
```

# 49. Common TypeScript Mistakes

### ❌ Excessive `any`

```ts
const user: any = response;
```

Prefer:

```ts
const user: User = response;
```

or validate unknown external data.

---

### ❌ Overusing type assertions

```ts
const user = data as User;
```

This doesn't validate `data`.

---

### ❌ Repeating types

```ts
function updateUser(
  user: {
    id: number;
    name: string;
  }
) {}
```

If the model is reused, define:

```ts
interface User {
  id: number;
  name: string;
}
```

---

### ❌ Overengineering types

Don't create complicated conditional/mapped types when a simple interface is enough.

# 🎯 Quick Interview Cheat Sheet

| Concept             | Remember                            |
| ------------------- | ----------------------------------- |
| `any`               | Disables type safety                |
| `unknown`           | Safe unknown value; narrow first    |
| `never`             | Value/function path never occurs    |
| `void`              | Function returns nothing            |
| `type`              | Flexible type composition           |
| `interface`         | Object contract + extension/merging |
| `union` `\|`        | OR                                  |
| `intersection` `&`  | AND                                 |
| `keyof`             | Keys of a type                      |
| `typeof`            | Type of a value                     |
| `extends`           | Constraint/inheritance/conditional  |
| `as`                | Type assertion                      |
| `Partial<T>`        | All optional                        |
| `Required<T>`       | All required                        |
| `Pick<T,K>`         | Select properties                   |
| `Omit<T,K>`         | Remove properties                   |
| `Record<K,T>`       | Object mapping                      |
| `ReturnType<T>`     | Function return type                |
| `Parameters<T>`     | Function parameter tuple            |
| Generics            | Reusable type-safe code             |
| Type guard          | Runtime check → type narrowing      |
| Discriminated union | Type-safe variants/actions          |
| `.tsx`              | TS + JSX                            |
| `strict`            | Strong type checking                |

### Senior-level takeaway

> **TypeScript isn't about adding types everywhere. It's about modeling your application's data and behavior so that incorrect states become difficult to represent while keeping the code maintainable.**

For React specifically, the highest-value combination is **Generics + Union Types + Type Narrowing + Utility Types + Discriminated Unions + React Props/Events/Hooks + API typing + strict mode**.
