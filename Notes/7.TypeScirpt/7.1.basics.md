# TypeScript (Highly Preferred for React Interviews)

> You are not expected to know every TypeScript feature. Interviewers mostly check whether you can write type-safe React applications, APIs, hooks, reusable components, and understand why TypeScript prevents runtime bugs.

---

# 1. Types

## What is TypeScript?

TypeScript is a **superset of JavaScript** that adds **static typing**.

Instead of finding errors at runtime, many errors are caught while coding.

```ts
let name: string = "John";
let age: number = 25;
let isAdmin: boolean = false;
```

---

## Common Primitive Types

```ts
string
number
boolean
null
undefined
symbol
bigint
```

Example

```ts
let username: string = "Veera";
let salary: number = 50000;
let active: boolean = true;
```

---

## Arrays

```ts
let users: string[] = ["John", "Peter"];

let marks: number[] = [90, 80];
```

or

```ts
let users: Array<string> = [];
```

---

## Object Types

```ts
const user: {
    id: number;
    name: string;
} = {
    id: 1,
    name: "John"
};
```

Usually interfaces are preferred instead.

---

## Union Type

Variable can have multiple types.

```ts
let value: string | number;

value = "Hello";

value = 100;
```

Very common in React.

---

## Literal Types

Only specific values allowed.

```ts
type Status = "loading" | "success" | "error";

let state: Status = "loading";
```

Excellent for API states.

---

## Any

Disables type checking.

```ts
let value: any;

value = 100;

value = "Hello";
```

❌ Avoid whenever possible.

---

## Unknown

Safer version of any.

```ts
let value: unknown;

if(typeof value === "string"){
    console.log(value.toUpperCase());
}
```

---

## Void

Function returns nothing.

```ts
function log(): void{
    console.log("Hello");
}
```

---

## Never

Function never finishes.

```ts
function throwError(): never{
    throw new Error();
}
```

# 2. Interfaces

Interface defines the **shape of an object**.

```ts
interface User{
    id:number;
    name:string;
}
```

Usage

```ts
const user:User={
    id:1,
    name:"John"
}
```

---

## Optional Properties

```ts
interface User{
    id:number;
    name:string;
    email?:string;
}
```

---

## Readonly

```ts
interface User{
    readonly id:number;
}
```

Cannot modify later.

---

## Extending Interfaces

```ts
interface Person{
    name:string;
}

interface Employee extends Person{
    salary:number;
}
```

---

## Interface vs Type

### Interface

* Object shapes
* Can extend
* Can merge declarations

### Type

* Unions
* Intersections
* Primitive aliases
* Tuples

Interview answer:

> Use **interface** for object models and **type** when working with unions, intersections, or advanced type compositions.

# 3. Generics

Generics allow writing reusable code while preserving types.

Without generic

```ts
function identity(value:any){
    return value;
}
```

Problem

Returns `any`.

---

With Generic

```ts
function identity<T>(value:T):T{
    return value;
}
```

for arrow functions

```ts
const identity = <T>(value:T):T => {
    return value;
}
```

Usage

```ts
identity<string>("Hello");

identity<number>(10);
```

---

## Generic Interface

```ts
interface ApiResponse<T>{
    data:T;
    success:boolean;
}
```

Usage

```ts
type user = {
    name1: string
}

const response:ApiResponse<User> = {
    data:user,
    success:true
}

const response: ApiResponse<User> = {
    data: {
        name: "mani"
    },
    success: false
};
```

Very common in API handling.

---

## Generic Components

```tsx
interface TableProps<T>{
    data:T[];
}

function Table<T>({data}:TableProps<T>){
    return <div>{data.length}</div>;
}

// example react
import React from 'react';

interface ChildProps<T> {
  users: T[];
}

const Child = <T,>({ users }: ChildProps<T>) => { //command needed after T or it is interpreted as a JSX tag, not a generic.
  return (
    <div>
      Child
      {users.map((user) => (
        <p>{user}</p>
      ))}
    </div>
  );
};

export default Child;

```

# 4. Utility Types

Very common interview topic.

---

## Partial

Makes everything optional.

```ts
interface User{
    id:number;
    name:string;
}

type UpdateUser = Partial<User>;
```

Result

```ts
{
 id?:number;
 name?:string;
}
```

Used for update APIs.

---

## Required

Everything mandatory.

```ts
type UserData = Required<User>;
```

---

## Readonly

Makes properties immutable.

```ts
Readonly<User>
```

---

## Pick

Select only required properties.

```ts
type UserInfo = Pick<User,"id" | "name">;
```

---

## Omit

Remove properties.

```ts
type UserWithoutId = Omit<User,"id">;
```

---

## Record

### `Record` (Short Explanation)

`Record` is a TypeScript utility type used to create an object where **all keys have the same value type**.

**Syntax**

```ts
Record<KeyType, ValueType>
```

### Example

Without `Record`

```ts
type Roles = {
  admin: string;
  user: string;
};
```

With `Record`

```ts
type Roles = Record<"admin" | "user", string>;

const roles: Roles = {
  admin: "Administrator",
  user: "Normal User",
};
```

### When to use?

Use `Record` when you're creating **lookup objects**, **configuration objects**, **feature flags**, or **ID-to-object mappings** where all values have the same type.

> **Interview one-liner:**
> "`Record<K, V>` creates an object type where every key `K` maps to a value of type `V`."

---

## Exclude

Removes union members.

```ts
type Status = "A" | "B" | "C";

type NewStatus = Exclude<Status,"C">;
```

---

## Extract

Keeps matching members.

```ts
type NewStatus = Extract<Status,"A" | "C">;
```

---

## ReturnType

Gets function return type.

```ts
function getUser(){
    return {id:1};
}

type User = ReturnType<typeof getUser>;
```

# 5. Enums

Group of related constants.

```ts
enum Status{
    Loading,
    Success,
    Error
}
```

String enum

```ts
enum Role{
    Admin="ADMIN",
    User="USER"
}
```

Usage

```ts
if(role===Role.Admin){}
```

### Interview Tip

Nowadays many teams prefer

```ts
const ROLE = {
  ADMIN: "ADMIN",
  USER: "USER"
} as const;
```

instead of enums because it's simpler, tree-shakable, and aligns well with JavaScript.

# 6. Type Guards

Used to narrow types.

Example

```ts
function print(value:string | number){

    if(typeof value==="string"){
        console.log(value.toUpperCase());
    }else{
        console.log(value.toFixed(2));
    }

}
```

---

## instanceof

```ts
if(error instanceof Error){
    console.log(error.message);
}
```

---

## in Operator

```ts
if("salary" in employee){
    console.log(employee.salary);
}
```

---

## Custom Type Guard

```ts
interface Dog{
    bark():void;
}

interface Cat{
    meow():void;
}

function isDog(animal:Dog | Cat):animal is Dog{
    return "bark" in animal;
}
```

---

# 7. keyof

Returns property names.

```ts

    name:string;
}
```

```ts

```

Result

```ts
"id" | "name"
```

Useful for generic utilities.

# 11. Typing Hooks

## useState

```tsx
const [count,setCount]=useState<number>(0);
```

Object

```tsx
interface User{
    name:string;
}

const [user,setUser]=useState<User | null>(null);
```

---

## useRef

```tsx
const inputRef=useRef<HTMLInputElement>(null);
```

---

## useReducer

```tsx
interface State{
    count:number;
}

type Action=
| {type:"increment"}
| {type:"decrement"};
```

```ts
function reducer(
    state:State,
    action:Action
){
    switch(action.type){
        case "increment":
            return {count:state.count+1};
        case "decrement":
            return {count:state.count-1};
    }
}
```

---

## useContext

```tsx
interface UserContextType{
    user:User | null;
}

const UserContext =
createContext<UserContextType | null>(null);
```

---

## Custom Hook

```tsx
function useFetch<T>(url:string){

    const [data,setData]=useState<T | null>(null);

    return data;
}
```

Usage

```tsx
const users = useFetch<User[]>("/users");
```

This is one of the best real-world uses of **generics** in React.

# Real-world TypeScript Best Practices

✅ Avoid `any`

✅ Prefer `interface` for API models

✅ Use `type` for unions and utility compositions

✅ Use generics for reusable hooks/components

✅ Use utility types (`Pick`, `Omit`, `Partial`) instead of creating duplicate interfaces

✅ Always type API responses

```ts
interface ApiResponse<T>{
    data:T;
    success:boolean;
}
```

✅ Type custom hooks

✅ Prefer literal union types over enums when possible

# Short Revision Notes (Cheat Sheet)

| Topic      | Remember                                                            |
| ---------- | ------------------------------------------------------------------- |
| Types      | string, number, boolean, union, literal, unknown                    |
| Interface  | Defines object structure                                            |
| Type       | Aliases, unions, intersections                                      |
| Generic    | Reusable typed code (`<T>`)                                         |
| Partial    | Makes all fields optional                                           |
| Required   | Makes all fields required                                           |
| Pick       | Select specific fields                                              |
| Omit       | Remove specific fields                                              |
| Record     | Create object type with key/value mapping                           |
| Enum       | Group constants (literal unions are often preferred)                |
| Type Guard | `typeof`, `instanceof`, `in`, custom predicate                      |
| keyof      | Gets property names of a type                                       |
| typeof     | Gets type from a variable/value                                     |
| Props      | Create interfaces for component props                               |
| Hooks      | Type `useState`, `useRef`, `useReducer`, `useContext`, custom hooks |

# Common React TypeScript Interview Questions (6 Years)

### 1. Why use TypeScript in React?

**Answer:** It provides static type checking, catches errors at compile time, improves IDE support, refactoring, maintainability, and self-documentation.

---

### 2. Interface vs Type?

**Answer:** Use **interface** for object shapes and extension. Use **type** for unions, intersections, mapped types, and advanced compositions.

---

### 3. What are Generics?

**Answer:** They allow writing reusable, type-safe functions, components, and hooks while preserving the type information.

---

### 4. Explain `keyof`.

**Answer:** It returns a union of property names of a type (e.g., `"id" | "name"`), useful for generic utilities.

---

### 5. Explain `typeof` in TypeScript.

**Answer:** It derives a type from an existing variable or object, avoiding duplicate type definitions.

---

### 6. What are Utility Types?

**Answer:** Built-in helper types like `Partial`, `Pick`, `Omit`, `Readonly`, `Record`, etc., used to transform existing types without redefining them.

---

### 7. How do you type `useState`?

```tsx
const [user, setUser] = useState<User | null>(null);
```

---

### 8. How do you type component props?

Create an interface/type for the props and use it as the function parameter type.

---

### 9. How do you type API responses?

```ts
interface ApiResponse<T> {
  data: T;
  success: boolean;
}
```

Using a generic allows the same response wrapper to work with any data model.

---

### 10. How do Type Guards help?

They narrow union types at runtime so TypeScript knows which properties and methods are safe to access. This improves both type safety and code readability.
